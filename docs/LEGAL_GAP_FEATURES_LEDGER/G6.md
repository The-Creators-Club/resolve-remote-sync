  and zipping.
- **`.github/workflows/release-windows.yml`**:
  - The companion is scanned inside release.ps1.
  - The onboard.exe step now scans `--component onboarding`. On a refusal it
    deletes `onboarding/dist/onboard.exe` and writes the reason to the run
    summary, so publish_latest has nothing to publish. The companion
    artefact still uploads, in line with that step's existing contract.
  - release-macos.yml needed no edit, because it calls the two scripts
    above.
- **`tools/scan_frozen.py` (new, stdlib only).** It reads every
  `(dest, source, typecode)` triple in the PyInstaller workpath's `*.toc`
  files. It maps each source under `site-packages` to its owning distribution
  through that directory's `*.dist-info/RECORD`. It **fails** (exit 1) when:
  - a frozen distribution is not in the component's lock (markers are
    ignored);
  - a frozen copyleft distribution has no allowlist entry with a reason
    whose `targets` include the component;
  - a site-packages file is claimed by no RECORD.

  It exits 2 when there is nothing to scan. The freezer itself
  (`pyinstaller`, `pyinstaller-hooks-contrib`) and the first-party
  `ccsync-companion` are exempt. Components:
  - `companion`: judged against `companion/requirements.lock`.
  - `onboarding`: judged against `onboarding/requirements.lock`, which names
    no runtime dependency, so any third-party wheel leaking out of the
    companion venv fails.
- **`companion/build.spec` and both onboarding specs**:
  `excludes += setuptools, pkg_resources, _distutils_hack`. See the
  measurement below.

**Measured, not assumed.** I built both binaries for real in a scratch venv
made exactly the CI way: the lock with `--require-hashes`, then `--no-deps
-e`, then `pyinstaller==6.21.0`. Workpath and distpath were in the scratchpad,
so nothing in the repo's `dist/` changed.

- The first companion build froze **setuptools 84.0.0**, and the first
  onboard build froze setuptools and `packaging`. The cause is config.py's
  dead `except ImportError: import tomli` fallback (the package requires
  >=3.12). It resolved to setuptools' vendored tomli, and PyInstaller's
  setuptools hook then collected all of setuptools. setuptools is not in any
  lock; it arrives as PyInstaller's own dependency, so it is also in every
  CI build today.
- `tomli` itself cannot be excluded: PyInstaller's pre-import hook raises
  `ValueError: Target module "tomli" already imported as ExcludedModule`. The
  excludes are therefore the setuptools names.
- After the fix:
  - `scan_frozen --component companion` reports OK: 14 third-party
    distributions, psycopg2-binary 2.9.13 "LGPL, allowlisted for
    companion", pyinstaller exempt;
  - `--component onboarding` reports OK with 0 third-party distributions;
  - both PKG TOCs contain the licence bundle and the notices.
- `check_licenses.py --strict --only companion --platform win32`, against
  the lock-built venv, reports no FAIL and psycopg2-binary ALLOWED.
- Plain `check_licenses.py --only companion`, against the developer venv,
  reports OK.

### LG-12 (build side): licence texts travel with every binary

- **`tools/gen_notices.py --write-texts`** writes
  `docs/legal/licenses/<component>/<dist>-<version>.txt` for every runtime
  distribution, plus one `THIRD_PARTY_LICENSES.txt` per frozen component
  (`companion`, `onboarding`).
  - **Runtime set.** Roots are pyproject's `dependencies` plus the `tray`
    extra, walked down the lock's own `# via` graph. `dev` (pytest, pluggy,
    iniconfig, colorama, pygments) is excluded. A root missing from the lock
    is refused.
  - **Texts** are read from each wheel's `.dist-info`: every `LICEN[CS]E*`,
    `COPYING*`, `NOTICE*` and `AUTHORS*` file and PEP 639 `licenses/`. When
    the dist-info has none, a plainly named file listed in RECORD is used,
    which is how onnxruntime's `ThirdPartyNotices.txt` gets in. A wheel with
    no licence file at all falls back to `tools/notices_extra/dists/<name>.txt`.
  - A distribution not installed in the scanned venv keeps its committed
    text. With no text at all it is a `NO TEXT` warning and exit 1.
  - Output is deterministic: no dates. Stale versions are deleted.
  - The bundle is an intro, a contents list, the notices_extra texts, and
    then each distribution.
- **`--venv LABEL=PATH`** (repeatable) scans another venv for the notices and
  for the texts. `shown_path()` prints the venv path relative to the repo.
- **`tools/notices_extra/` (new).** Each file has a provenance header, and
  the texts are verbatim:
  - `cpython.txt`: CPython 3.12.10 Windows `LICENSE.txt`;
  - `tcl-tk.txt`: `tk8.6/license.terms`;
  - `openssl.txt`: the Apache-2.0 text as CPython's LICENSE carries it for
    OpenSSL 3;
  - `libpq.txt`: PostgreSQL `COPYRIGHT`, REL_18_STABLE. The wheel's libpq is
    18.4, measured with `psycopg2.__libpq_version__ == 180004`;
  - `pyinstaller-bootloader.txt`: `pyinstaller-6.21.0.dist-info/licenses/COPYING.txt`;
  - `dists/flatbuffers.txt` and `dists/pyobjc-core.txt`: both wheels ship no
    licence file, checked 2026-09-25;
  - `music_text_encoder/{NOTICE,LICENSE}`: the committed source of the two
    files below;
  - `README.md`.
- **Generated and committed-ready**, using the lock-built scratch venv. The
  macOS pyobjc wheels' dist-info were unpacked into it, because pyobjc does
  not install on Windows:
  - `docs/legal/licenses/companion/`: 17 distribution texts plus a 653 KB
    `THIRD_PARTY_LICENSES.txt`;
  - `docs/legal/licenses/onboarding/THIRD_PARTY_LICENSES.txt`: the non-pip
    texts only.
- **Bundling.**
  - `companion/build.spec` adds the bundle and `THIRD_PARTY_NOTICES.md` to
    `ccsync_companion/assets`.
  - `build_onboard.spec` and `build_onboard_macos.spec` add them to `assets`.
  - All three **refuse to build** with `SystemExit` when either file is
    missing, and the message names `python tools/gen_notices.py --write-texts`.
- **Single files.**
  - `dashboard/static/htmx.LICENSE`: the 0BSD text from htmx's v1.9.12 tag.
  - `music/web/data/text_encoder/{NOTICE,LICENSE}`: the Apache-2.0 text,
    plus a NOTICE with the modification statement "exported to ONNX, text
    tower only". These copies are **gitignored** (`music/.gitignore: data/`),
    so the committed source is `tools/notices_extra/music_text_encoder/`.

## Departures from the plan, and why

1. **The "companion test" is in `tools/tests/test_scan_frozen.py`
   (`TestTheRealTree`), not in the companion suite.** It reads only
   `companion/build.spec` and the lock through an ast parser of the
   `hidden_imports` list, and G6 owns no companion test file.
2. **`tools/build_onboard*.ps1` does not exist.** The Windows onboard.exe is
   built by `installer/build_editor_package.ps1 -RebuildOnboard` (ship.cmd's
   path) and by release-windows.yml. I scanned the CI one; the other is a
   hand-off.
3. **`check_licenses.py` is unchanged.** Nothing in it needed to change: it
   already honours `targets`. With the lock and the allowlist changed, it
   passes as the plan requires.
4. **Scope added: the setuptools excludes** in the three specs. Without them
   scan_frozen fails every real build, including CI's.
5. **Scope added: `release.ps1` also installs the pinned PyInstaller**, so
   it is CI's recipe exactly. The base-rig venv had none.
6. **Scope added: fallback texts** for wheels that ship no licence file
   (flatbuffers, pyobjc-core). Without them `--write-texts` can never
   produce a complete bundle.
7. **The generated table covers more than the installer.** Its heading is
   the plan's, but it also lists the companion's sidecar downloads and the
   NAS ffmpeg, with a "Fetched by" column. The hand section names all of them
   as pinned downloads.

   40654 and 40963 held `build<0x08>uild`, in both the comment and the
   `--workpath` argument. The likely cause is a shell heredoc that turned
   `\b` into an escape; this session's own heredocs did the same, so the

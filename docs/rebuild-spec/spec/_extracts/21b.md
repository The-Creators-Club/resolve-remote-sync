# Extract of inventory section 21b

## Items

### 21b-001: Installing the server also puts the helper tools some parts need onto the NAS, and a helper that cannot be installed never stops the install.
- Where: server-install-and-running / Installing on a NAS
- What: Some switchable parts need a helper tool on the NAS: music and YouTube downloads need a media converter, signed-in YouTube downloads need a script runtime, and the Timeline Cards editor needs its own runtime. Each helper is installed only when a part that needs it is switched on, and the person installing can choose to skip it. If a helper cannot be fetched, verified or installed, the person is told it was NOT installed, why, and what will not work until it is; everything else is installed as normal. What the parts then show:
  - no media converter: adding tracks to the music library answers that it is not available, and the person is told where the converter must be placed;
  - no script runtime for YouTube: signed-in YouTube downloads find no formats to download;
  - no Timeline Cards editor runtime: the editor says it has no runtime.
  A helper already installed and working is left alone and the person is told it is already there, before anything is downloaded. A failed check of whether it is there counts as "not there". A downloaded helper is first run on the NAS to prove it works; one that does not run on that NAS is not installed and the person is told so. A rehearsal says what would be fetched and where it would go, and changes nothing.
- Flag: differs: the script runtime for YouTube is installed only when the part of YouTube downloads that works around YouTube's blocking is switched on, which is off for everyone by default

### 21b-002: A helper tool is installed only after its download is checked against a known checksum, and the rules differ by helper.
- Where: server-install-and-running / Installing on a NAS
- What: Every helper the product ships with has a known checksum, and a download that does not match is never sent to the NAS or installed; the person is told it does not match (with what was found) and that nothing was sent. A copy sent across to the NAS is checked again on the NAS before it is unpacked; a mismatch there is reported as a corrupted transfer and nothing is installed.
  - The Timeline Cards editor's runtime is never installed unverified: its checksum must match both the product's own and the one its publisher lists. If the publisher's list cannot be reached, lists nothing for that download, or lists a different checksum, nothing is fetched and the person is told which (a different one means the product's checksum is stale or the download site is not what it was).
  - For the media converter and the YouTube script runtime, the person installing may point at a different download or a copy already on their computer. With a different download and no checksum given, the person is warned that the download will NOT be checked; only an intact transfer is then proven.
- Flag: differs: the Timeline Cards runtime refuses to install without a checksum; the other helpers install unchecked when the person overrides the download without one

### 21b-003: The media converter can be fetched by the NAS itself (slow) or by the installer's own computer and sent over the studio's network.
- Where: server-install-and-running / NAS speed, load and clock
- What: By default the NAS downloads the media converter itself. The usual source serves the NAS at about 28 kB/s, about 25 minutes for the download, and the NAS is given up to 30 minutes before the step gives up. The person installing can instead have their own computer fetch it (up to 5 minutes) and send it over the studio's network, where it is unpacked on the NAS (up to 5 minutes). When the NAS's own download fails, the person is told of the slow source and of the alternative. When the installer's computer cannot fetch it, the person is told to retry, point at a copy already on their computer, or let the NAS download it.

### 21b-004: Sending a copyleft helper tool to a customer's NAS from the installer's computer makes the installer its distributor, and they are told what that obliges.
- Where: accounts-privacy-legal / Third-party licences and what customers receive
- What: When the installer's own computer fetches the media converter and sends it to the NAS, the person is told every time, rehearsals included, that they are passing on a binary under a copyleft licence and must accompany it with its source or a written offer of the source valid for three years, where the source is published, and where the product's third-party notices are. The version is named when it can be read, otherwise "version unknown". When the NAS downloads it itself, this notice is not shown.

### 21b-005: A newer approved version of the Timeline Cards editor's runtime replaces the old one on the next install; the other helpers are never upgraded once present.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: The Timeline Cards editor's runtime counts as present only if it reports exactly the version the product approves; any other version is replaced on the next install, and the previous one is kept beside it (one copy). The media converter and the YouTube script runtime count as present if they are there at all, so when the product approves a newer version, an installed older one stays.
- Flag: differs: the editor's runtime follows the approved version; the other helpers stay at whatever version was first installed

### 21b-006: A secret the person installing supplies is refused when it is too short, too plain or a known placeholder.
- Where: server-install-and-running / Settings and secrets
- What: The same rule the server applies when it starts: a secret passes only if it is set, at least 24 characters long, has at least 8 different characters, and is not one of the common placeholders (such as changeme, change-me, replaceme, todo, tbd, secret, password, token, test, example, your-token-here, xxx, none, null; letter case ignored). The person is told which: that it is not set; that it is the placeholder named (a value that is public); that it is only N characters and at least 24 are required; or that it has too little variety to be a random secret.

### 21b-007: Updating the server's software never leaves a half-installed server: the new version replaces the old one whole, after it has been checked, or not at all.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: The new version is sent to a holding place on the NAS first and checked there (number of files and total size against what was sent) before it replaces anything; the running server is not touched until then. What the person is told:
  - an empty bundle is refused, saying nothing would be installed;
  - if the holding place cannot be made, or the transfer does not finish, or the copy does not match what was sent, the person is told the installed server is untouched, and the partial copy is left on the NAS for inspection;
  - if putting the new version in place fails, the previous version is put back and the person is told so;
  - on success the person is told the version was installed and where the previous one was kept.
  A large update is given longer: roughly 5 minutes plus a few seconds per 5 MB (about 18 minutes for 1.4 GB). A rehearsal says how many files would be sent and changes nothing.

### 21b-008: The previous version of the server's software is kept on the NAS so it can be put back, and older ones are cleared away.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: After a successful update exactly one previous version is kept, named with the date and time it was replaced (on a first install, an empty one). Older ones are deleted, except any the running server is still using, which are kept and the person is told so. Leftovers from a failed update are cleared away automatically by a later install once they are more than 2 hours old, and the person is told how many were reclaimed.

### 21b-009: The server is installed with its licence agreement and its help guides, and says so on the right screen when one is missing.
- Where: server-install-and-running / Installing on a NAS
- What: Every install carries the licence agreement, the third-party licence texts, the guide to how the product works and the guide to setting up an editor's computer. If the licence agreement is missing from the build, nothing of these is installed and the person installing is told that the first-run set-up will say no licence agreement is included. If a guide is missing, everything else is still installed and the person is told the help will say that guide is not installed. If installing these fails for any other reason, the person is told the server is running either way and that the first-run set-up will say no licence agreement is included. This step never stops the install.

### 21b-010: On Synology the install makes the server's folders with the right privacy and never changes the permissions of the studio's shared tree.
- Where: server-install-and-running / Installing on a NAS
- What: The server's private folders (its stored data and the data of each part) are made readable only by the account the server runs as; what is already inside them is never touched. Inside the studio's shared tree (the b-roll archive, the music library) the install only creates missing folders and never changes owner or permissions, so the editors' group keeps the access it inherits from the shared folder.

### 21b-011: On Synology the server's secrets are kept out of the readable description of the server, and an install that might start with placeholder secrets is refused.
- Where: server-install-and-running / Settings and secrets
- What: The description of how the server runs is readable on the NAS, so every secret in it is replaced by a reference to the separate file only the NAS's administrator can read. Each secret must be found exactly once; otherwise the install is refused, saying the server could otherwise start with a placeholder as its secret.

### 21b-012: If an install fails after the new version is already in place, the server is restarted onto the new version before the failure is reported.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: So the server never keeps running from a copy the next install would remove, a failure late in an install first restarts the server and tells the person it did. If that restart fails, the person is told to restart the server from the NAS's own apps screen before installing again (harmless if the server is not installed yet). A restart is given up to 2 minutes on TrueNAS and up to 5 minutes on Synology.
- Flag: differs: the message names TrueNAS's apps screen on Synology too

### 21b-013: Reinstalling re-creates the server only when the version it would run changes; otherwise it is a routine restart, and the person is told which.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: On a reinstall the install first reads which version the running server uses. If it is the same, the person is told nothing would change, the update and data steps run and the server is restarted; they may ask for a full re-create anyway. If it differs, or cannot be read, the server is re-created, because a restart would keep the old version. Either way nothing in the server's own folder on the NAS is deleted. A rehearsal always reports a re-create and says a real run would ask the server first.

### accounts-privacy-legal-Q1: Should a studio keep the choice of three ways for people to sign in (their NAS account, the organisation's single sign-on, or accounts the product keeps itself)?
- Kind: either-or
- Today: the person installing the server picks one of three. What an admin can do differs between them: disabling an account and adding keys by hand exist only where the product keeps its own accounts; with NAS accounts the same password also opens the shared folders; with single sign-on there is no password here at all.
- Options: A: keep all three, with every action working the same for each. B: one account per person that the product keeps, whose password it keeps in step with the person's NAS login where the studio uses the shared folders, with single sign-on as an option a site can put in front of it. C: NAS accounts and single sign-on only.
- Recommend: B, because a person then has one account and one password everywhere, every admin action works the same, and the studio's NAS still opens with the same password.
- Changes for a person: with B an admin manages one kind of account and sees the same actions for everyone; an editor notices nothing except that disable and suspend no longer depend on the sign-in method. With A nothing changes.
- Text assumes: A (the three are written as a site setting), marked pending.

- Covers: 17-Q1, 13-Q9
- Answered by the owner 2026-11-24: B: one account per person kept by the product, kept in step with the person's NAS login, with single sign-on optionally in front

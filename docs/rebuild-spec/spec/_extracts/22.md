# Extract of inventory section 22

## Items

### 22-001: An editor gets the installer from the admin, with plain instructions for getting past the operating system's warnings.
- Where: editor-app / Security warnings, permissions and certificates
- What: The admin hands an editor an installer package (kept on the server's shared tree, and offered as an installer link on the dashboard). It carries a "start here" note that tells the editor to copy the installer to the Desktop first and run it from there, and how to get past the operating system's warnings about an unrecognised program: on Windows, SmartScreen ("More info", then "Run anyway"), unblocking the file, and Smart App Control; on macOS, Gatekeeper ("Open Anyway"). The note also explains connecting Resolve, how to update and how to uninstall, and warns never to map a server share to a drive letter by hand. While the Windows installer carries no publisher signature, Windows shows its unrecognised-publisher warning; the person publishing a release is warned of this in a box before it goes out.

### 22-002: The installer refuses to run from the shared drive, a network location or an external disk, and says where to copy it.
- Where: editor-app / Installing and setting up
- What: When a remote editor presses the install button, the installer first checks where it is itself running from. On Windows it refuses when it is on the studio's tree drive letter, on the drive letter P: at any site, or on a network path, telling the editor that the install is about to remove that drive from under itself (and that running it off the server locks the file for everyone) and to copy the installer to the Desktop and run it from there. On macOS it refuses when it is on an external or network volume rather than the start-up disk or the home folder, telling the editor to copy the app into Downloads or the Desktop. If the check cannot tell, it does not refuse. The editor can press retry after moving it. The check applies only to remote editors' installs.
- Flag: differs: Windows refuses on the tree drive, the drive letter P: and network paths; macOS refuses on any volume other than the start-up disk and the home folder.

### 22-003: One set-up wizard on Windows and macOS takes an editor from nothing to a signed-in, working computer, and is safe to run again at any time.
- Where: editor-app / Installing and setting up
- What: The same wizard runs on both operating systems. Its welcome page tells the editor that it sets up or refreshes this computer, removes every trace of older versions, installs the current app (which updates itself from the dashboard from then on) and signs it in; on Windows it also says it remounts the project drive, on macOS that it installs the sync tools and points Resolve's drive mapping at the local copy of the project tree. It says the editor needs two things from the admin: the dashboard address, and the username and password the admin set up. It says it is safe to re-run any time. A small grey line shows the installer's version and the version of the app it carries ("?" when unknown). One installer version number is shared by the Windows and macOS installers.

### 22-004: The wizard is a single window that can be driven entirely from the keyboard.
- Where: editor-app / Windows, dialogs and notifications
- What: Pages replace each other in one window. The window grows taller on its own when a page needs room (never wider, never shrinking, never taller than the screen less a margin), and each page's buttons are the last thing to lose space. Tab moves between buttons with a visible focus ring; Enter presses the focused button; Enter in a text field presses the page's main action (next on the role page, verify on the sign-in page). An enabled next button takes focus when a page opens; on form pages the first empty field does. Enter never presses a disabled button.

### 22-005: The wizard's pages come in a fixed order, with some shown only when they apply.
- Where: editor-app / Installing and setting up
- What: In order: the "last install did not finish" page (only when one did not); the licence; welcome; the wrong-account refusal (Windows, only when it applies); step 1, how this computer is connected and the dashboard address; step 2, joining the studio's private network (remote editors only); step 3, sign in; step 4, what this computer reports; step 5, install; then a finish page that differs for a remote editor and for a computer wired to the server. Back buttons return one page (the sign-in page goes back to the network page for a remote editor and to the role page for a wired computer).

### 22-006: Closing the wizard in the middle of an install asks first, and says what the computer will be left without.
- Where: editor-app / Installing and setting up
- What: The window closes freely on every page except while an install is running. Then a yes/no question (default no) says the install is part-way through and closing now leaves this computer with no CC Sync and, for a Windows remote editor, no project drive letter; for a wired computer or any Mac, just no CC Sync. Yes stops the install and everything it started, then closes. If the question itself cannot be shown, the window stays open.

### 22-007: If an install was cut short, the next run of the wizard says so first and offers to finish it.
- Where: editor-app / Installing and setting up
- What: Just before the install starts removing older versions, the computer records that an install is under way; the record is cleared only when a finish page is reached. While it exists, the wizard opens on a page "THE LAST INSTALL DID NOT FINISH" saying the computer was part-way through an install, that until it is finished there is no CC Sync (remote editor: "Nothing is syncing"; wired Windows: the drive mappings were not touched but the app is not running; wired Mac: the server mounts were not touched but the app is not running), when it started if known, and that finishing is safe, is the only fix, and will ask for the sign-in again. The role choice is preset to the interrupted run's role. Buttons: close, and finish the install (which goes on to the licence page). A record that cannot be read still counts as an unfinished install. If the record cannot be written, the install log carries a warning.
- Flag: undetermined: whether the app on the computer refuses to sync while an install is recorded as unfinished.

### 22-008: The editor must accept the licence before anything is installed, and is asked again only when the licence changes.
- Where: accounts-privacy-legal / The licence a person accepts
- What: The licence page shows the licence text read-only and scrollable, in plain text (headings in capitals, formatting removed, links shown as "text (address)"), with its version at the foot. The intro says accept records the agreement on this computer and continues; decline closes the installer and nothing is changed. Accepting records on the computer which version was accepted, when, and a fingerprint of the exact text; if that record cannot be written the wizard carries on regardless. The page is skipped when the computer has already accepted this version or a newer one (versions compared number by number); it is never skipped when the licence or its version cannot be found in the installer. If the licence is missing from the installer, the page says so and tells the editor to ask the administrator for a copy before continuing.

### 22-009: On Windows, an install run under a different account from the one signed in is refused before anything changes.
- Where: editor-app / Installing and setting up
- What: Everything is installed per person, so an install running under another account would give the signed-in person nothing. When leaving the welcome page (and at the start of a hand-run install), the wizard compares the account signed in at the screen with the account it runs as, ignoring letter case and any domain part. On a mismatch it shows WRONG ACCOUNT in red: "You are running as X but Y is signed in. Everything this installs is per-user, so Y would get nothing. Y does not need to sign in again: close this and start the installer again by double-clicking it, and do not choose Run as administrator or type another account's password if Windows asks (it does not need administrator rights)." then "Nothing on this computer has been changed." with only a close button. If the check cannot tell, it never refuses. macOS has no such check.
- Flag: differs: Windows only; macOS never checks.

### 22-010: The editor chooses whether this computer is a remote editor's computer or one wired to the server.
- Where: sync / Wired or remote
- What: Step 1 says: pick how this computer reaches the footage; any number of computers can sit on the studio network and work straight off the server. Two choices: "I'M A REMOTE EDITOR" (Windows: installs the network and sync tools and maps the project drive letter, re-created fresh; macOS: installs the sync tools and points Resolve's drive mapping at the local copy of the project tree) and "I'M PHYSICALLY CONNECTED TO THE SERVER/NAS" (installs only the app, no sync tools; on Windows the editor's drive mappings, on macOS the server shares mounted on the Mac, are not touched). The starting choice is what this computer was set to before, else remote editor. The role the person's account has on the dashboard never changes this choice: it belongs to the computer.

### 22-011: The editor types the dashboard address; a missing http or https is added, and plain http to the public internet is refused.
- Where: editor-app / Signing in, the computer's identity and the licence
- What: The address is required ("ask your admin for it", with an example). If typed without http:// or https://, the wizard adds one and writes it back into the field: http for an IP address, localhost or a local-network name; https for a name on the studio's private network, for a name with no port, or with port 443; otherwise http. The next page then shows an amber note that the address had nothing in front and to go back and edit it if the one shown is wrong. An address using plain http to a public internet address is refused: "your password would cross it unencrypted. Nothing was sent. Ask your admin for the dashboard's https address." A check that cannot decide never refuses. Plain http to a local or private-network address is allowed, with an amber note. A second press while the check runs is ignored; editing the address during the check discards its answer. The same refusal is checked again at sign-in and at install.

### 22-012: A remote editor joins the studio's private network inside the wizard, and cannot go on until the dashboard answers.
- Where: editor-app / Installing and setting up
- What: Step 2 (remote editors only) says the project server lives on a private network: install its app, sign in with the invite link the admin sent, then come back and check. A status line shows whether the network app is installed (green) or not (amber), refreshed when the page opens and after every check. On Windows an install button installs it through Windows' own package installer (in its own window), then reports green "installed, sign in to it from its tray icon, then press check connection" or red "did not install, try the download page". A second button opens the network app's download page for this operating system. The dashboard address is shown below. "Check connection" (one check at a time, greyed while running, shows "checking...") first asks whether this computer has joined the network (red: not joined yet, open its tray icon, or menu-bar icon on macOS, and sign in), then asks the dashboard whether it is up, waiting up to 10 seconds and never following a redirect. Failures are told plainly: no address set; the address does not exist on this network (check the spelling with your admin); did not answer in time (if you just joined, wait a few seconds and check again); refused the connection (the address exists but nothing serves the dashboard on that port, check the port with your admin); answered with an error code (the address is right, tell your admin); answered with a redirect (CC Sync never follows one, ask for the direct address); plain http to the public internet; any other error. Success shows green "connected: the dashboard is answering" and only then is next enabled and focused.
- Flag: differs: the install button exists on Windows only; on macOS the editor installs the network app from the download page.

### 22-013: The editor signs in with the username and password the admin set up, checked against the dashboard on the spot.
- Where: editor-app / Signing in, the computer's identity and the licence
- What: Step 3 says the username and password are checked against the dashboard right now and the install will not proceed if they do not match. The password is masked. Both fields are required; with no address the editor is sent back to the role page; a second press while checking shows "still verifying the last attempt...". The sign-in sends this computer's network name with it and waits up to 15 seconds, never following a redirect. Failure shows red "sign-in failed: <reason>" in the same words the app uses elsewhere (wrong credentials, too many attempts, server unavailable, redirect, network error) and clears the password. Success keeps the person's sign-in for this computer, fetches the site's settings (tree name, drive letter, server details, brand, which features are on) and keeps a copy; if that fetch fails, a copy no older than 30 days from the same dashboard is used where a value is needed. An answer arriving after the editor left the page is ignored.

### 22-014: Where the server gives every computer its own reporting key, the editor is asked to paste the one the admin made, and may leave it for later.

- What: Only when the dashboard hands out per-computer keys, gave none at sign-in, and this computer does not already hold one, the install page shows an amber explanation: this dashboard gives every computer its own key; paste the key your admin made for you (from the dashboard's user settings); you can leave it empty and add it later, but nothing syncs until it is in. Installing with it blank finishes with a warning that the dashboard will refuse every report from this computer, and the computer is NOT READY. A key already on the computer is never cleared.

### 22-022: Every install first removes older versions of CC Sync from the computer, but never the sign-in, settings, keys or the computer's sync identity.
- Where: editor-app / Installing and setting up
- What: Before installing, the wizard stops any running copy of the app, removes the ways older versions started themselves at sign-in (including ones left by versions with older names), deletes old copies of the app from every place an older version put one (retrying a locked file, then setting it aside with a warning), and stops only the background sync program CC Sync itself installed; a program of that kind the person runs for themselves is left alone and named in a warning. On Windows, for remote editors, it also unmaps the project drive if CC Sync mapped it (see 22-024 for one mapped by something else); if it stays mapped, the editor is told something has files open on it and to close those programs and retry. A wired computer's drive is never unmapped. Never removed by this step on either system: what CC Sync installed for syncing, the computer's sync identity (so the admin does not have to approve it again), its keys, its sign-in, its settings, its server connection entry and its record of the external drive. If removing an old start-at-sign-in task is denied, the warning gives the exact command for an administrator and says explicitly not to re-run the installer as administrator. Every action is written to the install log; none of it is fatal.

### 22-023: On Windows, a remote editor's project tree appears as the studio's drive letter, named after the tree, back by itself at every sign-in.
- Where: editor-app / Drive letters and network drives
- What: Resolve's clip paths all point at one drive letter (the site's, P: by default), so a remote editor's local folder is presented at that letter. It is re-created fresh on each install, comes back by itself every time the person signs in, and shows in Explorer under the tree's name. Doing this properly needs one administrator approval prompt during the install; the folder is then reachable from this computer only, and other computers on any network it joins are blocked from reaching it. If the editor declines the prompt (or it cannot be done), the drive still works but Explorer shows the disk's own name instead of the tree name, and the editor is told re-running and approving the prompt gives the nicer name. If the drive cannot be set to return at sign-in, the editor is told it will not come back after signing in again, given the command to run by hand, and told NOT to re-run as administrator. A hand-run install has an option to leave the folder reachable from other computers, with a warning that this serves the whole project tree to any network the computer joins.
- Flag: differs: Windows only; on macOS no drive letter is made (see 22-030).

### 22-024: A drive letter already used by something else is never taken over: the install says so and tells the editor what to do.

If the computer would not report its drive mappings at all, the message says to sign out and back in, then re-run.

### 22-025: Installing from an administrator window is warned against, because a drive mapped there is invisible to the editor's normal session.

### 22-026: For a remote editor, the install fetches the sync tools it needs, checks each against a known fingerprint, and refuses one that does not match.

### 22-027: A remote editor's computer gets its own key for reaching the server, made for it and offered to the admin for approval.
- Where: accounts-privacy-legal / How a computer proves who it belongs to
- What: If the computer has no key yet, the wizard makes one (with no passphrase); an existing key is never replaced, and a missing public half is rebuilt from the private half. ### 22-030: On macOS, the install points Resolve's own drive mapping at the editor's local folder, so Windows-style clip paths open on the Mac.
- Where: resolve-on-the-editors-computer / Setting Resolve up: edition, scripting switch, preferences
- What: On a Mac nothing is mounted at a drive letter. Instead the install adds a Mapped Mount to Resolve's media storage preferences that maps the studio's drive (for example P:\) to the local folder. Facts about Resolve this rests on: Resolve rewrites its own preferences when it quits, so they can only be changed while it is closed; its preference files exist only after it has been launched once; it may be installed in the Applications folder or from the Mac App Store, which keeps its preferences elsewhere. If Resolve is open, the install says "DaVinci Resolve is running. It rewrites its own preferences when it quits, so anything set now would be thrown away. Please quit DaVinci Resolve. This will continue automatically." and waits up to 3 minutes; on time-out it carries on without the mapping and says how to set only the mapping later. An existing mapping of the drive is repointed, never duplicated; both of Resolve's preference files are backed up first and everything else in them is kept. The closing summary says either "DONE FOR YOU: Resolve maps P:\ to <folder>" or NOT DONE with the fix: quit Resolve and re-run; launch Resolve once, quit it, then re-run; Resolve is not installed ("CC Sync needs Resolve Studio, the paid version"); the preferences are in a form the installer does not know, nothing changed, with the manual steps (Resolve, Preferences, Media Storage, add a Mapped Mount: local path, mapped path); or the developer tools are missing (install them and re-run). Each of these not-done outcomes is a warning on the wizard's finish page. A hand option sets only this mapping and touches nothing else.
- Flag: differs: macOS only; Windows uses a drive letter instead (22-023).

### 22-032: For a remote editor, the install switches on Resolve's external scripting, or says exactly how to do it by hand.

### 22-033: On macOS, an external sync drive is checked so that sync never fills the Mac's internal disk by mistake.
- Where: sync / The sync drive
- What: When the local folder is on an external drive: if the drive is not there, the install stops and says to plug it in (and unlock it if encrypted) and re-run. If the drive's usual name is a plain leftover folder, or the Mac mounted the drive under a numbered second name (for example "SSD 1"), the install stops with a boxed warning that the path IS NOT A MOUNTED VOLUME, explaining either that the drive is really mounted under the numbered name and must not be used that way, or that syncing into the leftover folder would fill the Mac's internal disk instead of the SSD; then the fix: eject, remove the leftover folder, unplug and replug, re-run. If the Mac cannot identify the volume at all, it refuses to guess. Two drives with the same name both mounted: a warning to rename one. A drive not formatted in the Mac's own format: a warning that other formats lose macOS file details and some cannot keep names differing only in letter case. The install records which drive it is, so the app can later tell "SSD unplugged" from "SSD plugged in but empty".
- Flag: differs: macOS only.

### 22-034: The app is installed, set to start at sign-in, started, and confirmed running within a few seconds.

It is started now and checked after about 3 seconds: "companion launched and running (check your tray)" (menu bar on a Mac), or a warning that it did not stay running, how to start it by hand, and where its log is. On a hand-run Mac install the app is downloaded from the dashboard (22-044) when not given; an identical copy already installed is left as is. On a Mac, background syncing is restarted by the system if it stops; on Windows it is started at sign-in only. The app itself is not restarted by the system on either.
- Flag: differs: on macOS background syncing is kept alive by the system; on Windows it only starts at sign-in.

### 22-035: A wired computer gets only the app: no sync tools, no network, no key, and its drives are left alone.
- Where: sync / Wired or remote
- What: For a computer physically connected to the server, the install first checks the app is inside the installer; if not, "companion app not bundled with this installer ... Nothing has been changed on this machine. Get a complete package and run that instead." with retry. It then removes older versions (without touching drive mappings or server mounts), records the settings, installs and starts the app (22-034). There is no location check, no key, no sync tool and no Resolve scripting step. The local root and the drive letter recorded are both the folder chosen.

### 22-036: What the install records for the computer, and what it keeps from before.
- Where: editor-app / Settings, records and background work
- What: The install records on the computer: the verified user name, the dashboard address, whether it is a remote or a wired computer (each always overwritten); the sign-in; the reporting choices (only when the reporting page was shown); the per-computer key when one was pasted (never cleared); for a remote editor, the local folder, the studio's drive letter (from the site, else P:), the server connection, and the server's tree location only if none was recorded before. Everything else already in the settings, including the editor's own changes, is kept as it was. A shared reporting key, when the dashboard gives one, replaces the old one; an existing one is never blanked. A settings file that cannot be read is set aside under a new name and replaced with defaults. After a hand-run install, an existing settings file is never overwritten and its key values are printed with "confirm these values match, the companion will not fix them for you".

### 22-037: Nothing syncs on a remote editor's computer until an admin approves it; the finish page shows what the admin needs.
- Where: editor-app / Installing and setting up
- What: When the install finishes with no problems, the finish page says nothing syncs until the admin approves this computer, and that the app is installed and signed in as the user. If the computer's key already reached the dashboard, the heading is "DONE: SEND YOUR DEVICE ID TO YOUR ADMIN" and the page says the key is already waiting on the dashboard's user page; otherwise "DONE: SEND THESE TWO VALUES TO YOUR ADMIN". The computer's sync identity code and its key are shown in read-only fields, each with a copy button that briefly shows "[ COPIED ]". If the identity code was not found, the field explains where to find it on this computer and the button reads "NOTHING TO COPY" (disabled); likewise for a missing key. A hand-run install prints the identity code in a closing banner with the same request to send it to the admin.

### 22-038: An install that finished with something missing says NOT READY and lists what, so the editor sends the list instead of saying they are set up.
- Where: editor-app / Telling the editor what is wrong
- What: Every required piece the install could not set up becomes a warning. The finish page is headed "COMPLETED WITH N WARNING(S): NOT READY YET" (wired: "INSTALLED WITH ..."), says in amber that the computer is NOT ready to sync and not to tell the admin they are set up until the problems are fixed, but to send them this list instead; up to 6 warnings are shown in red, then "... and N more. All of them are in the install log". A hand-run install ends with a red numbered list "THIS MACHINE IS NOT READY TO SYNC: N required piece(s) are missing" and "Do NOT tell the admin you are set up yet." A Mac hand-run install with no app ends with a reminder that the sync app is not installed on this Mac and "Do not report yourself ready."

### 22-039: The finish page lists what the editor still has to do in Resolve before opening a project.
- Where: resolve-on-the-editors-computer / Setting Resolve up: edition, scripting switch, preferences
- What: Under an amber heading "BEFORE YOU OPEN A PROJECT, CONNECT RESOLVE (needs DaVinci Resolve Studio)": 1. In Resolve's project manager add the studio's shared network project library (Resolve's database-server kind of library), with the host (the site's server, else the dashboard's host, else "ask your admin") and the user name and password from the admin; 2. external scripting is already set to Local, or the manual instruction plus the reason it was not set; 3. open the shared project and set Playback, Proxy Handling, Prefer Proxies. Below: "Problems? Contact" the site's support contact (else the vendor's), the log path, and buttons close, copy log, and open-source licences (a read-only window with the bundled licence texts, or a note that copies are available on request). A hand-run install's closing text adds: never map any server share to another drive letter yourself (on a Mac: never mount a server share alongside this), and on a Mac how to uninstall.

### 22-040: A wired computer's finish page says it is connected to the server and what the app still does there.
- Where: sync / Wired or remote
- What: Headed "DONE: CONNECTED TO THE NAS" (or the NOT READY form, in practice only for a missing per-computer key). It says the app is installed, signed in as the user, and starts automatically at sign-in; nothing syncs on this computer because it works directly off the server; the tray (menu bar on a Mac) still watches the Resolve timeline for media outside the project tree; and future updates arrive as a one-click prompt in the tray. It then shows the dashboard address, the same Resolve checklist (always with the manual scripting instruction), support contact, log path and the same three buttons.

### 22-041: An admin or technical person can install without the wizard, by hand, on either system.
- Where: editor-app / Installing and setting up
- What: A hand-run install takes the server's network name and the editor's server user name (both required; a user name is lowercased, with a warning when that changed it), and optionally the local folder (else the one recorded before, else a folder named after the tree on the system drive, or in the home folder on a Mac), the server's tree location, the drive letter, the tree name and the dashboard address and key. It reads the site's settings from the dashboard (waiting up to 8 seconds; if they cannot be fetched it warns and uses what was given). It refuses, before changing anything, when: no dashboard address is given; the site's drive is not a drive-letter path (it never falls back to P: then); the local folder contains a double quote (Windows); a required value is missing (Mac, which says the admin gives both). A missing or relative server tree location makes it NOT READY (uploads and proxy downloads have nowhere to go). A preview mode prints everything it would do and changes nothing, ending "No changes were made." Every step says what it did or skipped, and it can be run again safely. It does not join the private network and does not make the computer's key; its closing text lists those as steps for the editor (join the network, make a key and send its public half, sign in from the tray, "NOTHING SYNCS UNTIL YOU DO THIS"), or says the wizard did them when the wizard ran it. A Mac hand run can also be asked to leave Resolve's preferences alone.
- Flag: several ways in: the wizard and the hand-run install do the same job; the wizard is what editors are pointed at.

### 22-042: On Windows, CC Sync appears in the system's list of installed apps, with an uninstall button.
- Where: editor-app / Uninstalling
- What: The install lists CC Sync (with the studio's name in brackets when the site publishes one) under Settings, Apps, Installed apps, with its icon and version, and an uninstall button that runs CC Sync's uninstaller; there is no modify or repair. A re-install replaces the same entry. If the entry cannot be made, the editor is told the manual way to uninstall. The uninstaller keeps a copy of itself on the computer so the entry keeps working. On macOS there is no such entry: the uninstaller is kept in the person's own program folder and the closing text says how to run it (or to get it from the installer package or the admin).
- Flag: differs: Windows only; macOS has no listed-app entry.

### 22-043: Uninstalling on Windows removes the app and its pieces but never the synced media, and keeps the sign-in and sync identity unless a full uninstall is asked for.
- Where: editor-app / Uninstalling
- What: The uninstaller opens by saying which mode it is in and that synced media is never touched. It stops the app and its background syncing, removes everything that started them at sign-in, unmaps the project drive only if CC Sync mapped it (one mapped by anything else is left alone), and stops serving the folder only once the drive is confirmed unmapped; if the drive stays mapped, it keeps the share and prints the two commands to finish by hand. It removes the drive's name and CC Sync's program folder and its place on the command path. Default mode keeps the sign-in, settings and the sync identity ("a reinstall reuses the same device ID, no re-approval needed") and says how to ask for a full uninstall. Full mode also removes the sign-in, settings, logs, the licence record and the sync identity ("a reinstall generates a NEW device ID, send it to the admin"), but keeps the record of prompts already answered so they stay answered after a reinstall. Always left: the local folder and media, the computer's key, the server connection entry, the network app and any tools installed as system packages ("remove them from Apps & features if wanted"). If program files survive (a file in use), it lists up to 8 and tells the editor to sign out and back in, then run the uninstaller again; the installed-apps entry stays until the folder is clear. It ends "CCSync uninstall complete." or "CCSync uninstall NOT complete" with the reason. If it is itself still on disk, it says either to leave it there to retry, or that it may be deleted. A preview mode changes nothing.
- Flag: differs: the Windows default keeps the sync identity and the server connection entry; the macOS default removes both (22-044).

### 22-044: Uninstalling on macOS removes the app and the sync identity even in the default mode, and leaves Resolve's mapping in place.
- Where: editor-app / Uninstalling
- What: It says which mode it is in and that synced media is never touched. It removes everything that starts the app and its background syncing at sign-in (including old-named ones), stops only the copies CC Sync installed (one the person runs for themselves is left alone and named), and deletes CC Sync's program folder, including the sync identity, warning that a reinstall gets a NEW identity the admin must approve. If that folder cannot be removed, it gives the command to remove it and marks the run incomplete. It removes CC Sync's server connection entry (others are kept; no backup). Default mode keeps the sign-in and settings; full mode removes them except the record of prompts already answered, and says the admin must approve this Mac again after a reinstall. It always leaves Resolve's drive mapping ("remove it in DaVinci Resolve, Preferences, Media Storage if desired"), the computer's key, and tools installed through the Mac's package manager, and ends "YOUR SYNCED MEDIA ON THE SSD WAS NOT TOUCHED". A preview mode changes nothing.
- Flag: differs: see 22-043.

### 22-045: On Windows, a new build of the app can be swapped in by hand, keeping everything else and falling back to the old build if the new one will not start.
- Where: releases-and-updates / Installing an update on an editor's computer
- What: For a computer already set up, a hand-run upgrade replaces only the app; the sync identity, server connection, drive and settings are kept and the summary says so. It shows the new build's version, when it was built, and whether it came from unfinished work ("fine for testing, not for the fleet"); a version record that describes a different file is ignored and the version shown as unknown. It stops the app, sets the current build aside, and copies the new one in (trying 5 times, 2 seconds apart, then asking the editor to close anything that might hold the file, such as a preview or a virus scan, and run it again). If nothing could be copied the old build is put back. It starts the app and checks it after 3 seconds; if the new build exits, the old one is restored and started ("the new build would not start, this machine is back on" the old version); if nothing runs, it warns that the computer has NO app running and nothing retries before the next sign-in. It starts background syncing if it is not running, or says to re-run the install if it cannot. It adds the dashboard address and key to the settings only if missing (and warns that without an address the app will not report, take sync choices, or be offered another update); a given key replaces the old one. It ends "Upgrade complete" (with the version now running), "Upgrade INCOMPLETE", or "INSTALLED BUT NOT RUNNING". If the key is blank it warns that reporting and project choices are off until one is given. A preview mode changes nothing.
- Flag: several ways in: the hand upgrade, the app's own self-update, and re-running the wizard all put a new build on a computer.

### 22-046: After an update that comes with a newer licence, the computer must accept it again before it syncs.
- Where: accounts-privacy-legal / The licence a person accepts
- What: The hand upgrade checks whether this computer has accepted the licence carried in the new package (never accepted, unreadable record, or an older version than the package's). If it is needed: when the app is running, it is left to the app's own licence window or the tray's "Accept the licence agreement"; otherwise the wizard is opened for the licence, except on a wired computer or when asked not to (warning only); if the package has no wizard, the editor is told to get the current installer from the dashboard's installer link. A package without a licence version never asks again. The summary states whether the wizard is open, the app is asking, or the computer is NOT SYNCING until it is accepted.

### 22-047: A hand-run Mac install downloads the app from the dashboard and refuses a download that is unsigned or does not match its fingerprint.
- Where: releases-and-updates / Signing and trust
- What: Using the computer's key, the Mac install fetches the published Mac build (the current one by default, or a named version). It is NOT installed when the download fails (wrong key, no route to the dashboard, or no published Mac build), when the dashboard served it without a release signature, or when its fingerprint does not match the one stated (with "Tell the admin: either the published package is corrupt or something is rewriting the download."). With no key, an app already installed is left unchecked for updates; with no app at all, the boxed warning "THE SYNC APP IS NOT INSTALLED ON THIS MAC" says what will not work (no syncing in either direction, no reporting, no project picking).
- Flag: differs: the Windows install only copies a build carried in the installer; only the Mac hand-run install downloads one.

### 22-048: The person publishing a Windows release assembles the editor installer package and is stopped before publishing anything unsafe.
- Where: releases-and-updates / Making and publishing a release
- What: The publisher (an admin of the studio's own dashboard, with the release signing key on their computer) assembles the editor package into a folder on the studio's tree (the installers, uninstallers, upgrade, notes, licence, app and wizard for Windows, and the Mac install scripts), optionally rebuilds the app and the wizard, and optionally publishes both. Before building, publishing asks for the admin password (3 tries; a non-admin is refused) after checking the dashboard is reachable ("This is not a password problem"). Refused, with nothing published: an unreachable dashboard; a missing target drive; a rollback floor above the build's own version; a signing key that differs from the one that signed the fleet's current build (every computer would refuse it) unless key rotation is confirmed; mismatched or unreadable version numbers; a build older than the latest source; a build that failed to sign or whose signed record does not match; the same version with different contents (bump the version); making an unsigned wizard current without confirming. Builds from unfinished work are published staged, not current, unless confirmed. Uploads are always staged first; making them current is a separate step, and a refusal there leaves both published and staged with advice to try one computer first. Warnings, not refusals: the build or wizard is stale, unsigned (boxed, about SmartScreen), and the Mac channel is missing or behind (Mac builds can only be built and published on a Mac). It ends saying whether the run fully succeeded. A preview mode prints what it would do.

### 22-049: How the install differs between Windows and macOS, in one place.
- Where: editor-app / Installing and setting up
- What: Windows: a wrong-account check; the project tree at a drive letter, needing one administrator approval; a blocking rule so the tree is reachable from this computer only; a listed app with an uninstall button; the network app can be installed from the wizard; the app is carried in the installer; a hand upgrade with fall-back to the previous build; background syncing starts at sign-in only. macOS: no wrong-account check; no drive letter, Resolve's drive mapping instead; external sync drive checks and the drive recorded; the network app is installed from its download page; a hand install can download the app from the dashboard; background syncing is kept alive by the system; the default uninstall removes the sync identity and the server connection entry and leaves Resolve's mapping. Both: the same wizard, licence, sign-in, reporting choices, 200 GB space warning, NOT READY verdicts and finish pages.

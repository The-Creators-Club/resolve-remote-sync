# Runtime dependencies for the deployed dashboard container (run.sh installs
# exactly this file into the persistent /data/venv, and only when this file's
# hash changes -- keep it in sync with [project.dependencies] in
# ../pyproject.toml). The package itself is NOT pip-installed in the
# container: /app is mounted read-only and run.sh puts /app/src on
# PYTHONPATH instead.
#
# THESE ARE FLOORS. `requirements.lock` beside this file is the exact,
# hash-pinned closure resolved from them, and it is what run.sh installs
# (--require-hashes) and what deploy/Dockerfile bakes into the image. AFTER
# EDITING THIS FILE, REGENERATE THE LOCK -- otherwise the change reaches
# nothing (docs/RELEASE.md, "Refreshing the lockfiles"):
#
#   cd dashboard/deploy && uv pip compile --universal --generate-hashes \
#       --python-version 3.12 -o requirements.lock requirements.txt
#
# 2026-08-17, COMMERCIAL_READINESS.md item 13.
fastapi>=0.110
uvicorn>=0.29
jinja2>=3.1

# --- b-roll UI (mounted at /broll when DASH_BROLL_ENABLED=1) ----------------
# Runtime deps of broll-platform's web/ app. `fastapi`, `uvicorn` and
# `jinja2` above already cover the rest of it.
#
# `fastembed` is deliberately NOT here. It is optional in the b-roll app
# (app/semantic.py degrades to keyword-only without it) and on first use it
# downloads a ~100 MB model from Hugging Face at runtime -- a container-egress
# and cold-start decision to make deliberately, not to inherit by accident.
numpy>=1.26
rapidfuzz>=3.0

# The CJK keyword blob (`segments.search_norm`), computed by the SERVER since
# 2026-08-18 (docs/BROLL_INGEST_PLAN.md §3.1). It used to be the base-rig
# indexer's job alone: the HTTP ingest path inserted segments with an empty
# one, so anything indexed over HTTP was keyword-searchable only after somebody
# remembered to run `broll-index run --stages embed`. Dashboard b-roll ingest
# has no base rig behind it at all.
#
# Without these two the app still runs -- broll/web's normalize.py treats them
# as optional and returns raw text -- and that is exactly the failure worth
# paying 40 MB to avoid: a two-character CJK term (堵車) is below trigram's
# 3-character floor, and unicode61 makes an unbroken CJK run a single token, so
# the clip is in the archive, indexed, and unreachable by the words on its own
# screen. Licences: jieba MIT, opencc-python-reimplemented Apache-2.0.
jieba>=0.42
opencc-python-reimplemented>=0.1.7

# --- music UI (mounted at /music) ------------------------------------------
# `numpy` above already covers the embedding maths; the music app carries no
# torch, because the container never embeds audio -- only query text, and only
# when someone searches.
#
# python-multipart is NOT optional: FastAPI raises at *import* time for the
# `UploadFile` parameter on /api/ingest, not at request time. Without it the
# dashboard's mount reports the music tree as "absent" -- indistinguishable
# from never having shipped it -- instead of failing loudly.
python-multipart>=0.0.9

# Runs the exported CLAP text-tower artefact (music/web/data/text_encoder,
# ~500 MB, ships alongside music.db). Query text is the ONLY thing this
# container ever embeds; audio embeddings arrive precomputed from the base rig.
# Without this the app falls back to the full CLAP model and search 500s,
# because torch is deliberately absent.
onnxruntime>=1.17

# --- YouTube downloader UI (mounted at /ytdl) -------------------------------
# `fastapi`/`uvicorn` above cover the web half and ffmpeg comes from
# /opt/ffmpeg (PATH, see run.sh).
#
# The two AI calls (search-term expansion, relevance filtering) go through the
# ANTHROPIC SDK with ANTHROPIC_API_KEY from the container environment. Until
# 2026-08-17 they shelled out to the interactive `claude` CLI, provisioned onto
# the host by the installer and authenticated by a one-time `/login` under one
# human's personal account -- unshippable per customer, and an agent binary
# with filesystem tools inside a container that mounts the Projects tree rw
# (docs/COMMERCIAL_READINESS.md item 1). Floor pin, not exact: the SDK is
# backwards-compatible and this file's hash is what makes run.sh re-run pip.
anthropic>=0.69
#
# Pin the FLOOR generously and expect to raise it: yt-dlp releases track
# YouTube's extractor changes, and an old one does not degrade -- it fails
# every download with a signature/format error. Bumping this file's hash is
# also what makes run.sh re-run pip at all (it installs only when the hash
# changes), so a version bump here IS the upgrade mechanism.
yt-dlp>=2026.8.19

# yt-dlp's PO-token provider MOVED OUT of this file 2026-08-17

# --- the Synology NAS backend (DASH_NAS_KIND=synology) ----------------------
# DSM exposes NO API for writing an editor's ~/.ssh/authorized_keys, and a file
# written through FileStation is owned by the admin -- sshd's StrictModes then
# refuses the key while logging NOTHING, so the editor sees only
# "Authentication failed" (docs/synology-spikes-2026-08-17.md spike 2). The
# backend therefore opens its own SSH session, which needs paramiko.
#
# Installed on every site, TrueNAS included: this file is ONE file for one
# image, run.sh only re-runs pip when its hash changes, and an installed
# package nothing imports costs a few hundred KB. LGPL-2.1 -- it belongs in
# the NOTICE file (COMMERCIAL_READINESS item 1).
paramiko>=3.4

# --- OIDC login (DASH_AUTH_METHOD=oidc) -------------------------------------
# Verifies the id_token against the IdP's JWKS (jwt.PyJWKClient). PyJWT rather
# than authlib because that verification is the ONLY thing oidc.py needs from a
# JOSE library, and `cryptography` -- which does the RSA/EC maths -- is already
# here as a paramiko dependency. Installed on every site for the same reason
# paramiko is: one file, one image, and run.sh re-runs pip only when this
# file's hash changes. Imported lazily, so a container that somehow lacks it
# reports one clear boot problem rather than failing to import the dashboard.
PyJWT>=2.8

### M03-001: Signed-in YouTube downloads all failed "The page needs to be reloaded".
- What was going on: YouTube can flag a signed-in account for playback only: its feed still lists, but every download with its cookies fails, while anonymous downloads with an origin token reach 1080p.
- What the product must do: The YouTube health check proves a real download succeeds, and signed-in credentials are never assumed better than anonymous without both being tested.
- Kind: 1a
- Capability: youtube
- Found by: real use
- Date: 2026-08-26
- State: fixed and live
- Sources: M-cc-ytdl-cookies-flagged-cr80, M-cc-ytdl-resilience-built-2026-08-26

### M03-002: YouTube refused editors' media fetches with 403, and it looked intermittent.
- What was going on: YouTube binds most media addresses to a proof-of-origin token; a machine without one gets 403, and enforcement tightened mid-day (one clip worked at 13:06, failed at 14:45).
- What the product must do: Every machine that downloads from YouTube can pass the origin-token check, and any download failure is logged with YouTube's own error text.
- Kind: 1a
- Capability: youtube
- Found by: real use
- Date: 2026-08-19
- State: fixed and live
- Sources: M-cc-ytdl-po-token-403-cr39

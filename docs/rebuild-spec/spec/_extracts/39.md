### 39-001: Timeline Cards never knocks out Resolve's scripting by connecting while Resolve is still starting.
- Where: cards-to-resolve-and-exports / Talking to Resolve: restarts, dialogs and speed
- What: A fact about Resolve: its scripting is served by a separate script server that Resolve starts late in its own launch, listening on TCP port 1144, and Resolve then registers with it. A program that connects in the short moment after that server starts and before Resolve has registered gets nothing, and takes the server down; Resolve then gives up scripting for the whole session, for every program on that computer, and the only cure is to quit Resolve and everything that talks to it and start them again in order. Timeline Cards therefore connects to Resolve only when the computer's own network table shows the script server listening AND Resolve connected to it. When Resolve is closed, or the server is up but Resolve has not registered yet, Timeline Cards simply waits and keeps asking; this is a waiting state, not a failure, and it does not count towards giving up. Only when the check itself cannot be made (the table cannot be read, or the port is held by some other program) does it go ahead and connect. On Windows and macOS the check is made; on any other system it cannot be, so it always goes ahead. The same rule applies to every program on the computer that talks to Resolve.

### 39-002: Timeline Cards can show the timeline open in Resolve as cards, following it closely.
- Where: cards-to-resolve-and-exports / Bringing Resolve's changes back into the cut
- What: When a computer with Resolve is connected, the cards follow the timeline Resolve has open: within about a second of a change in Resolve the cards show the clips on video track 1 (each with its clip, its span in the source, its frame rate and its clip colour) and every timeline marker (frame, colour, name, note, length). Items on track 1 with no media pool clip behind them (titles, generators) show by name with no source span. The playhead follows within about a tenth of a second; when it is over a cut with a transcript, the spoken word under it is highlighted. Asking to jump to a frame moves Resolve's playhead there. Drop-frame is taken from Resolve's own timecode. Changing to another timeline in Resolve switches the cards to it. With a project open but no timeline, the state "no timeline is open" is shown and clips can still be found by name for a conform. With no project open, the person is told "no project is open in Resolve". A momentary error is ignored and the last good state stays on screen; after three in a row the error is shown and Timeline Cards reconnects about 2 seconds later.
- Flag: differs: this view edits Resolve directly, while an opened cut list never touches Resolve until it is sent (see 39-030)

### 39-004: Edits made in the live view are carried out by Resolve itself, as Resolve's own keyboard commands.
- Where: cards-to-resolve-and-exports / Edits sent live and staged edits
- What: In the live view every edit is performed by sending Resolve its own keyboard command: Resolve is brought to the front, the key is sent, and focus is handed back. This works on Windows only. The keys follow the editor's own Resolve keyboard preset (re-read whenever it changes; the first key bound to each command is used, and any command left unbound uses Resolve's default). If the helper that sends keys is missing from the computer, the person is told it must be installed. If Resolve will not come to the front, nothing is sent. For these edits to work the editor must have Resolve on the Edit page with the timeline visible, Resolve must not be playing, and auto-select must be on for video track 1 and audio track 1 only. Resolve's default keys for the commands used (a fact about Resolve): deselect all Ctrl+Shift+A; select clip at playhead Shift+V; ripple cut Ctrl+Shift+X; paste insert Ctrl+Shift+V; match frame F; insert F9; split clip Ctrl+\; ripple trim start to playhead Shift+[; ripple trim end to playhead Shift+]; undo Ctrl+Z; redo Ctrl+Shift+Z; focus the timeline panel Ctrl+4.
- Flag: differs: only on Windows; a Mac editor cannot edit Resolve live, and whether they are told so before trying could not be determined

### 39-007: Deleting in the live view ripple-deletes the cut in Resolve and keeps the removed piece on an "offcuts" timeline.

  - "could not create the offcuts timeline"
  - banking warning: "the piece stayed on the clipboard, not banked to offcuts: <reason>", where the reason is "paste into offcuts went nowhere", "paste into offcuts landed wrong -- undone" or "editing the offcuts timeline itself"
  - "could not switch back to the edited timeline" (after three tries)

### 39-063: The cut-list file: colours, forgiving reading, loud errors and tidy writing.
- Where: cards-editor / Editing, undo and the cut list
- What:
  - Colours are Resolve's clip colour names. "Brown" is never written: it is written as "Chocolate". A colour from a planning board is mapped to the nearest Resolve clip colour.
  - Reading forgives extra blank lines, a missing quote, a missing length, either kind of line ending, comments over several lines, transcript names containing square brackets, and a fade line under a note.
  - Reading is loud, always with a line number, about: no header ("a cut list starts with a --- frontmatter block"), an unclosed header, a bad header line, a clip entry without `{...}` or without fps, a file of another kind ("this is a '<x>' file, not timeline-cards/cut-list"), a bad timing value, an unreadable bullet ("cannot read this bullet: ..."), a line that is not a bullet, heading or blank, and a negative fade ("a fade in cannot be -1.0 seconds long").
  - Gain read from the file is rounded to 0.1 dB and limited to plus or minus 30 dB (a typed -40 becomes -30); unit and sign are optional when read.
  - Several gap lines before a cut are added into one; a gap always belongs to the cut after it.
  - Only balanced `==...==` pairs are highlights; a lone `==` is kept as typed. Each highlight is written on its first free occurrence at or after the previous one, so repeated phrases come back the same; a highlight no longer in the text is dropped. When words change, each highlight is refitted as the longest run of letters and digits it shares with the new words (ignoring case); under 2 matching characters it is dropped.
  - The same cut list always gives the same bytes, with LF line endings, and a save is never seen half-written.
  - Before each save the previous version is kept in the cut list's history. The newest 200 revisions are kept; older ones survive only if their revision number is a multiple of 10.
- Exact: yes

### 39-064: Seconds and frames convert exactly, at every frame rate including the NTSC ones.
- Where: cards-to-resolve-and-exports / Frames, frame rates and timecode
- What: Seconds become frames by rounding half up of seconds times the exact rate; 29.97 is exactly 30000/1001, and so on for the other NTSC rates; frames become seconds by exact division. A cut's source in and out are counted at the CLIP's own rate (the out at least one frame after the in); the black before it at the timeline's rate. A fact about timecode: a `;` in a timecode means drop-frame; drop-frame skips 2 frame numbers each minute except every tenth minute (4 at 60 frames per second). A timecode that is not four fields means nothing. The timecode base is the timeline rate rounded.

Deal with that one first."; "no project is open"; "no bin named '<x>' (have: ...)"; "N bins are named '<x>' -- rename one"; "'<bin>' already holds a multicam called '<name>'"; "bin '<x>' is empty: nothing to make a multicam of"; "could not open 'New Multicam Clip': ... Is the media pool in list view, or scrolled so that (430, 200) is not over a clip?"; "Create did not close the dialog: Resolve refused the clip (a screenshot of the dialog will say why)"; "no multicam called '<x>' appeared in '<bin>' within Ns (N new clip(s) in the bin)"; "the multicam arrived named '<a>' and the API would not rename it to '<b>'"; "<what> never took effect -- a modal dialog is probably up in front of Resolve"; and refusals when the dialog is not the expected size or a field other than Angle Sync moved, so nothing unsafe is created. It waits up to 2 minutes for the clip to appear. A preview opens and fills the dialog, takes a picture of it, and cancels.

### 39-086: An older way lays each camera's files out by clock and lines them up by sound as a corrected copy.
- Where: cards-footage-in / Grouping clips and building the multicam
- What: Each camera's files can be laid on their own timelines ("<prefix> — ANGLE n (<camera>)"), or all cameras on one timeline ("<prefix> — SYNC", one video and one stereo audio track per camera, tracks named "n <camera>"), placed by file dates, timecode as time of day, or each camera's own timecode, ending with the instruction to make the multicam by hand with Angle Sync by Sound. A preview shows each angle's file count, total material, span, start and each file's time with any "<-- GAP", and "NOTE: N camera groups detected, not 2." The combined timeline can then be measured by sound and, on request, a NEW timeline built ("<name> FRAMESYNC" by default) with every take moved to its measured place, the original left untouched ("Original timeline is untouched; compare the two before deleting either."); a preview only measures ("measure only -- nothing changed. Re-run with --apply to rebuild."). Messages include "no timed clips in that bin", "no clips match camera prefix ... (found: ...)", "no readable Date Created on N clip(s), e.g. <x> -- use --sync tc", "timeline(s) already exist: ... -- rename or delete them first", "timeline '<x>': Resolve placed N of N clips", "name the timeline with --timeline (found N ending in SYNC)", "no clips on video track N".
- Flag: built twice: superseded by the one-step build of 39-073 to 39-083, which does layout and lining up together; both remain

### 39-087: Angle timelines built out of sync can be repaired in place by slipping the picture onto its sound.
- Where: cards-footage-in / Grouping clips and building the multicam
- What: For every angle timeline (optionally only those whose names contain given text), each picture item on video track 1 is measured against the sound on audio track 1 under it at six points across the item, and, on request, re-laid so it matches; the sound never moves. An item needs at least 3 trusted points and half of those measured, agreeing within 2 frames, or it is left alone ("UNSURE -- N of N probes matched ..." or "the probes disagree: ..."). Each item is reported as "in sync" or "SLIP +N frames", with "-- DRIFT over a frame: a slip cannot fix it" when the points spread more than a frame. If the picture would start before its file, the item starts later instead; if Resolve lands it a frame off it is re-laid once; the item's colour is kept. If the sound track changes at all, the run stops ("A1 CHANGED -- stop. ..."). Messages: "no ANGLE timelines match"; "NOT MEASURED: <reason>"; "N item(s) to slip, N not measurable"; "dry run -- nothing changed. Re-run with --apply."; "Resolve refused to delete <item> -- nothing changed"; "the append of <item> FAILED after its delete -- V1 has a hole at record frame N; source a-b". The timeline that was open is made current again at the end.
- Flag: dormant: a one-off repair of timelines built wrongly

### 39-088: The Zoom recording can be put on the first audio track of every angle timeline, matched and loudness-normalised.
- Where: cards-footage-in / Grouping clips and building the multicam
- What: For each angle timeline, the interviewee is found by matching the words of the timeline's name to the interviewee's folders (Chinese characters ignored; one name may carry an extra given name when at least two words match; a trailing session number is dropped if needed). The reference is the interviewee's rendered multicam sound; every Zoom file whose sound matches it strongly enough is placed at its measured offset, longest first, and a later part of a split recording is expected where the previous part ended (its measured place is used only within 20 seconds of that). The new sound covers exactly the span the old sound on that track covered (or the whole timeline if it was empty), never more. A timeline already carrying exactly those Zoom files is skipped. On request, the old sound items are deleted, the Zoom parts placed, and each is set to EBU R128 loudness normalisation at -23 LUFS (a decision made on the editor's behalf, which can be switched off or done alone). The run stops if Resolve places fewer parts ("A1 is now PART-BUILT, fix by hand") or the timeline's length changes ("LENGTH MOVED a -> b frames"). Messages: "no project open in Resolve"; "** no Zoom recording -- left as it is **"; "** nothing correlated above X -- left as it is **"; "(no reference WAV or no media folder)"; "note: Resolve refused R128 on <item> -- the audio is placed, its loudness is untouched"; "ok <timeline>: A1 replaced, N frames, length unchanged (N)"; summary "[DRY RUN: ]N angle timeline(s) would be rewritten | rewritten, N interviewee(s) skipped" (a preview always counts 0).
- Flag: dormant: a one-off repair, with one episode's media folder built in as its default

### 39-089: A developer can look at and drive Resolve's own windows, menus and dialogs from a command line.
- Where: cards-to-resolve-and-exports / Talking to Resolve: restarts, dialogs and speed
- What: On Windows, without touching Resolve's scripting (so it is safe while Resolve launches), someone can list Resolve's windows, list the controls inside one, open a menu item by its path (or list a menu), wait for a window to appear or go, take a picture of a window, send keys, click a point, press a named button, and close a window. Facts about Resolve: its viewers come out black in a picture taken while the window is behind others, so Resolve is brought to the front and the screen area grabbed instead; Resolve's menus use an ellipsis character. Messages include "(none -- is Resolve running?)", "Resolve is not running", "no visible window matching '<t>'", "'<t>' is ambiguous: [...]", "empty menu path", "no top-level menu '<x>' (have: ...)", "no item '<x>' under '<path>' (have: ...)", "no menu bar found on the Resolve window".
- Flag: dev only

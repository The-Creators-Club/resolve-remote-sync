## The twelve that matter most

In the order a fix pass should take them. Nine of the twelve are in code
written today; three are the day's fixes reopening the finding they closed.

1. **`comp-sync-1` - a managed companion with an empty plan trashes EVERY
   file it is told to move, including a move within the project it holds**
   (high, proved from the venv). `_synced_project_rels` answers `[]` (not
   `None`) for a sequencer with no selection, `_dest_is_synced_here` is False
   for every path against an empty list, and CR-283Y's section-4b branch
   then fires for every move: the local copy goes to `.ccsync-trash`,
   `paths=None` means Resolve is never relinked, `ok=True` records the
   machine as having followed, and `prune_trash` deletes the copy on its age
   rule. An editor between projects, or one whose admin just cleared the
   ticks (`editor_media` rows and therefore `file_move_targets` survive),
   loses a local original that may have no other holder. Treat an empty
   plan as "cannot tell", never as "syncs nothing".
2. **`comp-sync-2` = `res-companion-1` - the 4b trash path becomes the
   "RELINK IT" destination** (high). The branch writes an INTENT row whose
   `new_local` is the trash path before moving the file, then completes with
   `paths=None` on purpose, but `FileMoveLedger.record()` carries the
   previous row's paths forward when `paths` is falsy, and `moved_to()`
   skips `applying` only, not `not_synced_here`. The watcher's RES-10 hook
   offers the editor a one-click relink of every clip under the folder into
   `.ccsync-trash`, a directory `prune_trash` deletes in 14 days.
3. **`dash-db-1` = `res-fleet-1` (= `dash-api-1`) - res-fleet-4 landed its
   OFFER half only** (high, reproduced in a scratch DB by three hunters).
   `pending_file_moves` / `pending_resolve_undos` now offer commands filed
   under a computer's former hostname and the delivery stamp follows the
   row's key, but `mark_file_move_applied`, `mark_resolve_undo_applied` and
   `_file_move_answer` still match on the REPORTING hostname: the machine's
   answer updates zero rows and is dropped without a log line, the command is
   re-offered every report for ever (permanently, if the rename adoption is
   refused), and it ages into the `file_move_expired` alert, the exact
   outcome the fix was written to end. The new test pins the offer only.
4. **`dash-db-2` - `command_machine_names` has no liveness test** (high).
   SYS-18a deliberately leaves two live rows on one `machine_id` for a cloned
   disk; the new helper hands each twin the other's commands, which its own
   docstring forbids. Only a QUIET former name is wanted.
5. **`dash-collector-alerts-1` - cross-cycle move pairing invents a
   fleet-wide file move** (high, reproduced from the venv). The within-pass
   matcher had an implicit proof that two halves are one act (one atomic
   picture of the same projects). `pair_across_cycles` (CR-285AL) pairs a
   vanish and an arrival up to two days apart on `(basename, size,
   mtime_ns)` alone, across every project, and feeds them straight to
   `record_file_move(state=DONE)` targeting every holder: an unrelated delete
   in A plus a first-time copy arriving in B makes every machine holding A's
   copy move its file into B and relink Resolve, unattended. The security
   lens flagged the same rule independently.
6. **`comp-resolve-1` = `regression-1` - the refresh verdict is written under
   a key nothing reads on any machine that cannot open the canonical
   spelling** (high, proved from the venv). `_geometry_disagrees` keys the
   memory on `probe` (the openable local twin); `apply_relinks` writes it
   back under `op["file_path"]` (the canonical `P:\...`); `_geometry_key`
   normcases both, so they differ wherever the spellings do: every macOS
   editor, any companion without the P: mapping. There the stand-in refresh
   is re-planned every 120 s pass and the 8-per-day `allow_automatic` budget
   is gone in about sixteen minutes, which stops all genuine proxy relinking
   on that machine for the rest of the day: CR-282D/E's harm, back, on the
   machines they were for. The tests use one `tmp_path` spelling and cannot
   see it.
7. **`proxy-tiers-1` - a `busy` or unobserved-failed fetch leaves a stand-in
   row nothing can ever falsify** (high, proved). CR-282C writes the intent
   row with `size=None` before the fetch, but `STATE_BUSY` returns three
   branches earlier (`poll_fetch`'s own docstring: "nothing started, nothing
   registered"), and a failed download nobody polls again leaves the same
   row; a `size=None` row reads "still a stand-in" for ever, and the 30-day
   prune needs the file absent, which the real original prevents. So the
   companion permanently believes the REAL original at that path is a lie:
   the 1080p preview is attached as its proxy (audit F1's exact harm), the
   refresh is suppressed, and the rel is broadcast to the fleet as a
   stand-in through `standins_placed`.
8. **`comp-broll-tiers-1` - a tree that is absent for one poll erases the
   stand-in ledger** (high). CR-284N's prune treats "cannot stat" as "gone":
   an unplugged sync drive, a `P:` not yet mapped at start, an SMB blip,
   drops every entry older than 30 days on the next write, after which
   `is_standin` answers False and a render on that machine renders 1080p
   H.264 under a 6K name. `root_guard` / `drive_swap` already answer the
   question the prune does not ask.
9. **`wire-1` - the two-stage `/uploaded` makes the item terminal, so the
   original's upload can never fail, be retried, or be noticed** (high).
   `_maybe_stage_live` (CR-284I) writes `ingest_items.state='live'`, which
   is in `ITEM_TERMINAL`; every later state write is refused `400
   illegal_transition`, swallowed at DEBUG by `_fail_item`; `retry_failed`
   re-queues `failed` rows only; the batch releases `done` with
   `videos.original_path` NULL for ever. Nothing in either suite exercises
   the second stage.
10. **`comp-app-1` - the remembered dashboard version is never forgotten, so
    a documented dashboard rollback 422s every report from that machine, for
    ever** (high). `_note_dashboard_version` writes only when the key is
    present; the docstring claims the opposite ("an ABSENT `dashboard_version`
    means an older dashboard"). After 0.7.50 has been seen once, a rollback
    to 0.7.49 (`docs/RELEASE.md`, a scripted operation) meets a companion
    still sending `state: "not_synced_here"`, and 0.7.49 rejects the whole
    report every 30 s with no recovery path: the failure res-fleet-3's gate
    was built to prevent, reached from the direction its test never tries.
11. **`res-companion-2` - the file-move ledger became multi-threaded today
    and has no lock** (high). `record_relocation` runs on the lane thread
    (CR-282B) and `record` / `record_intent` on the reporter thread; both
    `_save()` through one `file_moves.json.tmp` and `replace` it, so an
    interleaving promotes a truncated or doubly-written file to the live
    ledger and the loser's `replace` raises into a swallow.
12. **`broll-indexer-1` - the cheap frame check lets a 1-2 frame short
    proxy through, in both indexer producers** (high, proved with
    substituted seams). CR-286B skips the authoritative source packet count
    whenever the proxy is within `FRAME_SLACK` (2) of `duration * fps`; for
    a CFR camera original that is exactly the population the check exists
    for, so a proxy 1798 of 1800 frames lands `ok`, reopening the low end of
    the Reproductive Rights class and breaking `frames_match`'s "three
    producers, one exact rule" (the companion still counts both sides and
    would refuse the same file).

## Other findings worth reading before deciding

- **The busy-database handler now runs twice for a mounted app**
  (`dash-core-1`, medium, measured): `_install_busy_handler_on_mounts`
  (CR-285O) registers the parent's handler on the sub-apps, but Starlette's
  `ServerErrorMiddleware` re-raises after handling, so the parent's copy runs
  the same handler again: one mounted 503 writes a notice reading "2
  time(s)" with two DB writes and two tracebacks, doubling write pressure
  under the exact contention it reports.
- **The retry button still does not reach the page** (`ytdl-web-1`,
  medium): CR-286K's `renderRetry` reads `state.manifest`, but `poll()` never
  loads the manifest for a `failed` job, so in the no-room scenario the
  button stays hidden live and after a reload; its regression test is a
  source grep and cannot see it.
- **The cancel fix closed the dead-lease branch only** (`music-1`, medium):
  a cancel delivered to a machine holding a LIVE lease still nulls
  `lease_expires_at` while leaving `running`, the row no sweep can reach.
- **The restart path still dies on a full `/data`** (`dash-release-jobs-1`,
  medium): CR-285S guarded `request_restart` but `consume_restart_request`
  re-reads from disk and the two `_set_state(step="restarting")` calls before
  it are unguarded, so `apply` and `rollback` never reach the guarded call.
- **The retire banner is now permanent** (`dash-mounts-ui-1`, medium,
  proved with a three-boot scratch run): regression-3's retire carries
  `revert_refused_reason` into a record whose `version` is `""`, and
  `main()` returns before the clearing rule on every later boot, so the
  dashboard-update panel tells the admin to restore a backup on a server
  booting the image perfectly.
- **The sw.js kill switch still empties the live per-episode page's shell
  cache** (`dash-cards-1`, medium): `cards-shell-<VER>` is one origin-wide
  name shared by the old flat page and every `/cards/p/<slug>/`, so a phone
  that visits `/cards/` loses the installed app's offline ability.
- **The 15-minute idle release measures served requests** (`security-1`,
  medium): an editor in an offline Cards session or with a sleeping phone
  loses `occupants()`, and any other signed-in editor may then close their
  engine, where before only an admin could.
- **The macOS release script cancels CI's ffmpeg requirement**
  (`server-tools-1`, medium): `CCSYNC_REQUIRE_FFMPEG="$REQUIRE_FFMPEG"`
  exports an empty string when ffmpeg is absent and overrides the `"1"` the
  workflow set on that very step, so the macOS runner can silently skip the
  twenty media-job tests tests-1 made mandatory.
- **The tray leak fix frees neither the window nor its class**
  (`comp-ui-3`, medium): no `DestroyWindow` in `_teardown`, no
  `UnregisterClassW` anywhere; it nulls `_hwnd`, which is exactly what the
  new test asserts.
- **A kill stops the child, not the grandchild** (`comp-music-ytdl-jobs-1`,
  medium): `jobs_runner._terminate` and `ytdl_executor._kill_proc` kill the
  immediate process only, so a cancelled job or a FLEET HALT stops
  `pipeline.py` while the whisper worker it spawned keeps the GPU and keeps
  writing, and the halt is reported as honoured.
- **The full uninstall still leaves the fleet token behind**
  (`install-onboard-3`, medium): section 5 of `windows_uninstall.ps1`
  deletes `~/.ccsync` with `SilentlyContinue` and prints "removed", while
  the new leftovers scan looks only at `%LOCALAPPDATA%\ccsync`; with
  `companion.log` held open, `config.toml` (the `cce1.` token) survives a
  run that ends "complete".
- **NFC on one line but not the next** (`broll-1`, medium): the top-slot
  search was normalised, the editing-proxy stat two lines below was not, so
  a Mac's NFD-spelled editing proxy answers `edit_proxy_rel: null, known:
  true`, and a row with no bitrate (everything indexed before migration 012)
  pulls the full camera master to a remote editor.
- **Tests lens**: seven, led by
  `test_reapplying_the_running_version_keeps_the_rollback_target`, which
  never calls `dashboard_update.apply` and re-evaluates the corrected
  expression inside the test body, so the only test for dash-release-jobs-5
  stays green if the blanking arithmetic is put back.
- **Regression lens**: every ledger section that claims a fix has real code
  behind it, and none of CR-249..CR-266 was reverted; one of the twenty-one
  OWED hand-offs was not discharged (certifi for the frozen Mac bundle,
  CR-280), and the verdict-key mismatch above (`regression-1`) is the one
  place a high was reopened by its own fix.

# Extract of inventory section 03

## Items

### 03-001: The projects ticked for a computer sync in the order the dashboard gives them, and a project being worked on jumps the queue.
- Where: sync / What syncs where
- What: Each computer works through its ticked projects in the order set on the dashboard. When a file changes in a ticked project on the editor's computer, that project moves to the front of the remaining queue, right after the project being synced now; it never interrupts the project being synced now. A change in a project already handled this round does not send it round again; it only shortens the wait before the next round. When several projects are waiting, one project's uploads and proxy downloads get up to about ten minutes before the next project has its go; uploads still running at that point finish in the background rather than being cut off. If the order is changed on the dashboard, the new order takes effect within about a minute, without redoing projects already handled this round.

### 03-002: The app on the editor's computer shows one line saying what syncing is doing right now.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: The line reads one of:
  - "starting up";
  - "Waiting for the server: this computer has no plan saved yet" (the server cannot be reached and this computer has never received its list of projects);
  - "Waiting for the server: using the plan saved on this computer" (the server cannot be reached; the last list received is being used);
  - "Nothing to sync yet: no projects are ticked for this computer" (the server answered with an empty list; this is a normal, calm state, never a warning);
  - "syncing <project> (<n>/<total>)", or "uploading <project> (<n>/<total>)" when that project is ticked upload only;
  - "idle between passes";
  - "paused";
  - "stopped".
  The project is named by its label, else its path on the server.

### 03-003: A change on an editor's computer starts syncing within about a minute, and the product checks less often when nothing is changing.
- Where: sync / Load on the NAS when nothing changes
- What: After a round in which something moved, the next round starts about a minute later. After rounds that moved nothing, the wait grows to about two minutes and then about five minutes, and never goes beyond five. Any of these cut the wait short and bring it back to about a minute: a file changing in a ticked project, the editor pressing "sync now", resuming after a pause, and any change to what this computer syncs (a tick, an untick, a change of mode). With nothing ticked, the computer asks the server for its list about once a minute. When the server cannot be reached during a round (both uploading and downloading fail on a project), the rest of that round is abandoned and the next one is tried after the usual wait; the log says so. A project the product has recently found fully in step is not re-checked against the server on every round, but is always re-checked within about two hours, at once after "sync now" or a resume, and whenever there is any doubt (a restart, a change of plan, a recent change in the project, a failed download).

### 03-004: A project the server describes incompletely, or in a way that would reach outside the project tree, is never synced.
- Where: sync / A plan belongs to a computer
- What: A ticked project is skipped (never synced, never used to make a folder) when its path on the server is missing, blank, or would reach outside the project tree, when it has no short name, when the server marks it inactive, or when its mode is one this version of the app does not know. A missing mode means a full tick. An unknown mode means the project is not synced at all, so an older app never guesses at a newer kind of tick. A skipped project is noted in the log when its turn comes.

### 03-005: The folder structure of a ticked project is made on the editor's computer, empty folders included.
- Where: sync / Project folders on an editor's computer
- What: For a fully ticked project, every folder that exists in the project on the server is created on the editor's computer, including empty ones, so the editor sees the project laid out as on the server. This happens on the first round after the app starts, at once after the server moves the project, and every so often after that (about one round in ten), so a folder made on the server appears on editors' computers without anyone asking. It never happens for an upload-only project, and never when the sync drive is missing (the log says the drive may be disconnected), so no stray tree is built on the boot disk.

### 03-006: An upload-only project sends this computer's files up and brings nothing down.
- Where: sync / Upload only
- What: For a project ticked upload only on this computer, every file made on this computer goes up to the server (not only video), proxies do not come down, other project files do not come down, and it borrows no folders from other projects. Its status row adds "Uploads only. Proxies do not come down for this project." while it is syncing or waiting. Whether a file belongs to an upload-only project is decided ignoring letter case, slash direction and the two ways Windows and macOS spell accented letters; a file that cannot be placed counts as not upload only.

### 03-007: A proxy download that hangs on one project does not hold up the others, and the editor is told.
- Where: sync / Stuck, slow and fair transfers
- What: A proxy download that runs well past its project's time is ended so the other projects get their turn; the log names the folder. If it still will not end, no new proxy download starts anywhere on that computer until it does, and the proxy download state shows "stalled on <folder>: waiting for an earlier pass to end". Proxy downloads return on their own when it finally ends (the log says proxy download is back). Uploads and other project files carry on throughout.

### 03-008: A project with a large proxy backlog gets extra turns while every other project has nothing to do.
- Where: sync / Stuck, slow and fair transfers
- What: When a project's proxy download stops at the end of its turn with files still to fetch, and every other ticked project had a complete turn in roughly the last ten minutes that found nothing to do, and nothing has changed in any of them since, that project gets another turn straight away instead of waiting a round. The log says "<project> still has files to fetch and the other N project(s) found nothing in the last M min -- giving it another turn". It never happens while syncing is paused or stopped, while the sync drive is missing, while another project is still waiting to start syncing its project files, or when the round found the server unreachable; any change to the plan takes precedence. After the app restarts, the first round is the plain order.

### 03-009: An optional mode lets only the project whose turn it is sync its project files.
- Where: sync / Speed and routes
- What: Normally the project files (everything other than originals and proxies) of all fully ticked projects keep syncing whichever project has its turn. An optional mode instead holds every other project's files still while one project has its turn, for up to that project's whole turn.
- Flag: dormant: the one-project-at-a-time mode is off everywhere and can only be set by hand on a computer.

### 03-010: Half-finished uploads left on the server by an interrupted upload are counted and reported, never deleted.
- Where: sync / Saying truthfully what the sync is doing
- What: Every so often (about one round in twenty per project) each project on the server is checked for files left half-uploaded by an interrupted upload, and their number is reported. Nothing is deleted.

### 03-011: The editor can see a list of every ticked project with what it is doing and why.
- Where: editor-app / Windows, dialogs and notifications
- What: One row per ticked project: its name, its mode, its state, the state of its uploads, its proxy downloads and its other project files, and a sentence:
  - blocked, with the reason, when a move the server made could not be applied on this computer;
  - blocked, "Waiting for its filter list from the server. It starts by itself once that arrives." when the product cannot yet confirm which files must never sync in that project;
  - paused, "Sync is paused on this computer.";
  - syncing, "Syncing now (N of M).";
  - waiting, "Waiting its turn." for projects still due this round, and waiting with no sentence otherwise.
  Only the project being synced shows live states; others show "waiting" or "paused". Proxy downloads show "off" for an upload-only project or a computer that does not download proxies; other project files show "off" for an upload-only project. The same window lists the projects waiting for their filter list, one sentence per shared library or borrowed folder that is not working, and the last few moves the server made to projects with what happened to each (old and new place, when, and whether Resolve was relinked).
- Flag: several ways in: the problem sentences for shared libraries and borrowed folders appear on the one-line status, in this window, in the settings window and on the dashboard.

### 03-012: Some files never travel by the general sync, and a project whose rules for them cannot be confirmed stays offline until they can.
- Where: sync / Files that must never sync
- What: Within a ticked project, video originals only go up and proxies only come down; neither is ever carried as an ordinary project file. Never synced as project files: these video types (any letter case): BRAW, MOV, MP4, MXF, AVI, MTS, M2TS, MKV, R3D, CRM, MPG, MPEG, WMV, WEBM, INSV, 360; any folder named Proxy at any depth and everything under it; files still being uploaded, downloaded from the server or downloaded from YouTube; the product's own half-copied files. In the shared libraries the operating systems' hidden clutter files and temporary files are also never synced. A project, library or borrowed folder whose rules cannot be confirmed (they could not be read or written) is held offline rather than synced without them, shows as blocked, and starts by itself once the rules are confirmed. These same video types are what the product counts as video originals everywhere on the editor's computer.

### 03-013: A deletion made on another computer is never applied to this one, and changed files keep earlier versions for 30 days.
- Where: sync / Deletions and removing a project
- What: For project files and shared libraries, a file deleted on another computer or on the server is not deleted on this computer. A file changed by sync keeps its earlier versions on this computer for up to 30 days. Uploads of originals never delete anything on the server.

### 03-014: An editor can pause syncing, resume it, and ask for a sync now.
- Where: sync / Studio-wide stops and the editor's pause
- What: Pause stops uploads and proxy downloads after the current step; other project files keep syncing. A pause is never reported as a fault. Resume starts again at once and re-checks every project against the server. "Sync now" cuts the wait short and re-checks every project at once.

### 03-015: An editor can stop all syncing on their computer, and an admin can stop all syncing across the studio.
- Where: sync / Studio-wide stops and the editor's pause
- What: Stopping all syncing stops uploads, proxy downloads and every project, shared library and borrowed folder's file syncing, and holds across restarts of the app and the computer. An editor can stop and restart it on their own computer. An admin can stop it for every computer from the dashboard, with a reason; each computer picks this up the next time it reports. An editor cannot restart a studio-wide stop: they are told "your admin stopped syncing for the whole fleet: <reason>. Only they can start it again." When the admin gives no reason, the reason shown is "your administrator stopped syncing across the fleet". A studio-wide release lifts only the studio-wide stop; an editor's own stop stays. A computer that has not heard from the dashboard keeps whatever stop it has. Starting again when nothing is stopped is refused with "syncing is not stopped"; a successful restart says "syncing will start again". While stopped, nothing that would start syncing is allowed, including newly offered folders, and if it cannot be told whether syncing is stopped, it is treated as stopped. The dashboard is told whether a computer is stopped, by whom (the editor or the studio) and why.

### 03-016: Proxy downloading stops by itself when the server suddenly looks wrong, and only a person restarts it.
- Where: sync / Safety stops
- What: Proxy download on a computer stops by itself, and stays stopped across restarts, when:
  - the server does not look like the project tree at all (its projects folder is not there);
  - the server lists nothing where there were files last time;
  - the server lists fewer than half the entries it did last time, where there were at least four;
  - one round would remove more than 50 proxies from this computer, or more than a quarter of them where there were at least 20;
  - removals add up to more than 200 since the stop was last restarted (a slow leak).
  A proxy that the server moved elsewhere in the tree is not counted as removed; if it cannot be checked whether files were moved, they count as removed. A failed listing of the server is not a reason to stop (that round simply fails). Uploads and other project files keep running. The editor is told, once per stop, in a notification and on the status line, with one of these sentences, each followed by "Nothing was deleted and your uploads are still running. Ask your admin to check the server.":
  - "The server does not look like your project tree right now, so CCSync stopped downloading proxies before anything could be removed."
  - "The server suddenly listed nothing where your proxies were last time, so CCSync stopped downloading proxies before anything could be removed."
  - "Far fewer files are on the server than there were last time, so CCSync stopped downloading proxies before anything could be removed."
  - "One proxy download pass would have cleared out far more files than normal, so CCSync stopped it."
  - "Proxy download has been clearing out files steadily for a while, so CCSync stopped it."
  - otherwise "Proxy download stopped itself as a safety measure."
  The dashboard sees that it stopped, why, when, and how many files and bytes were removed. Only a person restarts it: the editor on their computer, or an admin from the dashboard (an admin's restart is applied once even though it is repeated until the admin clears it). Restarting clears every count and takes what the server shows next as the new normal. The limits can be changed on a computer.

### 03-017: A proxy removed from an editor's computer goes to a recovery folder first, and the folder is emptied by age and size.
- Where: sync / Deletions and removing a project
- What: A proxy that has gone from the server is moved into a hidden recovery folder at the top of the sync drive, one batch per download round, not deleted. Batches older than 14 days are removed. If what is left is over 50 GB, the oldest batches are removed until it is under; the newest batch is never removed by this rule. When the sync drive is short of free space, the oldest batches are removed until there is enough again, again never the newest (the log says recovery copies the age and size rules would have kept are being dropped). Nothing is removed while proxy download is stopped by its safety stop. Every removal is logged with its size and reason. The clean-up runs a few times a day. The editor is shown the folder's size, number of files, oldest batch and how long copies are kept, and can open the folder.

### 03-018: Proxy downloading pauses itself when the sync drive is nearly full, and restarts by itself when there is room again.
- Where: sync / Disk space
- What: When the sync drive has under 20 GB free, proxy download pauses (shown as paused, not as an error); uploads and other project files keep running. It starts again on its own once twice that (40 GB) is free; between the two it stays paused. The sentence shown is "this drive has N GB free, and proxy download needs F GB" below the floor, and "this drive has N GB free, and proxy download starts again on its own at C GB" between the floor and the restart point, updated as space changes. The editor is notified when it pauses. A restart by the editor or an admin tries again at once, and pauses again if there is still not enough room. A free-space reading that failed changes nothing. The floor can be changed on a computer, and set to nothing to turn this off. The dashboard sees whether it is paused, why, the free space and the floor.

### 03-019: The dashboard sees each computer's free and total space on the sync drive and its free space on the system drive.
- Where: dashboard / Each computer's state
- What: Each computer reports the free and total space of its sync drive and the free space of its system drive, with the time measured. A value that could not be measured is shown as unknown, never as zero.

### 03-020: A safety stop that could not be saved is held anyway and the dashboard is told.
- Where: sync / Safety stops
- What: If the proxy safety stop, the free-space pause or a stop-all cannot be saved on the computer, it still holds while the app runs, saving is retried about once a minute, and the dashboard is told the stop is not saved, why, and since when (a restart would lose it). The log says when it is saved again.

### 03-021: The editor and the dashboard are told truthfully what project-file syncing is doing.
- Where: sync / Saying truthfully what the sync is doing
- What: Project-file syncing is shown as idle, syncing, paused or in error, with a count and a sentence:
  - idle: "last synced" is the time of the last check that found everything in step; with no projects to check it says "no project folders to check yet" and the last-synced time is kept, never set to now;
  - syncing: the number of files still to come, else to go, and the direction (down, up, or both); "waiting: not connected to the server (N file(s) owed)" when nothing is connected; "sending N file(s) (<size>) to the server" when only sending; "setting up N newly ticked project(s)" while newly ticked projects are being offered by the server;
  - the detail adds when transfers are taking a slow, indirect route to the server;
  - paused: "N folder(s) paused" when every project is paused;
  - error: projects not set up or not shared on this computer, by name; projects in error, with the reason; "N project(s) are not sharing yet - waiting for their filter list: <up to 5 names>[, +K more]"; project-file syncing not working on this computer (see 03-023).
  Problems with shared libraries and borrowed folders are added to the sentence whatever the state: the first one, plus "(+N more)". The dashboard can tell a transfer that is stalled from one that is slow.

### 03-022: An external sync drive that is plugged back in is picked up within about a minute.
- Where: sync / The sync drive
- What: When a project reported its folder missing (the drive was out) and the folder is back, the product has it looked at again within about a minute, rather than waiting up to an hour. This only reads.

### 03-023: If project-file syncing stops working on a computer, it is restarted on its own, and the editor and the dashboard are told.
- Where: editor-app / Starting, staying running and crashing
- What: After about 30 seconds without an answer, it is restarted; further attempts follow after 30 seconds, 1, 2, 4 and 8 minutes, then every 10 minutes for as long as it is down. A restart is judged failed if syncing is not working again within 20 seconds. It is not restarted while syncing is stopped or paused, or while that cannot be told. On macOS and Windows alike. The status line and the dashboard show:
  - that syncing is not running on this computer and is being restarted;
  - that it could not be started, with the error, after three failed attempts;
  - "... it is not being restarted: automatic restarts are switched off on this machine";
  - "... it is not being restarted: <stop or pause reason>";
  - when the installation on the computer is damaged: "Ask your admin to re-run the CC Sync installer on this machine."
  Notifications: that syncing was not running and has been restarted, when it works again after a restart; and once, on the third failure, that it will not start, with the error. The dashboard sees since when it has been down, how many attempts, the last error and whether it is being restarted. The outage record survives a restart of the app. Automatic restarts can be switched off on a computer (on by default).

### 03-024: A ticked project that uses a folder from another, unticked project gets just that folder.
- Where: sync / What syncs where
- What: A project can borrow a subfolder of another project (at least two levels inside it, never a proxy folder). On a computer where the borrower is fully ticked and the other project is not, only the borrowed subfolders come to that computer, at their place inside the other project, with uploads, proxy downloads and project files, each borrowed folder getting its own full turn inside the borrower's turn. A change in a borrowed folder moves the borrower up the queue, and uploads go to the other project's place on the server. Where the other project is fully ticked on the computer, its own syncing covers the folder; where it is ticked upload only, the borrowed folder still comes down. Where two borrowed folders overlap, the one first in the order wins. An upload-only borrower borrows nothing. If the other project moves on the server, the borrowed folder follows it on the editor's computer (never when the sync drive is missing). When nothing borrows a folder any more, it stops syncing and its files stay on disk; this never happens on an empty or unknown list. If the editor then ticks the other project, the folder becomes part of a normally synced project. A stop-all covers borrowed folders. An incomplete description from the server gives "<project> could not be set up on this computer: the server's description of it is incomplete. It keeps trying."

### 03-025: Every editor's computer receives the studio's LUT library and Resolve gallery stills without ticking anything.
- Where: sync / What syncs where
- What: Two libraries come to every editor's computer whether or not anything is ticked: the LUT library (shown as "Assets/Luts (LUT library)") and the Resolve gallery stills ("Assets/Stills (Resolve gallery)"), at those places under the sync drive. No video ever travels in them. An admin must approve a library for a computer. If the library's place on the computer has moved, it is moved and re-pointed. A library is never set up when the sync drive is missing. While syncing is stopped, a newly offered library waits and is taken up after the stop is lifted. Problems are shown, each until a later attempt succeeds, with retries after 1 minute, doubling up to every 30 minutes:
  - "<name> has not been shared with this computer yet. Ask your admin to approve it."
  - "<name> is not set up yet: CC Sync could not check it on this computer. It keeps trying."
  - "<name> is not syncing yet: CC Sync could not confirm its filter list, and a folder without one must not go online. It keeps trying."
  - "<name> is not syncing on this computer: its folder moved and it will not start at the new place on its own. Ask your admin to remove it from this computer so it is offered again."
  - "<name> could not be set up on this computer[: <reason>]. It keeps trying."
  A stop-all covers both libraries.

### 03-026: Each computer gets its list of ticked projects from the dashboard, and keeps the last one for when the server cannot be reached.
- Where: sync / A plan belongs to a computer
- What: The app asks the dashboard for the projects ticked for this person on this computer. Nothing is asked until someone is signed in; signing in as someone else asks at once. A change on the dashboard reaches the computer within about a minute. When the dashboard cannot be reached, the last list received is used and the status line says so; a saved list that belongs to a different person than the one signed in is never used. The product knows how old the list is (from when it was saved or last confirmed) and never shows an unknown age as fresh. Signing out and back in brings proxy downloads back. Without a dashboard configured, the computer syncs nothing.

### 03-027: An editor can remove a project from their computer, and the product makes sure the dashboard has unticked it first.
- Where: sync / Deletions and removing a project
- What: The first step of removing a project from this computer is unticking it on the dashboard. Refusals:
  - no dashboard set up, or nobody signed in ("sign in first");
  - "dashboard refused the untick (HTTP <code>)", "dashboard unreachable: <error>";
  - "the dashboard still lists it in this computer's sync plan after the untick. Untick it on the dashboard's sync plans page";
  - "the dashboard has no tick for it under this computer's name (<computer>), but it is still ticked for another of your computers. If this computer was renamed, wait until the dashboard shows the new name, or untick it on the dashboard";
  - "the dashboard has no tick for it under this computer's name (<computer>), and could not be asked whether another of your computers holds it. Try again in a minute".
  When the dashboard does not know this computer's name, or the tick is the person's own rather than this computer's, the project is unticked for all of the person's computers. Success says "unticked" and the next check of the list goes to the dashboard. The project stops syncing on this computer and its files are left on disk; the product checks that nothing on this computer is still waiting to go to the server.

### 03-028: An editor can ask for particular originals of a project to come down to their computer.
- Where: sync / What syncs where
- What: An editor (by default from inside Resolve) can add or remove files or whole folders of a ticked project to the originals this computer should have. The dashboard records the pick for this computer. A refusal from the dashboard is shown to the editor word for word. The same sign-in and set-up refusals as removing a project apply.

### 03-029: The product knows which server folder each Resolve project's media belongs in, and refuses to guess when it cannot ask.
- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: The dashboard tells each computer which project folder on the server belongs to each Resolve project (by name, ignoring letter case). A folder that would reach outside the project tree is ignored. The answer is refreshed every few minutes; when the dashboard cannot be reached the last known answer is used; with no answer at all, the product refuses to choose where media should go.

### 03-030: The dashboard sees what video each computer holds for each project.
- Where: dashboard / Each computer's state
- What: Each computer reports, for every project on it, how many video originals and proxies it holds and their total size, and for ticked projects the list of those files with sizes. Only video counts. It is refreshed about every five minutes, starting at launch. Limits: up to 2,000 files per list per project (counts and sizes stay exact and the list is marked cut short) and up to 64 projects per computer, keeping ticked projects first, then the most recently changed (the log says which are left out and when it is whole again). When the sync drive is unplugged, or goes during a check, the last complete report stands. Ticked projects are matched however macOS spells accented names.

### 03-031: When a file was changed in two places at once, both versions are kept and counted.
- Where: sync / Saying truthfully what the sync is doing
- What: The product counts the conflict copies made when a project file was changed in two places at once, reports the count and up to 20 examples to the dashboard, and logs a warning while any exist. It never deletes or merges them.

### 03-032: The product checks every few seconds whether the sync drive is really there, and stops touching it when it is not.
- Where: sync / The sync drive
- What: Every 5 seconds the product checks the sync drive and acts only when the answer changes (at once after starting, so an app started with the drive out knows straight away). The drive is one of:
  - there;
  - disconnected: "the sync drive is disconnected";
  - mounted at the wrong place (macOS only): "the sync drive is mounted at the wrong place - eject it, delete the leftover empty folder, then plug it back in";
  - not answering (plugged in but its files have stopped answering): "the sync drive is not answering - reconnect it or restart".
  The sentences show on the status line, in a notification, in the sync detail and on the dashboard. In the last three states nothing touches the drive and every kind of syncing waits. A check that itself fails changes nothing. Until the first answer the drive is taken as there. On Windows only there or disconnected is told apart. On macOS, an external drive's empty leftover folder on the boot disk counts as disconnected, and the product remembers which volume is the sync drive (set up by the installer), so it can tell when that volume is mounted under a different name; an external drive being absent at start is a normal state, not a set-up error. While the app is quitting, a change is not acted on.

### 03-033: On macOS the product can tell when macOS has stopped letting it read the sync drive.
- Where: editor-app / Security warnings, permissions and certificates
- What: After an update, the product can check whether macOS is refusing it the sync drive while the drive is mounted (for example after Full Disk Access was lost), as opposed to the drive being out.
- Flag: undetermined: whether this check is used anywhere, and what the editor is told.

### 03-034: When the sync drive is pulled out with work still owed, the editor is told what is owed and reminded until it is back.
- Where: sync / What is owed
- What: Only work that is really moving counts (see 03-036). The summary names what is owed, for example "2 uploads and 14 other files (2.3 GB left)", using uploads, proxy downloads, original downloads, other file uploads, other file downloads, other files. Notifications:
  - first: "<Your ... drive> was disconnected before syncing finished: <summary> still to go. Plug it back in to finish syncing.";
  - reminder: "<Your ... drive> is still disconnected and syncing is unfinished: <summary> still to go. Plug it back in to finish syncing.";
  - for a drive plugged in but not answering: "<Your ... drive> is still not answering, so nothing is syncing. Reconnect it or restart this computer."
  The drive's name comes from the site's settings. With nothing owed, the editor gets only a calm "sync paused" notice. Reminders come every 30 minutes (a setting on the computer; 0 means the first warning only), and only when something owed is an upload; if everything owed is a download, only the first warning is given. A drive not answering is always reminded. The editor can snooze ("remind me later": one reminder after the chosen minutes, then the usual pace) or stop the reminders for this time; neither removes the standing warning line, and neither is remembered after a restart. The drive coming back ends it all. If the app restarts while the drive is still out with work owed, reminders carry on with one at once and no new first warning.

### 03-035: On Windows, an editor can point the sync drive letter at the server's camera originals for grading, and back.
- Where: resolve-on-the-editors-computer / Grading from the server's originals
- What: The letter (the site's drive letter, default P) is switched from the editor's local copy (proxies) to the server's share (camera originals); Resolve's paths stay the same. Syncing is unaffected. Refusals and messages:
  - no server share known: the server's share path is not set;
  - "<L> is currently mapped to <target>, which CCSync did not create. Swapping would replace it and CCSync cannot put it back.";
  - "CCSync could not tell what <L> is mapped to, so it is being left exactly as it is. Nothing was changed. If <L> is not mapped at all, restart the CCSync app or re-run the installer to put your local mapping back, then try the swap again.";
  - "<L> already shows the SERVER originals";
  - success: "<L> now shows the SERVER originals";
  - "the server did not answer within 30s -- the drive was not remapped";
  - Windows's refusals, each "System error N: " and a plain sentence: access denied; network path not found (is the server up?); share no longer available; wrong resource type; network name not found; letter already in use; wrong password; Windows already connected to this server as a different account (disconnect or sign out and try again); connection cancelled (the server wants credentials); not a valid device name; no network provider accepted the path; user name or password incorrect; blank password not allowed; any other "System error N mapping <L>".
  When the failure means a login is needed, the editor is asked for their server login and it is tried again; the login can then be remembered by Windows so later swaps and file browsing sign in silently. A password is never shown in a message or a log, and Windows never prompts. Swapping back: "<L> is back to your local copy (proxies)"; if that fails, a second way of pointing the letter at the local copy is tried; if both fail, "<L> could not be restored (<error>) -- remap it by hand or re-run the installer", or, with no local folder set, that the letter is now unmapped. Each step gives up after 30 seconds. When no share is set, it is worked out from the server's address and the NAS's own folder layout.
- Flag: differs: Windows only; there is no grading swap on macOS.

### 03-036: Shutting down while files are really moving is warned against.
- Where: sync / Uploads that cannot resume, shutdown and sleep
- What: Work counts as really moving only while something changed in the last 3 minutes, and not while it has nothing connected to send to; a backlog that has not moved for 3 minutes is treated as stalled, and after 8 hours of continuous work a part stops counting until it settles (each logged once). Paused or failed work never counts, and if it cannot be told, nothing counts. The sentence: "CCSync is still syncing[ -- <size> left[, about N min | about Nh Mm]]. Any file part-way uploaded has to start again from the beginning next time you switch on." (time shown only when a minute or more). On Windows, shutdown, restart and sign-out are held with Windows's own "this app is preventing you from shutting down" screen showing that sentence; the person can still choose to shut down anyway. A real shutdown is recorded as a deliberate exit, not a crash. On macOS a logout cannot be held: the app shuts down cleanly; the first Quit of the app while files are moving is cancelled once with a notification showing the sentence, and a Quit within 2 minutes goes through. Anything going wrong allows the shutdown or quit.
- Flag: differs: Windows holds shutdown with the system screen; macOS only warns on Quit and cannot hold a logout.

### 03-037: The computer is kept from falling asleep on its own while files are really moving.
- Where: sync / Uploads that cannot resume, shutdown and sleep
- What: About every 30 seconds the product checks whether work is really moving (as in 03-036). While it is, the computer is kept from idle sleep on Windows and macOS (the screen may still turn off), and released within about 30 seconds of the work finishing or when the app stops. It cannot stop a deliberate sleep (the sleep command or closing a laptop lid). Anything going wrong lets the computer sleep. The shutdown warning and the keep-awake can each be switched off.

### 03-038: A new version of the app that fails to start twice is replaced by the previous one on its own.
- Where: releases-and-updates / Rolling back and withdrawing a build
- What: One failed start of a new version is allowed (for example anti-virus holding the files). After two failed starts of the same version, the previous version is put back and started instead. A start that lost to an already-running copy, or that was the hand-over during an update, does not count. A start that finishes resets the count. If putting back is refused, one line in a start-up log says the version failed and was not rolled back, and why. None of this can stop the app from starting when it would otherwise start.

### 03-039: Every built app can be checked to load fully before it is published.
- Where: releases-and-updates / Making and publishing a release
- What: The built app can be run in a check mode that loads all its parts and prints "SELF-TEST OK v<version> (N modules)" or "SELF-TEST FAILED v<version>: <failures>", optionally into a file, without disturbing a copy already running. Parts meant only for the other operating system may fail.
- Flag: dev only

### 03-040: When the server moves a project, each editor's copy follows before anything syncs, and Resolve is relinked.
- Where: proxies-and-file-moves / Following a move on an editor's computer
- What: Before a round and again just before a project's turn, a project the server moved is moved on the editor's computer to match; any upload reading from the old folder is ended first ("its folder is being moved to where the server now keeps it"), and the project is relinked in Resolve. Its folder structure is refreshed on the next turn. If the move cannot be applied on this computer, that project does not sync at all (nothing is created at the new place) and it shows as blocked with the reason.

### 03-041: Syncing keeps going after a failed round, and the dashboard can tell a stopped sync from a slow one.
- Where: sync / Saying truthfully what the sync is doing
- What: A round that fails is logged, counted ("N failed pass(es) since launch") and kept as a local crash report, and the next round follows after the usual wait. If syncing stops altogether, the reason is recorded and it shows as stopped. A long upload of one big file is not taken as a stall while it is still moving. A deliberate pause is never reported as an outage.

### 03-042: A computer can be set not to download proxies.
- Where: sync / What syncs where
- What: Proxy downloading is on by default and can be switched off on a computer, for one that reads proxies straight from the server. With it off, proxy downloads show as "off".

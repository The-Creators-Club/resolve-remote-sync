### 05-001: The product never connects to Resolve while Resolve is still starting up, because doing so kills Resolve's scripting for the whole session on that computer.
- Where: resolve-on-the-editors-computer / Connecting to Resolve's scripting: launch, stalls and death
- What: Facts about Resolve that hold whatever is built:
  - Every outside program that talks to Resolve goes through a helper that Resolve starts late in its own launch (it can be minutes after Resolve opens), listening on TCP port 1144 on the computer. Resolve then connects to that helper and registers as its host. The helper exits when its last connection closes.
  - A program that connects in the short gap between the helper starting and Resolve registering gets no Resolve, drops, and takes the helper down. Resolve retries a few times (the editor sees Resolve hang for 10 to 20 seconds while it launches) and then gives up scripting for the whole session, for every program on that computer. The only cure is to quit Resolve and every such program, start Resolve, then start the programs.
  - Asking Resolve for a connection when no helper is present does not fail at once: it keeps retrying for about 4 seconds, so a program that "just checks whether Resolve is up" is mid-attempt when the helper appears.
  - Waiting a fixed time after Resolve opens does not work: the dangerous gap starts when the helper starts, not when Resolve does.
  The product therefore looks, without connecting, at which programs are listening and connected on the computer, and connects only when the helper is listening AND Resolve is connected to it. With no helper (Resolve closed) it stays quiet. With a helper but no Resolve yet, it holds off every call to Resolve until Resolve has registered. Only when it cannot tell at all (the computer's connection list cannot be read, or something else holds port 1144) does it go ahead and connect. On macOS this check was never tried against a live Mac. On Linux there is no such check and the product connects as if the guard did not exist. Every other program on the studio's computers that talks to Resolve must follow the same rule: one careless one is enough to kill scripting for all of them.

### 05-002: Only one request at a time goes to Resolve, and the product knows when Resolve has stopped answering.
- Where: resolve-on-the-editors-computer / Connecting to Resolve's scripting: launch, stalls and death
- What: Everything the app on the editor's computer asks of Resolve (noticing clips, fixing, inserting b-roll, Timeline Cards) takes turns, so two features never talk over each other inside Resolve. Nothing is ever cancelled. When one request has been inside Resolve for more than 30 seconds, the app treats Resolve as stuck: the tray and the computer's report to the dashboard can show which request is inside Resolve and for how long. Beyond that, a stuck request is only written to the app's log (at most once every five minutes, with the advice "if this does not clear, quit and reopen Resolve"); nobody is told.
- Flag: undetermined: where the "Resolve is stuck" state is shown to the editor (the tray and the report read it; their screens are outside this section).

### 05-003: Talking to Resolve never freezes the tray menu.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: While the editor has the tray menu open, the app waits before asking Resolve anything, so the menu stays responsive. Long readings of a big timeline or media pool are paced so the tray keeps answering throughout.

### 05-004: When Resolve cannot be reached, the editor is told which of four situations it is, in plain words.
- Where: resolve-on-the-editors-computer / Connecting to Resolve's scripting: launch, stalls and death
- What: The messages are:
  - Resolve is starting up: "DaVinci Resolve is starting up".
  - Resolve is not running: "DaVinci Resolve is not running".
  - Resolve is open but cannot be scripted, for less than 10 minutes: "DaVinci Resolve is open but its scripting isn't available right now (starting up or shutting down)".
  - The same for 10 minutes or more: "DaVinci Resolve is running but isn't accepting scripting connections. Quit and reopen Resolve. If that does not help, also restart the companion (<the quit item>, then relaunch it) before reopening Resolve."
  Whether Resolve is running is checked at most every 30 seconds; when the check cannot tell, Resolve is assumed to be running. When Resolve is connected but has nothing to work on, the messages are "no project open in Resolve", "no timeline open in Resolve", "no media pool available" or "no root folder in media pool". When Resolve stops answering in the middle of a request: "Resolve didn't answer. Make sure a project is open, then try again."

### 05-005: An editor whose Resolve is open but never scriptable is told how to fix it, and told when no setting can.
- Where: resolve-on-the-editors-computer / Setting Resolve up: edition, scripting switch, preferences
- What: Facts about Resolve: outside programs can only control the paid edition, DaVinci Resolve Studio; the free edition has no scripting at all and no setting adds it. Studio only allows it when Preferences > System > General > "External scripting using" is set to Local or Network; its default is None. The advice the editor gets depends on whether this computer has ever connected to Resolve (remembered across restarts, never forgotten) and on that preference:
  - Has connected before: the "Quit and reopen Resolve ... also restart the companion" advice.
  - Never connected, preference None or not set: says so, then "In Resolve open Preferences > System > General and set 'External scripting using' to Local, click Save, then quit and reopen Resolve." and "Scripting needs DaVinci Resolve Studio, the paid edition. The free edition has no scripting interface, and no setting can add it."
  - Never connected, preference already Local or Network: says it is already set, the Studio note, then "If this is Studio, quit and reopen Resolve; if that does not help, also restart the companion...".
  - Never connected, preference cannot be read: the Studio note and the instruction to set the preference.

### 05-006: Installing the app on an editor's computer finds Resolve and switches its scripting on.
- Where: resolve-on-the-editors-computer / Setting Resolve up: edition, scripting switch, preferences
- What: At install the product finds whether Resolve is installed, its version, and whether it has ever been run on this computer (its preferences exist). On Windows it can recognise the Studio edition from its licence; when it cannot, the edition is reported as unknown, never as "free". On macOS the edition is never recognised. It then sets "External scripting using" to Local, unless it is already Local or Network. Like every change to Resolve's preferences, this waits until Resolve is closed (05-007). On systems other than Windows and macOS everything about Resolve is reported as unknown and nothing is changed.

### 05-007: The product changes Resolve's preferences only while Resolve is closed, changes only what it must, and keeps a backup.
- Where: resolve-on-the-editors-computer / Setting Resolve up: edition, scripting switch, preferences
- What: Facts about Resolve: it keeps its preferences in two files that must agree with each other, and rewrites both whenever it quits, so a change made while it runs is lost. It does not create them until it has been run once. The product's rules for every change it makes to Resolve's preferences (the scripting switch, the shared LUT folder, the shared stills location):
  - Never while Resolve is running; the change waits until Resolve is closed. If the product cannot tell whether Resolve is running, it assumes it is.
  - Never creates the files. If they do not exist yet, the answer is "<path> does not exist -- launch Resolve once, quit it, and retry".
  - Only the lines being changed are touched; the editor's own entries, comments and layout are kept.
  - Both files are backed up beside themselves, stamped with the date and time, before any change. A change that changes nothing writes nothing.
  - If the files are not in the shape expected, nothing is changed and the editor is asked to make the change by hand in Resolve.
  Linux is not supported.

### 05-008: The product notices, within seconds, every clip in the open timeline whose media is in the wrong place or missing.
- Where: resolve-on-the-editors-computer / Missing clips, relinking and refreshing
- What: While Resolve has a timeline open, the app on the editor's computer looks at every clip on every video and audio track (including each angle inside a multicam clip and inside compound clips) about every 3 seconds, and does a complete fresh look at least about every 30 seconds. A change the editor makes is noticed within a few seconds, and at worst within about a minute. Titles, generators, adjustment clips and anything with no media file are ignored. This looking must not make Resolve stutter for the editor or for other programs talking to it. Each clip falls into one of these:
  - In the right place: nothing happens.
  - Outside the shared tree (it will never reach the server or other editors): offered to the editor to fix (05-016), unless the editor skipped it (05-026).
  - In the shared tree but spelled the way only this computer spells it, rather than the spelling every computer shares: fixed on its own (05-010).
  - On the shared drive letter but that letter does not lead anywhere on this computer (the drive mapping is broken): the editor gets one mapping-health warning per breakage, naming the first such clip; once clips resolve again, a later breakage warns again.
  - A path only another computer can open: one tray warning per path while the app runs.
  - Present in the shared tree but the file is not on this computer: counted as missing, unless a usable proxy is on this computer (05-009). The first 50 missing clips are kept by name and path for display. If this computer itself moved that file on the server's instruction, the editor is offered to point the clip at its new place.
  Totals shown in the tray and in the computer's health report: clips outside the tree (including skipped ones), clips on a broken mapping, missing clips, and when the last full look happened. A look that ended early (drive out, Resolve closed, ignored project) leaves the last real totals in place.
- Flag: undetermined: the exact rules for telling the kinds of path apart, and the wording of the warnings, are outside this section.

### 05-010: A clip stored under this computer's own spelling of a shared path is repointed on its own to the spelling every computer shares.
- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: So that a project opens with its media on every computer, a clip in the shared tree that Resolve holds under this computer's private spelling is relinked to the shared spelling without the editor asking. Clips Resolve refused to repoint are listed (name and path, the 200 most recent) for the editor to see; a later success removes the clip from that list. Like every change the product makes on its own, this is limited (05-014) and can be undone (05-012).

### 05-011: Pointing a clip at a different file keeps every edit that uses it, and is only reported as done when Resolve really shows the new file.
- Where: resolve-on-the-editors-computer / Missing clips, relinking and refreshing
- What: A relink points an existing clip in the media pool at another file; every timeline use of the clip is kept. If the clip already points at that file (ignoring letter case and slash direction), nothing is done: "Already linked to <path>". Otherwise the product tries a few times over a few seconds and judges success by reading the clip's path back from Resolve, never by Resolve's own claim. Messages: "Relinked to <path>"; "Resolve didn't answer. Make sure a project is open, then try again."; and, when Resolve accepted the request but the path did not change, "Copied the file in, but Resolve wouldn't relink it. Close the clip's timeline and use <Scan whole project> again."

### 05-012: Every clip path or proxy the product changes in Resolve is recorded so it can be put back.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: For each change the product records the project, the clip's name, its original file, the old and new path, and which feature made it. Changes to one project close together form one undoable change: it ends after 2 minutes with no further change to that project, except that one FIX ALL is always one change however long its copies take. An edit made after an undo starts a new change. At most 5,000 clip changes are recorded in one change; any beyond that are still made but cannot be undone. If the record cannot be written, the change still happens and is not undoable (the log says so; nobody is told). Records are kept 60 days, then deleted, along with any project's record folder left empty for a day.

### 05-013: Before the first change to a project in a while, the product saves the project and keeps a backup copy of it.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: At most once every 15 minutes per project, before changing clips, the product saves the project in Resolve and exports a backup copy of it (without stills and LUTs), stamped with the date and time and kept for 60 days. Facts about Resolve: some Resolve builds cannot export a project from outside, and a project open in a collaboration cannot be exported ("Resolve refused to export a backup copy (a project open in a collaboration cannot be exported)"). When there is no backup copy for any reason, the change still goes ahead. The backup copy is never used by the product's own undo; it exists for a person to restore by hand.

### 05-014: Changes the product makes in Resolve on its own are rate-limited, so a misconfiguration cannot keep rewriting a project.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: Changes made without anyone pressing a button (repointing a clip to the shared spelling, repointing proxies) run for a given project and kind at most once every 15 minutes, and at most 8 times a day per project across all kinds. Further ones are held and counted; this is written only to the log, saying it looks like a configuration problem; nobody is told. The limits survive restarts, and a clock put back does not stretch them. If the limiter itself fails, the change is allowed. FIX ALL and other button-driven work are never limited.

### 05-015: An editor can undo the last set of clip path changes the product made in the open project.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: The tray describes what undo would do: "N clip path(s) in “<project>”, <start time>" (blank if there is nothing). Undo puts every clip in the newest change not already undone, in the project open in Resolve, back where it was, newest first, so a clip changed twice ends at its first path. A proxy change puts the old proxy back, or removes the proxy if there was none. Pressing undo again goes to the change before. Answers:
  - "Put N clip path(s) back the way they were (from <change>)." plus " M were already back." and/or " K could not be undone: those clips are no longer in this project's media pool."
  - "Those clip paths were already back the way they were (from <change>): nothing to put back."
  - "Every clip-path change CCSync made in “<project>” has already been put back."
  - "CCSync has not changed any clip paths in “<open>”. The last change it made was in “<other>”: open that project and undo there."
  - "That change was made in “<A>” but “<B>” is open. Open “<A>” and undo there: replaying it here would re-address clips the two projects share."
  - "CCSync has not changed any clip paths on this machine."
  - "<change> records no changes."
  A change counts as undone only if something was put back, or everything was already back and nothing was skipped; an undo Resolve refused can be pressed again.

### 05-016: An admin can undo, from the dashboard, a change the product made in Resolve on any editor's computer.

  - Failed, with the undo's own message, otherwise.
  A request still waiting after 7 days is given up. A request delivered again after a restart is answered from what already happened, never carried out twice.
- Flag: several ways in: the editor's undo in the tray (newest change, open project) and the admin's undo on the dashboard (any listed change, waits for the project).

### 05-020: FIX ALL copies the file safely: the original is never touched, a half-finished copy never syncs, names never collide.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: The original file is never moved, changed or deleted. The copy keeps the original's file times and permissions. If the destination already holds an identical copy (same name or a numbered variant, same size, same content at start, middle and end; letter case ignored on Windows only), that copy is used and nothing is copied again ("already copied to"). A name already taken gets " (2)", " (3)" and so on, up to 10,000. A copy in progress is invisible to syncing and to other programs under its final name until it is complete. Progress is shown as it copies; the copy slows its steps on a slow drive so the skip and cancel buttons always answer promptly. If something else takes the chosen name during the copy, the copy lands beside it under a fresh name instead.

### 05-028: For a project that existed before the studio's sync, an editor can copy all its scattered media into the project folder in one go, after a preview.

### 05-029: The editor is reminded about Resolve projects they do not have open that use footage only on this computer.
- Where: resolve-on-the-editors-computer / Project libraries and projects
- What: About every 30 minutes (an editor setting; 0 turns it off, which forgets the findings), starting about 2 minutes after the app starts, the product looks through every Resolve project on this computer's project libraries without opening them in Resolve. A project is flagged when at least one of its clips is a file outside the shared tree that exists on this disk, AND at least one other clip is in a project in the shared tree; projects wholly outside the tree are left alone. A library that cannot be read is skipped until it answers; if none can be read, the last findings stand. Reminder (tray notification, titled for "footage only on this computer"), first on finding something and then every 30 minutes while anything is flagged, leaving out the project open now:
  - One project: "N clip(s) in '<project>' is/are only on this computer (<last two folder names>). Open that project in Resolve and press FIX ALL."
  - Several: "N clip(s) in '<top project>' (<folder>) and more in M other project(s) are only on this computer. Open each project in Resolve and press FIX ALL."
  Projects are ordered by most clips; names over 60 characters are cut with "...". The dashboard gets up to 20 project names with clip counts (never paths) and when the last look happened, and "not checked" until a look has finished.

### 05-032: Proxies the product attaches to clips are checked by Resolve, and a refusal is remembered.
- Where: resolve-on-the-editors-computer / Proxies in Resolve
- What: Fact about Resolve: when a file is attached as a clip's proxy, Resolve checks it matches (timecode and frame count) and may refuse. A proxy without embedded timecode is the usual cause of a refusal. Messages: "Proxy relinked to <path>"; "Resolve wouldn't accept <path> as this clip's proxy" (remembered, so the same proxy is not counted as usable for that clip again); "Resolve didn't answer. Make sure a project is open, then try again." (not remembered). Each attached proxy is recorded and undoable. The product can also read a clip's proxy state as Resolve shows it: a resolution such as "1920x1080" when online, "Offline" when attached but unreachable, "None" when there is none.

### 05-033: When a file changes on disk under the same name, the product can make Resolve re-read it.
- Where: resolve-on-the-editors-computer / Missing clips, relinking and refreshing
- What: The clip is relinked to the same path to force Resolve to read the file again, judged by whether its length or picture size changed. Not recorded for undo. Answers: "Re-read <path> from disk"; "Re-read <path>; its geometry did not change"; "Re-read <path>; Resolve did not answer cleanly" (tried again later).
- Flag: undetermined: which features ask for this.

### 05-034: Resolve's LUT list uses the studio's shared LUT folder on every computer.
- Where: resolve-on-the-editors-computer / Colour look-up tables (LUTs)
- What: On by default (an editor setting turns it off). The shared folder is "Assets/Luts" in the shared tree. It is added to the end of Resolve's Preferences > System > General > LUT Locations (the editor's own entries are kept), on Windows under the shared drive letter so it reads the same on every Windows computer, on macOS under the local path; a setting can give a different location. Outcomes:
  - Shared folder not on this computer yet: "the LUT library <path> has not synced to this machine yet".
  - Added: a running Resolve is asked to re-read its LUT list (the same as Project Settings > Color Management > "Update Lists").
  - Resolve running: "Resolve is running -- its LUT Locations will be set the next time it is closed (Resolve overwrites its own preferences on exit)".
  - Preferences not as expected: "Resolve's preference files are not in the expected shape -- add <location> by hand in Preferences > System > General > LUT Locations".
  - Already there: nothing changes.
  A warning is repeated at most once an hour while it stays the same.
- Flag: undetermined: how often the check runs and where its messages are shown to the editor.

### 05-035: When Resolve started before the shared LUT folder was reachable, the product makes Resolve pick up the shared LUTs without a restart.
- Where: resolve-on-the-editors-computer / Colour look-up tables (LUTs)
- What: Fact about Resolve: it scans its LUT locations once, at launch; if the shared drive was not connected yet, the shared LUTs are missing for the whole session, and Resolve's own log records that the folder was not there. The product notices this for the current Resolve session and, once the folder is reachable, asks Resolve to re-read its LUT list, once per Resolve session; if that fails (for example no project open) it tries again later. On by default; an editor setting turns it off (and it is off when shared LUTs are off).

### 05-036: LUTs that exist only on one editor's computer are found and can be shared into the studio's LUT folder.
- Where: resolve-on-the-editors-computer / Colour look-up tables (LUTs)
- What: The product looks in Resolve's own LUT folder on this computer for LUT files (the usual LUT file kinds; DCTL files are not counted) that the shared folder lacks. Not counted: files already in the shared folder; a file of the same name and size anywhere in it; Resolve's own factory LUTs (the camera makers' and standards folders Resolve ships, such as ACES, Arri, Blackmagic Design, Canon, DJI, Film Looks, Sony and the rest, extendable by a setting); a file whose place in the shared folder is taken. Up to 200 are listed, each with name, size and where it would go (keeping its pack folders). Sharing copies the chosen ones in: never overwrites (counted as skipped), never deletes the original, refuses any place outside the shared folder ("<name>: refused, <rel> is outside the LUT library"), leaves nothing half-copied, reports copied, skipped and errors, and asks Resolve to re-read its LUT list if anything was copied.
- Flag: undetermined: where the editor is shown the list and presses share.

### 05-037: Resolve's gallery (stills and PowerGrades) on every computer points at one shared folder.
- Where: resolve-on-the-editors-computer / Other givens on the editor's computer
- What: Fact about Resolve: the gallery on the Color page is kept in a folder on one of Resolve's media storage locations; computers sharing a project database must agree on it, and a Mac can give a location a second, Windows-style spelling that other computers see. On by default (an editor setting turns it off). The shared folder is "Assets/Stills" in the shared tree. The product adds it as a media storage location (before Resolve's own last entry, never touching the first) and points the gallery at it; on macOS the location carries the Windows spelling so the shared database agrees. The gallery is never pointed at a folder that has not arrived. Outcomes: "the shared stills folder <path> has not synced to this machine yet"; already set (nothing changes); "gallery moved to <root>\.gallery" (with / on macOS); "Resolve is running -- the shared stills location will be set the next time it is closed (Resolve overwrites its own preferences on exit)"; "Resolve's preference files are not in the expected shape -- add <root> as a media storage location by hand, and set the gallery to it". Each warning is repeated at most once per app run.
- Flag: differs: the LUT warnings repeat hourly, the stills warnings once per run; undetermined: how often the check runs and where its messages are shown.

### 05-038: Inside Resolve, an editor can ask for camera originals of chosen clips, or stop asking, from Resolve's own menu.
- Where: sync / What syncs where
- What: Resolve shows five items under Workspace > Scripts > CC Sync on the Edit page (fact about Resolve: newly added script items appear only after Resolve restarts):
  1. "Bring originals - selected media pool clips"
  2. "Bring originals - timeline clips between In and Out" (with no In and Out marks, the clip under the playhead)
  3. "Bring originals - whole timeline"
  4. "Stop originals - selected media pool clips"
  5. "Stop originals - timeline clips between In and Out" (or the clip under the playhead)
  There is no "Stop originals - whole timeline". Each counts every clip from the media pool once (titles and generators skipped); between In and Out means every clip on every video and audio track overlapping that range. Answers appear only in Resolve's console (Workspace > Console), no window, each beginning "CC Sync: ": "asked for the originals of N clip(s). The companion will confirm."; "asked to stop bringing the originals of N clip(s). The companion will confirm."; "this script runs from inside DaVinci Resolve (Workspace > Scripts)."; "no project is open."; "no clips are selected in the media pool. Select some and run this again."; "no timeline is open."; "no clips from the media pool sit between the In and Out marks."; "no In and Out marks are set and there is no clip under the playhead."; "this timeline has no clips from the media pool."; "could not find your home folder, so the request was not sent."; "could not write to <folder>, so the request was not sent."; "could not write the request file."; "could not finish the request file (<error>)."; "something went wrong, nothing was sent (<error>).". The items are put in place and kept current whenever the app starts, even with Resolve open; items the product no longer offers are removed, and nothing the editor put there is touched. If Resolve does not seem installed for this user: "DaVinci Resolve does not seem to be installed for this user (<path> is missing)."; a failure never stops the app starting. Not on Linux ("Resolve menu scripts are not supported on this system."). On Windows, asking for originals can flash a console window briefly when the request folder is missing.
- Flag: undetermined: how the request is carried out and how "the companion will confirm"; whether the In/Out reading is right and whether the menu location is as described were never tried against a running Resolve.

### 05-039: Sending a b-roll clip to Resolve puts it at the end of the timeline or over the playhead, and says exactly what happened.
- Where: broll / Sending a clip to Resolve
- What: Two ways: at the end (appended on video track 1) and at the playhead (on the lowest overlay track that is free). The result shows on the b-roll page. Refusals first: the disconnection message (05-004), "no project open in Resolve", "no timeline open - create one first"; any other way: "unknown insert mode '<mode>'". The clip goes into the bin "B-Roll/Archive" in the media pool, made if missing; if Resolve will not make it: "Resolve wouldn't create the B-Roll/Archive bin: the project is locked (or open elsewhere in a collaboration). Unlock it and try again." A clip already in that bin for the same file is reused; otherwise it is imported ("failed to import media at <path>"). A newly imported clip is pointed at the path spelling every computer shares (if Resolve refuses, the local spelling is kept).
  - At the end: the clip's In to Out range is appended to video track 1 whatever the timeline's destination buttons say, and checked to have landed. Fact about Resolve: with the video destination button (V1/A1, left of the timeline) off, an append is silently dropped. Messages: "failed to append clip to timeline"; "Resolve reported no error but nothing landed on the timeline. Check the destination track buttons (V1/A1) at the left of the timeline; with the video destination off, an append is silently dropped."; "Inserted <clip name> (<N> frames)".
  - At the playhead: reads the playhead (drop-frame aware; timeline start if unreadable), works out how long the clip will be on this timeline (assuming 24 fps if the clip's rate is unreadable), and picks the lowest track from V2 up whose video and audio are both free over that span, else one above the highest. Adds video and stereo audio tracks as needed. Messages: "couldn't read the playhead position from Resolve"; "couldn't read the timeline's tracks"; "couldn't add a <video|audio> track for the overlay -- is the timeline locked?"; "placement failed on V<n> at the playhead -- something already occupies that span, or the track is locked" (anything that landed in the wrong place is removed); "Placed <clip name> on V<n> at the playhead" plus " (new track)".
  - Anything unexpected: "Resolve didn't answer. Make sure a project is open, then try again."
- Flag: undetermined: whether the audio lands on the same-numbered audio track was never tried against a running Resolve.

### 05-040: A b-roll clip sent to Resolve gets its proxy attached, but never the browser preview when the real file is here.
- Where: broll / Sending a clip to Resolve
- What: Fact about Resolve: it attaches a proxy from the Proxy folder beside a clip on its own only for clips it imported itself, not for clips another program brings in. So, when the clip has no proxy, the product attaches one of the same name from the Proxy folder beside it. It does not attach the browser preview (a small preview made for the archive) when the real original is on this computer and is not a registered stand-in. If Resolve refuses (missing timecode in the preview is the usual cause), the clip is still inserted. The attach is recorded for undo.

### 05-041: Downloaded YouTube files go into a matching bin in Resolve without disturbing the editor's view.
- Where: youtube / Reaching the editor and Resolve
- What: Files go into the bin "Youtube/<search term>" (made as needed; a bin name already there matches even when the name was typed on a Mac with accented letters encoded differently). In bin names, slashes become "-", leading and trailing spaces and trailing dots are dropped, and an empty name becomes "Untitled". Nothing is imported if the editor has switched to another project ("project changed"). A file already anywhere in the media pool is skipped ("skipped existing"); the same file twice is imported once; nothing new gives "already in the media pool". The bin the editor has selected is never changed; if Resolve will not move the new clips into their bin, they stay where they landed and nothing is deleted. A file Resolve refuses ("Resolve refused N file(s)") is tried again, up to three times; "could not create the bin" when Resolve will not make it. Each imported clip is pointed at the path spelling every computer shares.

### 05-042: The media pool as a whole can be read, including clips never cut into a timeline, with each clip's bin and proxy state.
- Where: resolve-on-the-editors-computer / Bins, clip sorting and imports
- What: Used by "Scan whole project" and by the fixes: every clip in every bin of the open project (timelines, compound clips and generators excluded), with its bin, its proxy file and its proxy state. Bins nested more than 64 deep are not looked into. "Scan whole project" always takes a complete fresh look, never a remembered one. A clip that cannot be found again when it is time to change it is skipped, never acted on; a project closed and reopened is always read afresh.

### 05-043: A read-out of how long until the next automatic change exists but nobody can see it.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: The product can tell how many seconds remain before the next change it would make on its own is allowed (05-014), but nothing shows it.
- Flag: unreachable

# Extract of inventory section 36

## Items

### 36-001: The product keeps a record of every copy of every tracked file, on every drive, the NAS and the cloud backup.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The Footage Sorter keeps one record of where each copy of each piece of footage is: on each studio drive, laptop, client drive or camera card, on the NAS and in the cloud backup. Three kinds of file are tracked and everything else is ignored by every scan and every report:
  - camera originals (video and raw formats such as BRAW, R3D, ARRI, MXF, MOV, MP4, MTS, AVI, Canon, Sony and Nikon raw stills, DNG, 360-camera files);
  - sound recordings (WAV, broadcast WAV, AIFF, MP3, M4A, FLAC), wherever they sit, even inside a proxy folder;
  - proxies: a video file inside a folder called Proxy or Proxies (any letter case, any depth), or a Sony FX3's own proxy, which sits beside its clip with a name like the clip's number followed by S and two digits.
  A still or raw clip inside a proxy folder is not tracked, nor is an MKV or WebM outside one. Never tracked: files with no extension, hidden files, Mac resource-fork companions, files still being written or left by an interrupted copy, and anything inside the editing program's cache and optimised-media folders, a camera's thumbnail folder, a duplicates quarantine folder, recycle bins, operating-system housekeeping folders and the NAS's own index folders.

### 36-002: Two copies count as the same file when name, size and time agree.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Two copies are the same file when they have the same file name (letter case ignored) and the same size in bytes and, where both have a modified time, the times are within 3 seconds of each other (camera cards formatted exFAT only keep time to 2 seconds). A missing, zero or absurd time (beyond about the year 2096) counts as unknown and does not stop a match. A path spelled with a Mac's decomposed accents and the same path spelled the Windows way are one path. On drives, paths are compared without letter case; on the NAS and the cloud, with letter case.

### 36-003: Each place that holds copies has a kind, and only some kinds count toward a clip being safe.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Every drive or place is one of: the NAS, a studio drive ("ours"), a client's drive, a camera card, a laptop, the cloud, or unknown (what a newly seen drive starts as). A file is **backed up** when it has a live copy on the NAS ("at home"), or live copies on at least two different places that count. Places that count: studio drives, laptops and the NAS; the cloud counts for proxies and sound recordings but never for a camera original. Client drives, cards and unknown drives never count, and a copy known to be missing counts for nothing. A file is **laptop-only** when it has a live copy on a laptop and none on a studio drive or the NAS.

### 36-004: A scan that looks wrong never marks footage as missing.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: When a listing of a drive finds under 80 % of the copies the record held there, and the record held more than 100 there, it is treated as a bad scan (a half-mounted or damaged drive): nothing is marked missing. A scan that did not finish, or arrived incomplete, is partial and also marks nothing missing. Only a good scan marks copies missing and updates the drive's "last scanned" time, file count and free space. Folders the scan could not read, or was told to leave out, are never judged; if a drive's top folder cannot be read, nothing on that drive is judged.

### 36-005: An admin can describe each drive and choose what of it is tracked.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: Each drive is known by its volume serial, so it is recognised whatever letter it is plugged in as; a drive with no usable serial is ignored. The NAS appears as "Home NAS" and the cloud backup under its own label, both created by themselves the first time they are read and tracked whole. An admin can set on any drive:
  - a label, an owner and notes (text up to 200 characters; empty clears it);
  - its kind (one of the seven kinds);
  - which folders of it are tracked (default the whole drive). The whole drive swallows any other folder; a folder inside another chosen folder is dropped; a folder that climbs out of the drive or names a drive letter is refused with "a root must be a folder inside the volume".
  - whether it is tracked, meaning walked every time it is plugged in. Switching tracking on while the drive is plugged in starts its first scan at once.
  - whether automatic backup copies it to the NAS (36-025).
  A label or kind a person set is never overwritten by what a computer later reports: a label is only filled in when empty, a kind only while it is still unknown. A computer's system drive (the one Windows runs from) can never be tracked or backed up whole: "the system drive cannot be tracked as a whole: watch a folder on it instead", and "the system drive cannot be backed up as a whole: back up a watched folder on it instead".

### 36-006: The product knows which drives are plugged into which computer.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: The app on each editor's computer reports the drives plugged into it about every 5 minutes: serial, label, drive letter, file system, size, free space, and whether it is the system drive. A drive counts as plugged in while some computer has reported it within the last 15 minutes; when two computers report the same drive, the fresher report wins. A drive seen for the first time is recorded as unknown and untracked, with its label, size, free space, and when and where it was last seen; a system drive is never offered as a new drive. A computer can report at most 64 drives at once.

### 36-007: A tracked drive is scanned by itself when it is plugged in and something may have changed.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: When a tracked drive (not a system drive) is plugged in, it is scanned once during that plug-in if it has never been scanned, its free space differs from its last scan, or its last scan is older than the rescan period (default 24 hours, a setting). Each watched folder on a plugged-in drive is scanned when it has never been scanned or its last scan is older than its own interval. A drive is only ever scanned once at a time. If a scan could not be started, the next report from that computer tries again. The scan runs on the computer the drive is plugged into.

### 36-008: An admin can watch single folders, including folders on a computer's system drive.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: A watched folder is one folder on one drive, scanned on its own schedule. It works on drives that are not tracked whole, and it is the only way a system drive is ever scanned. An admin adds one by naming the drive, the folder (default the whole drive), a label (up to 120 characters), how often to scan it (default every 60 minutes, at least 5 minutes, at most 7 days) and the computer (default the one the drive is plugged into now). One folder at a time. A drive must have been reported by some computer first, else the person is told so, except a system drive that is plugged in right now. A whole system drive is refused: "the system drive can only be watched folder by folder, never as a whole". The same folder twice is refused: "already watching <folder> on <drive>". Adding a watch scans the folder at once when its drive is plugged in. An admin can switch automatic backup on or off for a watch, scan it now, or remove it; removing it keeps the copies it found. A watch is shown as visible when its drive is plugged in on the watch's own computer. Each watch shows when it was last scanned and how many files it found, and a scan of the whole drive or of a folder containing the watch updates it too.

### 36-009: The drives view shows every drive, what it holds, and where it is plugged in.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Every drive and place is listed in label order (letter case ignored), each with its label, kind, owner, notes, whether tracked, whether a system drive, tracked folders, size, free space, when and on which computer it was last seen, when it was last scanned and how many files that found, when it was first recorded, its automatic backup switch, the number and total size of live originals, proxies and sound recordings on it, the number of missing copies, the number of open questions about it, where it is plugged in now (computer, drive letter, since when) and any scan going on now. New drives are listed separately as untracked: drives seen but never scanned, unknown in kind, holding nothing, not system drives, each with its label, size, free space, computer, drive letter, file system and whether plugged in now. Watched folders are listed with whether each is visible now.

### 36-010: An admin can scan a drive, the NAS or the cloud backup now.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Scan now on the NAS walks the whole NAS footage tree. On the cloud backup it re-reads the backup's listing even if no new backup has been made. On a drive: the drive must be plugged in ("that drive is not plugged into any machine that reports to the dashboard right now"); a system drive is only scanned through its watched folders ("the system drive is only scanned through its watched folders"); a tracked drive scans its tracked folders plus every watched folder; an untracked drive scans only its watched folders, or the whole drive when it has none. A scan already going is not started twice; the person is pointed at the one running. When the dashboard cannot start work on the computers right now, the person is told so.

### 36-011: A scan survives interruptions and bad entries, and a scan that dies is closed and said so.
- Where: footage-sorter-and-camera-cards / Drives, speed and interruptions
- What: If a scan is interrupted and picked up again, it starts over cleanly; nothing half-sent is kept. A file whose name cannot be used (too long, unreadable characters, a path climbing out of the drive) or with no size is skipped and counted, never failing the whole drive; files of untracked types are ignored. A scan that ended without finishing, or, when that cannot be told, a scan nobody picked up for 3 hours or one silent for 30 minutes, is marked failed (the scan ended without finishing) and what it had sent is thrown away. This is noticed within about a minute.

### 36-012: A finished scan updates the record all at once, and footage that disappeared raises a question.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: A page never sees half a scan. New files are recorded as listed (the lowest level of checking). A file at the same path with a different size, or a time more than 3 seconds apart, replaces the old copy. A missing copy seen again unchanged becomes live again. Copies no longer found (good scans only, only under the scanned folders): if a copy with the same name, size and time is live elsewhere on the same drive, the file was moved within the drive and this is followed silently; otherwise the copy is marked missing since now and ONE question is opened per folder, "where did these go?", with the number of files and bytes. If one other drive (not the cloud, not a card) holds a twin of every missing file of that folder, it is offered as the likely answer. A second disappearance from a folder with an open question adds to that question. Cards and the cloud never raise questions (a card is formatted on purpose; cloud copies age out with the backup's retention). Questions settle themselves: when the missing files turn up again the question closes as "found again"; when they turn up elsewhere on the same drive it closes as "moved within the drive". Each scan reports how many files it saw, added, replaced, found missing and found back, and the questions it opened.

### 36-013: An admin answers "where did these go?" questions.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Open questions are listed largest first by size (or every question, answered too, on request), at most 500, each with its drive, folder, number of files, size, the suggested drive, when opened, and the answer, who gave it and when. An admin can answer:
  - **moved to another drive**: each missing file is linked to its twin there; if that drive has not been scanned yet, the question stays open with that answer and settles itself once it is; the reply says how many files were linked and how many wait. The drive must be a known one.
  - **moved or renamed within the same drive**: each missing file is linked to its twin on the drive; the question closes when none are left.
  - **deleted**: every missing file of the folder is marked deleted and the question closes.
  - **plug it in and rescan**: noted; the question stays open.
  An already answered question is refused with "already answered: <answer>".

### 36-014: Copies made by the product's own copy tools are recorded with how carefully they were checked.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: When the app on an editor's computer copies footage (a field backup, a card copy), each copy is recorded with how carefully it was checked (listed, quick, or full), when, and which person and computer made it. A drive can only name itself by its serial and label, so a USB stick can never claim to be the NAS. A copy already recorded is kept and upgraded if the new check was more thorough. A different file already live at the same path is counted as a conflict and left alone: a copy reported from an editor's computer never displaces one the record holds. Copies the server itself has checked on disk (its own card and drive copies) may replace a changed file at a known path. Either kind of record settles pending "moved to" answers and closes questions whose files are back.

### 36-015: Moving footage on the NAS through the Sorter keeps the record right.
- Where: footage-sorter-and-camera-cards / Moving footage on the NAS
- What: Every file the Sorter moves is followed in the record (old place marked as moved to the new one, no question raised); a moved folder takes every copy beneath it. After a move that finished cleanly, the NAS is scanned again by itself to catch anything else. A failure in this follow-up never fails the move.

### 36-016: Each clip shows where its copies are, and the clip grid shows a safety badge per clip.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: For one clip a person sees every live or missing copy of each of its files, grouped as original, proxy and sound, each with its drive and that drive's kind, path, how carefully checked, when recorded, whether missing and since when, whether its drive is plugged in now and on which computer, and, for a missing copy, the open question about it. A clip's summary gives how many copies of each kind exist, which drives hold it, whether it is backed up, laptop-only, at home or not, and whether every proxy is in the cloud. A recording split over several files is judged file by file: backed up and at home only if every file is, laptop-only if any file is, the copy count being the fewest places any file is in, and card-only when every copy of every file is on a card or client drive. A clip with no original is judged by its sound. On the clip grid each clip carries its copy count and flags: at home, laptop-only, not backed up, not at home, card-only, every proxy in the cloud, has a proxy not all in the cloud. A person can also list the clips that have a copy on a given drive.

### 36-017: Copying files from one drive to another is planned from the record, and refused when it would go wrong.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: A person picks files or folders on one drive, a destination drive and a destination folder; each file lands at the destination folder, then the name of what was picked, then the rest of its path. A file already at that exact place with the same size is skipped and counted. Optionally, everything that already has a copy on the NAS is left out. Refusals: an unknown drive; a destination folder outside the destination drive (it must be a folder inside the destination drive); two picks landing in the same place ("<a> and <b> would both land at <dst>: copy them one at a time, or into different folders"); more than 20,000 files ("more than 20000 files: copy a smaller folder").

### 36-018: A report says what footage is not yet on the NAS, and where it is instead.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Every original and sound recording with live copies but none on the NAS is grouped by category, by the folder it sits in, and by where it is (drive labels joined by " + "). Categories in this order, biggest first within each: only on a laptop; on at least one studio drive; only on drives that are not ours (client drives, cards, unknown drives). The report gives the total size and file count, the groups, the open questions, and a plain-text digest a person can read or paste:
  - "Not at home: <size> in <n> folder(s)."
  - "Only on a laptop - <size>:", "On drives we own, not at home - <size>:", "Only on drives that are not ours (client drives, cards) - <size>:", each followed by lines "<folder> (<size>, <n> files) on <where>".
  - "Where did these go? <n> folder(s) no longer where they were:" followed by "<folder> on <drive> (<n> files, <size>) - probably <suggested drive>".
  Sizes are shown in TB with one decimal from 1 TB, in GB with no decimals from 10 GB, otherwise GB with one decimal.

### 36-019: An activity panel shows every scan going on and waiting.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The panel lists:
  - the NAS walk: "Scanning <label>", files and size so far, files per second, the current folder;
  - the cloud listing being read: "Reading the <label> listing", files so far;
  - a drive scan on an editor's computer: "Scanning <label> on <computer>", shown as walking once files arrive or it reported in the last 2 minutes, else as queued; files, size, speed and current file when fresh;

### 36-020: The record of every copy backs itself up every day.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Every day at 04:00 on the NAS's clock (a setting), and whenever an admin presses back up now, a consistent copy of the record is taken and checked for damage; a damaged copy is deleted and the error shown. The Sorter's own settings and data (not its pictures or caches) are copied alongside. They go into the folder the NAS carries to the cloud when one is set up, else beside the record. The newest 7 days are kept; older ones are deleted. A file that could not be copied because it was being rewritten is skipped. The last result (time, size, whether it worked, error, number of files) is shown with the activity and the cloud backup status.

### 36-021: The whole NAS footage tree is walked every night and after each clean move.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The NAS walk runs every night at 04:30 on the NAS's clock (a setting), after every move that finished cleanly, and when an admin presses scan now on the NAS. Only one runs at a time. It skips the folders listed above and any folders an admin lists to leave out (paths inside the NAS tree, letter case ignored); left-out and unreadable folders are not judged, the rest of the tree still is. It records the NAS's total and free space. Progress updates about once a second. Refusals say that no NAS footage tree is set up so the NAS cannot be scanned from here, that the NAS tree is not reachable, or that it cannot be read (with the error). The nightly run does nothing quietly when it cannot run; nobody is told.

### 36-022: The cloud backup's contents and status are shown, and its schedule can be set.
- Where: server-install-and-running / Off-site backup
- What: The NAS uploads the footage tree to a cloud backup on its own; the Sorter does not make the upload, it reads what the upload reports and asks it for runs. Within about two minutes of a new cloud backup finishing, its contents are read into the record of every copy (only files under the NAS footage tree, of tracked kinds). A person sees: whether the cloud backup is set up; the last run's state (running, OK or failed, with its time and text), why it ran, when it started and finished and how it ended; while running, percent done, bytes and files done and in total, speed over the last two minutes, time left, current file, errors, time so far (fresh when updated in the last 30 seconds); the last backup's summary (new, changed and unchanged files, data added, totals, how long it took, when); which backup the record last read; the schedule and next run; whether a run has been asked for and when; and how long backups are kept (default 24 hourly, 30 daily, 12 weekly, 24 monthly, a setting).
  An admin can switch the nightly upload on or off and set its time (default on, 04:15). Refusals: "nightlyAt must be HH:MM (24 hours)"; with no backup folder set up, that the Sorter cannot tell the NAS when to upload; with it unreachable, "the backup folder is not mounted here". An admin can ask for a run now, which starts within 10 minutes; refused with "a cloud backup is running already" or "a run was already requested; the NAS starts it within 10 minutes". The next run shown is: none when off; today at the set time if not yet passed; "now" if passed and today's run has not happened; otherwise tomorrow. Re-reading the listing by hand needs the cloud backup's status to be readable, else the person is told it is not set up.

### 36-023: Times of day for the Sorter's nightly work follow the NAS's time zone.
- Where: footage-sorter-and-camera-cards / Clocks and file dates
- What: The times for the nightly NAS walk, the daily backup of the record and the next cloud run are on the NAS's clock, in the time zone an admin sets for the Sorter, else the server's own time zone. An unknown zone name falls back to the server's local time.

### 36-024: An earlier record of copies can be brought in once, safely.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The studio's earlier record of copies (and its open questions) can be imported into the record from a command line, page by page. By default it is a dry run that shows what would change and touches nothing; only when told to write does it import, then back the record up. Paths on the NAS can be moved under the studio's top folder, or every path of one drive put under a folder. Running it again changes nothing that has not changed in the old record, and never undoes what the Sorter has decided since (a copy a scan found gone, an answer "deleted", a replaced file). A copy the Sorter recorded itself is never displaced by an imported one. A summary of pages, rows, drives, questions, inserted, updated, unchanged and skipped is printed. The running Sorter notices the import within seconds.

### 36-025: Drives and folders with automatic backup switched on are copied to the NAS by themselves.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: About every 10 minutes (first about 90 seconds after the Sorter starts), for each drive with automatic backup on (never a system drive) and each watched folder with it on, while it is plugged into a computer that reports, the product copies the files under it that have no copy anywhere on the NAS, at most 2,000 files at a time (the rest on the next turn). They land on the NAS at "Auto backup" / the computer's name / the drive's label (else the watch's label, else the serial) / the same path as on the drive, so a whole drive lands as the whole drive would. Each name part has characters Windows cannot use turned into "-", leading and trailing spaces, dots and dashes trimmed, is cut to 80 characters, and becomes "drive" if empty. The copy only runs while the computer is on the studio's network; away, the source shows "waiting: this computer is away from home". After a failure or an away attempt, that drive is not tried again for 60 minutes. A watched folder whose drive is plugged into a different computer than the watch names counts as not plugged in. Nothing is ever deleted or overwritten. Settings: on or off for the whole product (default on), how often, how many files at a time, the folder name, and the studio's network.
  Each source shows one state: copying (files, size, whether more remains, destination, computer, also while waiting to start or verifying), done (files, size, when), away, error (no staging folder on the NAS to copy into, the copy's own refusal, or "the copy ended <state>"), nothing to copy, or not plugged in. These states are forgotten when the server restarts.

### 36-026: The crew's card tracker shows which camera cards were used on which day, and whether each is backed up.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Shooters record on their phones, on the studio's card-tracking site, which camera cards they used on which day. The Sorter fetches that record about every 15 minutes (a setting, at least 1 minute), keeps a copy so it still works offline, lays it against the calendar and the footage, and tells the site when a card's footage is backed up. Without the site's access key the list of cards still updates but the days of use do not. Usage is read from a start date (default 1 April 2026, a setting). If the site cannot be reached, the last copy stands and the error is shown. Errors a person sees: the site address is not set; no access key; the site's own error; "unauthorised"; "not configured".
  The card report shows: whether set up, when last synced, the last error, counts, how often it syncs, and which drive serials are named as which card; every card in fleet order (CF before SD, then by number) with backed up, active, last updated and by whom, last used, and the serials named for it; one row per day of use, newest first, with the cards used (who recorded it and when, backed up or not, and the footage that came off that card that day: clips, the folders it landed in, how many copies in staging and in the final tree); that day's calendar events (dismissed ones left out) with where the Sorter would file each and why, ranked shoots with a destination first, then timed events, then all-day events, then recurring all-day events, and one likely event (strong when exactly one event has a destination, weak when none has and exactly one timed event exists); footage that came off a named card on a day nobody recorded; and serials seen in the footage that nobody has named, with label, kind, clips, last seen, the last 4 days, and a hint (CF for BRAW cameras, SD for Sony), most recent first. Footage before the start date is not compared. A multi-day event counts on each day it touches (at most 60).
  Anyone who can reach the Sorter can ask for a fresh sync.

### 36-027: A card is marked backed up on the tracker by itself once all its footage has a backup copy.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: When a card copy on the Sorter finishes, the card is marked backed up on the tracker only if the tracker is set up, the card's serial has been named as a tracker card, and every clip on the card has a backup copy. Otherwise it stays marked used, and nobody is told why except in the server's log (serial not named; some clips still without a copy). An admin can also mark cards backed up or used by hand.

### 36-028: An admin names which tracker card a card in a reader is, helped by suggestions.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: A camera gives a card a new random serial every time it is formatted, and USB card readers report their own serial, so a card's serial must be named as a tracker card (like "SD-1": 1 to 4 letters, a dash, 1 to 3 digits; empty un-names it; a serial is 2 to 40 letters, digits, dashes or underscores). Naming one also records the card's size, and re-checks every copy from that serial for the automatic backed-up mark. For a card in a reader, the Sorter lists candidate tracker cards: only the card type the camera uses (BRAW cameras CF, Sony SD, drones and sound recorders either), never a card already named for another card in a reader, never one whose size differs by more than 2 %. A card scores 2 for "used <days>" when the crew recorded using it on a day this footage was shot, 1 for "marked used", and "same size" is noted. One suggestion is made only when the top card scores at least 2 and nothing ties it. A card already named still shows the list, so a person can say it is not that card. No list while the card is still being read.

### 36-029: The studio's calendar can be connected so footage can be placed by shoot.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: An admin connects the studio's online calendar, read-only, through the calendar provider's sign-in page. Without the provider's app credentials set up, the person is told what is missing and how to set it up. The sign-in link lasts 10 minutes; a stale or foreign one says "The sign-in link had expired or was not started from this app. Try again from the sorter." The provider's own error is shown as "Not connected" with what the provider said. On success: connected to the calendar, "Signed in as <account>." (or "Signed in."), "You can close this tab. An admin can disconnect, which forgets the access at once. An admin may change only: which calendars are read, how often, and the start date (default 1 April 2026); events are read up to one year after it. Cancelled and undated events are left out; all-day events run midnight to midnight; each occurrence of a repeating event is its own event and marked repeating. Event times are shown in a fixed time zone of UTC+8 with no daylight saving.

### 36-030: The Sorter proposes whose interview is on a sound recording, and never files it by itself.
- Where: footage-sorter-and-camera-cards / Placing sound recordings
- What: Field-recorder files often carry a wrong date (the recorder's clock was reset), so the calendar cannot place them. For sound clips that have been transcribed or had names heard in them, the Sorter weighs every clue and proposes a destination folder; it never assigns one itself. Clues, one candidate per folder (a second clue for the same folder adds 0.08, up to 1):
  - an identical file (same recorder name, size, and length within 2 s) already headed for or sitting in a folder: 0.92 if that is an interviewee's folder ("An identical file is already filed here: <path>"), else 0.3 ("An identical file was also copied to <path>");
  - the recording's words matching one of the studio's interview transcripts: counted at 6 % and 25 shared four-word runs or more (each Chinese character is a word); 0.85 to 0.95 from 25 % and 120 shared, 0.55 from 12 % and 60, else 0.3; the top 4 transcripts are shown. The folder is the interviewee's folder whose name matches the person (a Chinese name must appear whole; an English name needs two of its parts, or one part of 4 or more letters that is not a common Taiwanese surname); notes say "folder from the roster", "but two folders carry that name", or "no folder on P: carries that name";

### 36-050: A recording is placed, and its true start found, by matching its sound to the cameras' sound.
- Where: footage-sorter-and-camera-cards / Placing sound recordings

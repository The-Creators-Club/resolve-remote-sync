# Extract of inventory section 10

## Items

### 10-001: An editor in the field opens a field backup page on their own computer that works with no network at all.
- Where: footage-sorter-and-camera-cards / Field backup on the editor's computer
- What: The app on the editor's computer offers "Field backup..." in its menu, which opens the field backup page in the computer's default browser. The page, its look and its script are all carried inside the app, so it loads nothing from anywhere else and works with no internet and no studio network. It is on by default on every computer; the owner of the computer can switch it off for that computer. If the page is not running (switched off, or it could not start on this computer), choosing the menu item shows a notification saying the field backup page is not running on this computer and that it is either switched off or could not start; nothing else in the app is affected. When the app quits, the page stops and every copy it started is stopped first.
- Flag: undetermined: whether the menu item is hidden or shown-but-explaining when the page is switched off (the inventory says the item is shown only when the page was set up at start, and also that pressing it explains a switched-off page)

### 10-002: Only a person at the computer itself can use the field backup page.
- Where: footage-sorter-and-camera-cards / Field backup on the editor's computer
- What: The page can be reached only from the computer it runs on. A web page from anywhere else (any other site open in the same browser) is refused, except the studio's own dashboard. Anything that would change something (start a copy, add a folder, set a drive's kind) must come from the page itself, the dashboard, or the app's own tools on that computer. A request too large to be real is refused with the sentence "that request is too large" rather than a broken connection, and an unexpected failure answers "the companion failed to handle that" instead of hanging. Every refusal the page receives is a plain sentence.

### 10-003: The field backup page keeps itself up to date, and says so when the app stops answering.
- Where: footage-sorter-and-camera-cards / Field backup on the editor's computer
- What: The page refreshes every second while any copy is running and every 4 seconds otherwise. While its browser tab is hidden it does not refresh; when the tab is shown again it refreshes at once. The first load always takes a fresh look at the drives. Without JavaScript the page shows "This page needs JavaScript. It does not need the internet." If the app stops answering, the status indicators at the top are replaced by one red indicator, "Companion not answering". A refusal from adding a folder, setting a drive's kind or starting a copy is shown in a box at the bottom of the screen for 9 seconds. The page is two columns on a screen 900 px wide or more and one column below.

### 10-004: The top of the field backup page shows whether copies are waiting to reach the studio's record, whether the record is reachable, how copies are verified, and the computer's name.
- Where: footage-sorter-and-camera-cards / Field backup on the editor's computer
- What: Indicators along the top:
  - "<n> waiting to send" (yellow) when copy records made here have not yet reached the studio's record of copies;
  - "Ledger online" (green) when the last attempt reached the dashboard; "Offline" when it did not; "Ledger not asked yet" when a dashboard is set up but no attempt has been made; "No dashboard" when this computer has no dashboard set up;
  - which way of copying is in use, and on hovering, how it verifies: either a check by the copier after every file, or "every file read back in full and compared";
  - the computer's name.

### 10-005: The page lists every camera card in a reader and lets the editor pick one.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: A "Cards" heading with a "Look again" button that takes a fresh look at every drive at once. With no card: "No card in a reader. Put one in; this page looks every few seconds." Otherwise one entry per card, sorted by drive letter and then by the card's serial; the first card is selected on its own, and clicking a card selects it (the selected card is marked). Each card shows its label (or its serial when it has none), its type ("Sony", "Blackmagic", "Drone", "Audio", or "Card" for anything else holding media), "Copying" while it is being copied, and the line "<n> files · <size> · <drive> · lands in "<folder>"". Drives are looked at again at most every 4 seconds; a card being copied from is not re-read, and if it drops out of the list mid-copy it stays shown as last seen. A card that is taken out (and is not being copied) is forgotten. A card's file list is kept for 30 seconds unless the card's capacity, free space or place changes.

### 10-006: For the selected card the page gives a verdict: safe to format, safe but laptop only, not safe, or nothing to back up.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: A coloured block: green "Safe to format"; yellow "Safe to format · laptop only"; red "Not safe to format"; grey "Nothing to back up". Under it a headline sentence and notes:
  - A folder on the card could not be read: "Not safe to format: <n> folder(s) on this card could not be read (<up to 3 names> and <n> more), so nobody knows what is in them/it." with the notes "Of the <t> files that could be read, <n> are also short of copies." (when any are) and "Take the card out, put it back and look again. If the folder still will not read, try another reader before anything is formatted." This answer beats every other, including "nothing to back up".
  - No files that need backing up: "Nothing on this card needs backing up (no footage, audio or photos on it)."
  - All safe and all at the studio's NAS: "Safe to format: all <t> files are at home."
  - All safe, some resting on the laptop alone: "Safe to format, but <n> of <t> files rest on the laptop alone. Put one on a field drive when you can."
  - All safe otherwise: "Safe to format: all <t> files are on two drives that count."
  - Otherwise: "Not safe to format yet: <n> of <t> files are short (<n> with no copy, <n> with one copy)." with, when it applies, "Some copies are on drives that do not count (a client's drive, a card, or a drive with no kind set)."
  - When this computer has never heard from the studio's record: "This laptop has not heard from the ledger yet, so only copies made here count."
  Below the verdict, a collapsible "Files that are short of copies (<n>)" lists up to 40 files as "<path> (<n> counting, <n> in all)". The verdict is worked out again within 20 seconds, and at once when a copy is recorded, a drive's kind is set, a destination is added or removed, or the record is refreshed.

### 10-007: The verdict waits only for the originals a camera or recorder writes.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Files the verdict waits for: every original video, audio and still a camera or recorder writes, including raw camera formats (Blackmagic RAW, RED, ARRIRAW, Canon raw, Nikon N-RAW, Phantom, Magic Lantern raw), 360 camera files, HEIF photos, broadcast WAV and large WAV, DV, and every media kind the card recognition knows. Never waited for: camera proxies and thumbnails (anything in a "Proxy", "Proxies", "SUB" or "THMBNL" folder, and Sony's small proxy clips whose names end "S03"), files that accompany a clip (XML metadata, thumbnails, low-resolution previews, subtitles, playlists, logs, text and settings files and the like), hidden macOS "._" files, and files left half-written or set aside by an earlier copy. A file of a kind nobody listed is waited for when it is 1 MiB or larger, so an unknown format never makes a card look safe.

### 10-008: A file counts as safe when it is at the studio's NAS, or on two different physical drives of kinds that count.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Every drive has a kind: the studio's NAS ("Home NAS"), a studio field drive ("Ours"), the laptop's own disk ("Laptop"), a client's drive ("Client drive"), a card, or not set. Only copies on the NAS, studio field drives and the laptop count. A file is safe with a copy on the NAS, or with copies on two different physical drives that count. Two partitions of one physical drive count once, and a folder that is really a link onto a drive counts as that drive. Copies on the card itself, on a client's drive, on another card or on a drive whose kind is not set never count. A safe file whose only counting copies include the laptop and none on a studio field drive or the NAS makes the verdict "laptop only". Telling partitions of one drive apart works on Windows; on macOS each volume is treated as its own drive.
- Flag: differs: on Windows two partitions of one physical drive count once; on macOS they count as two drives

### 10-009: The verdict only believes copies that really are copies of this card's files and are still there.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: A copy known to the studio's record is matched to a card file by name, size and time (within 3 seconds), and then accepted only if it really belongs to this card: a copy made by field backup carries the card's identity and is accepted when its place matches the file's place on the card (a copy marked as coming from a different card is never accepted); otherwise its path must end with the file's path on the card, or, for a file at the card's top level, it must sit in this card's own landing folder; a copy on the NAS is accepted wherever it is (footage there is moved into project folders). When the drive holding a copy is plugged in, the copy is checked on that drive (size and time); a missing or changed copy is not counted. A copy on a drive that is not plugged in is believed. Copies made on this computer count the moment they are verified, before the studio's record has heard of them.

### 10-010: The page lists every place a card can be copied to, and what each already holds.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: A "Copy to" list with one row per destination: a tick box (unavailable when the destination is not there or is busy with another copy), its name, its type ("Drive", "Folder", "NAS"), and its kind ("Ours", "Laptop", "Home NAS", "Client drive", "Card", "Kind not set"; marked as counting or as not set). Each row shows where the copy will land and how much space is free, and "Already holds <have> of <of> files on this card" for the selected card. A destination that is not there is dimmed with a reason in yellow. With no destinations: "No drive to copy to. Plug one in, or add a folder below." Destinations offered:
  - every plugged-in drive that is not the system disk and not a recognised camera card (a drive that merely holds media is still offered); copies go into a "FieldBackup" folder on it; named by the studio record's name for the drive, else its label, else its drive letter;
  - every folder set up as a destination on this computer, and every folder added on the page; copies go straight into the folder; a folder whose drive is not plugged in is shown absent ("That folder's drive is not connected."); a folder that does not exist yet on a plugged-in drive is shown present and is made by the copy;
  - the studio's NAS, labelled "NAS pool", when this computer has it set up (10-013).
  The row details update in place so an open choice list is not closed by a refresh.

### 10-011: An editor sets what each drive is, and the product guesses until they do.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: Each drive (and each folder that sits on a drive) has a kind choice: "Set kind...", "Ours (counts)", "Laptop (counts, flagged)", "Client drive (never counts)", "Not set". Choosing one saves it for the whole drive and refreshes; "Set kind..." does nothing; "Not set" removes the person's choice. The kind a drive gets: first the person's choice on this page, then the kind the studio's record holds for that drive, then a guess. The guess: a drive labelled in the studio's field-drive naming (the letters CIB, then D and a number) is "Ours"; a drive labelled WD and a number, or with "passport" in its label, is a client's; a removable drive is a card; the system disk, or a fixed drive holding a laptop folder, is the laptop; anything else is not set. A folder on a fixed drive whose kind is not set (or is "card") counts as the laptop. The page shows whether each kind came from "you", the record ("ledger") or a "guess". Only drives can have their kind set: "only a drive's kind can be set", "a drive is ours, a laptop's, a client's or unknown".
- Flag: several ways in: a drive's kind can come from this page or from the studio's record (set elsewhere)

### 10-012: An editor adds and removes folders on this computer as copy destinations.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: An "Add folder" box (placeholder "Add a folder, like D:\FieldBackup"; Enter also adds; empty does nothing). Surrounding quotes are removed. Refusals: "give the full path of a folder, like D:\FieldBackup" (empty, not a full path, or stepping up a level); "that folder is not on a drive this computer has right now"; "that folder is on a card or a USB stick, not on this laptop's own drive, so a copy there would not count. A plugged-in drive is listed under Copy to already." A folder already listed (ignoring letter case) is not added twice. Each folder has a "Remove" button. Separately, the owner of the computer can set folders that are always offered; these also show "Remove", but pressing it leaves them listed.
- Flag: several ways in: folders come from the page and from the computer's own settings

### 10-013: The studio's NAS can be a copy destination, and the product makes sure a drive letter really is the NAS.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: When this computer has the studio's NAS set up, it is offered as "NAS pool", and card copies land in a folder on it (by default "FieldBackup"; the computer's settings can name another). Whether it can be reached is checked with a 2.5-second limit so a dead network share does not freeze the page: "The NAS pool cannot be reached from here." The NAS is accepted when its top folder carries a marker that says it is the studio's NAS. On macOS it is otherwise accepted. On Windows, without the marker: a local disk is refused, "That drive is a local disk, not the NAS pool (a drive letter can change hands). Put an empty marker file in the pool's top folder to say it is the pool." (the message names the marker file); a mapped network drive pointing somewhere other than the network path set for this computer is refused, "That drive is <network path>, not the NAS pool (<expected>)." With no network path set, any mapped network drive is accepted.
- Flag: differs: Windows checks that the drive is really the NAS; macOS accepts it

### 10-014: The destinations an editor ticks are remembered.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: Every tick and untick is saved on the computer at once. On the next visit the destinations last ticked are ticked again if they are there; a tick on a destination that has gone or become unusable is dropped without a word. Starting a copy also records the ticked set as the last ticked.

### 10-015: "Copy to all" copies the selected card to every ticked destination, copying only what is not already there and never overwriting.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The button reads "Copy to all" ("Copy to all (<n>)" with more than one ticked). It is unavailable, with the reason beside it, while starting ("Starting..."), with no card ("Put a card in a reader."), while the selected card is already copying ("This card is being copied."), or with nothing usable ticked ("Tick where to copy it."). When available the note reads "Only what is not already there is copied; nothing is overwritten. Lands in "<folder>"." Refusals when starting: "that card is not in a reader any more. Put it back and look again."; "tick at least one destination"; "one of the ticked destinations is not available any more. Look again."; "a card cannot be a destination for itself"; "<destination>: <why it is not there>"; "<destination>: the folder cannot be made (<reason>)"; "this card is already being copied: wait for it to finish, or stop it"; "<destinations> is busy with another copy" (a ticked destination, or another on the same physical drive, is in use by another copy).

### 10-016: Each card lands in a folder named by its day and label, and two cards with the same label never mix.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The landing folder is "<day> <card label>", where the day is the local date (year-month-day) of the newest file on the card, or today when no file has a time. When the label is blank or one cameras use for every card ("NO NAME", "Untitled", Canon's default card label, "NIKON", "LUMIX", "CANON", "SD", "SD Card", "USB Drive", "Removable Disk", "Disk", "New Volume", "Card", "DCIM" and the like), the card's serial is used instead. Characters not allowed in file names become underscores. The card's own folder tree is kept beneath it. On a drive it lands under "FieldBackup", on the NAS under the NAS's field folder, in a chosen folder directly inside it. The landing folder remembers which card it belongs to; when a folder of that name already belongs to a different card, the second card lands in "<day> <label> <serial>". A folder that does not say whose it is is taken to be this card's.

### 10-017: A card copies to several drives at once, but never twice to the same physical drive at once.
- Where: footage-sorter-and-camera-cards / Drives, speed and interruptions
- What: One copy per card at a time. Destinations on different physical drives copy at the same time; destinations on the same physical drive copy one after another, the waiting one showing "waiting for the other copy on this physical drive". A destination in use by one copy, or on the same physical drive as one, cannot be used by another.

### 10-018: Before copying, each destination is checked for what is already there and for room.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: State "Looking" ("looking at what is already there"). Refused at once: "<destination> is not there. Plug it in and try again."; "<destination> cannot be read. Is it still plugged in?" For each file on the card: if nothing is at its place but the same file (name, size, time) is already elsewhere on that drive, confirmed on the drive, it counts as "already there elsewhere" and is not copied again; the same size and time (within 2.5 seconds) at its place is "already there"; a smaller file at its place is an interrupted copy, which is finished rather than replaced; anything else at its place (bigger, or a folder) is a conflict and is never overwritten. If what needs copying plus 256 MiB spare is more than the free space, that destination is refused before anything moves: "Not enough room on <destination>: <free> free, and this card needs <need> more (plus 268 MB kept spare). Nothing was copied there." The other destinations carry on.

### 10-019: Files already at a destination are checked against the card, so running a card again also checks its backups.
- Where: footage-sorter-and-camera-cards / Checking a copy
- What: State "Checking what is there". Each file already present is compared with the card. When it is known that exactly this copy was verified when it was made, a quick check is used (size, the first and last MiB, and for camera video files the clip's index, compared in full up to 64 MiB and beyond that by its first and last MiB). Otherwise the whole file is compared byte for byte, shown as "comparing <file> in full (nothing says it was verified)". A match counts as "already there" and is recorded as a verified copy. A mismatch is left alone: "it is already at the destination but does not match the card: <reason>. It was left alone." A clip on the card with no index passes with the warning that the source has no index, so the clip itself is damaged, not the copy.

### 10-020: Every copied file is verified, and a copy that fails verification is set aside, never left looking like a good copy.
- Where: footage-sorter-and-camera-cards / Checking a copy
- What: State "Copying", then "Verifying". Folders are made first. Every copied file is verified against the card, either by the copier's own check or by reading it back in full and comparing. A file that fails verification is counted "copied but not verified", renamed with "failed" added to its name (numbered when one already exists, up to 49), and reported: "copied but not verified, and a full compare says: <why>. It was set aside as <name>." A file the copier finds identical counts "already identical". A conflict is reported "<why> It was not overwritten." A failed file is reported with its reason, and a part-written file from this copy is set aside the same way "so a later run cannot take it for a good copy". Only a file this copy wrote or finished is ever renamed; anything that was there before is left alone. Up to 40 problems are listed per destination. On Windows a separate copying program with its own verification is used when it is installed; otherwise the product's own copier reads every file back.
- Flag: differs: on Windows, when a particular outside copier is installed, its own check is used and it may leave a short part-written file under the real name (finished by the next run); the product's own copier never does

### 10-021: A copy stops cleanly, and says why, when a drive or card is pulled, a drive fills, or the editor presses Stop.
- Where: footage-sorter-and-camera-cards / Drives, speed and interruptions
- What: Checked about every 2 seconds. Reasons: "stopped by you" (state Stopped); "<destination> was taken out (or went away) during the copy"; "<destination> is now a different drive (its letter changed hands)"; "the card was taken out of its reader"; "<destination> is full" (under 48 MiB free). Each but the first gives state Failed and the message "Stopped: <reason>. <n> files are on <destination> whole and verified (they are kept and recorded); the rest were not copied. A half-written file is never left under its real name" (when an outside copier is in use on Windows the sentence instead says it may leave a short one, which the next run finishes). A copier error that means a full disk gives Failed, "<destination> ran out of room. <n> files are on it whole and verified; the rest were not copied. Free some space or pick another drive." A copy that cannot run at all: every destination Failed, "The copy could not run (see the companion log)."; one that crashes: "The copy could not run: <error>".
- Flag: differs: what is said about a half-written file depends on which copier was used (see 10-020)

### 10-022: The page shows each copy's progress, destination by destination, and lets the editor stop it.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The 3 most recent copies are shown; with none: "Nothing copying. Pick a card, tick where it goes, and press Copy to all." Each has the title "<card label> → <folder>" and a "Stop" button (hidden once finished; "Stopping..." and unavailable after pressing). For each destination: name, kind, state, percentage, a progress bar, and "<done> of <total> · <rate>/s · ETA <time> · <n> of <n> files · <how it is copying>" (rate and time left only while moving; how it is copying only while copying; no figures when refused), the file being worked on, the destination's message (red when failed, refused or stopped) and a yellow list of problems. States shown: Waiting, Looking, "Checking what is there", Copying, "Verifying", Done (green), "Needs a look" (yellow), Failed, Stopped, "Not started" (red). Time left is in seconds under 90 seconds, minutes under 90 minutes, otherwise hours to one decimal. The percentage stays at 99 or below until the end, and shows 100 for Done or "Needs a look". Speed is averaged over about 6 seconds and shows 0 while verifying. At the end the state is Done when nothing went wrong, otherwise "Needs a look", with the counts: "<n> copied and verified, <n> already identical, <n> already there, quick-checked, <n> left alone (something different is there), <n> failed, <n> copied but not verified." or "Nothing to copy." Up to 12 finished copies are remembered, until the app restarts.

### 10-023: Every verified copy made in the field is recorded at once on the computer and reaches the studio's record when the dashboard can be reached.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: After each destination finishes (also after a stop), every verified copy of a file the record tracks is recorded on this computer straight away, durably, so it counts towards "safe" at once and survives a power cut. If the destination's drive letter now holds a different drive, nothing is recorded: "<destination> is now a different drive, so nothing was recorded for it." and the destination fails "<destination> changed while copying; nothing was recorded." A folder on no known drive records nothing. A copy recorded here is forgotten locally once the studio's record holds it; local records older than 30 days are ignored, and at most 60,000 are kept (oldest dropped). Copies to drives and folders are sent to the studio's record; copies to the NAS made from this page are kept on the computer but not sent from here.

### 10-024: The page sends field copies to the studio and refreshes its offline copy of the record, on its own and on request.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The page's record section shows "Waiting to send: <n> copies"; "Last tried: <how long ago>" or "not yet"; "Ledger on this laptop: <n> copies, updated <how long ago>" or "never". It shows the last attempt's problem, or "No dashboard is set up here. Copies are kept on this laptop." A "Send and refresh now" button ("Sending..." while running; unavailable while one runs or with no dashboard set up) sends and refreshes, and the page refreshes 1.5 seconds later. Sending and refreshing also happens on its own when a copy finishes, and every 5 minutes while the page is open and nothing is copying. Messages: "No dashboard is set up on this computer."; "The dashboard could not be reached. Copies are kept here and sent when it can."; "The ledger was not refreshed: <error>"; "Could not sync: <error>". The refresh brings down what the studio's record knows about every drive plugged in now and the NAS, plus drives seen in the last 60 days that are not plugged in (never cards), at most 150 drives (most recently seen first). An unreachable dashboard leaves this computer's copy as it was. The record also gives drives their names and kinds, which the page uses.

### 10-025: Copies made on an editor's computer reach the studio's record within about a minute of the dashboard being reachable, and are never lost by being offline.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Verified copies made by field backup, and verified copies to a local drive made by work the studio hands this computer whose receipt could not be delivered, wait on the computer until the dashboard takes them. While the computer's drive reporting is on (the default), waiting copies are sent about every minute; the field page also sends them whenever it syncs, even with drive reporting off. A copy already waiting is not added twice; a record missing its drive or path is dropped. Up to 200,000 copies can wait; beyond that new ones are not kept and nobody is told. On a site that does not have the record, the computer tries again only every 10 minutes. Copies the dashboard refuses as malformed are set aside and tried again automatically after the dashboard is next updated. Nothing waiting is lost when the dashboard is unreachable or refuses the computer's credential; it is kept until it can be sent.
- Flag: differs: the computer's switch for drive reporting stops background sending but not sending from the field page

### 10-026: The studio's record tracks camera originals, sound and proxies on every drive, and nothing else.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The site's own rules decide which files the record tracks; where it gives none, these apply. Tracked anywhere: original video and stills (Blackmagic RAW, RED, ARRIRAW, MXF, QuickTime, MP4, M4V, AVCHD, MPEG transport streams, AVI, Canon raw video, DNG, Sony, Canon and Nikon raw stills, 360 camera video) and sound (WAV, broadcast WAV, AIFF, MP3, M4A, FLAC). Proxy video (QuickTime, MP4, M4V, MXF, AVI, AVCHD, MKV, WebM) is tracked only inside a folder named "proxy" or "proxies" (any case). Never looked into: Resolve's cache and optimised-media folders, camera thumbnail folders, a folder of quarantined duplicates, the operating systems' recycle bins, system and index folders, NAS recycle and thumbnail folders, and developer folders. Never tracked: part-written, interrupted or set-aside files, hidden macOS "._" files, and files with no extension.

### 10-027: The studio can ask an editor's computer to list everything the record tracks on one of its drives, without touching a file.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: When the studio asks, the computer lists every tracked file on the named drive (or on named folders of it) with its size and time, and hands the list to the studio's record, which works out what is new, replaced, gone or back. The drive is found by its identity, never by its letter. Nothing is opened, read, written or locked; links are not followed; very long Windows paths are included. The system drive is never listed from its top, only through folders named for it ("the system drive is only scanned through a watched folder, never from its root"). Refusals: the drive is not plugged in here ("the drive <serial> is not plugged into this computer"); none of the named folders is a safe folder on the drive; the studio has no such listing to do. While it runs the studio sees files done, data seen, speed, the current folder and folders visited, about every 2 seconds. Pulling the drive stops it ("the drive is gone"); what was gathered is still sent, marked incomplete. Folders that cannot be read are named (up to 200) so their files are not marked gone; more than 200 marks the listing incomplete ("<n> folders could not be read (more than can be listed)"). A listing the studio has handed to a newer attempt stops on its own.
- Flag: undetermined: who asks for a listing, how often, and when it is stopped are outside this section

### 10-028: Every drive plugged into an editor's computer is reported to the studio's record within about 10 seconds.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: The computer tells the studio's record about every card reader and fixed drive plugged in, so the record can show new drives, know which drives are visible on which computer, and list a tracked drive when it appears. Reported per drive: its identity, label, file system, size, free space, removable or fixed, whether it is the system drive, and its drive letter; no other path. Reported on start, within about 10 seconds of any change (a drive in or out, relabelled, reformatted, resized, or on another letter), every 5 minutes regardless, and within about a minute when free space moves by 1 GiB or 1 % of the drive, whichever is larger. A drive being copied from is reported as last seen even if it drops out. Left out: drives with no real identity, cloud-storage drives (Google Drive, OneDrive, Dropbox, iCloud, Box, Proton Drive, self-hosted cloud folders, pCloud, MEGA, Sync.com), network and virtual-machine file systems, optical discs, and a FAT32 drive of 2 TiB or more. On by default per computer; the owner of the computer can switch it off or change how often drives are looked at (default every 10 seconds). A refused credential is only logged; nobody is told. Needs a dashboard set up on the computer.
- Flag: differs: the field backup page does not leave out cloud-storage drives, so one can be offered as a backup destination while the record never hears of it

### 10-029: Every camera card put in a reader on an editor's computer is reported to the Footage Sorter, with its full file list, within about 10 seconds.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: The computer tells the Footage Sorter which camera cards are in its readers, with every file (path on the card, size, time), the first part of each XML metadata file, each WAV's length, the card's type, capacity, free space and when it was first seen (kept while it stays in), so the Sorter can decide where the footage goes. Cards are looked at every 10 seconds by default (the owner of the computer can change it, or switch reporting off; it is on by default). A drive just plugged in is looked at again over the next minute before it is taken not to be a card (a card can appear before its files can be read), and then for 5 minutes. The full set is sent when a card comes or goes or its file count or total size changes, and every 5 minutes while any card is in; when the last card goes an empty set is sent once. A card's file list is re-read when it changes or after 5 minutes, so a change that keeps the same count and size reaches the Sorter within 5 minutes. A card being copied (by field backup or by studio work) is not read by anything else and its last list is reported. A site with no Sorter is quietly retried every 10 minutes; a refused credential is only logged, nobody is told, and it is retried every 5 minutes. Needs a dashboard set up on the computer.

### 10-030: Camera cards are recognised by what is on them, never by drive letter.
- Where: footage-sorter-and-camera-cards / What cameras and recorders write
- What: In this order: Sony, a "PRIVATE/M4ROOT/CLIP" folder (an empty Sony card counts); drone, a "DCIM" folder with a sub-folder of three digits then "MEDIA" holding MP4 or QuickTime video; Blackmagic, a Blackmagic RAW clip in the top folder; audio recorder, a WAV in the top folder whose name contains "Wireless PRO" or is six digits, an underscore and three digits; otherwise any drive holding video, audio or photos within four folder levels is a generic card. A drive with no media is not a card. A fixed (non-removable) drive is a card only when it is one of the first four kinds, so CFexpress Type B and Blackmagic SSD readers (which appear as fixed disks) work, and an internal disk full of footage is not a card. The system disk is never a card. A card's list leaves out system, recycle and hidden folders and the operating systems' own small files. A folder or file that cannot be read is listed as unreadable and the card's listing says it is partial.

### 10-031: Which drives an editor's computer sees differs between Windows and macOS.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: On Windows: drive letters A to Z, removable and fixed drives only; network, optical and RAM drives are never seen; an empty card reader is skipped without the system's "There is no disk in the drive" box ever appearing; the system drive is the Windows drive. On macOS: every mounted volume; removable when macOS says removable, external or ejectable; the startup disk is seen as itself, with an identity that stays the same across macOS updates; a volume macOS cannot describe is skipped. Free space and size read as 0 when they cannot be read. On any other operating system no drives are seen, so there is no card reporting, drive reporting, field backup drive or drive listing.
- Flag: differs: Windows and macOS see drives differently, as described

### 10-032: Timeline Cards can drive Resolve on an editor's computer through the app, when switched on for that computer.
- Where: cards-to-resolve-and-exports / Which computer is driving Resolve
- What: When switched on for a computer (off by default on every computer), the app lets that computer's Resolve take part in Timeline Cards: the editor's Timeline Cards session sees what Resolve is showing (project and timeline) and the edits made in Timeline Cards are applied to Resolve's open timeline. It works through the studio's dashboard only; nothing secret to Timeline Cards is kept on the editor's computer. A person drives only the computers signed in to their own account; while that person is not in a Timeline Cards episode, what the computer sends is set aside and the health shows the reason, until they are in one again. The app never refuses an edit Timeline Cards sends, and never connects to Resolve during Resolve's start-up window. A new sign-in takes effect without restarting.
- Flag: dormant

### 10-033: Timeline Cards will not start driving Resolve on a computer when something stands in the way, and says what.
- Where: cards-to-resolve-and-exports / Which computer is driving Resolve
- What: Checked in this order, each with a sentence the admin sees:
  1. not switched on for this computer;
  2. no dashboard: "Sign in from the tray and this computer will pick the page up on its own within a minute";
  3. the studio has stopped work: "syncing is stopped by your admin, so this computer is not taking work of any kind" (a stop prevents starting only; one already running carries on);
  4. what Timeline Cards needs on this computer is not set up, or the folder of episodes it serves is not set;
  5. another Timeline Cards program is already driving Resolve on this computer: "a Timeline Cards process is already driving Resolve here: <name> (pid <n>): <command line, shortened>. Close the standalone Timeline Cards agent and this computer picks the page up within a minute" (the other program's name, number and command line are shown). The other program is never closed by the product;
  6. the computer's programs cannot be listed: treated as one running, and the admin is told that another Timeline Cards program may be running and the computer's programs could not be listed, so it is not starting;
  7. the Timeline Cards part on this computer cannot be loaded or is the wrong version for the app: says which needs updating.
  Once the obstacle is gone (signing in, closing the other program, a stop ending) it starts on its own within about a minute. After 5 failed starts in a row (failures, not refusals) it stops trying until the app is restarted; this is only logged. On an operating system other than Windows or macOS it never starts.
- Flag: dormant

### 10-034: An admin sees, per computer, whether Timeline Cards is driving its Resolve and if not why.
- Where: cards-to-resolve-and-exports / Which computer is driving Resolve
- What: Each computer reports a health word and a detail (up to 255 characters), and the admin's view of the computer goes green only on "running":
  - refused: never started; the refusal sentence;
  - stopped: it stopped working; what stopped it, or that it is no longer running;
  - credential refused: "the fleet credential is refused: sign in again from the tray";
  - unreachable: the dashboard has not answered (nothing in the first 30 seconds, or no answer for 50 seconds): the last error, or that the dashboard has not answered this computer;
  - running: "serving <episodes folder> to <dashboard>", or the reason the person's edits are being set aside (not in an episode).
  Also reported: when the dashboard last answered, the current timeline's name, the version of Timeline Cards running there and when it started. A part that stops working is restarted within about a minute.
- Flag: dormant

### 10-035: Clip paths in Resolve projects are written one way for the whole studio, so a project opens with its media on every computer.
- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: Every Resolve project in the studio stores media paths under the studio's shared drive letter (normally P:\), the only spelling that works on every computer, wherever the footage really sits on each computer. A path written back into Resolve is always in that spelling, with backslashes, on Windows and macOS alike; on macOS Resolve reaches it through its own mapped-mount preference. A file outside the shared folder keeps its real path. Paths are compared ignoring letter case and slash direction, and "inside a folder" means inside it, not a folder whose name merely starts the same way. A file name is shown from the end of the path whatever its spelling (a Windows-spelled path on a Mac shows just the file name). On the computer whose shared folder is the drive itself, paths pass through unchanged.

### 10-036: The product tells apart the reasons a clip on the open timeline might not play everywhere.
- Where: resolve-on-the-editors-computer / Missing clips, relinking and refreshing
- What: Every media path on the open timeline is put in one situation (what the editor is then shown or offered is decided elsewhere):
  - fine: in the shared folder, written the shared way, and the drive letter leads to the right place;
  - plays here only: in the shared folder but written with this computer's own path, so it is offline on every other computer; fixable by relinking to the shared spelling (never on a computer whose shared folder is the drive itself);
  - outside the shared folder but present here;
  - another computer's private path, not here: cannot be fixed here;
  - the shared drive letter itself is wrong on this computer (not mapped at sign-in, or pointing at the wrong folder): a set-up problem;
  - missing: written the shared way, letter healthy, file not here (normal for an original never downloaded to a remote editor's computer); an empty path counts as missing.
  Whether the drive letter leads to the right place is checked at most every 2 seconds; on Windows a letter pointing at this computer's own network share is followed back to its folder, in any display language. If that check itself fails, the letter is taken as healthy, so a fault in checking never floods the editor with warnings. On macOS a shared path is checked at its place in the local folder.
- Flag: differs: Windows checks where the drive letter leads; macOS only checks that the local shared folder exists

### 10-037: Files holding a computer's credentials are readable only by the person who owns them.
- Where: accounts-privacy-legal / How secrets and keys are kept
- What: On every editor's computer, files that hold credentials (the app's settings with the computer's sign-in key, the computer's identity, the key local tools use to talk to the app, the YouTube sign-in cookies) are made readable by their owner only, before they are put in place. On Windows only the signed-in user can read and write them; on macOS only the owner. This never stops the app; if it cannot be done, the file keeps the permissions of the user's folder and this is only logged: nobody is told.

### 10-038: On Windows, the app repairs its own settings folder at start when an older installer left parts of it unreadable.
- Where: editor-app / Starting, staying running and crashing
- What: At start on Windows, the app checks whether it can open everything in its settings folder (looking at up to 400 entries). An older installer left parts unreadable, which made the licence be asked for again, stopped the install record being written, and stopped safety stops from being saved. If anything is unreadable the app gives its folder back to the user (with the system and administrators) and makes everything inside follow it, then checks again. The result, good or bad, is only logged; nobody is told. It never stops the app starting. Nothing is done on macOS.

### 10-039: Cancelling a transcription or a YouTube download stops everything it started, and frees the graphics card and partial files.
- Where: fleet-jobs / Stopping and cancelling
- What: When the app cancels, stops or quits work that runs as its own program and starts others (transcription, which holds the graphics card; a YouTube download, whose joining step holds the partial files), the whole family of programs is stopped. It is asked to stop first; if it has not ended within about 10 seconds (5 for a YouTube download) it is forced, with a further 5 seconds allowed. Failures here are silent.

### 10-040: The app is one program per operating system, with no console window, living in the Windows tray or the macOS menu bar.
- Where: editor-app / Installing and setting up
- What: There is one program for Windows and one for macOS (no other operating system), each built on its own system. It opens no console window. On macOS it lives in the menu bar and is started at sign-in. On Windows the program carries the product's icon and the description "CC Sync companion". On macOS it is signed so that Apple silicon will run it; it carries a developer identity only when the studio's vendor has one, otherwise macOS treats it as from an unidentified developer. It is not compressed in a way that makes antivirus programs flag it.
- Flag: differs: macOS signing depends on whether a developer identity is available

### 10-041: The app relaunches itself after an unexpected death, and goes back to the previous version after repeated failed starts.
- Where: editor-app / Starting, staying running and crashing
- What: The app is relaunched on its own when it dies unexpectedly (not after the editor quits it). Every start is recorded first; when starts keep failing, the computer goes back to the version it had before and the failed version exits at once.

### 10-042: An editor brings originals down, or stops them, from Resolve's own scripts menu.
- Where: resolve-on-the-editors-computer / Bringing originals from inside Resolve
- What: The app installs entries in Resolve's scripts menu for asking for originals on request: "Bring originals - selected media pool clips", "Bring originals - timeline clips between In and Out", "Bring originals - whole timeline", "Stop originals - selected media pool clips", "Stop originals - timeline clips between In and Out". (What each does is described where originals on request are.)

### 10-043: The licence and every third-party licence travel inside the app, and a component whose licence demands it can be replaced by the user.
- Where: accounts-privacy-legal / Third-party licences and what customers receive
- What: The licence an editor accepts is carried inside the app; its version decides whether it must be accepted again. The third-party licence texts and notices are carried inside the app, and no build is made without them. A component whose licence gives users the right to swap it is shipped as separate, replaceable files, and a copy the user puts in the app's settings folder is used instead.

### 10-044: A developer-only check draws a second tray icon for about five seconds.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: Builders of the app have a manual check that draws a second tray icon for about 5 seconds. No editor meets it.
- Flag: dev only

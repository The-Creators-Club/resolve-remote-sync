# Extract of inventory section 09

## Items

### 09-001: The app keeps its settings in one file on the editor's computer that explains every setting and only that computer's user can read.
- Where: editor-app / Settings, records and background work
- What: On its first start the app writes its settings file with a plain explanation beside every setting a person may want to change, and makes it readable only by the computer's own user account, because it holds the computer's credential for the server. An older file is locked down the same way the next time the app starts. A file saved by an installer with an invisible marker at its start is read normally. When a setting is changed from the app's settings or by the dashboard, only that one setting's line changes: every other line and comment in the file stays exactly as it was, and a setting that was not in the file is added to its main part. If the change does not read back as written, the change is reported as failed, with the advice that a second copy of the same setting, or a section heading above it, is the usual cause and the file must be fixed by hand.

### 09-002: A damaged settings file never silently runs the computer on the wrong settings: the app falls back to the last good copy and stops syncing until someone fixes it.
- Where: editor-app / Telling the editor what is wrong
- What: Every time the settings file reads cleanly, the app keeps an exact copy of it as the last good settings. If the file later cannot be read:
  - with a last good copy, the app runs on that copy and reports an error saying the settings file could not be read, so the last good copy of the settings was loaded instead;
  - with no copy, or when the file cannot be opened at all, every setting is its default and the error says that every setting is a default, not what is in the file.
  In both cases no syncing starts until a person fixes the file. A setting with a nonsense value (a negative wait, a word where a number belongs) never crashes the app: that one setting falls back to its default.

### 09-003: The app checks its settings at start and when they are saved, and tells the editor which problems stop syncing and which only switch one feature off.
- Where: editor-app / Telling the editor what is wrong
- What: Problems that stop all syncing until fixed: the settings file could not be read (above); the computer's sync folder is not set, blank or does not exist ("nothing syncs until it names this computer's sync folder"); the server's address for the tree, or where the tree lives on the server, is missing, or the server location does not start from the server's root; a timing or count setting that must be a positive number is not one. When saving from the app's settings, a dashboard address that is plain http on the public internet is refused outright.
  Problems that only weaken one feature: the editor's name is blank (suggested destinations lose the name part; with sign-in switched off the server refuses every report); the folder suggested for added media is blank (the suggestion becomes the top of the tree); the dashboard address is blank ("this computer is not pointed at any dashboard, so there is no reporting, no managed sync selection, no updates and no site settings", adding, when sign-in is required, that nobody can sign in and no sync will ever start until it is set); the dashboard address does not begin with http or https; an address is set but the computer has no credential; making proxies is on but no media tool can be found; a separate download path is half set up; an unknown computer role (treated as an ordinary editor's computer).
  A dashboard address that is plain http on the studio's own network is accepted with the note "This address is not https. It is fine on your studio network or tailnet." One that is plain http on the public internet tells the editor: "The dashboard address is plain http on the internet, so CCSync will not send anything to it. Ask your admin for its https address."
- Flag: undetermined: where on the editor's computer these errors and warnings are shown.

### 09-004: A value set on the computer itself always beats what the site or the computer's role would choose.
- Where: editor-app / Settings, records and background work
- What: Each setting is its built-in default, then what the computer's role implies, then what the studio's site settings provide (only the server share path used for grading from the server's originals), then what is set on the computer. Anything set explicitly on the computer wins. A blank or zero value from the site never switches anything off on a computer.

### 09-005: A computer can be set to sync nothing, for a computer that works straight off the server.
- Where: sync / What syncs where
- What: A computer is either an ordinary editor's computer or one that works directly off the server and syncs nothing. A computer set to sync nothing keeps no local copies of proxies and runs no syncing, unless its own settings explicitly turn either back on. It still gets the warning about media used from outside the shared tree. The role the server holds for the person is shown in diagnostics only and never decides whether a computer syncs: the computer's own setting does.

### 09-006: Resolve projects with throwaway names are ignored by the product.
- Where: resolve-on-the-editors-computer / Project libraries and projects
- What: The app has a list of Resolve project names to ignore, by default "Untitled Project" and "New Doc", changeable on the computer. A project is ignored when its name matches an entry, ignoring letter case and extra spaces, or matches an entry followed only by a duplicate number with optional spaces, dashes, underscores or brackets ("New Doc 1", "New Doc 2", "Untitled Project (3)"). "New Doc Final" and "New Documentary" are not ignored. An ignored project is not reported to the server, never brings up the new-project prompt, and its clips never raise the warning about media outside the shared tree.

### 09-007: Each computer is told who its editor is, where its copy of the tree is, and where new media should go.
- Where: editor-app / Installing and setting up
- What: Settings on each computer, set up at install time and changeable on the computer:
  - the editor's name, used to suggest a destination for media the editor adds (B-roll / Editor Added / <name>), and as the identity reports are sent under when sign-in is switched off;
  - the computer's sync folder (required);
  - the shared-drive prefix Resolve clip paths are stored with, by default P:\, also kept as P:\ on a Mac, used to spot clips with the wrong prefix;
  - where the tree lives on the server (required);
  - the folder, inside the tree, suggested for media the editor adds.

### 09-008: A computer can be given a separate, faster way to download from the server, while everything it writes still goes the usual way.
- Where: sync / Speed and routes
- What: An admin can point one computer's downloads (proxies, b-roll fetched on demand, the folder layout) at a different address for the server, for example a faster path for a remote editor. Uploads and every other write always use the computer's normal connection. A separate download path that is only half described, or that names the normal one, is ignored with a warning. The server is told when a computer downloads this way.

### 09-009: How quickly a computer reacts can be adjusted on that computer.
- Where: sync / What syncs where
- What: Defaults, each changeable in the computer's settings:
  - a change in the open Resolve timeline is noticed within about 3 seconds;
  - a file that stops changing in the tree starts uploading about 10 seconds later; a full check for anything to upload runs every 5 minutes;
  - new proxies on the server are looked for every 2 minutes;
  - a project ticked or unticked on the dashboard reaches the computer within about a minute;
  - with several projects ticked, the computer moves on from one project to the next after at most 10 minutes;
  - once everything is caught up it looks again about a minute later.

### 09-010: The safety limits on downloading proxies can be adjusted per computer.
- Where: sync / Safety stops
- What: Defaults, changeable in the computer's settings:
  - a proxy that appeared on the server less than 2 minutes ago is not downloaded yet (0 turns this off);
  - one check may move at most 50 files, or a quarter of the computer's proxies, whichever is fewer, into the computer's own trash; beyond that downloading stops itself;
  - downloading also stops itself when the server's list has shrunk by more than half since the last check;
  - downloading pauses when the sync drive has less than 20 GiB free and resumes by itself at twice that, or when the editor chooses "Resume proxy download" in the tray (0 turns this off);
  - the computer's trash keeps removed files for 14 days and at most 50 GiB, dropping the oldest first and never the newest by the size rule; nothing is cleared from it while downloading is stopped by a safety stop;
  - a computer can be set to keep no local copies of proxies at all.

### 09-011: Uploads go newest first and downloads smallest first, both at once, and a new file does not wait for its project's turn.
- Where: sync / Stuck, slow and fair transfers
- What: Defaults, changeable in the computer's settings: originals upload newest first; proxies download smallest first; uploading and downloading run at the same time. A newly finished file is uploaded straight away, gathered for about 10 seconds; a burst of more than 200 files waits for the regular check instead. Uploads still running when the computer moves on to another project carry on and finish. From time to time the server's folder layout is recreated on the computer, including empty folders, and half-finished uploads left on the server are reported (never deleted).

### 09-012: The editor must sign in before the computer syncs, and without a dashboard address most of the product is missing.
- Where: editor-app / Signing in, the computer's identity and the licence
- What: By default sign-in is required: no syncing starts and no report naming the person is sent until the editor signs in from the tray. With no dashboard address set, the computer reports nothing, gets no project selection from the server, no updates, no site settings, and has no "Open dashboard" link.

### 09-013: The settings that govern making proxies on an editor's computer.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Defaults, changeable in the computer's settings:
  - a clip whose stored proxy location is stale is pointed at the synced proxy (on);
  - the editor is told about originals that have no proxy (on), the same notice at most once a day;
  - the computer makes proxies itself: by default exactly when it keeps no local copies of proxies, otherwise on or off as set;
  - it looks for originals without a proxy every 15 minutes;
  - it starts encoding only after 5 minutes without keyboard or mouse input;
  - it skips files changed in the last 2 minutes, and files whose size or time changed across a 5-second look;
  - proxies are at most 1080 lines tall, never enlarged, at about 7 megabits a second;
  - it tries a file at most 3 times per run of the app;
  - it keeps free the larger of 20 GB or 5% of the drive (0 turns this off);
  - it does not hold back while Resolve is open (off).
  A warning appears when making proxies is on but the media tool it needs cannot be found.

### 09-014: Rehearsal modes show what proxy making and FIX ALL would do without doing it.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Two settings, both off by default and reachable only by editing the computer's settings file: one makes the computer report which files it would encode and encode nothing; the other makes FIX ALL report the copies and relinks it would make and do nothing (read once when the app starts).
- Flag: dormant

### 09-015: The settings that govern bringing b-roll and music in from an editor's computer.
- Where: broll / Bringing new footage in
- What: Defaults, changeable in the computer's settings: bringing footage in is on; a batch marked "only when idle" waits for 5 minutes without keyboard or mouse input; it holds back while Resolve is open (on); it keeps 20 GB free; it encodes at most 2 files at once; the working copy of a finished batch is deleted after 7 days. Music uses the same keeping time.

### 09-016: The computer can feed Blackmagic Proxy Generator with folders of raw camera footage that have no proxies.
- Where: proxies-and-file-moves / Raw camera formats and Blackmagic Proxy Generator
- What: On a computer that makes proxies and has Blackmagic Proxy Generator installed (it comes with Resolve), the app by default adds folders holding raw camera files (BRAW, R3D, Canon raw) that have no proxies to the generator's watch list, only ever adding, after keeping one backup of the list, and presses Start in the generator's window. Each part can be switched off on the computer, and the generator's location can be given when it is not where Resolve installs it.

### 09-017: Downloaded YouTube clips are brought into the open Resolve project by themselves.
- Where: youtube / Reaching the editor and Resolve
- What: By default, YouTube clips that land on the computer are imported into the open Resolve project under Master > Youtube > <search term>. The computer looks every minute, waits until a file is 2 minutes old, takes up to 20 files per search folder at a time, and gives up on a file after 3 failures. Each can be changed in the computer's settings.

### 09-018: A computer downloads the YouTube clips it asked for itself, and keeps its downloader current.
- Where: youtube / Keeping the downloader working
- What: By default a computer downloads the YouTube clips its editor asked for. Switched off, the app installs and checks no downloader at all. The app keeps its own copy of the downloader and updates it daily; if updating has failed for 21 days the downloader is reported as out of date (0 or less switches its self-updating off). A computer can be given its own copy of the downloader instead, which the app then leaves alone. A file of YouTube sign-in cookies can be given; it is used only after an attempt without signing in hits YouTube's bot check.

### 09-019: The settings for shared LUTs and stills on an editor's computer.
- Where: resolve-on-the-editors-computer / Colour look-up tables (LUTs)
- What: Defaults, changeable in the computer's settings: Resolve's LUT locations are linked to the studio's shared LUT library (on), checked every 15 minutes; the shared library is P:\Assets\Luts on Windows and its real local path on a Mac, unless given; Resolve's own LUT folder is the usual one for the platform unless given; extra names of Resolve's factory LUTs can be listed so Share LUTs never offers them; Resolve's LUT list is re-scanned when Resolve's own log shows it missed the library at start (on); Resolve's stills gallery is pointed at the shared folder (on).

### 09-020: The app warns when Resolve's scripting has died, restarts itself when Resolve closes, and warns about VP9 media.
- Where: resolve-on-the-editors-computer / Connecting to Resolve's scripting: launch, stalls and death
- What: Defaults, changeable in the computer's settings: a repeating warning when Resolve is open but its scripting is dead, first after 5 minutes and then every 5 minutes (0 or less turns it off); the app restarts itself when the Resolve it was connected to exits, so its next connection starts clean; a warning when the open timeline uses VP9 source media.

### 09-021: The computer is kept awake and warns at shutdown while it is syncing.
- Where: sync / Uploads that cannot resume, shutdown and sleep
- What: Defaults, changeable in the computer's settings: on Windows, the shutdown screen warns while syncing is under way; the computer is kept from sleeping while it is transferring, except that a backlog unchanged for 3 minutes counts as stalled and no longer holds it awake, and it is never held awake for more than 8 hours in a row.

### 09-022: An editor who pulls out an external sync drive is reminded every half hour.
- Where: sync / The sync drive
- What: The reminder for an external sync drive pulled out with work still owed repeats every 30 minutes by default, changeable on the computer; 0 gives only the first warning.

### 09-023: Clips that exist only on this computer are looked for in every Resolve project, and media from outside the tree raises a popup.
- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: By default every 30 minutes the app looks through every project in the Resolve libraries for clips that exist only on this computer (0 turns it off). The popup about media used from outside the shared tree is on by default and can be snoozed for 5 minutes. Both can be changed on the computer.

### 09-024: Grading from the server's originals uses the studio's server share, and can be switched off per computer.
- Where: resolve-on-the-editors-computer / Grading from the server's originals
- What: On Windows only, "Grade from server originals" uses the server share path the studio's site settings provide, or one worked out from the tree when the site gives none, or one set on the computer. Setting it to off on a computer switches the feature off there.

### 09-025: Web pages of the product can reach this computer's Resolve through the app, and only pages from the studio's dashboard may.
- Where: editor-app / Settings, records and background work
- What: By default the app answers the b-roll, music and YouTube pages when they send something to Resolve; switched off on the computer, those buttons cannot reach it. Only pages from the studio's dashboard address are allowed. An admin can add further exact web addresses that may call it. A separate setting also accepts pages served from the computer itself, for people building the product.
- Flag: dev only: accepting pages served from the computer itself.

### 09-026: A laptop can offer a field backup page, with chosen destination folders.
- Where: footage-sorter-and-camera-cards / Field backup on a laptop
- What: By default the app serves a field backup page on the computer itself. Settings on the computer list the laptop folders offered as backup destinations and the folder name used for the pooled backup ("FieldBackup" by default). It can be switched off.

### 09-027: The settings that govern a computer taking on shared heavy work.
- Where: fleet-jobs / When a computer counts as free and able
- What: Defaults, changeable in the computer's settings:
  - taking shared work is on;
  - transcription is possible only once the transcription set-up has been installed and pointed to on that computer;
  - where the Timeline Cards episodes folder, the media folder and the footage pool are on this computer;
  - reporting camera cards to the Footage Sorter and taking card and drive copy work (on);
  - reporting drives and taking drive scans (on), noticing a drive plugged in within about 10 seconds;
  - card copies on Windows use a separate verifying copy program when one is installed with verifying switched on, otherwise the app's own copier; a person can insist on the app's own copier; copying without verifying is not allowed by default;
  - work starts only after 5 minutes without keyboard or mouse input, and not while Resolve is open (on);
  - lending the computer from the tray lasts 30 minutes;
  - a list of the only kinds of work this computer takes (empty means every kind). Unknown kinds in the list are ignored with a warning.

### 09-028: A computer can drive its own Resolve for Timeline Cards, switched off by default.
- Where: cards-to-resolve-and-exports / Which computer is driving Resolve
- What: A setting on the computer lets Timeline Cards drive this computer's Resolve. It is off on every computer by default. Its episodes folder defaults to the one set for shared work. The server is told whether it is connected, its state, the timeline it holds and since when.
- Flag: dormant

### 09-029: The computer reports itself to the server about once a minute, and every few seconds while it is syncing.
- Where: dashboard / Reports from computers
- What: The first report reaches the server about 2 seconds after the app starts, then one every minute, and one every 5 seconds while anything is syncing, so the dashboard's progress is live during transfers. The larger parts (the list of media on the disk, the Resolve bins, the list of undo records, the licence) go at most once a minute. Pressing "Sync now" in the tray, among other things, also sends one at once. Nothing is reported when no dashboard address is set, or when sign-in is required and nobody is signed in. Signing in as a different person makes the next report complete. Both timings can be changed on the computer.

### 09-030: What an admin can always learn about a computer.
- Where: accounts-privacy-legal / What the product records about a person
- What: Every report tells the server: who is signed in on it; the computer's name and its permanent identity; the app's version; the operating system and the kind of processor; for each direction of syncing its state, how much is waiting and moving, the last error, when it last synced, the project it is on, bytes done and total, speed, time left and the files moving now (each up to 256); which kinds of reporting this computer withholds. When available it also tells: files finished since the last report (up to 200); the queue of ticked projects and the one being synced; the open Resolve project; whether it syncs or works straight off the server; whether it downloads by a separate path; the state of its connection to the server; which originals have no proxy (up to 64 projects); the state of importing YouTube clips; the safety stops, its trash size, any studio-wide stop, Resolve's health; answers to the server's file moves and undo requests; what it can do (09-064); the shared-work settings and whether they await a restart; a b-roll or music batch in progress; how its reports and its updates are going; how many crash reports it holds. Finished files listed in a report that fails to arrive are not sent again.

### 09-031: What an admin can learn about a computer's media and Resolve, at most once a minute.
- Where: accounts-privacy-legal / What the product records about a person
- What: Besides the regular report, the server learns at most once a minute: which media files are on the computer's disk, per project; the Resolve bin structure; which undo records the computer holds; which licence the computer accepted. The computer rebuilds its media list every 5 minutes and re-reads the bins every 2 minutes (both changeable on the computer), so what the dashboard shows can be that old. The media list and bins are sent again even when unchanged after 10 minutes. On a computer holding a very large amount, the media list is trimmed to fit, the lowest-priority projects first, and each trimmed project is marked incomplete; if that is not enough, bins are cut to 500 clips each, the per-project list of missing proxies is reduced to totals, half the projects are dropped, then the bins and finally the whole media list. The sync status itself is never trimmed. When the server itself had to trim, that is only written to the log; nobody is told.

### 09-032: An editor's computer and the studio can each keep four kinds of information from being reported.
- Where: accounts-privacy-legal / What the product records about a person
- What: Four kinds can be switched off, each on a computer (all on by default) and for the whole site (all on unless the site explicitly says off): the open Resolve project's name; the list of media on the disk; the Resolve bin structure; how long since the keyboard or mouse was last used. A kind is reported only when both the computer and the site allow it, and withholding the project name also withholds the bins. The computer still uses the information itself: withholding never stops syncing, relinking or any other work. Every report says which kinds are withheld, so the admin knows the gap is deliberate. The server can never change these four switches.

### 09-033: What each privacy switch hides from the server.
- Where: accounts-privacy-legal / What the product records about a person
- What:
  - The project name: the open project wherever it appears in a report, the project named on each undo record, the bin structure, and project names inside the answers to undo requests (replaced by "<project>"; if that fails the text becomes "(detail withheld: this computer does not report project names)"). Undo records are still listed, under a masked name, so an admin can still ask for an undo.
  - The media list: the list itself, and the names of missing clips, refused clips, conflicting files, stray and moved project folders and sample files; counts remain.
  - The bins: the bin structure.
  - Keyboard and mouse idle time: the time itself. Without it the computer counts as someone being at it, so it is given less shared work.
  The editor's own undo from the tray works whatever is withheld.

### 09-034: The editor is told once when the server rejects the computer's credential, or when the dashboard address is unsafe.
- Where: editor-app / Telling the editor what is wrong
- What: When the server rejects the computer's credential, the editor gets one notification per run of the app: "Your CCSync credential was rejected by the dashboard - sign in again" (shown again after a report has got through and then failed again). When the dashboard address is plain http on the public internet, nothing is sent and the editor gets once: "Not sent: the dashboard address is plain http on the internet. Ask your admin for its https address." The computer remembers, across restarts, when a report last got through and how the last one ended, and the server is told how many have failed in a row. Other failures are only written to the log; nobody is told.

### 09-035: A computer whose clock disagrees with the server's is measured, and the difference is shown.
- Where: sync / Clocks and file age
- What: Each report that gets through compares the computer's clock with the server's. The difference is shown in the tray, at sign-in and in diagnostics as "N seconds" under 90 seconds, "N minutes" under 90 minutes, otherwise "N hours", followed by "ahead" or "behind". A difference of 5 minutes or more makes new-proxy waiting and every time the computer reports wrong; the warning about it is only written to the log, at most once an hour; nobody is told.

### 09-036: An editor can send their computer's diagnostics to the server.
- Where: editor-app / Telling the editor what is wrong
- What: A button sends the computer's diagnostics text (up to 262,144 characters) to the server, named with the person, the computer and its permanent identity. It is not sent when no dashboard address is set or nobody is signed in.

### 09-037: The app never sends anything to the server in the clear over the public internet, and never follows a redirect.
- Where: whole-product / Safety in what the product does
- What: Every call to the server that carries a credential (reports, sign-in, site settings, selections, shared work, update downloads) is refused before anything is sent when the address is plain http and every address its name leads to is on the public internet; the error says "not sent: <host> is plain http on the public internet; use the dashboard's https address". Plain http is allowed to the computer itself and to the studio's own network: private addresses, the studio's private remote-access network, a one-word name, names ending in the studio network's or local suffixes, test names, a name that does not resolve, and any name that leads to at least one private address. A number written without dots is read as the address it means, so it cannot pass as a local name. https addresses are always checked against the computer's trusted certificates, and nothing switches that off. If the server's address answers with a redirect, the call counts as failed rather than follow it, so the credential never goes anywhere else.
- Flag: differs: the update download allows plain http only to addresses that look local by their shape, without looking the name up, so an http address by a name that only resolves locally works for reporting but not for updates.

### 09-038: On Windows, an expired certificate left in the computer's store cannot stop the app reaching the server.
- Where: editor-app / Security warnings, permissions and certificates
- What: A fact about Windows: an expired intermediate certificate cached in a user's certificate store can make every secure connection the app makes fail with "certificate has expired" while the browser works fine. On Windows the app ignores certificates in the store whose expiry is certainly past; one whose date cannot be read is kept. Nothing changes on macOS.

### 09-039: An update, a rollback or a switch of build is offered in the tray, worded so the editor can tell which.
- Where: releases-and-updates / Offering an update to a computer
- What: The server offers whatever build is current for the computer with its replies, so an admin's rollback arrives exactly like an update. An offer is usable only when it names a version different from the one running. The tray item reads "Update available → v<X> (install)" for a newer build, "Roll back to v<X> (older build, install)" for an older one, and "Switch to v<X> (install)" when the order cannot be told (any version that is not plain dotted numbers), followed by " - <first line of the release notes>" cut to 48 characters. When a version is first offered a notification says "Update available → v<X>. Use the tray menu to install", or "Roll back to v<X> offered. That is OLDER than the v<running> you are running. Only install it if your admin asked you to.", or "Switch to v<X>. Use the tray menu to install", with "What's new: <first line>" (90 characters) when there are notes. Choosing it asks for confirmation: "Update to v<X>? The companion will restart itself." / "Roll back to v<X>? That is OLDER than the v<running> on this machine. You would LOSE whatever v<running> fixed. The companion will restart itself." / "Switch to v<X>? You are running v<running>. The companion will restart itself.", with buttons UPDATE, ROLL BACK or SWITCH, titled with the studio's brand, and the release notes after "What is new in v<X>:" up to 1,200 characters. Notes are cleaned of control characters and runs of spaces. The offer disappears when the server stops offering it. Signing in also brings an offer.

### 09-040: A build the computer will not trust is never offered to the editor, and the admin is told why.
- Where: releases-and-updates / Signing and trust
- What: Every offer is checked when it arrives, before it is shown. It is refused when: it is not signed with one of the vendor's release keys built into the app (the server cannot make such a signature; during a key change several keys are trusted); it is a build of something other than this app; it is for another operating system; it claims to need a newer version than itself (a malformed record, which changes nothing); or it is below the oldest version this computer has ever been told it must not go below. That floor only ever rises; going below it is a deliberate manual step on the computer itself. The processor kind is left to the server to match. A refused offer is never shown in the tray; the server is told the refused version, the reason and when, until the computer runs that version or the server stops offering it. Each signed build also states the oldest server it works with.

### 09-041: An update is downloaded only from the studio's own dashboard, safely, and only when there is room.
- Where: releases-and-updates / Installing an update on an editor's computer
- What: The download must come from the same address as the dashboard; anything else is refused. It must be secure (https), or plain http to an address that looks local; on plain http the computer accepts a build only on its vendor signature. At least 200 MB plus the build's size must be free, or the attempt fails as "no space". A download larger than the advertised size (or 300 MiB when none is given) is abandoned, and one whose contents do not match the signed record is thrown away. A redirect is refused and nothing is re-sent.

### 09-042: Installing an update replaces the app and restarts it, and if the new build dies at once the old one simply keeps running.
- Where: releases-and-updates / Installing an update on an editor's computer
- What: Only the installed app can update itself (a copy run by developers says so and does nothing). Only one install runs at a time; a second click does nothing. The app swaps in the new build, starts it, and waits up to 30 seconds for it to say it has started. If the new build exits first, everything is put back and the old build keeps running. If it is alive but silent at 30 seconds, the old one stands down anyway. If putting the old build back itself fails, the log names where the previous build is so a person can restore it by hand; nobody is told. The server is told why an attempt failed: download failed, contents did not match, no space, refused, the swap failed, the new build would not start, or it crash-looped.

### 09-043: A failed update is retried with growing waits, and an unattended update gives up after eight failures.
- Where: releases-and-updates / Installing an update on an editor's computer
- What: After a failed attempt at a version the next is no sooner than 10 minutes, then 1 hour, then every 6 hours, remembered across restarts. After 8 failures of the same version the computer stops trying it by itself (automatic update and an admin's push); the editor can still choose it from the tray. A different version starts the count again, and reaching the version clears it.

### 09-044: A build that keeps crashing at start is replaced by the previous one automatically, and is never put back on by itself.
- Where: releases-and-updates / Rolling back and withdrawing a build
- What: When the same version starts 3 times within 10 minutes without a clean shutdown, the computer restores the build it ran before and stands down. It does not do so when there is no previous build kept, when the previous version is unknown, or when the previous version is below the computer's floor: then a person must step in. The crashing version is marked so neither automatic update nor an admin's push installs it again; a newer published version is tried. The server is told which version the computer fled from, once. The mark clears only when the computer is running that version (for example a person installed it by hand).

### 09-045: The editor is told when an update has completed, and the previous build is kept for a while in case.
- Where: releases-and-updates / Installing an update on an editor's computer
- What: The first start on a new version (not a first-ever install) is announced to the editor as an update having completed. The previous build is kept until the new one has had a report accepted by the server and been running 10 minutes, or has been running an hour; if the app stops sooner it is kept to the next start. If the computer cannot keep its records of starts and versions, the server is told how many writes failed, and the crash-loop protection cannot work there.

### 09-046: The server sees each computer's update trouble.
- Where: releases-and-updates / Pushing updates and seeing who has what
- What: Every report carries the computer's update state: the version it failed to install, how many attempts, the last failure and when, the version it fled from after crash-looping, how many times this version has started, any build it refused and why, and how many record writes failed. All zero when nothing went wrong.

### 09-047: The app can restart itself without updating, to give Resolve a clean connection.
- Where: editor-app / Starting, staying running and crashing
- What: After the Resolve it was connected to exits, the app relaunches its own current build with the same 30-second hand-over as an update; if the replacement dies first, the running app carries on. A copy run by developers cannot, and says to restart the companion by hand to refresh its Resolve link.

### 09-048: Shared work is offered to a computer by the server, and only one computer can ever hold a piece of it.
- Where: fleet-jobs / Choosing who runs what
- What: The server's answers to a computer's reports carry the work it may take (up to 16 pieces), the work an admin asked it to stop, the work an admin marked "run now" (up to 16), and how long the queue is. The computer asks for a piece and the server gives it to exactly one computer. A new offer is acted on at once; otherwise the computer looks about every 20 seconds, or up to every 2 minutes when the server says nothing is waiting. When the server cannot be reached, the computer waits for the next offer.

### 09-049: A computer does one piece of shared work at a time, except that a drive scan can run beside a copy.
- Where: fleet-jobs / Load on the NAS and the computers
- What: A computer never asks for more work while it holds some. A drive scan runs on its own beside other work, one scan at a time; a second scan offered meanwhile is handed back to be done later.

### 09-050: Which kinds of shared work a computer can take depends on what is set up on it.
- Where: fleet-jobs / What a computer can honestly offer
- What: The kinds are: transcription; making a small preview copy of a clip; extracting a clip's sound; making a clip's waveform; copying a camera card; copying a drive; scanning a drive. A computer offers transcription only when its transcription set-up is present; the three media kinds only when the media tools are present; the two copy kinds when the Footage Sorter card feature is on; drive scans when the drive feature is on and no scan is running. A computer limited to some kinds offers only those. A piece of a kind this build of the app cannot do is handed straight back as "this companion has no runner for '<kind>' jobs", not to be retried. Placing a cut into Resolve and editing inside Resolve are never shared work.

### 09-051: The editor and the admin are told, in one sentence, whether a computer is taking shared work and why not.
- Where: fleet-jobs / When a computer counts as free and able
- What: Checked in this order, the first that applies is shown in the tray and the app's settings and reported to the server:
  1. "Fleet jobs are switched off on this computer."
  2. "This computer is not signed in to the dashboard, so the fleet has no way to give it work."
  3. "Your admin has stopped syncing for the whole fleet, so this computer is not taking work of any kind." (also when the stop cannot be checked)
  4. "This computer is running a fleet job."
  5. "This computer is not set up for any of the kinds of work the fleet queues." followed by "It is set to take only: <kinds>." or a sentence saying there is no transcription set-up and no media tool for the media work here.
  6. "This computer is busy with your own work, so it is not taking fleet work." with the reason (its own b-roll, music or proxy work, or that this could not be checked).
  7. "Somebody is at this computer, so it is not taking fleet work. It waits for <N minutes> of quiet." (also when idle time cannot be told)
  8. "Resolve is open here, so this computer is not taking fleet work." (also when that cannot be checked)
  9. "This computer is ready for fleet work. The dashboard has not offered it any."
  10. "This computer is ready for fleet work."
  While running work an admin marked "run now": "Your admin asked this computer to run a fleet job now." Steps 7 and 8 are skipped while the editor has lent the computer, and for work an admin marked "run now"; nothing skips steps 1 to 6.
- Flag: undetermined: sentence 2 is shown when the computer has no dashboard address or shared credential, not when nobody is signed in.

### 09-052: A computer whose shared work the server refuses says so.
- Where: fleet-jobs / Outages and withdrawn access
- What: When the server rejects the computer's credential while it asks for, reports on or finishes work, the computer stops that work and shows that it is not taking work, adding "This computer's fleet work is not being accepted right now: ask the studio to check this account." The next call that gets through clears it.

### 09-053: Shared work already running is not stopped when the editor comes back.
- Where: fleet-jobs / When a computer counts as free and able
- What: When someone starts using the keyboard or mouse, or opens Resolve, the computer takes no new work, but finishes what it is running.

### 09-054: The editor can lend their computer to the shared work for half an hour.
- Where: fleet-jobs / When a computer counts as free and able
- What: From the tray the editor can lend the computer for 30 minutes (changeable on the computer; 0 ends it at once). It runs out by itself. While lent, the computer takes work even with someone at it or Resolve open. The server sees until when. Work taken this way records "You lent this computer to the fleet, so it took this job while you are here."

### 09-055: An admin can make a computer run a piece of work now, even with someone at it.
- Where: fleet-jobs / Choosing who runs what
- What: Work an admin marks "run now" for a computer is taken even when someone is at the computer or Resolve is open, but never when shared work is switched off there, it is not connected, the studio is stopped, it is already busy, it cannot do that kind, or the editor's own work is using it. Only that work is taken. It records "Your admin asked this computer to run this job now, without waiting for you to step away."

### 09-056: The server sees the progress of each piece of shared work, and knows when a computer has lost it.
- Where: fleet-jobs / Progress
- What: A computer reports progress on its running work at least every 30 seconds (transcription also whenever it has moved by 1% and 5 seconds have passed), as a fraction when it can tell and never as a false zero; card and drive copies add how many files and bytes are done. A missed report is ignored. If the computer goes quiet for 5 minutes the server may give the work to another computer; a computer told the work is no longer its own stops it.

### 09-057: Shared work can be stopped by the admin, by the editor at the computer, by a studio-wide stop or by the app closing, and a cancelled piece is never retried.
- Where: fleet-jobs / Stopping and cancelling
- What: Running work stops when an admin cancels it, when the editor stops it from the tray (which returns at once), when the computer loses it, when the studio's syncing is stopped, or when the app shuts down. Everything it started is ended and any half-made output is thrown away. Cancelled work is never retried. A stop asked from the tray holds until the result has been sent; up to 16 such stops are remembered, and an admin's are never crowded out by the editor's.

### 09-058: The editor sees the last ten pieces of shared work their computer did.
- Where: fleet-jobs / Progress
- What: The computer keeps, across restarts, its last 10 finished pieces of work: what kind, which file or folder, done, failed or cancelled, the error (up to 300 characters) and when. The tray and diagnostics also show the current piece, when it started and why it was taken while someone was there.

### 09-059: A computer can transcribe a folder of an episode for the studio.
- Where: fleet-jobs / Results that are complete and current
- What: A transcription piece names a folder in the Timeline Cards episodes and its episode, and can ask for speakers to be told apart. Progress counts the files to do, which one is under way and how far through it; a folder with nothing left to do finishes at 100%. On success the server gets how long it took, how much faster than real time, and the transcripts made (up to 200), and the editor is told "Finished a transcription job for the fleet (Ns)." A computer without the transcription set-up refuses it. Failures (the transcription did not start or ended with an error, the work was lost, a studio-wide stop, the computer shutting down) are retried elsewhere; a cancelled one is not.

### 09-060: Media made for Timeline Cards by shared work is never made twice, never overwrites a newer copy, and is never seen half-made.
- Where: fleet-jobs / Results that are complete and current
- What: For the preview, sound and waveform kinds: the piece must say where its output goes; nothing guesses a place in somebody's episodes. A finished output no older than its source is reused and reported as skipped. A missing source is a failure another computer may retry. The output appears under its final name only when complete; if a current finished copy appeared meanwhile, the new one is thrown away instead of overwriting it. A stopped or failed run leaves nothing usable behind. On Windows the work runs with no window and at low priority, so it does not slow the editor. Progress is a fraction of the source's length. Sound and waveform give up after 30 minutes, a preview after 60. The server gets the files made, how long it took and how much faster than real time.

### 09-061: Extracting a clip's sound keeps it untouched where it can, and checks the length.
- Where: fleet-jobs / Results that are complete and current
- What: If the clip's sound can be played by a browser as it is, it is copied without change and kept only when its length is within 0.05 seconds of the source; otherwise it is converted to compact mono speech-quality sound. A clip with no sound fails as "no audio track", not retried.

### 09-062: A small preview copy of a clip is made for Timeline Cards.
- Where: fleet-jobs / Results that are complete and current
- What: The preview is at most 480 lines tall, never enlarged, with a fresh picture every second so it can be jumped about in quickly, and stereo sound. A computer with a graphics card that can encode video uses it; others encode on the processor. A preview whose sound length differs from the source by more than 0.05 seconds is only noted in the log. A clip with no picture fails as "no video track", not retried.

### 09-063: A clip's waveform is made for Timeline Cards.
- Where: fleet-jobs / Results that are complete and current
- What: The waveform holds 200 points a second, made with little memory even for very long recordings. One made at a different resolution is remade. A clip with no sound, or no samples, fails without retry.

### 09-064: What an admin can learn about what a computer is able to do.
- Where: fleet-jobs / What a computer can honestly offer
- What: Every report tells the server: whether there is a graphics card, its name and memory; whether its video encoder is usable; whether the media tools run; whether transcription is ready, and if not why (not both set up, the set-up is missing at its location, or incomplete); whether the assistant is available on it (advisory only: nothing uses it); which of the tree, episodes, media and footage pool folders are present now (an unplugged drive is absent); whether the Footage Sorter card and drive features are on; whether a verifying copy program is installed and set to verify; processor count and load; the app's version; whether shared work is on, the quiet time it waits for, and the kinds it is limited to; seconds since the last keyboard or mouse input (not given when withheld or when shared work is off); whether Resolve is running and which project is open; the state of driving Resolve for Timeline Cards; until when the computer is lent; and the one-sentence answer of 09-051. The hardware facts are at most 45 seconds old; the rest is fresh each report. Nothing here talks to Resolve's scripting.

### 09-065: Whether someone is at the computer is known on Windows and macOS, and treated as "someone is there" when it cannot be told.
- Where: fleet-jobs / When a computer counts as free and able
- What: Facts: on Windows, only the session the app runs in is seen, so another user's session or a remote session does not count. On macOS the time since the last input is read from the system. On any other system it can never be told, so work that waits for quiet never runs there. A render in Resolve with nobody at the keyboard counts as quiet. Whenever it cannot be told, every feature treats someone as present.

### 09-066: A piece of shared work names its files only relative to folders the computer knows, and is refused if it reaches outside them.
- Where: fleet-jobs / Failures, retries and the queue
- What: A piece names a folder by what it is (the tree, the Timeline Cards episodes, the media folder, the footage pool) and a path inside it, never a full path, because the same folder is in different places on different computers. A folder counts only when it is set up and present right now. Refusals, each becoming the reason the piece failed: the computer has no such folder ("this machine has no <name> root configured or reachable (it has: ...)", may succeed elsewhere); no path given; a full path; a path that climbs out of its folder; unprintable characters. An output name that is empty, "." or "..", or contains a slash is refused everywhere; one containing a backslash or a colon is refused only on Windows and left for a Mac or the server.

### 09-067: A camera card or a drive is copied as shared work, with progress and a receipt to the Footage Sorter.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The computer first fetches the list of what to copy from the server; if the Footage Sorter has none, the piece fails for good. While copying it reports files and bytes done every 30 seconds, and for a card every 2 seconds to the Sorter's page. At the end it sends a receipt of files copied, skipped, in conflict and failed, and which copier was used, marked unfinished if it stopped early; sending is tried up to 4 times, 3 seconds apart. If the receipt cannot be delivered, the copies on local drives are kept in the computer's own record to send later, and the piece fails so it can be retried: "the copy finished but the receipt could not be delivered to the dashboard". A copy that ran counts as done even when some files were skipped, conflicted or failed; the counts say so.

### 09-068: A drive is scanned as shared work, one at a time, and stops if the drive is being copied from.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: A drive is known by its serial number or volume id. A scan stops when cancelled, lost, by a studio-wide stop, at shutdown, or when a copy starts using that drive. It reports files, bytes, whether it completed and how long it took. An unfinished scan is retried unless it was cancelled or the drive is gone, being copied from, unreadable, the system drive, or no longer current.

### 09-069: Each computer has a permanent identity that survives renaming it.
- Where: editor-app / Signing in, the computer's identity and the licence
- What: The app gives the computer a random identity the first time it needs one and reports it always, so the server recognises the same computer after its name changes. It is not a credential and is not taken from the hardware. If the record of it exists but cannot be read, the app does not make a new one (a new identity would look like a new computer) and reports none until it is repaired. A Repair button in the app's settings sets the unreadable record aside and makes a new identity, or keeps the old one if it has become readable; reports use it at once without a restart.

### 09-070: An admin can ask one computer to start or stop taking shared work, or to take only some kinds, and nothing else.
- Where: fleet-jobs / Per-computer settings asked from the dashboard
- What: The server can ask a computer to change only two things: whether it takes shared work, and which kinds it takes. Anything else in the request, including wired or remote, refuses the whole request. Refusals: "this computer does not take <setting> from the dashboard", "the request named nothing to change", that taking work must be yes or no, that the kinds must be a list of kinds of work, "this computer does not know those kinds of work". A list naming every kind, or none, means every kind. The change is saved on the computer and takes effect only the next time the app starts; nothing restarts by itself. The answer is applied, refused, or failed (the settings file could not be saved); the request is repeated until answered, an answered one is never applied twice, and a failed one is tried again after 5 minutes. The editor is told: "<Who> asked this computer to stop taking fleet work / take fleet work again / take every kind of fleet work / take only these kinds of fleet work: <kinds>. It takes effect the next time CCSync starts." ("Your administrator" when no name is given). Every report tells the server which settings it accepts, the lend time, the drive-reminder time, the YouTube state when the site has YouTube downloads (downloads on, sign-in allowed, terms accepted, signed in or not), which settings are waiting for a restart (unknown when the file cannot be read), and the last answer.

### 09-071: The editor signs in to the server from the tray with their name and password.
- Where: editor-app / Signing in, the computer's identity and the licence
- What: Sign-in sends the name, password, the app's version, the operating system, the processor kind and the computer's name, and waits up to 15 seconds. When no dashboard address is set it is refused at once. Success is remembered on the computer, readable only by its user. On failure the editor sees the server's own sentence when it gives one, otherwise: "invalid username or password"; "this account is not allowed to sync -- ask an admin to add it to the 'editors' group on the NAS"; "too many sign-in attempts -- try again shortly"; "sign-in is not available on this server right now -- try again shortly"; "sign-in failed (HTTP N)"; "Not sent: the dashboard address is plain http on the internet. Ask your admin for its https address."; or the network error itself. A reply that cannot be used (often a wrong clock) shows "The server's sign-in reply couldn't be used. If this keeps happening, check this computer's clock is correct, then <how to send diagnostics>." A sign-in lasts in effect indefinitely.

### 09-072: Signing out forgets the person on that computer, and a person's own key is preferred over the studio's shared one.
- Where: accounts-privacy-legal / How a computer proves who it belongs to
- What: Signing out forgets who is signed in and the person's own key. A computer presents the signed-in person's own key when it has one, otherwise one set on the computer, otherwise the studio's shared key from the last sign-in or from its settings. A new key from a sign-in is used for the very next report.

### 09-073: The studio's site settings switch optional features and reporting for every computer, and still work offline.
- Where: whole-product / Behaviour common to all parts
- What: Each computer keeps the last copy of the studio's site settings it fetched (at install time, at least) and always works from that copy, so it starts offline. Optional features (YouTube downloads, getting round YouTube's blocking, automatic updates) are on only when the site explicitly says on; anything missing or unreadable means off. The four reporting switches are off only when the site explicitly says off. A site that cannot be reached, or an older server without site settings, changes nothing; nobody is told.
- Flag: dormant: automatic updates are off unless a site turns them on.

### 09-074: The app on the editor's computer carries the studio's brand.
- Where: whole-product / The product's names and branding
- What: Notification and dialog titles read "<studio short name, or the product name>: <what it is about>". The product name is the site's, otherwise "CC Sync". The support contact is the site's, otherwise the vendor's support address. Messages say "the <studio short name> server" or "the server", and "your <studio name> drive" or "your studio drive". The logo is the site's when given, otherwise the product's own mark. Changes are picked up when the stored site settings change.

### 09-075: Every crash of the app is written down on the computer, with secrets removed, and the server sees how many there are.
- Where: editor-app / Starting, staying running and crashing
- What: Every unexpected error in any part of the app writes a crash report on the computer, readable only by its user: when, which version, which part, whether it was the installed build, the system, the error and the last 200 lines of the app's log. Passwords, keys, secrets and sign-in details in it are replaced with "<redacted>" as far as can be told. At most 20 are kept, the oldest deleted. The server is told how many there are and the newest; diagnostics list the newest 3. Leftover reports from earlier runs are only noted in the log.

### 09-076: Crash reports can be sent to an outside crash-collection service, but no shipped build can.
- Where: editor-app / Starting, staying running and crashing
- What: A setting (off) plus an address to send to would also send each crash, with no personal data, to an outside service. No address is built in, and the part that sends is not in the installed app, so it never works.
- Flag: dormant

### 09-077: When the app dies without shutting down, the next start records it.
- Where: editor-app / Starting, staying running and crashing
- What: When the app stopped without ever starting a shutdown (a crash inside the system's own code, a forced kill, a pulled power cord), its next start writes a crash report saying "a companion (pid N, version V, started T) stopped without ever starting a shutdown", with when it was relaunched if it was, and what the system recorded at the moment of death, or a note to look in the Windows Event Log. An update hand-over is never counted.

### 09-078: The app relaunches itself after a crash, within about 10 seconds, at most three times an hour.
- Where: editor-app / Starting, staying running and crashing
- What: On installed Windows and macOS builds (never Linux, never a developer's copy), when the app dies without starting a shutdown it is started again after about 10 seconds, unless someone started it meanwhile. It is never relaunched after Quit, after an update or a manual start replaced it, or when it was ended on purpose (on Windows, ending it from the command line or closing its console). A freshly updated build that died before finishing its start is relaunched too. After 3 relaunches within an hour it is left down until the next sign-in to the computer and an admin. The relaunched app notes it was down for about 10 seconds and which relaunch this is. On macOS a Force Quit from Activity Monitor counts as a crash and is relaunched; an app killed before its watcher started is not covered. A setting (on by default) turns automatic relaunch off; then a crash leaves the computer without the app until the next sign-in.

### 09-079: An update interrupted halfway is repaired before relaunching.
- Where: releases-and-updates / Installing an update on an editor's computer
- What: If the app has died and its program is missing but the previous build is still there, the previous build is put back so there is something to start. With nothing to start, no relaunch happens.

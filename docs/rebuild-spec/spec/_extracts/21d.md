# Extract of inventory section 21d

## Items

### 21d-001: A site's identity and layout live in one settings file the person installing fills in, which never holds secrets.
- Where: server-install-and-running / Settings and secrets
- What: The settings file names the NAS, the tree's location and the server's folder on the NAS, and never a password or key. The person can point at a particular file for a run; a file named that does not exist is refused (at present with a raw error rather than a plain message, and the same for a file that cannot be read). With no settings file at all every value is blank and the first step that needs one refuses, naming it. There are deliberately no built-in defaults for the site's identity (the NAS's address, the administrator account, the storage pool and the tree): a missing one is refused with "is not configured", where to set it, and that the person should start from the example settings file. A value given for one run beats one set for the session, which beats the settings file. Yes/no values accept 1, true, yes, on and 0, false, no, off; anything unreadable falls back to the default.
- Flag: differs: a missing or broken named file gives a raw error instead of the plain one-line refusal every other setting problem gets

### 21d-002: The site's settings have these defaults.
- Where: server-install-and-running / Settings and secrets
- What:
  - Kind of NAS: TrueNAS. Synology's management port: 5001.
  - Projects folder inside the tree: "Projects". Editors' home folders: "homes" beside the tree in the storage pool.
  - Folders every new project starts with: AE, Audio/Music, Audio/Voiceover, B-roll, Interviewees, Render in Place, Subs, Youtube.
  - Shared asset folders: Assets/Luts ("the LUT library") and Assets/Stills ("the Resolve gallery"). A site that lists its own uses each path as its label.
  - The b-roll archive is Assets/B-roll Archive in the tree.
  - The account the server runs as: "broll"; the editors' group: "editors".
  - What editors may do on the NAS: only transfer files (default) or have a full shell; anything else is refused naming the two.
  - Projects: each private to its own people (default) or shared by all editors; anything else is refused naming the two.
  - Three old opt-outs, all off by default and only settable in the settings file: letting the server hold the NAS administrator's password, letting the NAS administrator be a dashboard admin, and turning off the check of the NAS's key on editors' computers.

### 21d-003: The person installing supplies the NAS administrator's password, and may supply a separate one for administrator rights and a limited key on TrueNAS.
- Where: server-install-and-running / Settings and secrets
- What: The administrator's password is required for a real run; a missing one is refused, naming what to set. The product looks first for the one meant for the site's kind of NAS and, if only the other kind's is set, uses it with a note saying so. A separate password for administrator rights may be given; otherwise the sign-in password is used. On TrueNAS a limited access key may be given instead: the NAS's management calls then need no administrator password (the remote sign-in still does), and the key's own account can be named (blank: the administrator's). A rehearsal needs no password.

### 21d-004: Typing a secret into the install command works, but the person is warned to put it in the environment instead.
- Where: server-install-and-running / Settings and secrets
- What: The warning says the secret ends up in the shell's history and the list of running programs, and to leave it off and set it in the environment. Pointing at a file holding the secret does not draw the warning. The warning names the studio's own Windows helper for loading secrets on every operating system.
- Flag: differs: the hint names a Windows tool even on a Mac

### 21d-005: Every install and maintenance step first says which NAS it is about to work on.
- Where: server-install-and-running / Installing on a NAS
- What: Once per run, before anything else (not when asking for help), the person sees one line: the administrator account and the NAS's address and port, its kind, which settings file is in use (or none), and the tree's location (or "not configured"); a missing value shows as "not configured" and an unknown kind as "unknown kind". A setting problem is refused as a single line starting "FAILED" with nothing changed. Choosing a kind of NAS the product cannot yet work with is refused the same way, before any connection is made.

### 21d-006: On TrueNAS the person is told when the NAS's version is older or newer than the product supports, without being refused.
- Where: server-install-and-running / Installing on a NAS
- What: Supported TrueNAS versions are 25.04 up to 26 (inclusive). An older one works through the older management interface but is not supported, and the person is told to upgrade. A newer one is untested, and the person is told to check the supported versions before upgrading the NAS. A version that cannot be read is said so. These are notes; any failure to ask is silent. TrueNAS 26 and later no longer have the older management interface, so the newer one must be reachable; when the NAS answers "not found" on the older interface, the person is told so.

### 21d-007: A step that changes the NAS asks the person to type the NAS's name first.
- Where: server-install-and-running / Installing on a NAS
- What: The person is told what is about to change and on which account and NAS, and asked to type the NAS's short name (the first part of its name, or the whole address when it is a number); letter case does not matter. A wrong answer stops with "Nothing was changed" and says how to skip the question. Given a confirming option up front, the step says it was confirmed and goes ahead. With no keyboard to answer on (run unattended), it is refused, telling the person to confirm up front if that is the NAS they mean or rehearse first; nothing changes. A rehearsal never asks.

### 21d-008: The product refuses to sign in to a NAS whose identity it has not been told to trust, and refuses forever once that identity changes.
- Where: server-install-and-running / Connections and credentials
- What: The remote sign-in carries the administrator's password, so the NAS's key is checked first:
  - When the site pins the NAS's key, only that key is accepted. A pin in the wrong form is refused with an example of the right one.
  - Otherwise a key recorded on the installer's computer on an earlier run is accepted, and only that one. A record that cannot be read is refused, saying to fix or delete it or pin the key instead.
  - Otherwise, when the person allowed trusting a new NAS once, the offered key is recorded and the person is told its fingerprint, that later runs are checked against it and a change is a refusal, and the exact line to paste into the site's settings to pin it.
  - Otherwise it is refused, explaining why and giving the ways forward: read the NAS's key and pin it in the site's settings or for the session, or allow trusting it once.
  - A key that has CHANGED from the pin or the record is refused with the expected and offered fingerprints, where the expected one came from, how to update it, and "Nothing was sent". It is never re-trusted on its own.
  The same "trust once" choice covers the NAS's web certificate (21d-009). The trusted key is also what editors' computers are given to check the NAS by. The administrator password is never placed where other programs on the NAS could read it.

### 21d-009: The product checks the certificate of the NAS's management interface, by fingerprint unless the site says otherwise.
- Where: server-install-and-running / Connections and credentials
- What: The certificate checked is TrueNAS's web port, or Synology's management port (5001 by default). The site can choose:
  - nothing (the default): the certificate must match a fingerprint recorded on an earlier run; with "trust once" allowed, it is recorded now and the person is told its fingerprint, that a change will be refused, and the line to paste to pin it; otherwise it is refused with three ways forward (read the fingerprint and pin it, allow trusting it once, or turn checking off). A NAS that presents no certificate, or a record that cannot be read, is refused.
  - checking off: allowed, with a warning once that the administrator's password and every account created cross that connection unchecked, and how to pin it instead;
  - the operating system's usual certificate checks;
  - an explicit fingerprint (letter case, colons and spaces ignored); a malformed one is refused, never treated as "off";
  - a certificate authority file.
  A certificate that no longer matches is refused and never re-trusted.

### 21d-010: TrueNAS revokes an access key sent over an unencrypted connection, so the product never sends one that way.
- Where: server-install-and-running / Facts about each kind of NAS
- What: Unencrypted connections to TrueNAS's management interface are refused unless the NAS is the same machine. When TrueNAS refuses the key, the person is told so, reminded that a key sent over a connection TrueNAS does not treat as secure is revoked by it, and told which account the key was presented as and how to name the right one (a key belongs to the account it was made for). A refused password says "the NAS refused the username or password". A change that may already have reached the NAS is never sent a second time after a dropped connection. Waiting for a TrueNAS task gives up after 2 minutes and reports that it did not finish.

### 21d-011: On Synology the product requires DSM 7 with every web service it installs through, and refuses rather than half-install.
- Where: server-install-and-running / Facts about each kind of NAS
- What: Before signing in, the product checks that the NAS offers each service it needs (sign-in, users, groups, group members, application permissions, file transfer, shared folders and their permissions, and shared-folder snapshots) at the version it needs. If any is missing or at another version, it refuses, listing each, because a half-installed NAS is worse than one never touched. A NAS that refuses the check itself is told not to look like DSM 7. The password is never put in a web address. Synology's answers are shown in plain words:
  - session has no privilege: almost always a session from an older sign-in;
  - session expired (signed in again once; a second expiry is reported);
  - invalid account or password; the account may not sign in to DSM;
  - needs a two-factor code, or the Snapshot Replication package is not installed;
  - no such user; user already exists; the password fails this DSM's password policy;
  - no such group; group already exists; bad or missing values;
  - any other: "DSM error" and its number.
  A rehearsal shows each call with passwords shown as redacted.

### 21d-012: Before a risky change across the whole tree, the NAS takes a snapshot, and the person is told whether the run had one behind it.
- Where: server-install-and-running / Snapshots, restoring and the server's disk
- What: Before any privileged change that reaches through a whole folder tree, a snapshot of the tree (or the path named) is taken. By default this is best effort: if there is nothing to snapshot, or the snapshot fails, the person is warned that the operation has nothing behind it and told how to set up regular snapshots, and the run continues. In strict mode (asked for by the step or set for the session) the same failures refuse the run, saying how to set up snapshots or how to accept the risk. Every attempt, rehearsals and failures included, is recorded on the installer's computer with its time, what it was for, the path and the result. Each run ends with one line: "this run had a snapshot behind it: yes", "NO (none was attempted)", or "NO" with the reason.
- Flag: differs: best effort by default, a refusal in strict mode

### 21d-013: Project names and the project's identity follow fixed rules, and a project's identity is never overwritten.
- Where: server-install-and-running / Installing on a NAS
- What: A project's year, series and name (or path) may not be empty, contain a slash, start with a dot or contain "..", and are refused naming the bad part. A project's identity is made from its name: lower case, every run of other characters turned into one hyphen; only a-z, 0-9 and hyphens are allowed, and an empty result is refused, because the identity appears in the dashboard's addresses. Each project folder carries a mark of its identity, written once. If a mark with the same identity is there it is left alone; if a mark with a DIFFERENT identity is there, it is not overwritten and the person is told the identity is permanent (every record about the project, its ticks, Resolve links, history and media list, hangs on it) and that changing it must be done deliberately. A mark that cannot be read is never taken as "no mark". Each project's NAS group is named from its identity and kept within the NAS's 32-character limit for group names (shortened, with a short code to keep it unique).

### 21d-014: The sync of a project's working files and of the shared asset folders leaves out video, unfinished downloads and proxy folders.
- Where: sync / Files that must never sync
- What: Left out, in any letter case: video files (BRAW, MOV, MP4, MXF, AVI, MTS, M2TS, MKV, R3D, CRM, MPG, MPEG, WMV, WEBM, INSV, 360), files still being transferred or downloaded, and in project folders any folder named Proxy. The shared asset folders also leave out the operating systems' clutter (macOS folder files, Windows thumbnail and folder-settings files, temporary files) but not Proxy folders. Video and proxies reach computers by their own rules.

### 21d-015: On Synology, editors' file-transfer speed settings are capped by what Synology's transfer server can carry, and over-limit values are refused, never lowered.
- Where: sync / Facts about the NAS and the operating systems
- What: Synology's transfer server silently cuts short downloads over 514 MiB when pieces bigger than 64 KiB are asked for, so on Synology a piece size over 64 KiB, a piece size that is not a size, and more than 16 transfers at once are each refused (several problems are listed together). Blank values become 64 KiB and 16. Sizes may be written like 64Ki, 64k, 1M or a plain number of bytes; every unit is 1024-based. TrueNAS has no such limits.
- Flag: differs: Synology only

### 21d-016: Resolve's shared project library gets a strong password the person never has to invent, and Resolve's well-known default is refused.
- Where: resolve-on-the-editors-computer / Project libraries and projects
- What: The person may give the password; otherwise a random 32-character one is made once, kept on the installer's computer and reused on every reinstall. "DaVinci" in any letter case is refused from any source, because anyone who can reach the library's port would have full control; the person is told to let the product make one or choose their own.

### 21d-017: The installer's computer keeps a private record of the NAS identities it trusts, the snapshots taken, and the library password it made.
- Where: server-install-and-running / Connections and credentials
- What: Kept in the installing person's own folder: the NAS keys and certificate fingerprints trusted once, the record of snapshot attempts, and the generated Resolve library password. Each can be moved elsewhere for a session. On macOS and Linux these are readable only by that person; on Windows that restriction is not applied.
- Flag: differs: not locked down on Windows

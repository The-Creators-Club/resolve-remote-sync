# Extract of inventory section 19

## Items

### 19-001: Heavy work is shared out across the studio's computers, one computer per piece of work.
- Where: fleet-jobs / Choosing who runs what
- What: The kinds of work the server can hand to editors' computers are: transcribing speech; making a small preview copy (480p) of a clip for Timeline Cards; pulling the sound out of a clip; drawing a clip's waveform; copying a camera or recorder card (started from the Footage Sorter); copying a drive; and reading a drive's contents into the record of which drives hold which copies. A piece of work is taken by exactly one computer; two computers can never both take it. Work of a kind this server does not recognise sits waiting but is never given to any computer, and its explanation says: "this dashboard does not know the job kind '<kind>', so no computer will ever be offered it".

### 19-002: Only so many pieces of each kind run across the studio at once.
- Where: fleet-jobs / Load on the NAS and the computers
- What: At most 2 transcriptions and 2 drive copies run at once across the whole studio; at most 4 at once of each other kind (preview copies, sound, waveforms, card copies, drive reads, and any kind not listed). An admin setting the server up can change the limit per kind; a value below 1 counts as 1 and a value that is not a number counts as 4. A piece of work held back by this limit is explained as "<N> <kind> job(s) are already running, which is this fleet's limit (<cap>); it starts as soon as one finishes", and starts as soon as one finishes.

### 19-003: A computer someone is using is not given work until it has been left alone long enough.
- Where: fleet-jobs / When a computer counts as free and able
- What: Before a computer is given a piece of work, nobody must have touched its keyboard or mouse for: 5 minutes for transcription and preview copies; 1 minute for pulling sound and drawing waveforms; no wait at all for card copies, drive copies and drive reads. A computer that cannot say how long it has been idle counts as somebody being at it. The reasons shown are: "this computer cannot say how long it has been idle, which counts as somebody being at it"; "somebody is at this computer (idle <N>s, <kind> needs <floor>s)"; "this computer's idle answer is unreadable". A computer set as wired to the server with nobody sitting at it never waits for idleness.

### 19-004: The person at a computer can offer it for shared work right now, until a time they choose.
- Where: fleet-jobs / When a computer counts as free and able
- What: From the app on their own computer (nothing on the dashboard can do it), a person can say "take shared work now" until a time. Until that time the computer is given any kind of work without waiting for idleness, and it becomes first choice for transcription, preview copies, sound and waveforms. It does not lift the wait after a failure or any other reason a computer is passed over. A time that cannot be read, or has passed, counts as not offered.

### 19-005: An admin can say a piece of work must start now.
- Where: fleet-jobs / Choosing who runs what
- What: Work an admin (or the Footage Sorter, for a card or drive copy) marks as "now" skips three waits only: the wait after a failure on that computer, the wait for idleness, and the one-minute wait for the best-placed computer. It still waits for a studio-wide or per-computer stop, a waiting update, a stopped proxy download, a computer already busy with other shared work, shared work switched off on the computer, and the computer's own list of kinds it accepts. The computer is told the work was marked "now" so it does not hold back because someone is using it.
- Flag: several ways in: work is pushed past the idle wait by an admin's "now", by the person at the computer offering it (19-004), and by a computer being wired to the server with nobody at it (19-003).

### 19-006: A piece of work can be meant for one named computer only.
- Where: fleet-jobs / Choosing who runs what
- What: Work can name the one computer that should do it, either by computer name (any person's computer of that name) or as person and computer together, in either letter case. Every other computer is passed over with "this job is for <target> only". Work meant for one computer is offered to it at once, with no wait for a better-placed computer.

### 19-007: A computer is only given work it can actually do.
- Where: fleet-jobs / What a computer can honestly offer
- What: Each computer tells the server what it can do: whether it has the video tools, whether it has a graphics card and how much memory it has, whether it has a hardware video encoder, how long it has been idle, how loaded it is, which shared folders it can reach, which kinds of work it accepts, whether shared work is on, and whether it is busy with its own media work. Preview copies, sound and waveforms need the video tools and need the computer to reach both the folder the clip is in and the folder the result goes in. A transcription can state a minimum amount of graphics memory. A computer that has never said what it can do (an app too old to take shared work) is passed over with "this computer has not reported what it can do". When a computer is missing a tool because its own install of that tool keeps failing, the explanation for that computer adds "the <tools> install on this computer is failing (<N> tries): <cause>" (the count only when above 1).

### 19-008: The reasons a computer is passed over for a piece of work, in the order they are asked.
- Where: fleet-jobs / When a computer counts as free and able
- What: The first of these that applies is the reason shown for that computer:
  1. the studio-wide limit for that kind is reached (19-002);
  2. the work is meant for another computer (19-006);
  3. the computer cannot do it (19-007);
  4. "syncing is stopped by your admin for the whole fleet";
  5. "this computer has not reported since <time> (<N min / N h / N days> ago), so it cannot claim anything until it is switched on": after 15 minutes of silence. A time that cannot be read is not treated as silent;
  6. "syncing is stopped on this computer";
  7. "this computer has an update waiting to apply" (an update the server has marked as undeliverable to that computer does not hold work back);
  8. "this computer's proxy download stopped itself, so it is not in a state anyone should add work to";
  9. "this computer is already holding job #<id> (<kind>)" (see 19-009);
  10. the computer has never said what it can do (19-007);
  11. "fleet jobs are switched off on this computer";
  12. "this computer's config allows only <kinds> jobs, not <kind>";
  13. "this computer is <busy with its own media work / busy indexing b-roll / busy indexing music>";
  14. "this computer is cooling down until <time> (<reason, default 'a job failed here'>)": a computer where a piece of work just failed is not given more until that time;
  15. somebody is at the computer (19-003);
  16. another computer is better placed and the one-minute wait has not run out (19-013).

### 19-009: A computer does one piece of shared work at a time, except that a drive read can run beside one other.
- Where: fleet-jobs / Load on the NAS and the computers
- What: A computer holding a piece of shared work is not given another. The one exception is reading a drive for the record of copies: a computer may hold one drive read alongside one other piece of work, but never two drive reads at once.

### 19-010: Each computer can switch shared work off, or accept only some kinds.
- Where: fleet-jobs / What a computer can honestly offer
- What: Two settings belong to each computer: shared work on or off (default on), and a list of the kinds it accepts (empty, the default, means every kind). This lets an editor keep a laptop out of one kind of work without leaving shared work altogether. The reasons shown when they apply are in 19-008.

### 19-011: Among the computers able to do a piece of work, the best-placed one is asked first, and after a minute every able computer is.
- Where: fleet-jobs / Choosing who runs what
- What: Able computers are ranked by, in order:
  1. how well suited they are to the kind: for transcription, a person offering the computer now (19-004) counts most, then a graphics card with room for the model plus 1 GB to spare (with no stated minimum, any graphics card that reports its memory), then any graphics card; for preview copies, a person offering it now, then a hardware video encoder; for sound and waveforms, a person offering it now, then being the computer wired to the server next to the media; card copies, drive copies and drive reads have no preference;
  2. holding less shared work right now;
  3. being less loaded (a computer that cannot report its load counts as unloaded, not as a penalty);
  4. having been idle longer.
  Names never break a tie. For the first 60 seconds after a piece of work is queued, only the best-ranked computers (all of them, if tied) are offered it; after that every able computer is. Work marked "now" and work meant for one computer skip this wait. If no computer is able, the wait counts as over.

### 19-012: For any waiting piece of work, an admin can see why it is not running, computer by computer.
- Where: fleet-jobs / Failures, retries and the queue
- What: For a piece of work still waiting, there is one line for every computer that has ever reported to the server. A computer passed over shows its reason (19-008). An able computer shows either "this computer can take it, and is first choice", or "this computer can take it (choice <n> of <m>; <why it lost>; <offer clause>)". Why it lost names the first thing it lost on: "the first choice has <signal words> and this computer has not", where the signal words are "somebody at it who said to take fleet jobs now", "an NVIDIA encoder", "a GPU with room for this model", "a GPU" or "is wired to the server, next to the media"; or "the first choice is better placed for this kind of work", "is holding less work right now", "is less loaded", "has been idle longer". The offer clause is "it is being offered the job now too" or "it is offered the job too in <N>s if nobody ahead of it has taken it by then".

### 19-013: Each piece of work has one overall answer to "why is this not running".
- Where: fleet-jobs / Failures, retries and the queue
- What: The overall answer, in words:
  - being done by a computer: "<person>/<computer> is holding this job (lease until <time>)";
  - handed to the server itself: see 19-015;
  - finished: "this job is done"; given up: "given up after <N> attempt(s): <last error or 'no error recorded'>"; failed for good: "this job failed and will not be retried: <last error>";
  - the studio-wide limit reached: the sentence in 19-002;
  - some computer can take it: "<N> computer(s) can take this job; it is waiting to be claimed on their next report";
  - no computer has ever reported: "no computer has ever reported to this dashboard";
  - meant for one computer that has never reported: "this job is for <target> only, and no computer of that name has ever reported to this dashboard"; meant for one that cannot take it now: "this job is for <target> only, and it cannot take it: <why>";
  - otherwise: "no computer can take this job right now: <count> of <total> <words>", naming the commonest reason, with words such as "have somebody sitting at them", "cannot do this kind of work", "have not reported in the last 15 min", "are busy with their own media work"; when the commonest reason is a missing tool and a computer's install of it is failing, it adds ". On <person>/<computer>, <cause>".
  Alongside the sentence, the answer says whether the hold-up is temporary (busy computers, the limit, waiting for idleness, cooling down, being held, handed to the server, the one named computer being away) or not (no computer able, the named computer unknown, no computer reporting). The answer also says how many computers could ever do it, and how many of the kind are running against the limit.
- Flag: differs: the temporary-or-not verdict is taken from the most hopeful reason across all computers, while the sentence names the commonest reason, so the two can point at different causes.

### 19-014: Timeline Cards keeps waiting for shared work only while the hold-up is temporary, and otherwise makes the file itself.
- Where: fleet-jobs / Failures, retries and the queue
- What: When Timeline Cards has asked for a preview copy, sound or waveform and the overall answer (19-013) says the hold-up is temporary, it keeps waiting. When it says no computer will be able to (none able, the named computer unknown, none reporting), Timeline Cards makes the file on its own instead.

### 19-015: Media work the computers kept failing at can be finished by the server itself.
- Where: fleet-jobs / Failures, retries and the queue
- What: When preview copies, sound or waveform work has used up its retries on the computers, and the server is able to do such work itself, the work is handed to the server instead of being given up. It never goes back to the computers; if it fails on the server too, it is given up with the error. Transcription is never handed to the server (the server has no graphics card for it). The server looks for such work about every 10 seconds, records progress as it goes, and when done lists the files it wrote. Explanations: "the fleet could not finish this, so it is pinned to the dashboard's own worker; it never goes back to the fleet", with ". It is waiting: no Timeline Cards episode is open on the dashboard, and it runs as soon as somebody opens one" when it is waiting. A piece handed over that can no longer be run reads: "the fleet could not finish this, and it was pinned to the dashboard's own worker, but <reason>. Nothing will run it here: cancel it and queue it again". Cancelling such work stops it; the server shutting down stops it with "this dashboard is shutting down". When the server cannot do such work, work that used up its retries is simply given up.
- Flag: dormant: in the present build this only works beside the old Timeline Cards page; with the new editor on, nothing on the server can finish such work, so it is always given up.

### 19-016: Shared work names its files relative to the studio's shared folders, so it can run on any computer, and bad output names are refused.
- Where: fleet-jobs / Results that are complete and current
- What: A piece of work names its source and its output folder as a place inside one of the studio's shared folders (the footage, the episodes folder, the project tree), never as a full path, so the same work runs on any computer whatever its drive letters. The output folder must be named ("a media job must name the directory its output goes in"). The output file name defaults to the source's own name. An output name that is a dot name, or holds a "/" or a control character, is refused when the work is queued, with a sentence saying the output name is not a plain file name: it cannot be a dot name or hold a "/" or a control character, on any computer. ":" and "\" are allowed. On the server, a place that leaves its shared folder ("'<path>' leaves its root"), a shared folder the server does not have (a sentence naming the folder the server has not been set up with), or a bad output name gives up the work with that sentence.

### 19-017: Pressing Copy on a card in the Footage Sorter starts the copy at once on the computer the card is in.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: When a person presses Copy on a camera card (or a drive) in the Footage Sorter, a piece of shared work is queued meant for that person's computer where the card sits (or the computer by name when the Sorter does not know the person), marked "now": no idle wait, no wait after a failure, no wait for a better-placed computer. It is recorded as queued by that person. The Sorter shows the copy's state, progress (updated about every 2 seconds), result and last error. A copy that has vanished from the queue reads as given up, "the job is gone from the queue". The person can cancel the copy from the Sorter. Only the computer that took the copy can fetch its file list, report progress or hand in the finished copy's receipt; another gets "this job is not claimed by you".

### 19-018: Every computer tells the server which camera cards are in its readers.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: Each computer sends the full list of camera cards currently in its readers, at most 16 cards in one report, so the Footage Sorter can show them. When the Sorter is not running on the server, the computer is told "the Footage Sorter is not running on this dashboard" and asks less often.

### 19-019: The server keeps a record of which drives hold copies of which clips, fed by every computer.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Each computer reports the drives, cards and fixed disks it has, whenever they change and every five minutes (at most 64 in one report). The record answers which of them it wants read now, and reading a drive becomes a piece of shared work on that computer (19-009). A drive is known only by its serial number; a computer cannot give it another identity. Each copy a computer makes and verifies is added to the record; reporting the same copy again does not add it twice, and the computer is told how many were new and how many already known. Each computer can fetch, for its own drives, what the record holds about them. A computer whose person's account is suspended is refused all of this. When the record is not running: "the Footage Sorter's ledger is not running on this dashboard". A drive read that is already finished or given up refuses further results.

### 19-020: While the Footage Sorter is getting ready, people wait briefly, and a Sorter that fails to load is hidden and explained.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: The Sorter loads its records after the server starts. A request made meanwhile is held for up to 2 minutes, then answered "the footage sorter is still loading: try again in a moment". If loading fails, the Sorter is removed from the menu and the server's status for it says "the footage sorter could not load its data (<error>)". When the folder the studio's footage pool lives in is not there, the Sorter does not come up and the status says the pool is not mounted. The Sorter can only use the folders the server was set up with.

### 19-021: In the Footage Sorter, only an admin may carry out a move, and every move is recorded under the name of the person signed in.
- Where: footage-sorter-and-camera-cards / Moving footage on the NAS
- What: The Sorter always knows who is signed in and whether they are an admin, from their sign-in; nobody can claim to be someone else. Only an admin may carry out a move, and the person's name goes into the Sorter's record of moves. Changes in the Sorter carry the dashboard's usual protection against another site acting on a signed-in person's behalf.

### 19-022: A move made in the Footage Sorter inside a project reaches every editor's copy.
- Where: proxies-and-file-moves / Moving footage through the product
- What: When the Sorter moves a clip that is inside the project tree, the move is made the same way as the dashboard's own "move on the server and on every machine", so every editor's computer follows it. The clip and its destination must each be inside an active CC Sync project; otherwise the move fails with "<path> is in no CC Sync project, so no editor's copy can follow it". A refusal from that move is passed back to the Sorter as the error. Moves into the project tree from outside it (for example from a transfer folder) are plain moves on the server.

### 19-023: A switchable part that is missing or broken never stops the dashboard or any other part.
- Where: whole-product / Could not check, refusals and nothing silent
- What: Timeline Cards, the b-roll archive, music, YouTube downloads and the Footage Sorter each come up on their own. If one is not set up, is missing pieces, or fails to start, the dashboard and every other part still start and work. A part that came up but cannot work (for example its data folder cannot be written) is removed from the menu rather than shown broken.

### 19-024: An admin can see, for each switchable part, whether it is off, missing, partly working or working, and why.
- Where: server-install-and-running / Health checks and alerts
- What: The server's status shows each part as off, not there, partly working (hidden from the menu) or working, with a sentence. The sentences a person meets include: the part is not switched on for this site; the part's program is not installed on the server or did not load; the folder the part needs is not reachable; "the b-roll database was written by a newer version of the b-roll app than this server runs, so no /broll page can open it" (likewise for music); the part's data folder "could not be prepared ... every request will fail until it is writable"; for Timeline Cards, which episodes are open and the editor's state (19-047). The server also keeps checking that the shared folder holding each part's data is still there, and raises a problem when it goes away.

### 19-025: Every switchable part is behind the dashboard sign-in and knows who the person is and whether they are an admin.
- Where: accounts-privacy-legal / What each person may see and reach
- What: B-roll, music, YouTube downloads, the Footage Sorter and Timeline Cards are only reachable when signed in to the dashboard. Each is told who is signed in, and b-roll, music and the Sorter are told whether the person is an admin; nobody can pass themselves off as someone else, and a sign-in that the server has withdrawn is not honoured. YouTube downloads use the person to decide which projects a download may go into and whose downloads they may see.
- Flag: differs: YouTube downloads are told who the person is but not whether they are an admin.

### 19-026: A suspended or barred person is not recognised by the switchable parts, nor is their computer.
- Where: accounts-privacy-legal / Suspending, disabling and removing a person
- What: B-roll, music and YouTube downloads do not recognise a suspended or barred person. Requests from that person's computer (for example sending a clip from b-roll, or downloading a YouTube video on the editor's own computer) are not accepted as coming from a studio computer. When the account's state cannot be read, the computer is not blocked.

### 19-027: A person whose sign-in name has characters outside Western European letters is refused by several parts.
- Where: accounts-privacy-legal / What each person may see and reach
- What: B-roll, music, YouTube downloads and the Footage Sorter cannot be told the name of a person whose sign-in name uses characters beyond Western European letters (for example Chinese). Such a person is treated as not signed in by those parts (b-roll refuses them), and their computer is not recognised either. Nobody is told why.

### 19-028: The YouTube downloader can be switched on or off for the site while the server runs, taking effect within 5 seconds.
- Where: youtube / Keeping the downloader working
- What: Switching YouTube downloads on or off in the site's settings takes effect within 5 seconds, with no restart. Off: every YouTube address answers "Not Found" and the part's status says "this site has not enabled the YouTube downloader". Switched on while running: the next visit brings it up. If bringing it up fails, it is not tried again for a minute, and meanwhile the addresses answer "Not Found". If the downloader could not be loaded at all when the server started, switching it on later does nothing until the server is updated. The YouTube link appears in the menu only while the part is working.
- Flag: differs: the other switchable parts (Timeline Cards, the Footage Sorter, b-roll, music) are switched on when the server is set up and do not change while it runs.

### 19-029: Downloads left half-done by a server restart are picked up again.
- Where: youtube / Jobs on the page: queue, retry, cancel
- What: When the YouTube part comes up, downloads that a restart interrupted are recovered and continue.

### 19-030: A periodic test download can check that YouTube downloads still work, but is off.
- Where: youtube / Keeping the downloader working
- What: The downloader can run a test download at a set interval to notice when YouTube has started refusing it. It ships switched off and does nothing until an interval is set.
- Flag: dormant

### 19-031: The server's own checks include the health of the YouTube downloader.
- Where: youtube / Keeping the downloader working
- What: While YouTube downloads are working or partly working, the server's self-checks and alerts can see how old the download tool is, whether the help YouTube now demands for downloads is in place, whether a YouTube sign-in is set, when the last download happened, the result of the test download, whether the assistant is reachable, and whether downloading is alive. When the part is off, none of this is checked.

### 19-032: YouTube downloads use the site's assistant settings, and a changed key applies at once.
- Where: youtube / The assistant behind search
- What: The two places YouTube downloads use the assistant follow the site's assistant settings, read fresh each time, so a key entered or changed in settings applies to the next search with no restart.

### 19-033: A person's YouTube records can be exported, their history erased, or the person removed, whether or not downloads are switched on.
- Where: accounts-privacy-legal / What the product records about a person
- What: The account-privacy features reach the YouTube records too, even while downloads are switched off. Export: everything held about the person. Erase history: deletes the person's finished downloads with their search terms and videos, but keeps the record that stops the same video being downloaded twice, the person's rights statements, and anything still running; it says how many were removed. Delete a person: stops and cancels their unfinished downloads, and replaces their name and their computers' names with the dashboard's stand-in name, all at once. It is refused when no stand-in name can be made. Failures are told as "the YouTube downloader's records could not be opened / read", "the YouTube downloader's history could not be erased" or "the YouTube downloader's records could not be updated".

### 19-034: B-roll does not come up unless the admin has set a strong secret for adding clips to the index.
- Where: server-install-and-running / Settings and secrets
- What: Adding clips to the b-roll index needs a secret the admin sets on the server, and it is required always, even from a signed-in person. B-roll is not brought up, and the server will not start with b-roll on, when the secret is missing, is a well-known placeholder word (such as "changeme", "secret", "password", "token", "test"), is shorter than 24 characters, or has fewer than 8 different characters. The status says "no usable ... is configured, so the b-roll ingest write path cannot be guarded".

### 19-035: Anyone signed in can add tracks to the music library by dropping them in.
- Where: music / Adding tracks to the library
- What: Dropping tracks into the music page adds them for any signed-in person; no separate key is needed.

### 19-036: Timeline Cards finds every episode in the studio's episodes folder by itself.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: Any folder that holds an "Interviewees" or a "Clips" folder is an episode. Episodes are looked for up to four folder levels below the episodes folder (the episodes folder itself counts if it is one); a folder that is an episode is not looked into further; hidden folders (starting with ".") and unreadable folders are skipped. Each episode has a name (its folder), a show (the folder above) and a last-changed date. The list is sorted by show then name, ignoring letter case, and a new episode appears within about 30 seconds.

### 19-037: The Timeline Cards episode list shows every episode as a folder tree, with who opened what and when.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: The page lists every episode as a folder tree with a count per folder (levels every episode shares are left out, but at least one is kept); folders holding something the reader has opened are shown unfolded. Above it, "recent": up to 5 episodes this person opened, newest first; and a filter by year. Each episode shows its folder path; its year (from a year folder above it, otherwise its last-changed date); "you opened it <ago>", "<name> opened it <ago>", "somebody opened it <ago>" or "never opened"; its size, marked "partial" when it could not all be counted; and its last-changed date written like "3 Sep 2026". Ago is "just now" (under 90 seconds), "<N> min ago", "<N> h ago", "<N> d ago" (under 60 days), then "<N> mo ago". Sizes are in B and KB with no decimals, MB, GB and TB with one. If the record of who opened what cannot be read, the list still shows without it. A person whose display name is "you", "somebody", "nobody" or "someone" is shown by their sign-in name instead.

### 19-038: Episode sizes are counted in the background and kept fresh for about 12 hours.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: Each episode's size (bytes, file count, newest change) is counted one episode at a time in the background, oldest first, and counted again after 12 hours. Counting stops after 400,000 files and folders and marks the size partial; an unreadable folder inside also marks it partial. If the episode folder itself cannot be read, the last good size stays.

### 19-039: The episode list offers to carry on with the episode this browser last opened.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: "Carry on with ..." names the last episode opened in this browser, remembered for 90 days. It is updated whenever the person opens an episode.
- Flag: several ways in: the last episode is offered both as "carry on" (per browser) and at the top of "recent" (per person).

### 19-040: Opening an episode goes straight into the editor at that episode's newest cut list.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: Pressing Open on an episode records it as opened by this person, remembers it for "carry on", and takes them into the editor at the newest cut list in the episode's cuts folder (by last change; hidden files ignored). An episode with no cut list, or outside the episodes folder, opens the editor's own start sheet. An episode that is not in the episodes folder is refused, back on the list, with a sentence saying the episode is not in the episodes folder; when Timeline Cards is not running, "Timeline Cards is not mounted". Who opened what is recorded per person (when each person last opened each episode, and who opened each one last).

### 19-041: Each episode has a stable address, and links people saved to the old Timeline Cards page lead into the editor.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: An episode's address is made from a readable form of its folder name (plain letters and digits, at most 32 characters) and a short code from its full path, ignoring letter case and the two ways a Mac and Windows can spell the same accented name. The same episode has the same address on every computer and after every restart, so it can be bookmarked; a name with no Latin letters gets the code alone. Opening a saved link to an episode on the old Timeline Cards page takes the person into the editor for that episode; anything else at an old address is told "The old Timeline Cards page is retired. Open the episode from the Timeline Cards page.", with a link back to the episode list.

### 19-042: Timeline Cards can be installed on a phone as its own app, which opens on the episode list.
- Where: cards-editor / Phone and game controller
- What: Timeline Cards can be added to a phone's home screen as an app called "Timeline Cards" (short name "Cards"), opening full-screen without browser bars. Whichever Timeline Cards page it is installed from, the one app opens on the episode list. Its icon is the Timeline Cards mark, shaped to fit any phone's icon style. Installing it does not need a sign-in.

### 19-043: When the editor is starting or not running, a person is told so, and that their cut lists are untouched.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: Opening the editor while it is starting shows a page headed "Timeline Cards is starting", which reloads itself every 4 seconds; while it cannot run, "Timeline Cards is not running". Both give the reason, the line "Your cut lists are untouched.", and a link "Back to the Timeline Cards page". The reasons an admin might read there are, in plain terms: Timeline Cards is not installed on this server, or its editor is missing from what was installed; the episodes folder is not set or not reachable; the server lacks what it needs to run the editor; the editor's working folder cannot be made. Anything else that fails to reach the editor answers "the editor did not answer".

### 19-044: The editor comes back by itself if it stops, and picks up a missing piece without a restart.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: If the editor stops, it is started again after about a second, waiting longer after each quick failure, up to a minute; after five quick failures in a row it is shown as failing and tried at most every 5 minutes. Once it has stayed up for a minute the count starts over. An editor that never becomes reachable within 2 minutes of starting is stopped and started again. While something the editor needs is missing, it is looked for again every 30 seconds, so installing it brings the editor up with no restart of the server.

### 19-045: When the server stops, every open cut list is saved first.
- Where: cards-editor / Editing, undo and the cut list
- What: When the server is stopped or restarted, the editor is given 15 seconds to save every open cut list before it is stopped. The editor works directly on the episode's own files on the NAS.

### 19-046: The editor is only for signed-in people, and its live connection checks this itself.
- Where: cards-editor / Working offline, connections and several devices
- What: Every page and file of the editor needs a dashboard sign-in ("login required" otherwise). The editor is told who the person is (their sign-in name, up to 120 characters). The editor's live connection, which keeps several devices in step, is refused when there is no sign-in or it comes from another site, and is closed with a "try again later" answer when the editor is not running. Video and audio play and seek normally through the server; a stream a browser has abandoned stops at once.

### 19-047: An admin can see the editor's state, restarts and last exit.
- Where: server-install-and-running / Health checks and alerts
- What: The server's status shows the editor as not started or stopped, missing something (with the first missing thing), starting, running, waiting to restart, or failing repeatedly (still retrying, slowly). It shows how many times it has been restarted and its last exit, with "the editor exited (exit <code> after <N>s); starting it again in <N>s. Last output: <...>" (the last three lines it wrote) or "the editor could not be started (<error>); trying again in <N>s".

### 19-048: Timeline Cards drives each editor's own Resolve for the episode that editor is in, through that editor's own computer sign-in.
- Where: cards-to-resolve-and-exports / Which computer is driving Resolve
- What: The app on an editor's computer drives that editor's Resolve for Timeline Cards, talking to Timeline Cards through the server with the computer's own credential; Timeline Cards' own secret is never put on an editor's computer. An editor's Resolve follows the episode the editor last opened as a page; other activity (playing media, polling) moves it only when the editor has not opened the previous episode's page for 2 minutes. The computer is shown as "<person>/<computer>". When the editor is in no episode, the computer is told "<person> is not in a Timeline Cards episode on this dashboard: open one" on the episode list "and this agent attaches to it", and waits up to 25 seconds for one to be opened before being told again. A problem inside Timeline Cards comes back as a sentence, never a crash. Resolve activity that changes something (a timeline sent, the playhead moved, the result of an edit) also counts as the editor being in that episode.
- Flag: undetermined: in the present build this only works beside the old Timeline Cards page; with the new editor on, every such call is told the editor is in no episode, and how the new editor reaches an editor's Resolve is not in this section.

### 19-049: Timeline Cards' assistant features say plainly when the assistant cannot be used, and why.
- Where: whole-product / The assistant
- What: Searching transcripts by meaning, section summaries, montage conversations and the edit chat use the site's assistant. They work only with the assistant they were written for: if the site has chosen another provider, every call fails with "this site's AI provider is <label>, and Timeline Cards' translate, semantic search and summaries are written for <the assistant>", telling the admin to set its key or pin it in settings. With no provider at all, the reason given is "no provider has a working credential". A dimmed button's tooltip says why: the provider is not the right one, or that the assistant has not been checked on this server yet and the admin should test it in the assistant settings. Finding this out never costs a call. Failures (a key refused for a model, a model not known, no answer in time, the assistant exiting) come back to the page as a sentence, never a crash.
- Flag: undetermined: this is how the old Timeline Cards page reaches the assistant; the new editor reaches it its own way, not described in this section.

### 19-050: Choosing a model family always uses that family's newest model, and naming an exact model pins it.
- Where: whole-product / The assistant
- What: The model the person picks comes from the page. Picking a family name uses the newest model in that family, so the choice moves forward by itself when a newer one is released; naming an exact dated model, or a family version older than the newest one seen, keeps exactly that model. The list of models offered follows what the site's assistant actually has. What each family name last turned out to mean is remembered.

### 19-051: The edit chat sees the cards that are selected and the ones staged on the shelf.
- Where: cards-editor / Shortening, the edit chat and the assistant
- What: When the person asks the assistant about the cut, the cards selected now, and those staged on the shelf, are given to it in the order selected, each with its label, person, timecode, text (up to 120 characters) and section, group and lane (up to 80). Beyond 40 cards the rest are named only.

### 19-052: A montage conversation with the assistant remembers its recent turns, and says so when it has lost them.
- Where: cards-editor / Shortening, the edit chat and the assistant
- What: A conversation keeps the material it was started with plus its most recent turns, 40 turns in all, dropped in whole question-and-answer pairs. Starting a conversation again replaces the old one. When a conversation has been lost, the next turn says so, once, and the page decides whether to send the material again. When the assistant must answer with structured data, a reply that holds none, or holds unreadable data, is reported as such with the end of the reply.

- Duplicate of: none
- Reasoning: the mechanism is real - `blind=len(errors) + refused` is computed over the whole 8-project window (`collector.py:1799`), a missing project dir and a marker-less dir are both durable, and on a fleet of 8 or fewer active projects every pass is blind, so `db.mark_notice_checked("file_move_detected", now)` never runs again while detection does run over the readable projects. But the rendered consequence the finding is titled for is not what the panel does. `ui._notices_context` passes `checked_kinds` as a SET (`ui.py:1634`) and `templates/partials/notice_checks.html` tests membership only - the timestamp is never read by anything. Worth saying in the ledger: the same reading means CR-285's blind skip is a no-op on every established fleet, since a stale stamp and a fresh one render identically.

## dash-core-1
- Verdict: CONFIRMED
- Duplicate of: none (dash-core-2 is the other defect in the same handler, same cause)
- Reasoning: I reproduced the double entry independently on the venv's starlette 1.6.0 - a parent FastAPI with `add_exception_handler(Exception, h)` and a mounted sub-app carrying the same handler calls `h` twice for one request into the sub-app and once for a parent route, because `ServerErrorMiddleware` runs the handler, sends its response and then re-raises, so the parent's copy catches the same exception and runs the same handler again. `unhandled_error` logs `log.exception` and then `_record_off_the_loop(...)` unconditionally, so every failure under `/broll`, `/music` and `/ytdl` logs twice and performs two connect-write-close cycles against the database whose contention the notice exists to report. Nothing between the two entries suppresses the second: the scope carries no marker, and `notices.record_db_busy` upserts a count.
- Evidence: scratch script under the dashboard venv - `sub status 503 calls ['/sub/boom', '/sub/boom']` vs `parent status 503 calls ['/pboom']`, starlette 1.6.0, fastapi 0.141.1 (both as pinned in `dashboard/requirements.lock`).
- Fix note: the suggested per-request scope flag is right and cheap; put it in the wrapper `_install_busy_handler_on_mounts` builds rather than in `unhandled_error`, so a parent-route error keeps its single record without a flag read. It must still RETURN the response on the second entry (Starlette requires a response object even though it is discarded). `tests/test_bug_hunt_2026_09_18_dashboard_mediums.py::test_a_mounted_sub_app_answers_a_busy_database_with_the_same_503` asserts the status only and will keep passing; a new test should count `notices` rows / the `N time(s)` body, and it should be the same test that pins dash-core-2's subject.

## dash-core-2
- Verdict: CONFIRMED (conclusion), with the hunter's mechanism and suggested fix both WRONG
- Duplicate of: none
- Reasoning: the finding's premise is out of date. On starlette 1.6.0 a `Mount` does NOT strip the prefix from `scope["path"]`; it sets `root_path` and leaves the full path in place, and `URL(scope=scope)` uses `scope["path"]` verbatim - my repro shows `request.url.path == '/sub/boom'` with `root_path == '/sub'` in both handler entries. So `request.url.path` is correct and `redact_path`'s two-segment fallback would have kept `/broll/api/…`. The prefix is nevertheless lost, by a different road that only exists because of wire-2: now that the handler runs INSIDE the sub-app, `scope["route"]` is the sub-app's own `APIRoute`, so `route_path` is the INNER template and `redact_path` returns it unchanged (`route` wins over `path`). The collision is real too, and worse than the hunter argued: `/broll` and `/music` expose twelve identical inner templates, including every `/batches/{uid}/...` ingest route, so one row and one count serve two features.
- Evidence: scratch script on the venv - parent mounting a sub-app at `/broll` with an inner `/api/ingest` route gives, for both handler entries, `url.path='/broll/api/ingest'`, `scope['route'].path='/api/ingest'`, `notices.redact_path(...) -> '/api/ingest'`. `comm -12` over the two web packages' route decorators lists `/`, `/precheck`, `/{uid}`, `/{uid}/cancel`, `/{uid}/retry-failed`, `/{uid}/upload-paused` and the six `/batches/...` routes as shared templates.
- Fix note: do NOT apply the suggested `request.scope.get("root_path", "") + request.url.path` - on this starlette that yields `/broll/broll/api/ingest`. The correct fix is to prefix the ROUTE template instead: `route_path = (scope.get("root_path") or "") + getattr(route_obj, "path", "")` when a route matched, leaving the untouched `redact_path` fallback for an unmatched request. `notices.redact_path`'s docstring is also now wrong ("route is absent for an exception raised inside a MOUNTED SUB-APP") and must be corrected in the same change, and the 120-character truncation in `redact_path` still applies after the prefix.

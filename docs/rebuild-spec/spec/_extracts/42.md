# Extract of inventory section 42

## Items

### 42-001: A timeline can be read back out of Resolve's project library without Resolve running.
- Where: cards-to-resolve-and-exports / Bringing Resolve's changes back into the cut
- What: The product can read an edit straight out of the studio's Resolve project library, whether Resolve is running, closed, or on a computer that is asleep, and without ever starting Resolve or touching its scripting. What it gets for a timeline: its name, its project's name, its frame rate and whether it is drop frame, its start, when it was last changed, every cut on the first video track (V1) in timeline order, and the timeline markers. For each cut: where it starts on the timeline and how long it is (in timeline frames), which clip it uses and that clip's name, where in the clip it starts (in the clip's own frames), the clip's own frame rate, the cut's clip colour, and the audio fade-in and fade-out of its audio on the first audio track (A1). For each marker: its frame, colour, name, note and duration (at least one frame).
  Everything read is the state at Resolve's last save: work not yet saved in a running Resolve is invisible.
  Limits a person meets: cuts on any video track other than V1 are not read (even when V1 is empty and the cuts sit on V2); audio is consulted only for fades; a fade, colour or marker that cannot be understood reads as "none" rather than stopping the read; a marker list that exists but cannot be understood reads as "unknown", so markers known from elsewhere are kept rather than wiped.
  A read is refused, with a message naming what is wrong, when the timeline does not exist in that library, has no content or no video track, a cut's position is not a number, or the timeline's frame rate is not between 1 and 1000 frames per second.

### 42-002: A change to a timeline in Resolve is noticed within a couple of seconds of Resolve saving it.
- Where: cards-to-resolve-and-exports / Bringing Resolve's changes back into the cut
- What: The product can watch a timeline in the project library cheaply enough to check every couple of seconds, and re-reads it as soon as anything about it changes after a save in Resolve. A change that touches only tracks other than V1, and leaves the number of V1 cuts, the latest V1 start and the largest V1 source start alone, is not noticed.

### 42-003: Libraries, projects and timelines can be listed, with the timeline that was open at the last save marked.
- Where: resolve-on-the-editors-computer / Project libraries and projects
- What: The product can list every project library on the studio's library server (sorted by name), every project in a library (with which timeline was open at its last save, and when it was last changed; sorted by name), and every timeline of a project in Resolve's own order, each with when it was last changed, whether it is the one open at the last save ("current" means open at the LAST SAVE, not open now), and whether it is a helper. The helper timelines that building a multicam leaves behind (one per camera angle, and the syncing ones) are still listed but marked so a picker can put them lower.

### 42-004: Facts about Resolve's project library that the product relies on.
- Where: resolve-on-the-editors-computer / Project libraries and projects
- What: Givens about DaVinci Resolve, whatever is built:
  - Resolve keeps its projects in a project library; a library server can hold several libraries, each holding many projects, each with many timelines. Two projects in one library can hold clips of the same name.
  - What the library holds is what Resolve last saved; unsaved work in a running Resolve is not there.
  - When a Resolve has a project open, the library records that it is open and by which Resolve.
  - A Resolve that has a timeline open never re-reads it, so a change made to that timeline behind its back silently diverges from what the editor sees and may be overwritten.
  - In a Resolve timeline each cut is a video piece on V1 and an audio piece on A1 that Resolve keeps linked to each other.
  - A clip in the media pool may be a plain file, a multicam clip, a compound clip, or a timeline used as a clip. Each video track of a multicam is one angle; the lowest is Angle 1.
  - A cut's clip colour is one of 16 named colours: Green, Teal, Blue, Purple, Pink, Tan, Brown, Apricot, Beige, Chocolate, Lime, Navy, Olive, Orange, Violet, Yellow (or none).
  - Marker colours are 16 named colours: Blue, Cyan, Green, Yellow, Red, Pink, Purple, Fuchsia, Rose, Lavender, Sky, Mint, Lemon, Sand, Cocoa, Cream.
  - Resolve keeps at most one timeline marker per frame.
  - Resolve itself has been seen to give a cut's source start one frame differently depending on where it is read from (about a quarter of the cuts on one measured timeline).
- Flag: undetermined: eight of the clip colour names (Purple, Apricot, Beige, Lime, Navy, Olive, Orange, Yellow) and the whole marker colour order were never checked against a real Resolve; a wrong one shows a cut or marker in the wrong colour.

### 42-005: Drop-frame timecode and start timecode are read the way Resolve counts them.
- Where: cards-to-resolve-and-exports / Frames, frame rates and timecode
- What: A frame rate is a decimal number (for example 29.97002997) plus whether it is drop frame. Drop-frame timecode at 29.97 skips 2 frame numbers each minute except every tenth minute; at 59.94 it skips 4. A clip's start timecode is turned into nominal seconds, so 01:00:00;00 is exactly one hour even at 29.97; transcript timing uses the same nominal seconds. Frame rates anywhere strictly between 1 and 1000 frames per second are accepted. Mixed clip and timeline rates are handled by converting and rounding to whole frames.
- Flag: undetermined: a drop-frame rate other than the 29.97 and 59.94 families is treated as dropping 2 frames, unchecked.

### 42-006: The clips of a project, their files, frame rates, start timecodes and multicam angles can be read from the library.
- Where: resolve-on-the-editors-computer / Project libraries and projects
- What: For a project the product can list its media pool clips (plain video files first, then the rest, each by name), and for every clip in the library its file as it is now, so a relink done in Resolve is reflected (audio-only clips, timelines and compound clips have none). For one clip it can tell its name, frame rate and start timecode: a multicam or compound clip takes these from the edit it is made of; a plain clip with an unreadable start is taken to start at 01:00:00:00; a clip with no stored rate (seen on downloaded YouTube clips) takes them from its video, or is unknown. For a multicam it can list each angle's cuts (with file, clip rate and whether the piece carries a speed change; the speed itself is not known). The audio of a multicam is not read. Resolve's own transcription of a clip can be read from the library too.

### 42-007: A cut can be written into a brand-new timeline in the project library, without Resolve.
- Where: cards-to-resolve-and-exports / Sending a cut to Resolve
- What: Given a library, a project, a new timeline name and a cut list (for each cut: which clip, which source frames, how much black before it, and optionally a clip colour, markers on its first frame, a note for the black gap before it, and audio fade-in and fade-out), the product builds a new timeline in that project straight in the library. Nothing existing is changed: only the new timeline and its media pool entry are added (placed at the end of the bin that holds the template timeline, and at the end of the project's timeline list), and the project's last-changed time moves.
  Where each cut lands: cuts butt end to end in list order from the timeline's start, each after its black gap (a negative gap counts as none); each cut lasts its source length converted from the clip's rate to the timeline's rate and rounded to a whole frame, never less than 1 frame.
  The new timeline always has exactly one video track and one audio track, and each cut is a linked video and audio pair.
- Flag: dev only: reachable today from a command line, and from the Timeline Cards server only when a library has been allowed for writing; refused for every real library (42-013).

### 42-008: A conformed cut takes its multicam angle and speed from a cut of the same clip already in the project, and arrives ungraded.
- Where: cards-to-resolve-and-exports / Placing, deleting and linking clips in Resolve
- What: Each new cut is copied from an existing linked cut of the same clip in that project (preferably one on the template timeline, otherwise the earliest one). So a multicam cut shows whatever angle that existing cut showed, and the cut list cannot choose the angle; a speed change on that existing cut is copied to every new cut of the clip. New cuts arrive with no colour grade, no effects, no Fusion composition and no per-cut markers; only the audio fade asked for is put on. A clip that has never been on a timeline in the project, or whose cuts there are not linked video and audio, cannot be conformed at all. Audio-only clips cannot be conformed.

### 42-009: Decision made on the person's behalf: which existing timeline the new timeline copies its settings from.
- Where: cards-to-resolve-and-exports / Sending a cut to Resolve
- What: The new timeline's frame rate, drop frame, start timecode and every other timeline setting are copied from a template timeline in the same project. It is chosen, in this order: the one the person named; else the timeline that was open at the project's last save; else the first non-helper timeline in project order; else the first timeline. The template's first video track and first audio track set the new timeline's tracks, whatever else the template has. A named template that does not exist is refused.

### 42-010: Decision made on the person's behalf: which frame rate a clip is taken to have when placing it.
- Where: cards-to-resolve-and-exports / Frames, frame rates and timecode
- What: To work out a cut's length on the timeline, the clip's own rate is used where it can be read; failing that, the rate stored on the existing cut it is copied from; failing that, the timeline's rate.

### 42-011: Each conformed cut can carry a clip colour and an audio fade.
- Where: cards-to-resolve-and-exports / Undo, markers, titles, fades and properties
- What: A cut that names a clip colour gets it (it must be one of Resolve's 16, or the whole conform is refused); a cut with no colour keeps the colour of the cut it was copied from. Audio fades are put on the audio of the cut only, in whole timeline frames (rounded), never negative and never not-a-number (else refused), each shortened to the cut's own length if longer; fade-in and fade-out together may still be longer than the cut. Zero means no fade. Video fades are never written.

### 42-012: Markers and gap notes on a conformed timeline, and what the person is told when one is dropped.
- Where: cards-to-resolve-and-exports / Undo, markers, titles, fades and properties
- What: Each cut's markers go on its first frame; extra timeline markers go on their own frames. Marker colours are matched ignoring case; an unknown colour becomes Blue; duration is at least one frame. A note on a black gap of at least one frame becomes a Green marker spanning the gap, named with the note text (runs of spaces collapsed) and noted "Gap note from Timeline Cards (N.N s)" with the gap's length; if the gap's first frame already has a marker it moves one frame in and becomes a frame shorter; if no frame is free it is dropped. Gap notes are placed after every other marker so other markers never move. Because Resolve keeps one marker per frame, a second marker for a used frame is dropped. The person is told, in one sentence, how many markers were dropped for wanting a used frame, how many gap notes found no free frame, and that a marker's hidden custom data is not carried.

### 42-013: The product never writes a cut straight into one of the studio's real project libraries.
- Where: cards-to-resolve-and-exports / Sending a cut to Resolve
- What: Writing into a library is refused unless that library is on a list of libraries allowed for writing, which is empty by default (so nothing can be written until an admin names one). Even when allowed, a conform or an in-place edit into any of the studio's real libraries is refused, telling the person that a library holding real work is never written into since the first such write (into a real episode) left 63 half-linked clips that crash Resolve, and to conform through Resolve or into the sandbox copy instead. Only a sandbox library can receive one. Undoing and deleting (42-016, 42-017) are still allowed into a real library that is on the list, and the person is warned at start-up when a real library is on it.
- Flag: dev only: the allowed-libraries list is set only where the server is installed, not on any page.

### 42-014: A conform or in-place edit is refused, with a reason, before anything is written.
- Where: cards-to-resolve-and-exports / Sending a cut to Resolve
- What: Every check runs before any write, and a refusal writes nothing. The person is told:
  - the library is not allowed for writing (naming the ones that are), or is a real library;
  - the new timeline has no name, or the project already has a timeline of exactly that name (case counts): "pick another name";
  - the cut list is empty;
  - there is no project of that name, or several share it ("refusing to guess which");
  - the project is open in a Resolve, which never re-reads a timeline it holds, so the write would silently diverge: close the project (or let the product close and reopen it) and try again;
  - the project has no timeline to copy settings from, or the template lacks a video or audio track;
  - a cut has no clip; a clip has never been on a timeline in this project, or its cuts there are not linked (every such clip is named);
  - per cut, numbered from 1 and naming the person speaking: no usable source frames, an empty span (start not before end), a start before the clip begins, an end past the end of a multicam or compound clip (plain files are not checked for their end), an unknown clip colour, a fade that is not a number or is negative.

### 42-015: A write to the library lands whole or not at all, and is checked before it counts.
- Where: cards-to-resolve-and-exports / Sending a cut to Resolve
- What: The whole timeline (or the whole edit) is written at once and read back before it counts: name, rate, start, number of cuts, each cut's place, length, source start and clip, every video piece still linked to its audio piece both ways with the same place and length, the cuts' order, no two cuts overlapping, and the marker count. Any disagreement throws the whole write away and the person is told "did not read back as planned, so nothing was written", with the first eight problems and how many more. When it succeeds the person is told the new timeline's name, number of cuts, length in frames and seconds, number of markers and the marker sentence, gap notes written and dropped, which template was used, how many cuts arrived ungraded or without effects, how many were recoloured, how many carry an audio fade, where the undo record is, and how long it took.

### 42-016: Every write to the library leaves an undo record, kept for good.
- Where: cards-to-resolve-and-exports / Undo, markers, titles, fades and properties
- What: Just before a conform or an in-place edit counts, a dated undo record is kept naming the library, project, timeline and everything added, changed or removed (removed cuts in full, grades and all, and every cut's place before the edit). Nothing ever deletes these records. Undoing from one puts the library back: for a conform it deletes the timeline it made; for an edit it removes what was added, puts back what was removed with its grades intact, and restores every changed value, then re-reads the timeline and confirms every cut is back where it was ("reads back exactly as it was"); if not, the person is told the undo ran but the timeline does not read back as before, naming the first six problems, and must look by hand. A conform's undo is refused while the project is open in a Resolve; an edit's undo makes no such check and runs even with the project open. If the timeline a conform made is already gone, the undo says so and carries on.
- Flag: differs: undoing a conform checks whether the project is open, undoing an in-place edit does not.

### 42-017: A timeline the product made in the library can be deleted, with refusals that protect other timelines.
- Where: cards-to-resolve-and-exports / Undo, markers, titles, fades and properties
- What: Deleting a timeline removes it and everything that belongs only to it, closes up the project's timeline list and the bin so there are no holes, and keeps the "open at last save" pointer on the right timeline (or none if it was the deleted one). Refused, with the reason, when: the library is not allowed; the project is missing or ambiguous; the project is open and no override is given; the timeline is not in the project; it is the project's current timeline while the project is open (even with the override); it is used as a clip on other timelines; or another timeline shares its content or its media pool clip. If anything would still hang off the deleted timeline afterwards, everything is put back. By name, when several timelines share it, the first in project order is deleted. No undo record is kept for a delete.

### 42-018: Whether a project is open in a Resolve can be checked.
- Where: resolve-on-the-editors-computer / Knowing which project is open
- What: The product can tell, from the library alone, whether a project is open in some Resolve and which one, or that nobody has it open. Reading this needs no permission to write.

### 42-019: An existing timeline can be made to match a cut list in place, leaving untouched cuts exactly as they were.
- Where: cards-to-resolve-and-exports / Edits sent live and staged edits
- What: The product can rewrite an existing timeline in the library so it becomes a cut list, reproducing the end result of the edits made in Timeline Cards without replaying them. Each cut ends up one of: kept (nothing about it written; its grade, effects and colour stay), moved (only its start changes), trimmed (its source start or length changes, at the head or tail, or extended within the clip), new (no existing cut could be reused: a fresh linked pair copied from the first existing cut of the same clip on this timeline, so a multicam insert inherits that cut's angle and speed, or from the project-wide template when the timeline has none), or removed. A split is one kept or trimmed half plus one new half. Separately, a cut whose audio fade differs gets only its audio fade changed; every other effect and the clip volume on that audio stay. A cut that was on the timeline and is untouched in the cut list stays exactly as it was, even if the cut list's own arithmetic is a frame off. New cuts arrive ungraded and without effects, as in a conform.
  Before writing, the person can ask for a plan: the counts of kept, moved, trimmed, new, removed, faded and banked cuts and how many shifted, with nothing written (allowed on any library). A dry run does the whole write and check, then throws it away. When the timeline already is the cut list (and any markers asked for are identical), nothing is written and the person is told "already IS this cut list: nothing to write".
- Flag: dev only: reachable from a command line and from the Timeline Cards server; refused for every real library (42-013).

### 42-020: Decision made on the person's behalf: which existing cut each cut of the list is.
- Where: cards-to-resolve-and-exports / Edits sent live and staged edits
- What: Each existing cut is reused at most once and only for the same clip. A cut the list says came from a particular existing cut (by trimming or splitting it) is matched to that cut first. The rest, in list order: an existing cut with exactly the same source span; then one whose span contains it (a trim); then one whose span merely overlaps it (an extend). Ties go to the existing cut nearest where the cut must land, then the earlier one. Anything inserted from a transcript, or a clip the timeline never had, becomes a new cut.

### 42-021: Cuts removed by an in-place edit are kept on an OffCuts timeline rather than lost.
- Where: cards-to-resolve-and-exports / Edits sent live and staged edits
- What: By default, every cut the edit removes is first copied (same clip, same source span, same length, same angle) onto the project's OffCuts timeline (found by name, ignoring case), placed end to end after whatever is already there, at the same length in frames even if OffCuts runs at another frame rate. The person can turn this off, in which case removed cuts are simply deleted, and can name another timeline instead of OffCuts. Only when something is actually removed is the person refused with a reason if: the project has no timeline of that name (it is never created: make it in Resolve, or discard the cuts instead); several timelines share the name; the timeline being edited IS that timeline; or it has no linked video and audio pair to place after.

### 42-022: Which timelines an in-place edit refuses, and what it does not change.
- Where: cards-to-resolve-and-exports / Edits sent live and staged edits
- What: Refused, with the reason, before anything is written, besides every refusal of a conform that applies (42-014): the timeline is not in the project; it lacks a video or audio track; it has cuts on more than one video track ("multi-track is out of scope"); any video cut has no linked audio; the audio is spread over more than one track; the video and audio cut counts differ; or the cut list would empty the timeline. A cut's clip colour is checked but never applied in place: kept, moved and trimmed cuts keep their colour, new ones copy the colour of the cut they were copied from. Existing markers never move to follow moved cuts.
- Flag: differs: a conform applies each cut's colour; an in-place edit ignores it.

### 42-023: Asking an in-place edit to set markers fails outright.
- Where: cards-to-resolve-and-exports / Edits sent live and staged edits
- What: When any markers are passed with an in-place edit (including the gap notes, which only become markers that way), both the plan and the write stop with an internal error before anything is written; a person at the command line sees a raw error trace. So markers and gap notes cannot be set by an in-place edit today. An empty marker list is meant to delete the timeline's markers.
- Flag: undetermined: whether Timeline Cards ever passes markers to an in-place edit.

### 42-024: The limits of what the product understands in a Resolve timeline it reads or writes directly.
- Where: cards-to-resolve-and-exports / Placing, deleting and linking clips in Resolve
- What: Cuts are read from V1 and fades from A1 only; a conform builds V1 and A1 only; an in-place edit only accepts a timeline whose cuts are all on one video track, each linked to audio on one audio track. Transitions are neither read nor written. Speed changes are only noticed, copied unchanged onto new cuts, never set. Fades are audio only, in whole frames. Grades and effects stay on cuts that are kept, moved or trimmed, and are absent on every new cut. Only timeline markers are handled; per-cut markers are cleared on new cuts; a marker's hidden custom data is lost. Where something is not understood the person gets either a refusal sentence, a raw error trace (an unreadable record met outside the checks), or a silent fallback while reading (unknown colour or fade reads as none, an unreadable cut rate makes that piece skipped).
- Flag: undetermined: only one Resolve version (21.0.1) is cited for how the library is laid out.

### 42-025: The library tools are command lines for the people building the product.
- Where: cards-to-resolve-and-exports / Sending a cut to Resolve
- What: Reading, conforming, deleting, checking whether a project is open, planning, applying and undoing an in-place edit are each reachable from a command line, taking the library, project, timeline name or id, and a cut list file, and printing the result. A read-only listing shows every library, each project with the timeline open at its last save, and each timeline with its last-changed time. A refusal is printed after "REFUSED" and the command fails; a missing argument prints the usage; anything else unexpected (an unreadable library record, an unreachable library server) ends in a raw error trace.
- Flag: dev only

### 42-026: Preparation checks that the editing program's own transcription has not silently dropped a stretch.
- Where: cards-footage-in / Facts about Resolve's own transcription
- What: Fact about Resolve: its transcription can silently drop a section of speech (a cut-off end, or a passage in the middle) with no error and no visible seam. Preparation must catch this: a stretch with no words that is unusually long for that interview (judged against that interview's own usual gap between lines, not a fixed number), a thinned stretch (few words per minute), and an end that stops short of the recording's length. Listening to the sound tells a real gap in the transcript from a genuine pause in speech. The missing stretches are transcribed again so their text is not lost. Timing must be compared in the same time base as the transcript (the edit's time, which normally starts at 01:00:00:00), never against a source clip with a different time base.

### 42-027: Decision made on the person's behalf: whether a stretch of the transcript is missing, and what its text is.
- Where: cards-footage-in / Running on its own, with a hand on every decision
- What: Decided from the gaps between transcribed words compared with that interview's own usual gap, the density of words per minute, the last word compared with the recording's length, and whether there is voice in the sound during the gap. Also decided: the text put into a missing stretch, from transcribing that stretch again.
- Flag: undetermined: today the recovered text is only shown; nothing says where it goes, and the check is not required before preparation continues.

### 42-028: Every interview becomes a transcript broken into paragraphs, one point each.
- Where: cards-footage-in / The transcript and its English
- What: Preparation turns a run-on transcription into paragraphs, the units that later become cards. Rules it must get right:
  - one interviewer question per paragraph;
  - one coherent answer point per paragraph; places where the transcription broke a sentence with an ellipsis marker are joined back (marker dropped, pieces joined with a space);
  - off-topic chatter (sound checks, a door closing, talk about translating) goes in its own small paragraphs;
  - about 1 to 6 sentences per paragraph;
  - aim for about 20 seconds of speech per paragraph (about 90 Mandarin characters or 50 English words), and never more than 60 seconds: a long answer is split even when it is one point, at its own internal turns (a new example, a move from problem to solution, a "but", a change of subject);
  - a paragraph that would be longer than 60 seconds is refused, never let through.
  A well-paragraphed interview of about an hour comes out at 60 to 200 paragraphs, the middle one about 10 to 30 seconds of tape; far fewer means it was split too coarsely and must be split further. The person is told how many paragraphs each interviewee's transcript came to.

### 42-029: Decision made on the person's behalf: where each paragraph begins and ends.
- Where: cards-footage-in / Running on its own, with a hand on every decision
- What: Decided from the transcript's text and its timing, by the rules in 42-028 (one question or one answer point, the 20-second aim and 60-second ceiling, splits at the answer's own turns). Splitting a paragraph that is already on the board must not lose its place there.

### 42-030: Decision made on the person's behalf: which paragraphs are the interviewer's questions.
- Where: cards-footage-in / Running on its own, with a hand on every decision
- What: Every paragraph that is an interviewer's question is marked as a question, in both its languages. Decided from the transcript's content (the questions are buried in the run-on text). The mark matters later: a question travels with the answer it sets up.

### 42-031: Decision made on the person's behalf: which paragraphs are off-topic chatter.
- Where: cards-footage-in / Running on its own, with a hand on every decision
- What: Sound checks, door noise, filming and scheduling logistics, restarts, goodbyes and talk about translating are put in their own paragraphs and treated as non-content, decided from the content. They are left out of the themes later (42-041).

### 42-032: A Mandarin interview gets an English translation of every paragraph; the original words are never corrected.
- Where: cards-footage-in / The transcript and its English
- What: For an interview not in English, each paragraph carries an English translation alongside the original. An English interview stays English only. The original-language text must stay character for character what was transcribed, including mishearings (a misheard place or name stays misheard), because each paragraph's words must still be found at their exact times in the recording; corrections go only in the English. Simplified or traditional Chinese characters are kept exactly as transcribed, never converted. The same holds for misheard names and terms in English interviews.

### 42-033: Decision made on the person's behalf: the English of each paragraph, and whether an interview needs one.
- Where: cards-footage-in / Running on its own, with a hand on every decision
- What: Decided from the original text: whether the interview is in a language that needs an English translation, and the English text of each paragraph, including the correction of anything the transcription misheard (put only in the English).

### 42-034: Decision made on the person's behalf: which interviewee a transcript belongs to, and whether they are already prepared.
- Where: cards-footage-in / Running on its own, with a hand on every decision
- What: Each transcript is filed to one interviewee; an interviewee whose transcript is already prepared is not prepared again; a prepared transcript is never overwritten. Decided from which interviewee's footage it came from. An interviewee may have more than one transcript (a second session): all of them count, none is silently ignored.

### 42-035: The assistant proposes themes for an episode, by the owner's rules.
- Where: cards-board / The owner's editorial rules
- What: From every paragraph of every interviewee (an episode runs to about 300 to 700 paragraphs), the assistant proposes the themes the film could be built from, without yet placing any paragraph. Rules:
  - at most 25 themes, fewer is fine; two are always present: **Personal Stories** (how each contributor came to this, who they are) and **Ending** (the closing beat: what it was all for, the next generation, where this leaves us), so at most 23 come from the content;
  - broad homes for material, not narrow topics: the test is how much of the episode fits;
  - two candidates that would draw on the same passages are one theme;
  - each should plausibly hold 20 or more paragraphs from 2 or more interviewees; less is a detail inside a bigger theme;
  - 80 or more paragraphs suggests two stories under one label: look for the seam and propose two (100 or more is almost always two or three);
  - one interviewee's large story (a campaign, a place, an event) is a valid theme when it can carry a section;
  - short, punchy names;
  - if every paragraph were placed now, most should land somewhere; if many would not, merge and try again.
  Each proposed theme has a name, a one- or two-sentence description and honest evidence (how many interviewees and about how many paragraphs, and whose). The list is ordered strongest first (most paragraphs, then most interviewees); that order is only for choosing, not the film's order.

### 42-036: Decision made on the person's behalf: which themes are proposed, and how many the person is asked to pick.
- Where: cards-board / What the assistant may do
- What: The themes, their names, descriptions and evidence counts are decided by the assistant from the paragraphs (42-035). A suggested number of themes to keep is also given (the example is 18; no rule for it is stated). The person then picks any number, may rename any, and may add their own themes with a description; the assistant never makes the pick itself.

### 42-037: Every paragraph is placed in exactly one theme, by the owner's rules.
- Where: cards-board / The owner's editorial rules
- What: After the themes are chosen, every paragraph goes to exactly one theme: none twice, none thrown away; one that fits two goes to the single most relevant. Place aggressively: a serviceable home beats a leftover. Judge on substance, from either language. A theme the person typed in is treated exactly like a proposed one, matched on the person's description (or its name when the description is thin). A theme the person renamed keeps the material it was proposed with. Leftovers go to **Uncategorised**, shown last; the person is told how many paragraphs were placed against how many exist (it must read all of them), how many landed in Uncategorised, and plainly when that is more than 10% of the episode.

### 42-038: Decision made on the person's behalf: which theme each paragraph goes into.
- Where: cards-board / What the assistant may do
- What: Decided from the paragraph's substance (in either language) against each chosen theme's description or name, choosing the single most relevant.

### 42-039: An interviewer's question sits with the answer it sets up.
- Where: cards-board / The owner's editorial rules
- What: A question goes into the same theme as the answer it sets up, directly above it. Only a question that sets nothing up ("Could you repeat that?", "Shall we start again?", "Do you want some water?") goes to Uncategorised. Questions are kept, not dropped (a deliberate change from the studio's older planning).

### 42-040: Decision made on the person's behalf: which answer each question belongs to.
- Where: cards-board / What the assistant may do
- What: Decided from the content: the answer a question sets up, or that it sets up nothing and is non-content.

### 42-041: Decision made on the person's behalf: what is non-content and goes to Uncategorised.
- Where: cards-board / What the assistant may do
- What: Uncategorised is for non-content only (sound checks, door noise, filming and scheduling logistics, restarts, goodbyes, and questions that set nothing up), decided from the content; anything that is content gets a theme.

### 42-042: Within a theme, paragraphs run as a story; themes run in the order a viewer should meet them.
- Where: cards-board / The owner's editorial rules
- What: Within a theme, paragraphs are ordered as a story (setup, detail, punchline), not in transcript order, and that order is kept within each interviewee's group in the theme. Themes are ordered: Personal Stories (the opening) first, then the body themes in the order a viewer should meet them (context before consequence, problem before response, a specific case before what it means), never by size, then Ending, then Uncategorised last. Each theme is opening, body or ending; Personal Stories and Ending are recognised by name. The person is told why the middle themes run in the chosen order.

### 42-043: Decision made on the person's behalf: the story order within each theme, and the order of the themes.
- Where: cards-board / What the assistant may do
- What: Decided by the assistant from the content: the order of paragraphs within each theme, whether each theme is opening, body or ending, and the order of the body themes.

### 42-044: On the board each interviewee has their own colour, and a theme groups its cards by interviewee.
- Where: cards-board / Cards on the board
- What: Within a theme, cards are grouped by interviewee, each group kept to a short column (about 8 to 10 cards high, wrapping into further columns), and every card is coloured by its interviewee from a fixed set, with a legend saying which colour is whom. An interviewee keeps the same colour on a board when more of their material is added. The interviewee is recognised from their folder of footage, not from the transcript's file name. Card heights are only an estimate.
- Flag: undetermined: the present product gives both 8 and 10 as the column height.

### 42-045: Decision made on the person's behalf: each interviewee's colour.
- Where: cards-board / What the assistant may do
- What: Each interviewee is given a colour from a fixed set when first placed on a board, and keeps it.

### 42-046: A later interview can be added to a board already in use without rebuilding it.
- Where: cards-board / Working the board by hand
- What: A board being worked on is never rebuilt from scratch, because that throws away the person's arrangement. An interview that arrives later is prepared first, then its paragraphs are added either all into one theme or split across themes as listed (anything not listed is not placed, and is not swept into Uncategorised). Chatter can be left out. Paragraphs already on the board are skipped, so adding again is safe. The person can preview before anything changes. The added cards go beside the theme's existing cards without overlapping anything, and the board refuses the change if they would overlap. A copy of the board from before the change is kept.

### 42-047: Timeline Cards can also run stand-alone on the NAS, with the Resolve-driving part on the editing computer.
- Where: server-install-and-running / Installing on a NAS
- What: Besides running inside the dashboard, Timeline Cards can be installed as its own app on the NAS, reachable only on the studio network and the private remote-access network addresses the admin sets (a blank address publishes nothing, never everything). The part that drives Resolve stays on the editing computer and connects to it with a shared secret; the app refuses to start without that secret, refuses when the episode folder does not exist, refuses when writing to a library is allowed but no library is named, and warns when the episode folder cannot be written. It reports itself healthy whether or not the editing computer is connected. In this form the page's own restart button and saving a different root folder do not work; the admin restarts it from the NAS. Without an assistant credential, translation, semantic search and summaries fail on first use, and only the app's start-up messages say so.
- Flag: built twice: this duplicates Timeline Cards inside the dashboard.

### 42-048: The stand-alone Timeline Cards can require a per-device browser key, and without one anyone who reaches it can drive Resolve.
- Where: accounts-privacy-legal / What each person may see and reach
- What: In the stand-alone form there is no sign-in. If a browser key is set, each device opens the page once with the key and is let in from then on. If none is set, every device that can reach the app's address gets the page, and through it can drive Resolve on the editing computer; the start-up messages say so.
- Flag: built twice: the dashboard form sits behind the dashboard's sign-in instead.

### 42-049: Installing the stand-alone Timeline Cards checks everything first and installs nothing on its own.
- Where: server-install-and-running / Installing on a NAS
- What: The install helper by default only checks the admin's site answers and shows what would be installed, touching no network; a second mode also checks the NAS can be reached; a third copies the program to the NAS and then prints the steps the admin takes by hand (build, set folder ownership, install through the NAS's custom-app screen, open the page, start the Resolve-driving part on the editing computer with the same secret). Nothing is built, installed, started or stopped by the helper. It refuses to go on while any answer is missing, and shows every secret only as "set (N characters, ending ...)" or "unset". A missing secret is not a refusal: the file is written with a placeholder and a warning. It reaches the NAS only when the NAS's identity key is already known AND equals the one pinned in the site answers; a changed key is refused ("somebody re-imaged the NAS, or is answering for it; do not re-trust it from here"), with no way to override.
- Flag: differs: a missing shared secret only warns, while every other missing answer refuses.

### 42-050: Fact about TrueNAS: its custom-app install from a pasted definition does no filling-in and cannot build images.
- Where: server-install-and-running / Installing on a NAS
- What: TrueNAS's "Install via YAML" custom app takes the definition exactly as pasted: it substitutes no values and cannot build an image, so anything site-specific must already be filled in and any image already built on the NAS before the admin pastes it.

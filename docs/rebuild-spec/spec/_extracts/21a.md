# Extract of inventory section 21a

## Items

### 21a-001: The person installing the server says which of the two kinds of NAS the studio owns, TrueNAS or Synology.
- Where: server-install-and-running / Installing on a NAS
- What: The product supports exactly two kinds of NAS: TrueNAS and Synology. The kind is given by the person installing it, or comes from the site's settings; when nothing says otherwise it is TrueNAS. Any other kind is refused with a message naming the two that are accepted. Both kinds are fully supported; neither is refused as unfinished. A step that one kind of NAS does not allow to be automated is refused with a message that tells the person what to do instead (by hand, on the NAS's own screens).

### 21a-002: Every install step on the NAS can be rehearsed first, showing what it would do and changing nothing.
- Where: server-install-and-running / Installing on a NAS
- What: A rehearsal prints each change it would make on the NAS and answers as a real run would, without touching the NAS. In a rehearsal, "is the server already installed?" is always answered "not installed". On TrueNAS, rehearsing the steps that look up, create, update or lock down an editor's account does not work: the rehearsal fails partway instead of printing its plan.
- Flag: differs: on TrueNAS the account steps cannot be rehearsed; on Synology they can

### 21a-003: The server can only be installed into a folder of the expected shape on the NAS, and anything else is refused before anything moves.
- Where: server-install-and-running / Installing on a NAS
- What: Installing replaces everything in the server's app folder, so a mistyped folder is refused before anything changes. On TrueNAS the folder must be the product's own folder inside the apps area of a storage pool (or a folder below it). On Synology it must be the product's own folder inside a shared folder on a volume (or below it), and the refusal tells the person to use a folder of that shape, which defaults to the app folder named in the site's settings.

### 21a-004: Before installing, the product checks whether the server is already on the NAS, and says so when it cannot tell.
- Where: server-install-and-running / Installing on a NAS
- What: The answer is installed, not installed, or "could not tell". "Could not tell" comes with the NAS's own reason (the NAS refused the question, or answered with something unreadable), and is never treated as "not installed".

### 21a-005: Reinstalling the server from scratch never deletes what the server has stored.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: When the person asks for a fresh install over an existing one, the old installation is taken down first, but the server's stored data (its database and everything else it keeps on the NAS) is always kept. On TrueNAS the product waits up to 3 minutes for the NAS to finish removing the old installation. A failure to take it down is reported with the NAS's reason and stops the reinstall.

### 21a-006: Installing the server on TrueNAS goes through the NAS's own apps system and waits for it, with a by-hand fallback when it fails.
- Where: server-install-and-running / Installing on a NAS
- What: On TrueNAS the server is installed as an app in the NAS's own apps system. The person is told the install was accepted and that downloading the server can take a few minutes; the product waits up to 15 minutes for it to finish. On failure the person is told the NAS's reason and given a fallback: install it by hand from the TrueNAS apps screen, pasting the server's app description and filling in two secrets. If the server was told to listen on an address the NAS does not have, the install fails at this point with "cannot assign requested address", and the person is told to look at the app on the TrueNAS apps screen, where a half-created app may need deleting. If the NAS accepts the install without giving anything to wait on, the person is told to confirm on the TrueNAS apps screen that the server is actually running before going on, and the install carries on.

### 21a-007: Installing the server on Synology uploads its files, puts them in place, starts it and shows the state of each part, with a by-hand fallback when starting fails.
- Where: server-install-and-running / Installing on a NAS
- What: On Synology the server's files are uploaded to a holding folder first; if the upload fails the person is told nothing was changed on the NAS. They are then put in place so that only the NAS's administrator can read the file holding the secrets. The person is told starting can take a few minutes while the server is downloaded; the product waits up to 30 minutes. After it starts, the person sees one line per running part with its state. If it fails to start, the person is shown the command to run by hand on the NAS. A rehearsal prints the plan and the port the server would answer on.

### 21a-008: The server keeps its secrets, including the NAS administrator's password, on the NAS, and some characters cannot be used in them on Synology.
- Where: server-install-and-running / Settings and secrets
- What: On Synology the server's secrets (its session secret, the computers' report key, the sync key, the b-roll intake key and the NAS administrator's password) are kept in one file on the NAS, readable only by the NAS's administrator, headed with a warning that it must not be copied anywhere. A secret containing a line break or a single quote is refused. When it is the NAS administrator's password, the person is told to set one without that character on Synology's user screen (Control Panel, User & Group) and run the install again; for any other secret they are told to replace it with a fresh random one.

### 21a-009: An admin can restart the server on either kind of NAS, and a failure to reach the NAS is reported rather than crashing.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: A restart restarts only the server itself. If the NAS cannot be reached, the restart reports a failure the caller can show, rather than stopping with an error. A rehearsal counts as success.

### 21a-010: The person installing can read which build of the server the NAS is running right now.
- Where: server-install-and-running / Updates, restarts and rollbacks
- What: The answer comes from the running server on the NAS, not from the site's settings, and is read-only. When it cannot be read the answer is blank, never a guess.

### 21a-011: On TrueNAS the server must be given both of the addresses it answers on; on Synology both are optional and it never listens on every address.
- Where: server-install-and-running / Connections and credentials
- What: The server answers on an address on the studio's own network and an address on the studio's private network. On TrueNAS both must be given (in the site's settings or by the person installing); a missing one is refused with a message saying where to set it, and that there are deliberately no built-in defaults for the site's own identity (its host, storage pool and tree). On Synology both are optional: blank ones are skipped, and with neither the server can be reached only from the NAS itself. Synology refuses "every address" in any spelling, because Synology's own web server holds the network ports and editors reach the server through the private network's publishing or Synology's own reverse proxy; the refusal tells the person to bind it to the NAS itself or a specific address. TrueNAS has no such check.
- Flag: differs: TrueNAS requires both addresses and accepts any; Synology makes both optional and refuses every-address

### 21a-012: On Synology every account, the administrator included, sees only the shared folders when it transfers files to the NAS.
- Where: server-install-and-running / Connections and credentials
- What: Synology shows a file-transfer connection its shared folders as the top level, without the volume they live on, and nothing outside them (the system's temporary folder cannot be reached). On TrueNAS a path on the NAS is the same path over a file-transfer connection.

### 21a-013: The server runs as a dedicated account on the NAS: made by hand on TrueNAS, made automatically on Synology.
- Where: server-install-and-running / Connections and credentials
- What: On TrueNAS the account is created once, by hand, when the storage pool is built; the product refuses to create it and says so, and the server runs with the user and group numbers in the site's settings (3000 and 3001 by default). On Synology the product creates the account if it is missing (it cannot sign in interactively, its password is random and never kept) and reports its number, or says it already exists. It refuses to run the server as an account numbered outside 1024 to 169999, because Synology's own accounts start at 1024 and its package accounts at 170000. If the site names the shared folder holding the tree, the account is given its own read-write access to it; if that fails the person is told and the install goes on. If the account is in the editors' group it is taken out, because it is not an editor, and the person is told if it is still listed after that.
- Flag: differs: created by hand on TrueNAS, by the product on Synology

### 21a-014: The install makes sure the NAS has an editors' group, creating it if needed.
- Where: server-install-and-running / Installing on a NAS
- What: The group is called "editors" unless the site's settings name another. If it exists the person is told it was left alone; otherwise it is created and reported with its number. On TrueNAS the new group is also enabled for Windows file sharing. On Synology new groups are numbered from 65536, and a group created by someone else in the meantime is accepted. Any failure to read or create the group stops the install with the NAS's reason. On Synology, adding an account to a group can report success while doing nothing, so membership is always read back and the step fails, saying so, when the account is not there.

### 21a-015: Looking up an editor's account on the NAS follows each NAS's own rules.
- Where: server-install-and-running / Connections and credentials
- What: On Synology account names match regardless of letter case, an account counts as locked when it has expired, and editors' accounts never have an interactive shell. Synology can sometimes report an existing account as missing when asked for it by name, so the product finds accounts by listing them. A failure to look an account up stops the step with the NAS's reason.

### 21a-016: The install creates an editor's account on the NAS with a random password and the editor's computer's sign-in key.
- Where: server-install-and-running / Connections and credentials
- What: Each editor gets an account on the NAS, in the editors' group, with a home folder, a random password the editor never needs, and the key their computer signs in to the NAS with. The key replaces any key already there rather than being added beside it. On TrueNAS the account is enabled for Windows file sharing and, by default, may only transfer files; a site may instead give editors a full shell, and any other choice of that setting is refused naming the two allowed. On Synology:
  - Refused before anything is created: Synology's built-in account names (admin, guest, anonymous, root, system, http, in any letter case); names starting "sc-", which look like Synology package accounts; an existing account numbered outside 1024 to 169999; and an existing account not in the editors' group, which the product will not take over (the person is told to add it to the group on the NAS first or pick another name).
  - The random password meets Synology's rule of mixed case and a digit; it never expires, no e-mail is sent and the editor may change it.
  - If Synology says the name exists but does not list it as an ordinary account, the person is told it is probably a package account and to pick another name.
  - The account's home folder must exist: if Synology's "User Home" service is off, the step is refused and the person is told to turn it on (Control Panel, User & Group, Advanced) and run it again.
  - Every Synology account's main group is the NAS's "users" group; the editors' group is an extra one.
  - The key is read back after it is written, and the step fails if it is not there.
  - New Synology accounts can never transfer anything but files, whatever the site's shell setting says.

### 21a-017: Running the install again for an existing editor re-adds them to the editors' group and replaces their key.
- Where: server-install-and-running / Connections and credentials
- What: On both kinds the editor's computer key is replaced. On Synology the same refusals as for a new account apply, worded as refusing to modify the account, and group membership is read back.

### 21a-018: Editors' accounts sign in by key only, which each NAS achieves differently.
- Where: server-install-and-running / Connections and credentials
- What: On TrueNAS the product asks the NAS to switch off password sign-in for the account; TrueNAS refuses this for accounts that use Windows file sharing, and that refusal is expected and reported as such. Synology has no such switch: the account's password is used only for Windows file sharing and the dashboard's sign-in, and sign-in by key is the only way the editor's computer reaches the NAS.
- Flag: differs: TrueNAS can be asked and may refuse; Synology has nothing to ask

### 21a-019: On Synology editors can never have an interactive shell; on TrueNAS a site may give them one.
- Where: server-install-and-running / Connections and credentials
- What: Synology offers interactive sign-in only to its administrators. Asking for anything but file-transfer-only for an editor on Synology is refused, telling the person to leave the setting at file-transfer-only on a Synology site. On TrueNAS an existing editor's shell can be changed when moving older accounts over; if TrueNAS refuses the shell's name, the person is pointed at the NAS's own list of allowed shells.
- Flag: differs: Synology refuses, TrueNAS allows

### 21a-020: The install can list the NAS's editor accounts on TrueNAS; on Synology the listing always fails.
- Where: server-install-and-running / Connections and credentials
- What: On TrueNAS the listing is every account in the editors' group. On Synology it is meant to list the editors' group's members, but in a real run it always fails; it is used only when moving older accounts over. On Synology, asking for the members of a group that does not exist answers that there are no editor accounts yet.
- Flag: unreachable: on Synology the listing always fails

### 21a-021: When an editor leaves, their computer's key is removed from the NAS and their account can be locked.
- Where: server-install-and-running / Connections and credentials
- What: On both kinds the editor's key is removed so their computer can no longer reach the NAS. When locking is asked for, TrueNAS locks the account and Synology expires it at once. On Synology, if the key was removed but the account could not be expired, the person is told exactly that.

### 21a-022: On TrueNAS, editors' connections to the NAS are limited to file transfer; on Synology the NAS already limits them.
- Where: server-install-and-running / Connections and credentials
- What: On TrueNAS the product adds rules for the editors' group to the NAS's sign-in service: file transfer only, no password sign-in, no forwarding or tunnels, no terminal. The administrator's own settings in that service are kept, and an unchanged rule set is reported as unchanged. Editors are not confined to one folder by these rules: what they can reach is governed by the folders' permissions. On Synology nothing is added: editors cannot sign in interactively, interactive sign-in is for administrators only, and the person is told to keep Synology's file-transfer service on and its terminal access restricted (Control Panel, Terminal and SNMP).
- Flag: differs: TrueNAS needs rules added; Synology needs none

### 21a-023: An editor's key sign-in is refused by the NAS when their home folder's permissions are too open, and the install sets and checks them.
- Where: server-install-and-running / Connections and credentials
- What: Both kinds of NAS refuse key sign-in when the editor's home folder (or, on Synology, the hidden folder and file holding the key) can be written by anyone but the editor, or is not owned by them. The install sets the permissions and then checks them, warning the person when the NAS will still refuse.
  - On TrueNAS the home folder is made the editor's alone, with any extra access rules removed. The NAS's sign-in log records such a refusal.
  - On Synology the home folder itself must never have its permissions changed by hand, because that deletes Synology's access rules on it; only the hidden key folder (editor only) and the key file (editor read-write only) are set. Synology logs nothing for this refusal: the editor only sees "Authentication failed". The person is told to repair the key folder directly and the home folder by having Synology re-apply inherited access, never by changing its mode.
- Flag: differs: what is changed, and whether the NAS says why it refused

### 21a-024: On Synology the install turns on the NAS's file-transfer service and checks no rule denies it to editors.
- Where: server-install-and-running / Connections and credentials
- What: With Synology's file-transfer service off, an editor's key sign-in succeeds and the connection is then closed, with nothing in any log. The install turns the service on (on port 22 unless the site says otherwise) and says so, or reports it already on with its port. Synology grants file transfer to everyone by default, but an "application privilege" rule can deny it: a rule denying it to everyone or to the editors' group stops the install, telling the person to remove it on Synology's Application Privileges screen; rules for single accounts or other groups are not checked. If the rules cannot be read, the person is told to check that screen by hand and the install goes on. On TrueNAS there is nothing to turn on.
- Flag: differs: Synology only

### 21a-025: On Synology the install creates the shared folder for the project tree; on TrueNAS it must be made by hand.
- Where: server-install-and-running / Installing on a NAS
- What: On TrueNAS the product refuses and tells the person to create the storage area and the Windows file share on the TrueNAS screens. On Synology a shared folder is always a top-level folder on a volume, so its name and path must agree; a path of another shape is refused saying why. An existing shared folder is left alone and reported. A new one is created with copy-on-write storage on (needed for snapshots), the recycle bin off, compression off, not hidden, described as the product's tree. The editors' group is then given read-write access, read back and refused if Synology does not show it as writable; that access is what every folder and file below inherits.
- Flag: differs: Synology only

### 21a-026: On TrueNAS the project tree is owned by the editors' group, and one editor cannot delete another's project folder.
- Where: server-install-and-running / Installing on a NAS
- What: Everything in the tree is given to the editors' group (or, when each project has its own group, to that project's group). The folders above each project are protected so that one editor cannot delete another editor's project folder, and every folder makes new files inside it belong to the same group. If the storage area forbids those permission changes, the person is told that the protection or the group inheritance is missing and why it was blocked, the ownership is still correct, and the install goes on.

### 21a-027: On Synology the project tree's permissions come from Synology's own inherited access rules, and the install never changes modes or owners.
- Where: server-install-and-running / Installing on a NAS
- What: The install checks that the tree carries an inherited rule letting the editors' group read, write and delete. If it is missing it first has Synology re-apply inheritance, and only then adds the rule itself, reporting which it did. If a folder has lost its Synology access rules (Synology calls this "Linux mode", caused by anything changing its mode or owner), the person is warned that new files there inherit nothing and land writable by everyone, because Synology's file transfer creates files with no restriction, and told how to repair it. When each project has its own group, the project's group is given access, but the person is always told that the share-wide editors' rule still reaches that folder and still lets every editor in: they must break inheritance on that folder by hand in Synology's File Station and remove the editors' entry, because Synology offers no scripted way. The folders above each project are not protected against deletion on Synology.
- Flag: differs: per-project privacy needs a step by hand on Synology, and project folders are not protected against other editors

### 21a-028: A check of a Synology tree folder's access rules exists but nothing runs it.
- Where: server-install-and-running / Shares that go away, and checks that cannot run
- What: For a folder it answers one of: could not read its rules; its Synology rules are gone (it was changed by hand) with the repair; no rule lets editors write there, with the repair; or intact. TrueNAS has no equivalent.
- Flag: unreachable

### 21a-029: A snapshot is taken before anything risky, following each NAS's own rules about what can be snapshotted and how it is named.
- Where: server-install-and-running / Snapshots, restoring and the server's disk
- What: On TrueNAS a snapshot is of a storage area (a dataset) on a pool: a folder not on a pool is refused, and a folder that is not its own storage area causes the one containing it to be snapshotted, and the person is told so. The snapshot is named with a "pre" prefix, a label (by default "manual") and the date and time; a name may contain only letters, digits and - _ . : and must start with a letter or digit. A snapshot that already exists under that name counts as taken. On Synology a snapshot is of a whole shared folder: a path not inside one is refused. Synology names snapshots by the clock itself, so the label becomes the snapshot's description. On both, the person is told what was snapshotted and when, or the NAS's reason it failed.
- Flag: differs: what is snapshotted and how it is named

### 21a-030: The existing snapshots of the tree or the app folder can be listed.
- Where: server-install-and-running / Snapshots, restoring and the server's disk
- What: On TrueNAS the list is oldest first and shows each snapshot's name, the space it uses and when it was made. On Synology it shows when each was made, no space used, in no guaranteed order. A failure to list is reported and gives an empty list.
- Flag: differs: order and space shown

### 21a-031: The install sets up regular snapshots: fully on TrueNAS, and on Synology only when the snapshot package is present, otherwise with steps to do by hand.
- Where: server-install-and-running / Snapshots, restoring and the server's disk
- What: On TrueNAS snapshots can only be scheduled for a storage area of its own: a whole pool is refused (it would snapshot everything on it), and a folder that is only a plain folder in a pool is told it has no snapshot protection of its own and to make it a storage area first. Each kind of regular snapshot is created, corrected or left alone and reported as such, with how long it is kept; snapshots are taken even when nothing changed. On Synology only an hour and minute of the day and a number of snapshots to keep are used (the other parts of the schedule are ignored), the result is always reported as created, never as corrected or unchanged, and if Synology will not schedule from outside the person is given the steps by hand: install Synology's free "Snapshot Replication" package, schedule the share every hour and every day, keep 24 hourly and 30 daily snapshots, do the same for the share holding the server's app, and check that the snapshots appear.
- Flag: differs: TrueNAS is complete and repeatable; Synology may need steps by hand and always reports "created"

### 21a-032: The state of the NAS's connection to the studio's private network can be read on both kinds of NAS.
- Where: server-install-and-running / Health checks and alerts
- What: On TrueNAS the private network runs as one of the NAS's apps; on Synology it is a Synology package. The product reads its status from whichever is there.

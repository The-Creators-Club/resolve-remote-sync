## Questions for the owner

### releases-and-updates-Q1: Should the editor's "install this update" stay in both the app's menu and its settings window?
- Kind: several ways in
- Today: an offered update can be installed from a menu item and from a button in the app's settings window. Both open the same confirmation.
- Options: A: keep both (the menu for quick use, the settings window because it holds everything about this computer). B: only the menu.
- Recommend: A, because it is one action reached from the two places an editor looks, with one confirmation behind both.
- Changes for a person: with B, an editor who lives in the settings window must go to the menu to update.
- Text assumes: A
- Items: 04-017, 09-039, 01-075
- Answered by the owner 2026-11-24: A: keep both, the menu and the settings window

### releases-and-updates-Q2: Which ways of putting a new version on an editor's computer stay?
- Kind: several ways in
- Today: a new version reaches a computer by the editor's click, by an admin's push, by the studio's unattended updates, by a hand-run upgrade on Windows, and by running the installer again.
- Options: A: keep the app's own update (started by the editor, by an admin's push, or by the unattended setting) and the installer for setting a computer up, and drop the separate hand-run Windows upgrade. B: keep all five.
- Recommend: A, because the hand-run upgrade does what the app's own update and a rerun of the installer already do, with a second set of rules.
- Changes for a person: with A, someone fixing a computer by hand runs the installer again instead of a separate upgrade, and keeps the computer's settings either way.
- Text assumes: A, with the hand-run upgrade still written and marked pending so it can be deleted
- Items: 01-075, 01-078, 01-079, 22-045
- Answered by the owner 2026-11-24: A: the app's own update (editor, admin's push, unattended setting) and the installer; the hand-run Windows upgrade goes

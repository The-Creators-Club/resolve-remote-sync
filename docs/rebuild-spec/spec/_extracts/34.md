# Extract of inventory section 34

## Items

### 34-001: The editor can be run in a trial mode that never changes the studio's cut-list files.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: By default a stand-alone run of the editor leaves the studio's cut-list files untouched: the first time it starts, every cut list it finds is copied to a private copy on that computer, and every edit goes to the private copy. A later start keeps the private copy's edits (they are the newer truth) and copies only cut lists the private copy does not have yet. Throwing the private copy away starts again from the studio's files. A cut list that appears in the studio's folders after the editor started is not seen until the next start. Waveform pictures made in this mode are not saved, so they are made again after a restart. Whoever starts the editor can choose instead to edit the studio's cut lists in place, which is how the studio's own editor runs. The private copy may never sit inside the studio's episode folders; the editor refuses to start if it would.
- Flag: dev only

### 34-002: Stopping the editor's server never loses an edit.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: When the server the editor runs on is stopped (including the console window being closed, or Ctrl+Break on Windows), every open cut list is written to its file and released before it exits. A second stop request during that is ignored. A part that fails to close does not stop the others closing. Any assistant or background work it started is stopped with it, so nothing keeps running afterwards. A cut list nobody has had open for 10 minutes is written and put away by itself, and opens again the moment someone uses it.

### 34-003: When the editor is run on its own and reachable from the network, it asks for a password.
- Where: accounts-privacy-legal / Passwords, sessions and failed sign-ins
- What: A stand-alone editor reachable only from its own computer needs no sign-in. One reachable from other computers will not start without a password of at least 8 characters ("set a password (8 or more characters) and the editor will ask for it"); a password may also be required on the computer itself.
  - The sign-in page: title "Log in - Timeline Cards", the Timeline Cards mark and "TIMELINE CARDS", heading "Log in", the text "This editor is open to the network, so it asks for its password.", one "Password" field (focused, the browser may fill it), and a "Log in" button, disabled while sending. A wrong password shows "That is not the password." under the form and selects the field; any other failure shows the server's sentence, or "The login failed."; no answer shows "The server did not answer.". It works without scripts too (a wrong password redraws the page with the sentence). The page cannot be shown inside another page.
  - After signing in the person lands on the page they first asked for (anything odd becomes the start page). Visiting the sign-in page while signed in goes straight there.
  - A sign-in lasts 30 days by default (the person running the editor can set the length, at least 1 day) and is renewed on a page load once less than half of it is left. Restarting the editor keeps everyone signed in; changing the password signs everyone out. Signing out ends that browser's sign-in.
  - Wrong-password slowdown: from one address, the first 5 failures are free, then each further failure means waiting 2, 4, 8 ... seconds, at most 5 minutes; this count clears only on a successful sign-in. From one network, 20 free failures, then the same doubling; across the whole editor, 100 free failures, then the same. The network and whole-editor counts are forgotten 10 minutes after their last failure. While a wait applies: "Too many wrong passwords. Try again in N s.".
  - Any page asked for without a sign-in goes to the sign-in page; anything else is refused "log in first".
- Flag: several ways in: run on its own with this password, or reached through the dashboard (34-004), where the dashboard's sign-in is the only door.

### 34-004: Reached through the dashboard, the editor answers only through the dashboard and knows who is signed in there.
- Where: accounts-privacy-legal / What each person may see and reach
- What: When the editor lives inside the dashboard, the dashboard's sign-in is the only door: a request that does not come through the dashboard is refused "this editor is reached through its dashboard". The editor knows the signed-in person's name from the dashboard (cut to 120 characters).

### 34-005: The editor refuses requests from other websites and from unknown names.
- Where: accounts-privacy-legal / What each person may see and reach
- What: Any change, any data request and any live connection coming from a page on another website is refused ("requests from another site are not accepted"), including a sound or picture another site tries to load. Only the editor's own address, and those the dashboard names, are accepted. The editor answers only to its own computer's names, plain numeric addresses, and any extra names the person running it lists (none by default); anything else is refused "this server does not answer to that host name", which stops an outside website from posing as it.

### 34-006: A part of the editor that fails to start does not stop the editor.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: The editor's capabilities (transcripts, search, markers, gap notes, shortening, montage, the edit chat, the hand-over to Resolve, video, projects, the lane, the shelf, looks, and any added later) each start on their own. One that cannot start is skipped and the editor carries on without it; the page shows the same set the server runs. The person running a stand-alone editor can switch individual capabilities on or off when starting it (all on by default; "off" wins when both are given).
- Flag: several ways in: per-capability switches here, while the rebuild switches Timeline Cards on or off as one part per site.

### 34-007: Something can offer the person a set of edits to preview and accept, which the editor never applies by itself.
- Where: cards-editor / Shortening, the edit chat and the assistant
- What: An offer is a titled list of edits with a reason. The editor lists the offers for a cut list (oldest first), previews one, and applies it as one undo step only when the person accepts; it can also be dismissed ("that proposal is gone" when it already is). An offer holds 1 to 2000 edits, every one of a kind the editor knows; a title is required (cut to 200 characters) and the reason is cut to 4000. Up to 50 open offers per cut list (the oldest dropped), across up to 200 cut lists; an offer lasts one day and is forgotten when the server restarts.
- Flag: unreachable: nothing in the product makes an offer; only an outside caller could.

### 34-008: Heavy work the server does for the editor always ends with a sentence, never a hang.
- Where: whole-product / Could not check, refusals and nothing silent
- What: Work the editor's server does on request (outside the assistant) ends in an answer or a plain sentence naming the part that failed:
  - it gives up after 2 minutes by default (a part may allow longer): "the <part> helper did not answer \"<request>\" within N s";
  - too much at once: "the <part> helper is busy with other requests; try again in a moment";
  - it failed: "the <part> helper stopped ...; ask again and it will be restarted";
  - it keeps failing: "the <part> helper keeps stopping; it will be tried again in a few seconds";
  - a program the server needs is missing: the sentence names it and says the part cannot run;
  - the person cancelled: "stopped"; the server is stopping: "the server is shutting down".
  One part's long work never holds up another part's quick requests, and progress is passed to the page while the work runs.

### 34-009: The assistant's runs are limited, timed and can be capped by spend.
- Where: whole-product / The assistant
- What: At most 4 assistant runs at once (the person running the server may change this) and 32 waiting; beyond that "the assistant is busy with other requests; try again in a moment", and a run that waited too long is told it "did not get a turn within N s". A run is stopped after 15 minutes ("did not answer within N s, so the run was stopped"), when it writes far more than an answer, or when it needs more steps than allowed. A run asked for a structured answer that does not give one is told so. A cancelled run says "stopped". An optional spend limit per rolling hour (off by default, set by the person running the server) refuses new runs once reached: "the AI budget of $X for this hour is spent; try again later". The reply streams to the page as it is written. The assistant is given no ability to change files, run commands or browse unless a part of the editor asks for one specific ability. Stopping a run stops everything it started.

### 34-010: A conversation with the assistant is kept per cut list and starts fresh when the transcripts change.
- Where: whole-product / The assistant
- What: A part of the editor may keep one ongoing conversation with the assistant per cut list, so later questions build on earlier ones. When the set of transcripts it was given changes, a new conversation starts. The person can reset it. Conversations are kept on the server, never in the episode's folders. A conversation the assistant no longer recognises fails at once rather than retrying.

### 34-011: The builders can stand a fake assistant in for the real one when testing.
- Where: whole-product / The assistant
- What: For tests, a stand-in answers instead of the assistant, by rules (a reply, a delay, a failure, a cost, a lost conversation), records every call, and never uses the network. While tests run with no stand-in named, every assistant run is refused, so a test can never reach the real one.
- Flag: dev only

### 34-012: Background assistant work is done in order of who is waiting, and can be capped per day.
- Where: whole-product / The assistant
- What: Work that a part of the editor queues for the assistant or the server runs most urgent first: something a person is waiting for, then what is on screen, then background work; oldest first within each. When the queue is full, the lowest-priority newest piece nobody waits for is dropped; work someone waits for is never dropped, and a person whose request cannot be queued is told "too much work is queued already; try again in a moment". An optional daily count of assistant calls (per calendar day, UTC) stops the queue when spent and tells a waiting person at once "today's budget is spent (N assistant calls)"; raising the count starts it again. When the assistant or a needed language model is missing, the queue holds, tells waiting people at once, and looks again a minute later. A piece left out of an answer is asked once more on its own, then fails "it was left out of the answer". A person who leaves withdraws their request. Queued work survives a restart and resumes; people waiting at shutdown are told "the server is stopping".
- Flag: differs: this daily count of calls and the hourly spend limit of 34-009 both apply on top of each other.

### 34-013: The editor finds each clip's sound by itself and lists the clips it cannot play.
- Where: cards-editor / Media the browser gets
- What: For each clip a cut list names, the editor plays, in order of preference: the clip's small listening copy; the interviewee's multicam sound file (a file whose name ends " Multicam"); or the sound extracted from a video clip (used for news montages). A clip named after a video file is found by its name without the file ending. A clip name too long for the disk still finds its file. Only files that exist are matched; a clip name never reaches outside the episode. The editor can list the sound of every clip a cut list uses (in the cut and on the bench, in first-use order) and of every clip an episode has, each with its length, rate and channels; clips with no sound, or whose sound cannot be read, are listed as missing. A small preview video of a clip is shown when one exists ("no preview video for this clip" when not). Sound plays from any point. Under heavy load a sound request may be turned away for about a second and asked again; one that cannot be decoded gives up after 20 seconds, a whole-file job after 10 minutes, with the reason. A cut list longer than 16 MiB is refused as too large. The editor writes nothing into the episode's folders except the waveform files of 34-014.

### 34-014: Each clip's waveform is made once and reused.
- Where: cards-editor / Media the browser gets
- What: A clip's waveform shows the loudest moment of every 1/200 s. The first time it is needed it is made from the sound (up to 10 minutes for a long file; several viewers asking at once share the one making) and saved beside the clip's listening copy, where anyone's later request reuses it as long as it is not older than the sound. If two computers make one at the same moment, the first one saved is kept. A waveform that cannot be saved is still shown.

### 34-015: The editor levels every source to a common loudness, and a person's gain sits on top.
- Where: cards-editor / Playback and audio
- What: Every source's loudness is measured once (per second, over a 3-second window, by the broadcast loudness standard; anything at or below -120 LUFS counts as silence) and the whole source's gated level is kept. The level around a moment is the gated level of 120 seconds either side (centre rounded to 5 s), used only when at least 20 seconds were measured, and kept within 18 dB of the whole source's level. The target is the median of the sources' whole levels. A cut's levelling gain is constant across the cut (judged at its middle) and clamped between -26 dB (0.05x) and +18 dB (8x). A person's own gain on a cut (34-033) is added on top.

### 34-016: Several people and devices edit one cut list live, and every edit is on disk before it counts.
- Where: cards-editor / Working offline, connections and several devices
- What: Every device with a cut list open sees every edit anyone makes, its own included, as soon as it is saved. An edit is confirmed to the device that made it only once it is safely on disk; an edit that does not apply is refused with its sentence and changes nothing. Sending the same edit twice is harmless: the first answer comes back. A device that joins gets the whole cut list; one coming back gets only what it missed when that is under 5000 edits and its copy still matches, otherwise the whole cut list. Warnings of the last 10 minutes (up to 20) are shown to anyone who joins in that time.
  - Limits: 64 devices per cut list ("too many editors have this cut list open"), 256 per server ("too many editors are connected to this server"); one edit at most 512 KB ("that edit is too large to send (over 524288 bytes)"); a device may have 64 edits awaiting confirmation, and more than 256 waiting is refused "more than 256 edits waiting: slow down and reconnect". An edit the editor does not know is refused "that edit is not one the editor knows how to make"; anything unreadable is ignored with a warning ("a message I could not read was ignored").
  - A page from a different build is told to reload ("this server speaks protocol 1, not N: reload the editor").
  - Who made each edit is recorded as a person's device, a hand edit of the file, or the editor's own automatic work.

### 34-017: A device that loses its connection keeps its edits and catches up when it comes back.
- Where: cards-editor / Working offline, connections and several devices
- What: A connection silent for three heartbeats (about 45 seconds) is dropped. The device reconnects by itself, waiting 250 ms at first and doubling up to 10 seconds. Edits made meanwhile are kept on the device and, on reconnecting, re-applied in order on top of the newest cut list; any that no longer apply are dropped and the person is shown each one's refusal sentence. A device too slow to keep up is dropped and catches up on reconnecting.

### 34-018: When an edit cannot be saved, the person is told and nothing is lost.
- Where: cards-editor / Working offline, connections and several devices
- What: If the server cannot save edits, none of them is confirmed, every device is told "could not save to the edit history (<reason>); your edits are kept in the editor and will be sent again", and the device reconnects and sends them again in order. That device's later edits wait (for at most 10 minutes) until the failed one arrives again, so they never land out of order. Sent by a plain request instead of the live connection, the answer is "the edit could not be saved yet; send it again". If the history itself cannot be put right, no edit is saved until the cut list is opened again.

### 34-019: A cut list renamed on one device is followed by every other device.
- Where: cards-editor / Working offline, connections and several devices
- What: When a cut list is renamed, a device still holding the old name is moved to the new one and told: "this cut list was renamed to \"<new name>\" on another device; your edits go there". Edits held offline under the old name land on the renamed list. The newest 500 renames are remembered; renaming back undoes the forwarding; a chain of renames is followed up to 16 steps.

### 34-020: The editor lists every cut list it finds, with its title, size and when it last changed.
- Where: cards-editor / Opening episodes and keeping the editor running
- What: An episode is any folder up to four levels below the studio's episode root that holds the episode's script-docs folder; its cut lists are the files in that folder's Cuts folder (hidden ones are not listed). It is not a search of every folder. Each cut list shows its title, the number of cuts in the cut (not counting the bench), how many edits it has had, and when it last changed, sorted by path. A file over 16 MiB shows no title and no cuts; one that cannot be read is left out. A cut-list name is refused when it is empty, over 1024 characters, holds a character a path cannot have (\ : * ? " < > | or a control character), is not a cut-list file, has an empty, "." or ".." part, names a hidden folder or file, has a part starting or ending with a space, or leads outside the episode folders.

### 34-021: A cut list survives a crash, and damage costs only what came after it.
- Where: cards-editor / Editing, undo and the cut list
- What: Opening a cut list never trusts luck:
  - The first time, the file is the whole truth. A file with a line the editor cannot read is not opened: "the cut list has a line I cannot read: line N: <reason>". Rows without an id are given one and the file is written back at once so the ids stay.
  - After that the cut list is rebuilt from its saved history. If the history is damaged part way, the cut list opens at the last good point and every device is told: "the edit history of this cut list was damaged after version N (<reason>); everything up to version N is safe, and the rest is kept aside". An edit cut off mid-save that was never confirmed is quietly dropped.
  - A file left half-written by a stop is written again from the history: "the cut list file was being written when the server stopped and holds only part of it; it was written again from the edit history (nothing was lost; the partial copy is kept aside)".
  - If nothing can be rebuilt and the file is not the one last written, the cut list is refused with a sentence telling the person to move the history aside to start again from the file.
  - A file claiming more edits than the history holds is treated as a hand edit and merged (34-024).

### 34-022: The cut list file follows the editor within a moment and keeps a backup of its previous version.
- Where: cards-editor / Editing, undo and the cut list
- What: About 0.15 s after the last confirmed edit, and when the cut list is put away, the file is rewritten with its edit count and a "written by Timeline Cards" stamp (UTC). The previous version is kept as a backup beside it. If the file changed on disk in a way the editor did not make, that change is merged first, never overwritten ("the file changed while it was being written; merging that first"). A file held open by another program on Windows is still written. A failed write tells every device once: "could not write the cut list file (<reason>); every edit is safe in the edit history and the write will be tried again", and it is retried after 0.5, 1, 2, 4 ... seconds, at most 30 seconds apart. A file deleted while the cut list is open is written again: "the cut list file had gone, so it was written again; nothing was lost".

### 34-023: Only one server at a time may hold a cut list.
- Where: cards-editor / Working offline, connections and several devices
- What: A cut list another running editor server has open is refused: "another Timeline Cards server (on <computer>) has this cut list open" (or that another opened or took it over at the same moment). A holder that has stopped is recognised and replaced: on the same computer when its program is gone or it has been silent 30 seconds; on another computer when it has been silent past 30 seconds and shows no sign of life, or its clock is more than an hour off; a damaged claim that stays unchanged for 2 seconds counts as a crash. If another server takes a cut list over, the first stops saving and every device is told: "another Timeline Cards server took this cut list over; this one has stopped saving edits (they stay pending in the editor). Reload to connect to the server that has it now".

### 34-024: The cut list file can be edited by hand, and the editor merges the change.
- Where: cards-editor / Editing, undo and the cut list
- What: A change made to the file in a text editor is noticed within about 2 seconds (sooner when the computer reports it), when the cut list opens, and before every write. A file still reading the same as the last write is ignored.
  - A file that cannot be read is looked at twice more (the person may still be typing); then a copy is kept aside and every device is told: "the file has a line I cannot read: line N: <reason>. A copy is kept aside; the editor's version stands and is written back on the next edit".
  - A file that reads is compared with what the editor last wrote and turned into edits applied on top of the current cut list, then rewritten keeping the person's formatting where possible. Rows are matched by their ids; a row whose id line was deleted is matched back (cuts by clip and span: exact, one inside the other, then overlapping, ties to the nearest in order; headings, note rows, bench sections and gaps by kind and words, gaps by length). Only then is a row new.
  - What a hand edit can change: the title, clip facts, timeline name and hand-over stamps; new cuts, headings, note rows and bench sections; a hand-fixed clip name, speaker or link; removed headings and sections; the order (merged so only what the file moved moves); each cut's edges, fades, gain, colour, note and highlights; each gap's length and note; each heading's summary.
  - A cut bullet removed from the cut goes to a shelf, never lost; one removed from the bench is really removed. A cut whose new span cannot be reached by moving its edges is replaced whole.
  - Ignored and written back as they were: a cut's words, its "(12.4s)" length and its transcript link text; the episode, root, canvas, rate, drop-frame, start and timing facts at the top ("the frontmatter's X was edited; no edit can change it, so it is kept as it was").
  - The person is told "merged an edit made to the file outside the editor (N change(s))"; or "the file was edited outside the editor, but nothing in the edit changes the cut (the words are written from the transcript), so it was written back as it was"; plus "K of the file's changes no longer apply and were skipped: <up to 5 reasons>" and up to 5 warnings. A merge that could not be saved is tried again at the next look; the same file after a crash gives the same edits, which can never apply twice.
- Flag: differs: bringing Resolve's changes back (34-041) turns a changed cut list into edits by other rules.


### 34-025: A cut list holds the cut, the bench, and the timeline's facts.
- Where: cards-editor / Editing, undo and the cut list
- What: A cut list has the timeline's facts, an optional title, the cut's rows in order, then the bench sections in order, and any extra data a part of the editor keeps with it.
  - Rows in the cut: a cut, a gap, a heading, or a note row.
  - A cut is one piece of a source: the clip's name exactly as written (that name is the clip's identity, never an editing program's own id), the speaker or none (a montage clip), in and out in source seconds (in always before out), a fade in and fade out (each no longer than the cut; they may overlap), a gain of its own in dB (0.1 dB steps, within plus or minus 30, on top of levelling), a clip colour or none (the speaker's colour), a link into the transcript or none, its words (kept fresh from the transcript, never cut up by an edit), its highlighted phrases in order, and a free note of one or more lines. A cut can be marked as an interviewer's question: a question can never be in the cut (the house rule "no questions included in the edit ever"), only on the bench, and the mark is not kept in the file.
  - A gap is black and silence of a set length (more than 0) with an optional note. It is its own row: it stays where it was put when a neighbour moves or is deleted, and is selected, moved, resized, deleted and copied like a cut.
  - A heading is a section (default colour Blue), a note heading (default colour Green) or a plain heading (no colour); it has a title, a marker colour, and optionally an assistant-written summary of its section with a mark of the words it was written from, so a changed section can read "out of date".
  - A note row is a direction card or an "unmatched" line, one line of text (may be empty).
  - The bench, always after the cut: shelves (each named by its category; the unnamed one is the plain shelf; holding cuts, note rows and gaps), saved sequences (a run kept whole with its gaps and note rows), and the old alternates section, kept as it is. Each has a name, its title as read, and a colour.
  - Timeline facts: the edit count, when and by what it was written, the episode, the root, the planning canvas, the Resolve timeline's name, when it was handed over and when it was last updated from the timeline, the timeline rate (default 29.97), drop-frame (default on for a new list), the start timecode (default 01:00:00:00), whether the text was timed by words or by subtitle cues, and per clip its rate, start timecode and Resolve id (hints for exports only).
  - Times are seconds, never frames; frames appear only in exports. Every edit rounds what it writes to 6 decimal places; a time beyond 1,000,000,000 seconds is refused ("X is past 1 000 000 000 seconds -- no clip is that long").
  - Limits: the shortest cut or gap an edit may leave is 1/24 s (a file may hold a shorter cut, such as one 29.97 frame); category and sequence names at most 60 characters; gap notes at most 2000 characters; summaries at most 4000.
  - A new cut list is empty, edit count 0, 29.97 drop-frame, starting 01:00:00:00, timed by words.
  - The timeline is worked out from the cut, never stored: each cut and gap starts where the ones before it end, so every trim ripples; each knows the heading it sits under; the total length follows.
  - Every cut, gap, heading, note row and bench section has a permanent id written in the file and is never matched by name, time or position; a row arriving without one gets the same id from the same content every time.

### 34-026: Clip colours and marker colours come from Resolve's own lists.
- Where: cards-editor / Colours
- What: Clip colours (16): Orange, Apricot, Yellow, Lime, Olive, Green, Teal, Navy, Blue, Purple, Violet, Pink, Tan, Beige, Chocolate, Brown. Brown is never written: it becomes Chocolate. Marker colours (16): Blue, Cyan, Green, Yellow, Red, Pink, Purple, Fuchsia, Rose, Lavender, Sky, Mint, Lemon, Sand, Cocoa, Cream. A new section takes the next colour in the rotation Blue, Sand, Purple, Mint, Rose, Sky, Lemon, Fuchsia, Cyan, Cocoa, Lavender, Yellow, Pink, Cream after the section above it (Blue when there is none, or when that section's colour is not in the rotation); a note heading takes Green; a plain heading none.

### 34-027: Every edit names what it changes, applies cleanly or is refused with a sentence, and can never break the cut list.
- Where: cards-editor / Editing, undo and the cut list
- What: Edits name cuts, gaps and headings by their ids (shelves and sequences by name), never by position, and set values outright (set an edge to X, a gain to Y), so applying one twice changes nothing more. A refused edit changes nothing and shows its sentence. After every edit the cut list is checked; an edit that would add a problem the cut list did not already have is refused ("internal: that edit would break the cut list (...)"), while a cut list that arrived with an oddity of its own can still be edited. The cut list always keeps: every id unique; every cut with a clip name, in before out, fades within the cut and gain within plus or minus 30; no question in the cut; every gap longer than 0; every section and note heading with a colour; no two shelves with the same category and no two sequences with the same name.
  - Common refusals: "name at least one of the cuts", "cuts are named by id", "the same cut is named twice (<id>)", "a place is before a cut OR after one, not both", "X must be a number of seconds", "that cut is no longer in the cut list", "that gap is no longer in the cut list".
  - Where a moved or inserted block lands: "before X" lands between the rows above X and X, so the block joins X's section (headings above X stay above the block); "after X" lands directly after X; neither means the end of the cut. The anchor is a cut or gap in the cut.
  - Where a block lands on the bench: a category (made when first used; no name is the plain shelf), or before or after a cut already there (that cut's shelf wins over a category; "a cut cannot be put next to itself"; "that staged cut is no longer in the file"; an anchor in the alternates section is ignored and the category used).

### 34-028: A person can trim or extend one edge of a cut, and everything after it ripples.
- Where: cards-editor / Editing, undo and the cut list
- What: An edge is set to a source second, on a cut in the cut or on the bench. Refusals: an in point before 0, "the clip starts N s later than that -- there is no more source before this cut"; an out point past the known end of the source, "the clip runs out N s before that -- there is no more source after this cut"; a cut left at 0 or less, or under 1/24 s and shorter than before, "that would leave nothing of the cut -- delete it instead" (a cut already under 1/24 s may still be lengthened). Fades shrink to fit. Pulling an edge out over a neighbouring cut of the same source is allowed (that stretch then plays twice).

### 34-029: A person can take a stretch out of the middle of a cut, or split it in two.
- Where: cards-editor / Editing, undo and the cut list
- What: Taking a stretch out leaves the cut up to the stretch and a new cut from its end to the cut's out, placed right after it (the stretch is kept within the cut). Splitting does the same with nothing removed. The first piece keeps the cut's id and fade in; the second takes the fade out; both keep gain, colour, note, link, words and highlights. Gaps are not touched. Refusals: "the selection is empty -- nothing removed" (under 1/24 s); "that is the whole cut -- delete it instead"; "that would leave a piece shorter than a frame -- trim the edge instead"; for a split within 1/24 s of an edge, "the blade is at the edge of the cut -- nothing to split"; "the second piece needs a well-formed id"; "that id is already in use in this cut list".

### 34-030: A person can move cuts, delete them to a shelf, stage and unstage them, and throw away what is on the bench.
- Where: cards-editor / Editing, undo and the cut list
- What:
  - Move: a block of cuts and gaps, in the order named, to a place in the cut. A gap moves only when named. Only items in the cut move. "a block cannot be put next to itself".
  - Delete: each cut leaves the cut and goes onto the shelf named after the last section heading above it (a note heading or plain heading does not count); before the first section, or when the title cannot be a category name, onto the plain shelf. Shelves are made as needed at the end of the bench. A deleted gap is simply removed. Nothing is lost by a delete.
  - Stage: cuts out of the cut onto a chosen shelf place; named gaps are removed.
  - Unstage: cuts from any shelf, sequence or the alternates section back into the cut at a place. Refusals: "that cut is already in the cut"; "that staged cut is no longer in the file"; "that is an interviewer question -- questions never go in the cut".
  - Move on the bench: within or between shelves. "that cut is in the cut -- stage it first"; "a staged cut moves next to another staged cut". With an anchor, the anchor's section decides; with a category, cuts already in it stay put and the rest go to its end.
  - Throw away: the only true delete, for cuts on the bench only: "that cut is in the cut -- only a cut on the bench can be thrown away".

### 34-031: A person can insert a new cut, paste a run of cuts and gaps, or insert a gap.

### 34-040: The editor names the language of a stretch of speech by its script.

Switcher labels: 中文, RU, UK, RU/UK, 日本語, 한국어, EN, or "Original"; a Russian and Ukrainian mix says RU/UK; three or more languages say "Original".

### 34-043: The frontmatter block carries the timeline's facts in a fixed canonical form.
- Where: cards-editor / The cut-list file
- What:
  - **Must** start on line 1 with `---` and end with a line `---`. Otherwise problems: line 1 "a cut list starts with a --- frontmatter block"; "the frontmatter is never closed".
  - **Written in this order** (canonical form):
    - `---`
    - `kind: timeline-cards/cut-list`
    - `rev: <whole number>`: the edit count the file encodes.
    - `written: <stamp>`: `YYYY-MM-DDTHH:MM:SS+0000 by Timeline Cards` (UTC) when the editor writes.
    - `project: <text>`, `vault_root: <text>`, `canvas: <text>`, `timeline: <text>`: written even when empty (as `key:` with nothing after).
    - `conformed: <text>` and `updated_from_timeline: <text>`: only when set.
    - `fps: <rate>`: `25.0` for a whole rate, else up to 8 decimal places with trailing zeros removed (`29.97002997`).
    - `drop: true` or `drop: false`.
    - `tl_start: <timecode>`
    - `timing: word` or `timing: srt`
    - `x-<name>: "<json>"` lines (extra data, 34-044), sorted by name.
    - `clips:` then one indented line per clip (34-044).
    - `---`
  - **Value quoting** (writer): none is written as nothing; an empty string as `""`; a value is double-quoted (with `\` and `"` escaped) when it has leading or trailing whitespace, starts with a double quote, single quote, `[`, `{`, `>`, `|`, `&`, `*`, `#`, `!`, `%`, `@`, a backtick, `-` or `?`, contains `:` or `#`, or looks like a number; otherwise bare.
  - **Reading values**: empty is none; a value in matching single or double quotes is the inside with `\"` and `\\` unescaped; bare `true` / `false` are booleans (written back as `true` / `false`); anything else verbatim.
  - **Reading rules per key**:
    - `kind`: if present and not `timeline-cards/cut-list`: problem "this is a 'X' file, not timeline-cards/cut-list".
    - `rev`: a whole number (Unicode digits, `_` separators and a sign accepted), else problem "rev is not a whole number: 'X'". Absent: 0. Negative counts as 0.
    - `fps`: a number (including exponents, `inf`, `nan`), else problem "fps is not a number: 'X'". Snapped to the exact rate (within 0.01 of 23.976, 29.97, 47.952 or 59.94 it IS that rate; else the nearest fraction with denominator at most 1001). Absent: 30000/1001.
    - `drop`: true when `true` or any non-empty text (even `0`); false when `false` or empty.
    - `tl_start`: absent means `01:00:00:00`.
    - `timing`: `word` or `srt`; anything else is a problem ("timing is 'word' or 'srt', not 'X'"); absent means `word`.
    - `conformed`, `updated_from_timeline`: empty means none.
    - The same key twice: the last one counts; the earlier lines are kept as written.
    - A line with no `:`: problem "'X' is not a frontmatter key".
    - An unknown key: warning "unknown frontmatter key 'X' kept as written"; kept on write.
    - Blank lines are allowed.
  - Meaning: `rev` the edit count; `written` the last writer's stamp; `project` the episode; `vault_root` the episode root; `canvas` the planning board it came from; `timeline` the Resolve timeline's name; `conformed` when it was handed over; `updated_from_timeline` when Resolve's changes were last brought back; `fps`, `drop`, `tl_start` the timeline's rate, drop-frame and start; `timing` whether the words were placed by word timing or matched from subtitle cues.
- Exact: yes

### 34-044: Clip lines and extra-data lines in the frontmatter.
- Where: cards-editor / The cut-list file
- What:
  - **Clip lines** (indented, after `clips:`), written one per clip sorted by Unicode code point: `  <name>:<padding> {fps: <rate>, start_tc: <timecode>, uid: <uid>}`; the padding aligns the braces one column past the longest name; `uid` left out when none. They are hints for exports only.

    - A bare value is also read (`x-flag: true`, `x-n: 3`).
    - A value that does not decode, or decodes to null: warning "line N: the X data on this line cannot be read; it is left out"; it disappears on the next write.

### 34-045: The comment preamble and the title.

### 34-046: Headings: how each kind is written and recognised.
- Where: cards-editor / The cut-list file
- What:
  - Any line starting `## ` is a heading. A trailing `<!-- ... -->` on it is its colour (or its tag). The kind is decided in this order:
    1. Trailing `<!-- heading -->` or `<!-- heading <Colour> -->`: a **plain heading** whatever the title says, with that colour or none.
    2. Title starts `§`: a **section** heading (in the cut). No colour comment means Blue.
    3. Title starts `◆`: a **note** heading (in the cut). No colour comment means Green.
    4. Title starts `⧉`: a **saved sequence** (bench). Name is the rest.
    5. Title starts `Alternates` (exact case): an **alternates** section (bench), title kept verbatim.
    6. Title starts `staged` (any case): a **shelf** (bench). The category is the rest after leading spaces, colons, slashes, bars, en or em dashes, middle dots and hyphens are removed; empty means the plain shelf.
    7. Anything else: a **plain heading** in the cut.
  - Rows after a bench heading belong to that bench section until the next `##`. An in-cut heading after a bench section returns following rows to the cut (the writer then writes all in-cut rows before the bench).
  - **Written forms**:
    - Section: `## § <title>` then the colour comment. Note heading: `## ◆ <title>` then the colour comment. Plain: `## <title>`, colour comment only when it has one.
    - A plain heading whose title would read as another kind (starts with `§`, `◆`, `⧉`, `Alternates` or `staged`) is written with the tag: `## <title>  <!-- heading -->` or `<!-- heading <Colour> -->`. (New edits refuse such titles; this form only round-trips files that already have them.)
    - The colour comment `<!-- <Colour> -->` starts at column 66 (at least one space after the title).
    - Shelf: the title as read when it still names the same category; otherwise `## staged`, or `## staged` + space + U+2014 (em dash) + space + category.
    - Sequence: `## ⧉ <name>`. Alternates: `## <title as read>`.
    - Every heading is followed by its id line, flush left: `<!-- id: s1234567 -->`.
    - An in-cut heading's summary follows its id line, one comment line per line of text: `<!-- summary [<hash>]: <text> -->` (the hash only on the first line, and only when there is one).
- Exact: yes

### 34-047: Bullets: cut lines, gap lines and note rows.
- Where: cards-editor / The cut-list file
- What:
  - A **cut line**: `` - **<Speaker>** `<clip>` <in> → <out> (<duration>) <!-- <Colour> --> ``
    - The speaker part is optional. The clip is between backticks (trimmed); it is the source's name and identity.
    - In and out are source seconds: optional minus, digits, optional decimals; any Unicode decimal digits are accepted (fullwidth digits typed with a Chinese input method read as numbers).
    - The separator may be `→`, `->`, `-->`, an en dash or an em dash, with any spacing.
    - The `(...)` duration is optional and ignored on read.
    - The colour comment is optional: a clip colour name (Brown read as Chocolate), or a hex colour `#rrggbb` / `#rgb` mapped to the nearest Resolve clip colour (an exact planning-board palette colour first, else the nearest by weighted RGB distance, never Brown). An unknown name is kept as written with warning "unknown clip colour 'X' kept as written".
    - Written as `` - **<Speaker>** `<clip>` <in to 6 places> → <out to 6 places> (<length to 1 place>s) ``, plus ` <!-- <Colour> -->` when coloured, then the id line `  <!-- id: c1234567 -->`.
  - A **gap line**: `- gap <seconds>` with an optional `s` (`gap` in any case): black and silence of that length. The length is rounded to 6 places. A length of 0 or less: warning "line N: a gap of N s is no gap; it is not part of the cut list", dropped. Each gap line is a gap row where it stands (consecutive gap lines stay separate rows). Written `- gap <seconds with as few decimals as needed, always one>s`, then `  <!-- id: g1234567 -->`, then its note lines `  <!-- note: <text> -->`, one per line.
  - A **note row**: `- (note) <text>` (a direction card) or `- (unmatched) <text>` (text trimmed, may be empty). Written the same, then `  <!-- id: n1234567 -->`.
  - Any other line starting `-`: problem "cannot read this bullet: '<first 72 characters>'".
  - Any other line that is not blank, not a comment, not a heading and not a continuation of a cut: problem "expected a bullet, a heading or a blank line, got '<first 48 characters>'".
- Exact: yes

### 34-048: Lines under a cut: fade, gain, note, transcript link and words.
- Where: cards-editor / The cut-list file
- What:
  - Read only directly under a cut bullet (before the next bullet or heading), tried in this order:
    - **Fade**: `  - fade: in <s>s out <s>s` (indented; either part optional; the `s` optional; any case). Rounded to 6 places. A negative value: problem "a fade in cannot be -N seconds long" (or "fade out"). Written `  - fade: in <s>s out <s>s` with only the non-zero parts; no line when both are zero.
    - **Gain**: `  - gain: +6.0 dB` (indented; sign and `dB` optional; any case). Rounded to 0.1 and clamped to plus or minus 30. Written `  - gain: <sign><one decimal> dB` only when non-zero.
    - **Note**: `  - note: <text>` (indented). Several note lines join with line breaks. An indented line after a note line that matches nothing else continues the note (trimmed).
    - **Link**: `  [[<target>]]` (greedy to the last `]]`, so targets containing `]` work). When the target starts `<speaker or clip>_Transcript#^`, only the part after `^` is kept as the ref; otherwise the whole target is kept.
    - **Words**: `  > <text>` lines, joined with line breaks. `==text==` marks a highlight (trimmed; a lone `==` is literal; an empty one is ignored).
  - **Written order under a cut**: id line; link (`  [[<speaker or clip>_Transcript#^<ref>]]`, or the full target when the ref contains `#`); words, one `  > ` line per line with `==` put back around each highlight (a line with no words written `  >`); fade; gain; note.
  - **Note lines after the first** are written indented four spaces when the line is plain; a line that is empty, has leading or trailing spaces, or starts with `-`, `>`, `<`, `#` or `[` is written as another `  - note: <line>` line instead (both forms read back the same).
- Exact: yes

### 34-049: Comments, id lines, gap notes and section summaries.
- Where: cards-editor / The cut-list file
- What:
  - Any line whose trimmed text starts `<!--` is a comment. One without `-->` on the same line runs until a line containing `-->`; everything inside is skipped.
  - **Id line** `<!-- id: <letter><7 characters> -->` (any spacing): the letter is `c` cut, `g` gap, `s` heading or bench section, `n` note row, and the 7 characters are from `0-9a-z`. It attaches to the row directly above it when the letter matches that row's kind and the row has no id yet. Otherwise warning "line N: an id line that belongs to no row above it is kept as a comment".
  - An id used twice in the file: the second row gets a new id, warning "line N: id X is used twice; this row is given a new one".
  - A row with no id line gets a deterministic id: its kind letter plus 7 characters worked out from its kind, its content (cut: clip, in and out to 6 places; gap: length; heading or bench section: kind and title; note row: kind and text) and how many times that content has occurred, counted up until unused. The same bytes always get the same ids. Ids are never matched back by name, time or position.
  - **Gap note lines** `<!-- note: <text> -->` directly under a gap (after its id line, before any other non-comment line). **Summary lines** `<!-- summary: <text> -->` or `<!-- summary [<hash>]: <text> -->` directly under an in-cut heading; the first hash given wins; the hash is 1 to 32 characters of `0-9a-z`. A note line under a heading, a summary under a gap, or a `note [hash]` form is just a comment.
    - Escapes inside these lines: `\` is written `\\`; the `>` of `-->` or `--!>` is written `\>`. A lone backslash in a hand edit is kept.
    - Read text is normalised as an edit would (lines trimmed, control characters become spaces, broken surrogate characters become U+FFFD, blank end lines dropped); a gap note over 2000 characters or a summary over 4000 is cut there with a warning ("a gap note is longer than 2000 characters; the rest is not read").
  - Every other comment is ignored by the reader, and kept by the preserving writer (34-050).
- Exact: yes

### 34-050: The writer: the same cut list always gives the same text, and a hand-formatted file keeps its formatting.
- Where: cards-editor / The cut-list file
- What:
  - **Canonical**: the same cut list always gives the same bytes, with LF line endings: frontmatter, preamble, title, every in-cut row, then each bench section heading followed by its items; one blank line between blocks; one final newline. Extra-data lines are placed in the frontmatter.
  - **Preserving** (used when rewriting a file that was read): the file is cut into blocks when read (frontmatter, preamble, title, and one per row and bench section).
    - A block whose content is unchanged is written exactly as it was read: line endings, spacing, hand comments, unreadable lines and the blank lines after it.
    - A changed block is written in canonical form, followed by the complete hand comments it contained (stray id lines and unreadable lines inside it are dropped).
    - Blank lines and complete comments between blocks travel with the block before them when blocks are reordered.
    - The frontmatter is merged line by line: unchanged keys keep their raw line, changed keys are rewritten, keys the file lacked are inserted in canonical order, unknown keys, comments and blank lines are kept. (`rev:` and `written:` change on every write by the editor.)
    - When the editor writes, every row gets its id line (added under a row that had none, corrected where the file's id was a duplicate).
    - The result is read back and must give exactly the cut list it was asked to write (ids included); otherwise the canonical text is written instead (in the file's line ending).
  - Not stored in the file: the interviewer-question mark.
  - Older cut lists that carried "black before this cut" on a cut are read as a gap row directly in front of that cut (a zero or negative value dropped).
- Exact: yes

### 34-051: Numbers and white space in the file follow fixed rules so a file reads and writes back identically.
- Where: cards-editor / The cut-list file
- What:
  - White space and line breaks include U+001C to U+001F and U+0085, and exclude the byte-order mark.
  - Numbers are written with a fixed 6 decimal places and rounded halves-to-even on the exact binary value, so a value written by an earlier writer of the same format reads and writes back identically.
  - Lengths and sorting count Unicode code points.
  - Frontmatter numbers accept signs, `_` separators, exponents, `inf`, `nan` and any Unicode decimal digits.
  - Cut notes: each line trimmed, blank lines at the ends dropped, blank lines inside kept. Gap notes and summaries: the same, plus control characters become spaces and broken surrogate characters become U+FFFD.
- Exact: yes

### youtube-Q2: An editor can give their computer a signed-in YouTube session three ways: the one-click sign-in in a browser window, choosing an exported cookies file, or naming a cookies file in the computer's settings. Which stay?
- Kind: several ways in
- Today: all three exist; the cookies file is also what the app falls back to when no suitable browser is installed.
- Options: A: keep the one-click sign-in and the cookies file chooser, drop the setting that names a file elsewhere. B: keep all three. C: keep the one-click sign-in only.
- Recommend: A, one click is the ruled way and the chooser is the only way on a computer without Edge, Chrome, Brave or Chromium; the third is the same thing again.
- Changes for a person: with A, an editor who pointed the computer at a cookies file elsewhere chooses it once with the chooser instead.
- Text assumes: all three written, the setting marked pending.

### youtube-Q3: When an admin gives the server a signed-in YouTube session, should searches use it only after YouTube bot-checks them, as downloads do?
- Kind: differs
- Today: searches and detail lookups always use the server's session when one is given; downloads use it only after a bot check. Every search therefore exposes the account to being flagged by YouTube, after which it breaks everything.
- Options: A: one rule: the session is used only after a bot check, for searches and downloads alike. B: searches always use it, downloads only after a bot check.
- Recommend: A, one rule, and the account is used as little as possible so it lasts.
- Changes for a person: with A, a search may first be bot-checked and then retried signed in; the account is flagged less often.
- Text assumes: A.

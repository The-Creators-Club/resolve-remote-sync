## Questions for the owner

### proxies-and-file-moves-Q1: When a clip has failed to become a proxy three times, or Resolve has refused a proxy, should that be remembered across a restart of the app?
- Kind: other
- Today: a clip given up on after three failed attempts is tried again after any restart of the app, and a proxy Resolve refused is offered to Resolve again after a restart. So a broken clip is retried every time the computer restarts, and a refused proxy is offered again each time.
- Options: A: remember both for that version of the file across restarts; a changed file starts afresh, and "make the missing proxies now" retries every clip given up on at once. B: forget both whenever the app restarts, as today.
- Recommend: A, because a restart then changes nothing a person can see and the editor still has one button to retry everything.
- Changes for a person: with A, a broken clip stops being retried after three tries until the file changes or the editor presses "make the missing proxies now"; with B, it is tried three more times after every restart.
- Text assumes: A
- Items: 06-018, 06-032
- Covers: 06-Q3
- Answered by the owner 2026-11-24: A, remembered for that version of the file across restarts, with "make the missing proxies now" retrying all

### proxies-and-file-moves-Q2: Should the two rehearsal settings (make no proxies but list what would be made, and FIX ALL listing its copies and relinks without doing them) stay in the product?
- Kind: dormant
- Today: both exist, are off, and can only be switched on by editing the computer's settings file by hand. They were made for the people building the product but ship to every computer.
- Options: A: cut both. B: keep both, as settings an admin can switch for a computer.
- Recommend: A, because nobody running the studio uses them, and a setting nobody can reach is a moving part with no job.
- Changes for a person: nothing visible either way unless an admin wants to preview what FIX ALL would do; with B there are two more settings on each computer.
- Text assumes: B is written, marked pending, so it can be deleted if A is chosen.
- Items: 09-014
- Covers: 06-Q6, 09-Q7
- Answered by the owner 2026-11-24: A, both rehearsal settings cut

### proxies-and-file-moves-Q3: On a Mac, should CC Sync find, open and start Blackmagic Proxy Generator for raw clips by itself, as it does on Windows?
- Kind: differs
- Today: on Windows the generator is found where Resolve installs it, opened for raw clips and started with its Start button pressed. On a Mac it is off until someone types in where the generator is, and even then the app leaves it idle for the editor to press Start.
- Options: A: the same on both: found where Resolve installs it, opened and started without the editor's help, with the "could not press Start" note when that fails. B: keep the Mac as it is: off until its location is given, and never started for the editor.
- Recommend: A, because raw clips on a Mac otherwise sit without proxies until someone notices, and one behaviour on both systems is simpler.
- Changes for a person: with A, a Mac editor's raw clips get proxies while they are away, like a Windows editor's; with B, a Mac editor must set the location once and press Start each time.
- Text assumes: A
- Items: 06-028, 06-029
- Covers:
- Answered by the owner 2026-11-24: A, the same on both: found, opened and started without the editor's help

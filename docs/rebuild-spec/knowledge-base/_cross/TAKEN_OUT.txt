# tools/check_spec.py and tools/check_seams.py.
#
# One line per finished lesson id, seven fields separated by " | ":
#
#   id | action | sealed file | tool | reason | piece | heading
#
# action    withdraw  the lesson leaves the knowledge base for the trace
#                     (knowledge-base/_trace/taken_out.tsv). Used when the
#                     owner's later answer overruled it, or when it only makes
#                     sense for the present build's arrangement and what a
#                     person needs is already a behaviour of the specification.
#           seal      the lesson moves to the sealed drawer (../sealed/<file>.md)
#                     and is released only when the rebuild's own design names
#                     that tool or technique. Used for a true fact about a
#                     given whose rule only applies under a design choice.
# sealed file, tool   for `seal` only: the drawer file (no .md) and the
#                     `Tool:` line the note is filed under. Empty for withdraw.
# reason    why. A ruling (kind 2) may only be taken out with a reason that
#           starts "overruled": the owner's later word is the only thing that
#           removes one.
# piece, heading      where the promise a person needs is written, when the
#                     lesson was tied to an arrangement. check_seams.py fails
#                     if that heading is no longer in that piece. Empty when
#                     overruled.
#
# An id is never renumbered and never reused. To put a lesson back, delete its
# line and run assemble_kb.py.

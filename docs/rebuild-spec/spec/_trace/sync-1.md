## Questions for the owner

### sync-1-Q1: Should every transfer that is cut off carry on where it stopped, instead of a camera original starting again from nothing?
- Kind: differs
- Today: an upload of a camera original cut off by quitting, an update, a stop, a shutdown or a lost connection starts again from the beginning next time (the shutdown warning tells the editor so, and a large upload is kept running past its project's turn to avoid it), while project files pick up where they were.
- Options: A: every transfer, up or down, carries on where it stopped. B: keep it as it is, with the warning saying a part-way file starts again.
- Recommend: A, because a field editor on a slow connection may otherwise never finish a large file, and with it the special handling for long uploads is no longer needed.
- Changes for a person: with A, switching off mid-upload loses nothing and the shutdown warning says so; with B, a half-sent 20 GB clip goes again from zero.
- Text assumes: A.
- Items: 02-025, 03-036, 02-024, 01-036
- Answered by the owner 2026-11-24: quitting stops an upload and it carries on where it left off next time; an update waits for the file in flight up to a limit, then does the same. Still open: the same promise for a transfer cut off by a dropped connection, sleep, a shutdown, signing out, the pause or a stop, and for downloads; the text keeps those marked pending on this question.

- Changes for a person: with A, a document deleted on the server leaves an editor's computer too, recoverable from the recovery folder for its keep period; with B it stays on every computer until removed by hand.
- Text assumes: A.

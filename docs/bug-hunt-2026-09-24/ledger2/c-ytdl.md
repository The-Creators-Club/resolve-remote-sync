## bug-comp-ytdl-4 - One failed yt-dlp install or floor update switches local downloads off for 24 h
- Status: FIXED
- Verified as: `YtDlpManager._loop` waited `CHECK_INTERVAL_SECONDS` (86400) after any enabled pass, whatever the action. An ACTION_FAILED pass publishes ok=False, and capabilities() then refuses every job, so the executor's `_maybe_poke_ytdlp` never runs. The loop is the only retry.
- Fix: companion/src/ccsync_companion/ytdlp_manager.py adds `FAILED_RETRY_FIRST_SECONDS = 300`. `_loop` counts consecutive failed passes: yt-dlp ACTION_FAILED, sidecar ACTION_FAILED, or either half raising. After a failed pass it waits `min(ordinary wait, 300 * 2**(n-1))`, which gives 5, 10, 20 ... minutes, capped at the daily interval (or at the 15-minute recheck while the feature is off). A pass that succeeds resets the count. A machine that can never reach GitHub is back to one attempt a day within about a day.
- Regression test: test_bug_hunt_2026_09_24_w2_c-ytdl.py::test_a_failed_install_retries_with_backoff_then_settles_daily. Fails on HEAD with `assert 86400.0 <= 900`. Also ::test_a_failed_sidecar_pass_or_a_raise_also_retries_soon and ::test_the_backoff_never_exceeds_the_ordinary_cadence, which drive `_loop` synchronously through a recording stop event.
- Skew / deploy order: companion only.
- OWED: none
- Review round (2026-09-25): the reviewer was right. The backoff counted only ACTION_FAILED, but two other enabled passes publish ok=False, and capabilities() refuses every job on ok=False just the same. One is an install that lands but whose `--version` comes back None ("installed yt-dlp (version unreadable)", ACTION_INSTALLED). The other is an update that runs but leaves the version unreadable or still below the floor (ACTION_UPDATED, from the floor branch or from `_enforce_max_age`). Both still waited 86400 s. Fix: the new `_ytdlp_pass_failed(status, enabled)` in ytdlp_manager.py counts ACTION_FAILED, or any ENABLED pass with ok=False. The exceptions are ACTION_CHECKED (the hand-managed override: nothing here installs over it, so retrying sooner cannot fix it) and ACTION_DISABLED. New tests: ::test_an_enabled_pass_that_leaves_ok_false_also_retries_soon (installed/updated with ok=False back off 300, 600; an override with ok=False stays daily) and ::test_an_installed_but_unreadable_binary_is_rechecked_soon (through the REAL ensure(): install True, the first version() None, the next pass reads it; waits 300 then 86400). Both fail with the pre-review check (`86400.0 == 300.0`, `[86400.0, 86400.0, 86400.0] == [300.0, 600.0, 86400.0]`). Re-run: test_bug_hunt_2026_09_24_w2_c-ytdl.py, test_ytdlp_manager.py, test_sidecar_tools.py, test_ytdl_feature_gate.py, test_ytdl_executor.py, test_sweep_2026_09_04_copy.py -> 729 passed.

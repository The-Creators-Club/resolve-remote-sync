# Extract of inventory section 04

## Items

### 04-001: The app's icon shows at a glance whether this computer's syncing is all well, needs attention, or has a problem.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: The icon is the product mark alone; its shape never changes, only its status colour and brightness. There are three states, decided in this order (the first that applies wins):
  - Problem: a transfer has failed; this computer is not set up; this computer's clock is wrong against the server's; a transfer has stopped moving; keeping the shared project files (audio, graphics, subtitles, project files) in step has stopped working on this computer.
  - Needs attention: the sync drive is absent (unplugged, not answering, or mounted in the wrong place); nobody is signed in where the site requires it; syncing is paused; syncing is switched off on this computer (except on a computer wired straight to the server, where that is normal and the icon stays all well); any other reason sync is blocked; Resolve has not answered the app for more than 20 seconds; something is transferring.
  - All well: signed in, not paused, set up, caught up and not blocked.
  - Nothing being ticked for this computer never changes the icon. On a computer wired to the server, "nothing ticked" and "projects waiting for their list of what to sync" are ignored.
  - If the app cannot work out its own state, the icon shows "needs attention".
  - The icon and its hover text are brought up to date within about two seconds of a change.

### 04-002: The icon breathes while files are actually moving or while there is a problem, and stays still otherwise.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: The icon slowly dims and brightens, one breath every 3 seconds, never dimmer than about half brightness. It does so only in the problem state, or in the attention state while bytes are really moving. A transfer that claims to be syncing while no server is connected does not count as moving. All well never breathes, and steady attention states (paused, signed out, drive gone, sync switched off) never breathe. When breathing stops the icon returns to full brightness.

### 04-003: The icon, its hover text and its menu never change while the editor has the menu open.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: While the menu is open nothing about the icon, its hover text or the menu itself is changed, so an item never moves under the pointer; updates resume within about a quarter of a second of the menu closing. The menu also never freezes while open, even if Resolve is slow to answer.

### 04-004: On Windows, if the icon cannot be shown at all, the computer keeps syncing and the admin learns of it; the icon returns by itself after the taskbar restarts.
- Where: editor-app / Starting, staying running and crashing
- What: At start-up the app keeps trying to place its icon for about two minutes. If Windows never accepts it, the icon, its menu, the settings window and Quit are unreachable and every notification on that computer is lost; nobody on that computer is told, but a crash report reaches the dashboard. When the Windows taskbar restarts (for example Explorer restarting), the icon is put back by itself, retrying about once a minute until it succeeds; nobody is told. Syncing is unaffected either way.

### 04-005: On macOS, if the menu bar is too full to show the icon, the editor is told how to fix it.
- Where: editor-app / Starting, staying running and crashing
- What: About 3 seconds after start the app checks whether macOS really placed its menu-bar item where it can be seen (not hidden behind the camera notch of a notched screen, not left off the bar). If it is invisible, the editor gets the notification "CCSync is running, but the menu bar is full so its icon can't be shown. Free a menu bar slot and restart CCSync." (A slot is freed in System Settings, Control Center.)
- Flag: differs: macOS only; Windows has no equivalent check.

### 04-006: Clicking the icon opens the menu, and notifications appear as the operating system's own messages headed with the product's name and mark.
- Where: editor-app / The tray or menu-bar icon and its menu
- What:
  - Windows: right-click, left-click and double-click all open the same menu at the pointer; if the click lands on the taskbar (for example an auto-hiding one) the menu is moved clear of it, whichever edge the taskbar is on. Greyed rows cannot be clicked; rows with an on/off state show a tick. An empty group of items never leaves a stray divider. Notifications show the product name and mark as their header, and the taskbar shows the product's own icon for the app's windows.
  - macOS: the item sits in the menu bar; clicking it opens the menu.
  - A notification longer than 250 characters is shortened by cutting the middle and keeping its last sentence, so the closing instruction survives; its title is cut to 60 characters. Notifications raised before the icon has appeared are held (the five most recent) and shown once it does. On macOS, line breaks inside a notification become spaces.
  - On any other operating system there is no icon and no notifications; syncing continues.
- Flag: differs: Windows opens the menu on any click and moves it clear of the taskbar; macOS uses the standard menu-bar click.

### 04-007: Hovering over the icon shows one short line saying what this computer's syncing is doing.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: The line is at most 127 characters (Windows cuts there). The first that applies is shown:
  1. "CCSync: NOT SET UP (nothing syncs)".
  2. Sync drive absent: "CCSync: PAUSED (<phrase>)", or "CCSync: PAUSED (<phrase>, <what is owed> still to go)" when something is still owed. The phrase is "drive disconnected", "the drive is mounted at the wrong place" or "the drive is not answering".
  3. "CCSync: not signed in (nothing syncs)" when sign-in is required.
  4. "CCSync: PAUSED".
  5. "CCSync: PROBLEM with <kind of transfer>", where the kind is "Uploads", "Proxies", "Everything else, both ways" or "Originals you asked for".
  6. Something moving: "CCSync: syncing · <end of the project's name, about 40 characters> · <speed>/s · <time> left".
  7. The reason sync is blocked: "CCSync: <sentence>", shortened in the middle so its closing instruction survives.
  8. "CCSync: waiting, not connected to the server (N files owed)".
  9. Files that will never upload because the server holds a file of the same name and a different size: "CCSync: will not upload <up to three names with sizes>", for example "A001.mov (yours 4.2 GB, the server's 3.1 GB)".
  10. A YouTube download running on this computer: "CCSync: downloading YouTube clip 3/12 (...)".
  11. Otherwise "CCSync: up to date".

### 04-008: The hover line also mentions proxies being made, indexing, and further Resolve counts when there is room.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: Added only when the whole line stays at or under 120 characters, and only to "syncing" and "up to date":
  - proxies: " · making N proxy files" (or " · making proxies") plus ", next at P%" for the furthest clip in progress; otherwise " · N need proxies" / " · 1 needs a proxy";
  - indexing, b-roll before music, one only: " · fetching the <b-roll|music> model P%" while the indexing model downloads, or " · indexing <b-roll|music> D/T";
  - Resolve (on "up to date" only): the counts that did not fit on the menu's Resolve line, " · Resolve: <phrases>".

### 04-009: The menu says who is signed in and offers sign-in when needed.
- Where: editor-app / Signing in, the computer's identity and the licence
- What: A greyed line "Signed in as <username>" or "NOT SIGNED IN". When nobody is signed in, an item "► Sign in… (nothing syncs until you do)" (plain "Sign in…" when the site does not require sign-in). When the dashboard has refused this computer's credentials ten or more times in a row, an item "► Sign in again (the server rejected this computer's sign-in)". Both open the sign-in window. Signing out is not on the menu; it is in the settings window.
- Flag: several ways in: the menu's sign-in item, the menu's sign-in-again item, and the settings window's sign-in and sign-in-again buttons all open the same window.

### 04-010: The menu shows a not-set-up warning while this computer's configuration is broken.
- Where: editor-app / Telling the editor what is wrong
- What: A greyed line "⚠ NOT SET UP: nothing will sync (Settings > HELP > COPY DIAGNOSTICS FOR YOUR ADMIN)" while the computer is not set up.

### 04-011: The menu's prompts appear only while they apply.
- Where: editor-app / The tray or menu-bar icon and its menu
- What: Each of these is present only while its condition holds; the group can be empty:
  - "► Accept the licence agreement to start syncing…" while the licence blocks syncing (04-090);
  - "Set up '<project name>' on the server…" while the project open in Resolve has no home on the server (04-091);
  - "► N LUT(s) only on this computer: share with the team" (04-013);
  - "► Resume proxy download…" (04-042);
  - "► Clear the sync stop on this computer (set today at 14:32)" (04-043);
  - "► Stop the YouTube download" (04-016);
  - an offered build of the app (04-017).

### 04-012: The menu's "Sync:" line says in one phrase what syncing is doing now.
- Where: sync / Saying truthfully what the sync is doing
- What: Always present. The first that applies:
  1. A stop is in force: "Sync: stopped by your admin" (a studio-wide stop) or "Sync: stopped on this computer", with " (and paused)" when a pause is also set.
  2. Proxy download stopped itself for safety: "Sync: proxy download stopped (see Settings)".
  3. Not set up, or licence not accepted: "Sync: not set up yet".
  4. Drive absent: "Sync: paused (<phrase>)" or "Sync: paused (<phrase>, <owed> still to go)".
  5. "Sync: paused".
  6. The reason sync is blocked: "Sync: <sentence>".
  7. Moving: "Sync: up U · down D files · 4.2 MB/s", "Sync: uploading N files · <rate>" or "Sync: downloading N files · <rate>". The rate is in megabytes per second (decimal) with one decimal.
  8. Waiting: "Sync: waiting, not connected to the server (N files owed)" when everything waiting needs a server that is not connected, otherwise "Sync: N files waiting", with " (not connected to the server)" if part of it lacks a connection.
  9. "Sync: up to date".
  - When both a stop and a pause are set, an extra line: "⚠ Two things are stopping sync on this computer: your admin's stop and a pause." or "⚠ Two things are stopping sync on this computer: a stop and a pause. Clear both to sync again."
- Flag: built twice: the hover line (04-007), this line and the settings window (04-057) each restate the same "blocked" and "waiting, not connected" sentences.

### 04-013: The editor is offered to share LUTs that exist only on their computer.
- Where: resolve-on-the-editors-computer / Colour look-up tables (LUTs)
- What: While Resolve's own LUT folder on this computer holds LUTs the studio's shared LUT library does not, the menu shows "► N LUT(s) only on this computer: share with the team"; clicking copies them into the shared library. The same action is available from the settings window.
- Flag: several ways in: the menu item and the settings window.

### 04-014: The menu's Resolve line says whether the app can see Resolve and what is wrong in the open project.
- Where: resolve-on-the-editors-computer / Connecting to Resolve's scripting: launch, stalls and death
- What: Absent until the app has tried to talk to Resolve. Otherwise:
  - "Resolve: not answering for N s (<what it asked>)" when Resolve has not answered for over 20 seconds;
  - "Resolve: connected", or "Resolve: connected - <up to two counts>", the counts being (zero counts left out) "N clips outside the tree", "N missing", "N on the wrong drive", "N other projects with clips only here", "N proxies not attached", "N clips still on a preview copy"; further counts go to the hover line;
  - "Resolve: not connected right now (<reason>)" if this computer has connected before;
  - "Resolve: NOT CONNECTED this session (<reason>)" if it never has; when the reason is that scripting is switched off in Resolve, advice about Resolve's scripting preference is shown instead.

### 04-015: The menu shows lines for originals being fetched, YouTube work, forced fleet work and b-roll that could not be indexed.
- Where: editor-app / Telling the editor what is wrong
- What: Each present only while it applies:
  - originals the editor asked for: for example "Bringing originals: 12 of 80, 140.0 GB to go";
  - a YouTube download on this computer: "Downloading YouTube clips" (total unknown), "Downloading YouTube clip 3/12 (4.2 MB/s, 38%)" (speed and percentage only when known), or "Converting YouTube clip 3/12 to <a format Resolve can decode>" while a clip Resolve could not decode is converted; the clip number is done plus failed plus one, never above the total;
  - "Waiting for you to finish signing in in the browser (240 s left)" (no countdown when unknown) during a YouTube sign-in;
  - "CCSync is <transcribing|transcoding|running a job> for the fleet while you work because <reason>", only when an admin forced a job onto this computer;
  - a warning that this computer could not install the helper the downloader needs to process video;
  - "N b-roll clips could not be indexed: <first file name> (<reason>), and M more" (or "... could not be indexed. See the log" when the reasons are unknown).

### 04-016: An editor can stop a YouTube download running on their computer, and the server finishes it.
- Where: youtube / Where a download runs, and saying so
- What: While a YouTube download runs on this computer the menu offers "► Stop the YouTube download". It stops the local downloads and says "Stopped. The server will download the clips this computer did not finish." If stopping fails: "CCSync could not stop the download. Tray > Settings > HELP > COPY DIAGNOSTICS FOR YOUR ADMIN."

### 04-017: When the dashboard offers a different build of the app, the editor can install it from the menu or the settings window after a confirmation.
- Where: releases-and-updates / Installing an update on an editor's computer
- What:
  - Menu wording: "Update available → v<version> (install)" for a newer build, "Roll back to v<version> (older build, install)" for an older one, "Switch to v<version> (install)" for a different build of the same rank; followed by " - <first line of the release notes>" when there are notes. The settings window shows the same button.
  - Refused while another app window is open: "Can't update while a CCSync window is open. Close it and try again." Nothing happens if there is no offer.
  - The confirmation: newer: heading "► UPDATE COMPANION", "Update to v<version>? The companion will restart itself.", button UPDATE. Older: heading "► ROLL BACK COMPANION", "Roll back to v<version>? That is OLDER than the v<current> on this machine. You would LOSE whatever v<current> fixed. The companion will restart itself.", button ROLL BACK. Same rank: "Switch to v<version>? You are running v<current>. The companion will restart itself.", button SWITCH. The full release notes follow under "What is new in v<version>:". If anything is syncing: "A sync is currently running. It will resume automatically after the restart." Buttons CANCEL and the action; Enter confirms, closing the window cancels.
  - If the window cannot be opened, nothing is installed: "Couldn't open the update window, so nothing was changed. Restart CCSync and try again."
  - If installing fails: "Update failed. You're still on v<version>, nothing is broken. Tray > Settings > HELP > COPY DIAGNOSTICS FOR YOUR ADMIN."
- Flag: several ways in: the menu item and a button in the settings window.

### 04-024: The editor can restart the app from the menu or from the settings window.

- What: "Restart CCSync" on the menu and "RESTART CCSYNC NOW" in the settings window (always present) both restart the app. Refused while an app window is open or media is being copied in: "Can't restart while a CCSync window is open or media is being copied in. Try again once it's done." If the restart fails, nobody is told.
- Flag: several ways in: the menu and the settings window, behaving the same.

### 04-025: The editor can quit the app, and is warned first if media is being copied in.
- Where: editor-app / Starting, staying running and crashing
- What: The item reads "Quit CCSync (nothing syncs until you start it again, or log in to this computer again)". If a FIX ALL copy is running it first asks:
  - Windows: a box titled "CCSync" with Yes/No: "CCSync is copying file I of N files into your synced folder. Quitting now abandons the file it is on. The rest of the batch is not copied and Resolve is not repointed at it. Quit anyway? [ Yes ] quits. [ No ] keeps copying."
  - macOS: an alert "CCSync is still copying" with "Quit anyway" and "Keep copying" (the default); it gives up after 120 seconds.
  - Without a file number or total the wording becomes "CCSync is copying N files into ...", "CCSync is copying a file into ..." or "CCSync is copying files into ...".
  - If the app cannot tell whether a copy is running, or cannot show the question, it quits.
- Flag: differs: Windows asks Yes/No with no time limit; macOS defaults to keep copying and gives up asking after 120 seconds.

### 04-031: The editor can sign in to YouTube in a private browser window so age-restricted and blocked downloads work on their computer.
- Where: youtube / Signing in to YouTube
- What: The app looks for Edge or Chrome on the computer.
  - None found: "No Edge/Chrome found for the one-click sign-in: choose an exported cookies file instead", and the file chooser for an exported browser cookies file opens (04-032).
  - Found: "<browser> is opening. Sign in to YouTube in that window; it closes by itself when you're done. Close the window to cancel." A private window opens on Google's sign-in page and the menu shows the waiting line with a countdown (04-015).
  - The browser window crashing: "The sign-in window failed unexpectedly." plus a pointer to using an exported cookies file instead.
  - Running out of time: "The sign-in did not finish in time. Nothing was saved: try again from Tray > Settings > Sign in to YouTube."
  - Success or any other failure: a message saying what happened.
  - The settings button reads "Sign in to YouTube (for downloads)…" (never signed in), "YouTube: signed in ✓ (sign in again…)" (working) or "Sign in to YouTube again (session expired)…" (stale or expired).

### 04-032: The editor can instead give the app a cookies file exported from their browser.
- Where: youtube / Signing in to YouTube
- What: A button "Use an exported cookies file…" opens the system file chooser titled "Choose your exported YouTube cookies file", showing text files or all files. Cancelling does nothing. ### 04-036: The editor can remove a project from their computer only once its work has reached the server, or by typing its name to override.
- Where: sync / Deletions and removing a project
- What: Started from a "REMOVE '<folder>' FROM THIS COMPUTER…" button per removable project in the settings window (" (upload only)" is added before "FROM" for upload-only projects).

  - Not ready: heading "► project not ready to remove". "'<project>' is NOT ready to be removed." then each reason as a bullet, then "Deleting it now would destroy work that exists nowhere else. Leave CCSync running until this finishes, then try again. If you have to delete it anyway (a dead server, a full disk), type the project's folder name exactly to confirm:" and the name.   - Ready: "Remove '<project>' from THIS computer? Proxy folders are not counted, because the server makes those again." then "Tick the project again any time to sync it back." Button "REMOVE FROM THIS COMPUTER".

- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: One window per batch of such clips. Several uses of the same file in the timeline (compared ignoring letter case) are one row, and fixing it relinks every use. Heading "► MEDIA OUTSIDE PROJECT TREE", then "N timeline clips live outside <sync folder> and will NOT sync. Pick a destination. FIX ALL copies them in and relinks Resolve. Your original file is left exactly where it is. Nothing is moved or deleted." The window stays on top, fits within 80 % of the screen's height and 90 % of its width, and only the list of rows shrinks to fit. The action buttons sit above the list so they stay reachable with many rows.

### 04-077: Each clip outside the synced folder is given a suggested destination that the editor can change.
- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: The suggestion is the first of: the destination the dashboard remembers for that Resolve project (matched by name, ignoring case); a project folder whose name matches the open Resolve project; the project this computer is set to work in; the top of the synced tree, under the editor's own folder. Per row: the clip's name, its full path, and "  dest:" with a drop-down of destination folders (built from the row's project and the editor's name) that also accepts typed text. When the destination is outside every project a red line appears under the row, updating as the editor picks or types: "This folder is outside every project and will not sync. Pick one under Projects to share the copy." It warns but does not stop the copy.

### 04-078: The window warns about free space and about cloud files that must download first.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What:
  - "N clips, X GB in total. This computer has Y GB free.", in red with " That is not much room. Everything copied in is also uploaded to the server." when the batch is over 90 % of the free space. Shown only when sizes can be measured; it never stops the copy.
  - "N of M files are online-only in your cloud drive and have to download before they can be copied. That happens automatically, but it can be slow, so the bar will sit at 0% for those while they download." (Cloud drives that keep files online-only, such as Google Drive or OneDrive, behave this way.)
  - In rehearsal: "FIX ALL is in rehearsal mode on this computer and will copy nothing." (04-073).

### 04-079: The editor can put off every clip in the window for 30 minutes.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: "SKIP FOR 30 MINUTES" skips every row for 30 minutes and closes the window. It does nothing while a copy runs. Skipping a single file during a run never puts it on the 30-minute list.

### 04-080: FIX ALL copies every listed clip into the synced folder and repoints Resolve at the copies, showing progress and letting the editor stop, skip or cancel.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What:
  - "FIX ALL" starts. FIX ALL and SKIP are disabled; the status reads "Copying N files in. Your originals stay exactly where they are. Nothing is moved or deleted." (plus the cloud warning when relevant).
  - Progress, updated continuously: a file line and bar, `Copying "<name>": 4.1 GB of 12.7 GB · 33 MB/s · ~4 min left` (while a cloud file downloads: `Waiting for your cloud drive to download "<name>" (<size>). This can take a while`; in rehearsal: `Checking "<name>"`), and a batch line and bar, "File I of N: X GB of Y GB done" (or "File I of N"; in rehearsal the batch bar counts clips). Speed is measured over the last 6 seconds. Time left reads "almost done", "~N sec left", "~N min left" or "~Nh Mm left".
  - "STOP AFTER THIS FILE": "Stopping after the current file finishes. Please wait."
  - "SKIP THIS FILE": "Skipping the file being copied now. The half-copied file is deleted and the rest of the list carries on." Nothing is relinked for it.
  - "CANCEL ALL": "Cancelling. The file being copied now is abandoned and its half-copied file deleted. Everything already copied in stays." All three buttons are then disabled.
  - Closing the window during a run means CANCEL ALL; the window closes once the copy has really stopped.
  - "RETRY FAILED" is hidden until a run leaves failed, skipped or part-way rows; it re-runs only those, with the same destinations.

### 04-081: A clip is not copied if the editor has switched to a different Resolve project since it was listed.
- Where: resolve-on-the-editors-computer / Knowing which project is open
- What: Before each file the open project is checked. A clip listed from another project is refused: "Not copied. This clip belongs to the Resolve project "<A>", but "<B>" is open now. Open "<A>" and press FIX ALL again." When either name is unknown, nothing is refused.

### 04-082: When FIX ALL finishes, the editor is told what was copied, what failed and how to undo.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What:
  - All done cleanly: the window closes and a notice "media copied in" says "Fixed N of M, copied X.X GB" (decimal gigabytes; a copy reused from an earlier run is not counted), "Will not sync: <names>. Its/Their copy/copies are outside every project, so it/they stay on this computer and never reach(es) the server or other editors." for copies outside every project, and "To undo: Settings, RESOLVE, [ UNDO LAST FIX ]" when anything was relinked.
  - Otherwise the window stays open, FIX ALL and SKIP come back, RETRY FAILED appears if anything can be retried, and the status shows:
    - "N of M copied in, P stopped part way, S skipped by you, F failed", starting "Stopped: " and ending ", K left alone" when stopped early;
    - in rehearsal: "REHEARSAL: nothing was copied. N files would be copied into <folder>." (plus " Stopped: K left alone."), up to 12 lines "<name> would be copied to <path>", "… and N more (see Tray > Settings > OPEN LOG)", and "FIX ALL is in rehearsal mode on this computer and will copy nothing. Turn it off in Settings, ADVANCED, [ TURN REHEARSAL OFF ].";
    - copied but not repointed: up to 12 lines "■ <name>: <message>", then "Press RETRY FAILED to finish repointing them. The copy is not made again.";
    - skipped: "You skipped: <up to 6 names>. Nothing was copied in or relinked for them, and the half-copied files were deleted. Press RETRY FAILED to try them again.", and if a half copy could not be deleted: "⚠ CCSync could NOT delete the N half-copied files: <paths>. Please delete them by hand.";
    - failed: up to 12 lines "✗ <name>: <reason>", "… and N more (see Tray > Settings > OPEN LOG)", and for cloud files "These are online-only cloud files. Make them available offline in your cloud drive, then press RETRY FAILED.";
    - only stopped: "Nothing was moved or deleted.";
    - the "Will not sync" line and the undo pointer as above.

### 04-083: If the window cannot be shown, the clips are put off for 30 minutes and nobody is told.
- Where: resolve-on-the-editors-computer / Clip paths and media outside the shared tree
- What: With no display, every clip is skipped for 30 minutes and nothing else happens; nobody is told.

### 04-084: Bringing a whole project's media into the synced folder shows a progress window with the same controls as FIX ALL.
- Where: resolve-on-the-editors-computer / Fixing media: copying in, rehearsals and undo
- What: Stays on top; a heading and an optional second line. The same file line, batch line and bars as FIX ALL; a later step (for example uploading) shows its own headline instead of the file line. In rehearsal the file bar stays empty and the batch bar counts clips. Buttons "STOP AFTER THIS FILE", "SKIP THIS FILE" ("Skipping the file being copied now. Carrying on with the rest…") and "CANCEL ALL" ("Cancelling. The half-copied file is deleted; everything already copied in stays…"); closing the window means CANCEL ALL. It closes itself when the work ends. With no display the work still runs and nobody is told its progress.

### 04-085: The editor can watch long background work (proxies, b-roll indexing, music indexing) in a window and pause, resume, start or cancel it.
- Where: editor-app / Windows, dialogs and notifications
- What: Opened from the "SHOW ... PROGRESS" buttons. Not forced on top. Heading and optional second line, then three labelled bars: what is being fetched (for example the indexing model), the current item ("<label> - P%"), and overall ("D of T clips · F failed · ~12 min left", or "estimating…" until 2 items are done; "tracks" for music). Time left follows recent items more than old ones. A note line, and in red up to 5 failures "✗ <name>: <reason>" plus "and N more". Buttons PAUSE, RESUME, START NOW and CANCEL, each enabled only when that action is possible. Updates several times a second. Closing the window leaves the work running and it can be reopened; when the work finishes the window closes itself 4 seconds later. Only one copy of each such window opens at a time.

### 04-086: Confirmations default to the safe answer and the keyboard works the same in every window.
- Where: editor-app / Windows, dialogs and notifications
- What: A confirmation has a heading, its text, CANCEL (or another chosen label) and the action. It stays on top; the focus starts on CANCEL; Escape cancels; Enter does NOT confirm; closing the window cancels; if it cannot be shown the answer is cancel. A notice has one OK button; Enter and Escape both close it. In every window Tab reaches each button, Enter (including the keypad Enter) and Space press the focused one, and a disabled button ignores them. Every app window shows the product mark as its icon, as does its taskbar button on Windows.

### 04-087: Counts, sizes, durations and directions are worded the same everywhere in the app.
- Where: whole-product / Wording
- What: Real plurals ("1 file", "3 files"), never "file(s)". Sizes as "512 B", "1.5 KB" up to "TB". Durations as "<1 min", "45s", "~12 min", "~2h 5m". The same words as the dashboard for each kind of movement: upload, proxy download, originals download, folder sync, express upload. A message that sends the editor somewhere names the place the control lives, in one consistent style. Notification titles carry the site's name (or the product's when the site has none).

### 04-088: The licence window shows the whole licence text and lets the editor accept or decline.
- Where: accounts-privacy-legal / The licence a person accepts
- What: Heading "► licence agreement" and the introduction "This computer is NOT SYNCING until someone here accepts the <product> licence agreement (version <current version>). Read it below. Accepting records your agreement on this computer only, and syncing starts straight away." then the full licence in a scrolling, read-only box (shown cleaned of authoring notes and markup). Declining: "NOT SYNCING: the licence agreement was not accepted. Tray > Accept the licence agreement." A failed save: "Couldn't save your acceptance. Check disk space and try again."

### 04-089: The b-roll ingest page can ask the editor's own computer to pick clips or a folder of clips.
- Where: broll / Bringing new footage in
- What: The page asks the app on the editor's computer to open a system chooser: a folder chooser titled "Choose a folder of clips to index" (the whole folder and its sub-folders are offered, video files only, each with its size and sub-folder) or a multi-file chooser titled "Choose clips to index". At most 2,000 files are offered; beyond that only the first 2,000. Only one chooser opens at a time; a second request gets the first one's answer. Refused while another app window is open: "Another CCSync window is open on this computer. Close it, then choose again." The page waits up to 5 minutes; after that, on Windows the chooser is closed as if cancelled, on macOS it stays open and a later choice is thrown away.
- Flag: differs: on macOS a chooser left open past 5 minutes stays on screen and its answer is lost.

### 04-090: Nothing syncs on a computer until someone there has accepted the current licence, and a new licence version asks everyone again.
- Where: accounts-privacy-legal / The licence a person accepts
- What:
  - The licence window opens by itself 3 seconds after start whenever this computer has not accepted the current version; if another app window is in the way it tries again every minute until it has been shown once, whatever the answer. It can be opened again any number of times from the menu item "► Accept the licence agreement to start syncing…" and the settings button. The first-run set-up shows the same licence and is usually where it is first accepted.
  - Syncing may run only when the accepted version is the current one or later (versions compared number by number).
  - Refusals, shown in the menu and the settings window: "The CC Sync licence agreement has not been accepted on this computer." / "The licence acceptance record on this computer is unreadable." / "The CC Sync licence agreement has been updated (version <new>; this computer accepted <old>).", each followed by where to read and accept it.
  - A new version of the licence puts every computer back to not syncing until it is accepted.
  - The dashboard is told which version this computer accepted and when; with no usable acceptance it is told nothing ("not reported", not "not accepted").
  - If the licence text cannot be read: "NOT SYNCING: this build is missing its licence document. <diagnostics route>."
- Flag: several ways in: opened automatically, from the menu and from the settings window.

### 04-091: When the project open in Resolve has no home on the server, the editor is asked once to set it up and can do it later from the menu.
- Where: editor-app / Windows, dialogs and notifications
- What: Asked only once ever per project (names compared ignoring case, remembered across restarts), and only while that project is the one open; if another app window is open, it waits and asks later. The question "NEW PROJECT": "Project '<name>' isn't set up on the server. No media will sync for it until it has a home. Set it up now? (Opens the dashboard in your browser.)" Button "SET UP NOW" opens the dashboard's project set-up page with the Resolve project's name filled in. Declining, closing, or having no display counts as asked, and the notification says "You can set up '<name>' later: open the CCSync menu and choose Set up '<name>' on the server." While the project still has no home the menu item "Set up '<name>' on the server…" opens the same page with no question. When the dashboard stops naming it, or another project is opened, the item goes.
- Flag: several ways in: the one-time question and the menu item.

### 04-092: A site can replace the product mark with its own logo on the icon and every window.
- Where: whole-product / Windows, text and names
- What: The default mark is the Creators Club mark. A site can supply its own logo for every computer without reinstalling; a single computer can also be given its own, which beats the site's. The logo must be white on transparent (a coloured logo comes out as a solid shape in the status colour). The icon and every window's icon change together. On Windows, notifications are headed with the site's product name (CC Sync by default) and the mark.
- Flag: several ways in: set for the whole site, or overridden on one computer.

### 04-093: Two hatches exist only for the people building the app.
- Where: whole-product / The rebuild itself
- What: In a run from source, the icon can be switched to an alternative implementation; the shipped app ignores this. A diagnostic switch writes a detailed account of every open window to the log after each window closes. Nobody using the product meets either.
- Flag: dev only

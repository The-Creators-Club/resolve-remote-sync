# G0 ledger: database (legal-gap features, wave 0)

2026-09-25. Plan: `docs/LEGAL_GAP_FEATURES_PLAN.md` revision 2, Tier 1 + Tier 2a,
recommended defaults for every decision. Built against acdcfba (schema v58).
No version bumped, nothing committed.

## What was built

All in `dashboard/src/ccsync_dashboard/db.py`, plus the new
`dashboard/tests/test_legal_db.py`.

### Schema v59 (`SCHEMA_V59`, step 59)

Four nullable `machine_state` columns: `report_optouts`, `report_optouts_local`,
`report_via` and `eula_json`. Nothing is backfilled, so NULL means "not
reported". The step is idempotent through `_already_applied`. It was tested on
a fresh database, on a v58 database, run twice, replayed after an
interruption, and refused by an older image. The pseudonym salt is a `meta`
row (`pseudonym_salt`), not a column.

### LG-1: telemetry switches

- `REPORT_CATEGORIES` holds the four names.
- `clean_report_categories(names)` keeps only known names, returns them
  sorted, and adds `media_tree` whenever `resolve_project` is present.
- `apply_report_optouts(conn, editor, machine, withheld, local)` stores both
  columns and runs the clearing in the plan's §4.1 table:
  - `resolve_project`: NULLs `resolve_project` and `cap_resolve_project`,
    deletes the `resolve_health:` meta row, and blanks `project` in the stored
    `resolve_journals`.
  - `local_manifest`: deletes `editor_media` and `editor_media_project`, and
    drops only the path keys from the meta row. `sync_conflicts` keeps its
    count.
  - `media_tree`: deletes `media_tree_clips`.
  - `input_idle`: NULLs `cap_idle_seconds`.
  - It deletes the machine's diagnostics bundles when a category is **newly**
    withheld.
  - It returns `{withheld, newly, deleted}`.
- `apply_site_optouts(conn, names)`:
  - `names` is the site's **full** set, not a change list.
  - It recomputes every machine's union with its own list, then clears every
    machine. That includes machines with no `machine_state` row that still
    have media rows.
  - It deletes all diagnostics when a category is newly withheld at site
    level, and records the applied set in `meta['site_report_optouts']`.
- Readers:
  - `withheld(conn, editor, machine) -> set[str]` is the predicate the plan
    names.
  - `withheld_map(conn)` answers for the whole fleet at once, which is the
    shape `alerts.py`'s Ctx needs.
  - `machines_withholding(conn, category)` returns the machines that withhold
    one category.
- **File-move rule.** `file_move_target_machines` adds every machine that
  withholds `local_manifest`, for a move in an **active** project, ticked or
  not. Wired machines (`base_machines`) are excluded.
- **Backlog.** `fetch_sync_backlog(..., include_not_reported=False)` is
  unchanged by default. With True it adds one row per ticked active project
  of each opted-out machine, with `not_reported: True` and `n_files`/`bytes`
  set to None, never 0. Wired machines are excluded.

### LG-2 and LG-3: subject registry, export, erase, delete

- **The registry.**
  - `SUBJECT_TABLES` has 36 rows. Each is a `SubjectTable(table, match_sql,
    kind, columns_excluded)`, with `match_sql` bound to a single `:username`.
  - Excluded columns: `users.password_hash`, `editor_report_tokens.token_hash`,
    `companion_packages.signature` and `site_settings.value`.
  - `NOT_SUBJECT_TABLES` holds `triage_replies`, with its reason.
  - `OTHER_STORE_SUBJECT_TABLES` maps each other store's person tables to the
    helper that covers them: `sessions`, `ytdl`, `broll`, `music` and
    `client_shares`.
- **The coverage test** reads every schema the plan lists:
  - the migrated dashboard database;
  - `sessions.SCHEMA`;
  - ytdl, broll and music, from `schema.sql` plus `migrations/*.sql`;
  - `client_folders.py`.

  A planted `editor_username` column fails it.
- `fetch_subject_rows(conn, username)` is the dashboard-database half of the
  export, with the secret columns dropped. G3 can use it directly.
- `purge_subject_history(conn, username)` deletes the `history` kind only:
  `lane_report_history`, `transfer_history`, `completion_history` and
  `missing_files` (through the person's devices), and `diagnostics`. It
  touches no `current` row.
- `pseudonym_salt`, `pseudonym` and `machine_pseudonym` produce
  `deleted-user-<10 hex>` and `deleted-machine-<10 hex>`, an HMAC-SHA256 with
  a salt that never rotates.
- `pseudonymise_subject(conn, username, machines, *, keep_actor)`:
  - rewrites whole words in `fleet_audit.subject/detail_json`,
    `alert_log.subject/detail` and `notices.subject/body/fix`;
  - replaces exact values in the "who did it" columns of rows that outlive
    the person (jobs, file_moves, resolve_undo_requests, and the rest listed
    under departures);
  - replaces `jobs.claimed_machine` and `target_machine` for their machines;
  - on a notices UNIQUE(kind, subject) collision, keeps the newer row;
  - leaves alone any machine name that another person also uses.
- `forget_editor(conn, editor, *, was_admin=None)` now:
  1. collects every machine name the person reported under;
  2. runs `purge_subject_history` first;
  3. runs the existing deletes;
  4. pseudonymises.

  It returns `pseudonymised` and `pseudonym` as well. `was_admin=None` reads
  `users.role`.
- `delete_revoked_report_tokens(conn, editor)` deletes revoked rows only.
- `prune` deletes `editor_report_tokens` whose revocation is more than
  `REVOKED_TOKEN_MAX_AGE_DAYS` (180) old.

### LG-4 and LG-5

- `set_machine_report_via(conn, e, m, via) -> bool` writes only when the value
  changes, and refuses anything outside `REPORT_VIA_VALUES`.
  `report_via_map(conn)` gives the whole fleet.
- `set_machine_eula(conn, e, m, block)` stores only `version`,
  `accepted_at` and `eula_sha256`. An absent section leaves the column alone,
  and a block with no version is ignored. `machine_eula_map(conn)` gives the
  whole fleet.

### LG-17: retention overdue

- `kind_start_gaps(conn)` is the per-kind observed cadence. It was factored
  out of `collector_stale_bound`, whose behaviour is unchanged.
- `collector_kind_scheduled(kind, settings)` returns whether the collector
  runs that kind. Without settings, only `SYNCTHING_FREE_KINDS` count.
- `collector_kind_overdue_after(kind, gap, settings)` returns
  `max(180 s, 2 × max(observed gap, configured interval))`.
- `collector_health` changes:
  - each kind gains `overdue`;
  - an ok kind that is scheduled and past its bound turns `amber` with
    `note="overdue"` (an existing note is kept);
  - the result gains a top-level `retention_last_ran`, the `prune` kind's
    finished_at.
  - Red stays red and is never marked overdue.

## Departures from the plan, and why

1. **Triage rows are not in `SUBJECT_TABLES`.**
   - `triage_replies.from_addr` is a mailbox address from `alerts_smtp_to`,
     and the dashboard has no mapping from a username to an email address.
     So no row can be tied to a person.
   - It is in `NOT_SUBJECT_TABLES` with that reason.
   - `triage_runs` and `triage_actions` have no column that names a person.
   - Export already lists triage report bodies under `not_included`.
2. **`setup_tasks` is not in the registry.** It has no column that names a
   person (id, status, detail, at, skipped).
3. **More "who did it" columns are pseudonymised than the plan lists.** Also
   rewritten: `selections.created_by`, `editor_prefs.updated_by`,
   `project_roots.updated_by`, `site_settings.updated_by`,
   `companion_packages.published_by`, `projects.archived_by`,
   `known_editors.suspended_by`, `editor_report_tokens.created_by/revoked_by`,
   `user_profiles.updated_by`, `machine_setting_requests.requested_by`, and
   `machines.*_requested_by`. Reasons:
   - the cleared wording says the person is removed "from the whole product";
   - the coverage test would otherwise find these as person columns that
     outlive the delete.

   The audit `actor` is the only column kept for an admin (safety M5).
4. **Diagnostics are deleted only for the three categories that can ride a
   bundle.** A newly withheld `input_idle` alone keeps the bundles. The plan
   says "a category"; idle time is never in a bundle.
5. **Note J (journals).** The stored journals keep their ids, and `project`
   is blanked. That is correct in both of note J's cases, so G2a's answer
   changes only what the companion sends.
6. **Extra keys in `SubjectTable` rows and `collector_health`.** A few small
   additions on top of the planned names: `withheld_map`,
   `machines_withholding`, `report_via_map`, `machine_eula_map`,
   `fetch_subject_rows`, `kind_start_gaps` and the `retention_last_ran` key.
   Every one of them is additive.

## Review round (2026-09-25)

The adversarial reviewer raised six points. Each one was checked against the
code, and five were reproduced. All six are fixed in `db.py`, each with a
test in `test_legal_db.py` that fails on the first build. The failure for
each is traced in its entry below.

1. **Fixed: pseudonymising rewrote colleagues' records (high).**
   - **Confirmed:**
     - `_word_re` treated `.` and `-` as boundaries and ignored case;
     - every free-text row containing the name was rewritten.
   - **Now:**
     - A `subject` changes only in structured positions, matched exactly and
       case-sensitively: `user`, `user/...`, the machine in `user/machine`,
       and a bare machine subject only on a row already tied to the person.
     - Audit `detail_json` is parsed. Values under the known keys (`editor`,
       `username`, `machine`, `actor`, `requested_by`, ...) change on exact
       match only.
     - Prose changes only on a row that a structured position ties to the
       person:
       - notice body and fix;
       - alert detail;
       - other JSON strings.

       There the pattern is case-sensitive and treats `.` and `-` as part of
       the name: `(?<![A-Za-z0-9_.-])name(?![A-Za-z0-9_-])(?!\.[A-Za-z0-9_-])`.
       A sentence-ending `.` still matches.
   - **Tests:**
     - `alice-b/LAPTOP` and `{"editor":"alice.smith"}` survive, and
       `clear_notice` still clears the notice;
     - a user called `test` leaves "Send a test email" alone while their own
       notice is pseudonymised;
     - a deleted person's machine called `server` leaves the
       `syncthing_unreachable`/`server` notice clearable, while the audit row
       tied to them by `{"editor": ...}` is rewritten.
   - **Trade-off:** a notice or alert whose only link to the person is a bare
     machine subject now keeps that machine name. A bare subject cannot be
     told apart from a collector key, and those rows are transient.
2. **Fixed: the "not reported" rows were unsafe both ways (high).**
   - **Confirmed both failures:**
     - the default hid the machine, so `safe_to_close` said "Safe to close";
     - True raised `TypeError` at `api.py:686`.
   - **Now:**
     - The flag is removed and the row is always emitted, as `lane "a"`,
       `direction "up"`, `kind "original"`, `n_files 0`, `bytes 0`,
       `uncertain True` and `not_reported True`.
     - A (machine, project) that already has a manifest row is not
       duplicated.
     - `build_transfers_view` keeps the row, and `safe_to_close` answers
       "Cannot tell yet".
     - `api.py:949` sums the fleet grid, drops an uncertain zero, and makes
       no claim.
   - **Test:** runs through `api.build_transfers_view` and `ui.safe_to_close`.
   - **Hand-off 6 is withdrawn.** New hand-off 8 below covers the wording.
3. **Fixed: export leaked another owner of the same hostname (medium).**
   - **Confirmed:** a bare machine subject matched through `_MINE`.
   - **Now:**
     - `_SUBJECT_IS_MINE` matches a bare machine subject only through
       `_MINE_ALONE`, which applies the same "shared name" rule as
       pseudonymise, over `machines` and `machine_state`.
     - `fleet_audit` also matches on `detail_json` `$.editor` or
       `$.username`, guarded by `json_valid`. So alice's own
       `machine.update_push` on a shared hostname is still exported.
   - **Test:** a two-owner `MacBook-Pro`, plus a damaged JSON row.
4. **Fixed: `local=None` wiped the stored list (low).**
   - **Confirmed.**
   - **Now:** absent keeps `report_optouts_local`, and `report_optouts` is
     the stored local list plus `withheld`. An explicit `[]` still switches it
     off.
   - **Test:** covers the absent key, then a well-formed report (not newly
     withheld, so diagnostics stay), then `[]`.
5. **Recorded as hand-off 7 (low).** Nothing to change in `db.py`, because
   `apply_site_optouts` is already idempotent on the full set.
6. **Fixed: fast kinds read overdue behind a slow cycle (low).**
   - **Confirmed:** the collector is single-threaded and sequential.
   - **Now:**
     - New `collector_cycle_seconds(conn)` returns the sum of each kind's
       longest recent run.
     - `collector_kind_overdue_after(..., cycle_seconds=)` adds that sum to
       the bound.
     - `collector_health` passes it, and marks nothing overdue while
       `collector_stale` is true, so one fault raises one finding.
   - **Tests:**
     - a 240 s inventory cycle keeps a 15 s kind on time;
     - a stopped collector is stale with no per-kind overdue.
     - The existing retention-overdue test now has a live faster kind: with
       prune as the only kind, being overdue and being stale are the same
       event.

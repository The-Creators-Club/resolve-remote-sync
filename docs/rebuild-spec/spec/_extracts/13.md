# Extract of inventory section 13

## Items

### 13-001: Every page's browser tab is titled with the studio's name and the page's name.
- Where: whole-product / Windows, text and names
- What: The browser tab reads the studio's short name in capitals followed by the page's name (for example "STUDIO: SYNC STATUS"). The studio name falls back in this order: the studio's short name, its full name, the product name the site set, the server's own product name, then "CC Sync". Every page also carries the product's icon for a browser tab and a phone's home screen, and colours a phone's status bar to match.

### 13-002: A person whose sign-in is about to run out is warned on the page before it ends.
- Where: accounts-privacy-legal / Passwords, sessions and failed sign-ins
- What: Every signed-in page knows when that sign-in ends and shows a warning banner as the end approaches. The sign-in page itself shows none.

### 13-003: Pages that refresh by themselves keep what the person had open, folded and scrolled.
- Where: dashboard / Pages that refresh and answer clicks
- What: When part of a page refreshes on its own, every section the person folded open or closed stays as they left it, and an open pop-up sheet inside the refreshed part reopens at the same scroll position. A link to a particular place on a page still scrolls there when that place only arrives a moment after the page loads (once per page load).

### 13-004: A page left open from before a dashboard update reloads itself instead of acting on a click.
- Where: dashboard / Pages that refresh and answer clicks
- What: When a person clicks something on a page drawn by an older version of the dashboard, the page reloads before anything is done, so nothing is written from a stale page.
- Flag: undetermined: the inventory saw only the page's side of this, not the server's check.

### 13-005: Every "are you sure" question looks and behaves the same.
- Where: whole-product / Safety in what the product does
- What: Any action that asks first shows one dialog titled "are you sure" with the question, a Cancel button that has the focus, and "Yes, do it". The two "sign out everywhere" buttons use the browser's own confirmation box instead.
- Flag: differs: signing out everywhere asks through the browser's own box, everything else through the product's dialog.

### 13-006: Tapping or pointing at any state word or status light explains it.
- Where: dashboard / Overview, menus and finding things
- What: Almost every state label, status light and short tag carries a plain explanation. On a desk computer it appears when pointed at; on a touch screen tapping it opens a sheet with the label and the explanation and "tap anywhere to close".

### 13-007: Every signed-in person is told on every page while syncing is stopped across the whole studio, and after such a stop has run out.
- Where: dashboard / Stopping and resuming the fleet
- What: The line is re-read every minute while the page is in view. Nothing is shown while syncing is normal.
  - While stopped: a "stopped" state ("Every computer has stopped syncing because an admin stopped the fleet."), "Syncing is stopped on every computer (N hours so far, M computers in the fleet).", the reason the admin typed, and "Set by <who> <time ago>; it releases itself <in Xh Ym> unless somebody keeps it on." M counts every registered computer, including ones switched off. Hours are whole hours since it was set. The release time reads "any moment now" under one minute, then "in Nm", "in Nh Nm", "in Nd Nh". Admins also get "Start syncing again", which takes them to the stop control.
  - After the stop has run out: an "expired" state, "The fleet-wide stop has expired and syncing has started again everywhere.", "It was set for: <reason>", "Set by <who> <ago>, expired <ago>." Admins get "Take this notice down".
- Flag: several ways in: the same stop is shown on every page, at the top of the computers list, in the stop control itself, as a shortcut on the overview, and named in a person's own settings list.

### 13-008: Times, sizes, time left and progress are worded the same everywhere.
- Where: whole-product / Wording
- What: A time is "never" when there is none, else "Ns ago" under a minute, then "Nm ago", "Nh ago", "Nd ago"; a time with no zone is read as universal time and an unreadable one is shown as written. Sizes go B, KB, MB, GB, TB in steps of 1024 with one decimal above bytes, "-" for none. Time left reads "Ns", "Nm", "Nh MMm", "Nd Nh", "-" for none. A text progress bar is ten (or sixteen) blocks filled in proportion, shown as question marks when the amount is unknown.

### 13-009: Any "fix" sentence that says to send something to support names the site's support contact.
- Where: whole-product / Wording
- What: Wherever a problem's fix says "send us" or "to support", the site's support contact is put in. It is the vendor's contact unless the site has set its own.

### 13-010: People are shown by the display name they chose, wherever they are named.
- Where: dashboard / People and computers
- What: On signed-in pages a person appears under their chosen display name if they have one, otherwise their sign-in name. A display name is only a label: it never replaces the sign-in name in any record.

### 13-011: The main places of the dashboard, and which of them a person sees.
- Where: dashboard / Overview, menus and finding things
- What: A signed-in person can always reach the sync status overview and the transfers view. Each switchable part (b-roll, music, YouTube downloads, Timeline Cards, the Footage Sorter) is reachable only when it is switched on and started without fault; a part that failed or is running degraded gets no entry. Settings are reachable by admins only. The product's mark with the studio name always leads back to the sync status overview. On a phone the main places stay reachable with one hand. When nobody is signed in only "sign in" is offered.
- Flag: several ways in: the same header is also drawn inside the b-roll, music and YouTube parts.

### 13-012: Admins see on every page how many problems and alerts are open.
- Where: dashboard / Problems the server finds
- What: An admin sees "N problem(s)" (open problems of error severity the server found: "the server has found problems it cannot fix by itself"), leading to the list of those problems, and "N alert(s)" (errors plus warnings from the last alert check), which shows whether any is an error, leading to the health summary. Each is absent at zero. The alert count is hidden on small screens.

### 13-013: Every page says how fresh its data is, and warns when it may be stale.
- Where: dashboard / Pages that refresh and answer clicks
- What: Signed-in pages show "updated <time ago>" (the server's own clock when it last answered), re-read every 30 seconds while the page is in view. When the server cannot read the state of project-folder syncing it adds a "stale" warning ("the data on this page may be stale"). On a phone only the warning is shown, never the time. When the server cannot tell, no warning is shown. On the sync status overview the same condition draws a line: "The server cannot reach the project-folder syncing. The numbers below may be old. Nothing is lost: every computer keeps syncing." with a "What to do" link to the recovery help.
- Flag: several ways in: the freshness stamp on every page and the line on the overview.

### 13-014: The account menu: who is signed in, the person's own page, help, the installer and signing out.
- Where: dashboard / Overview, menus and finding things
- What: Shows "signed in as <name> (admin)" and offers: the person's own account page, help, the installer download (the click is the download), sign out, and sign out everywhere, which asks "Sign yourself out of every browser, including this one? You will need to sign in again to finish what you are doing." When the browser offers to install the dashboard as an app, an INSTALL button appears. The person's name (with "@admin" for admins) is shown and leads to their account page; it is hidden on small screens.

### 13-015: The dashboard can be installed as an app and shows an offline page when it cannot be reached.
- Where: dashboard / Phones and the installed app
- What: The installed app carries the site's product name. When the phone or computer cannot reach the dashboard, an offline page shows the studio name and "This device cannot reach the dashboard right now. Nothing here is live: check the network, then try again." with "Try again", which reloads the address that failed (from the offline page itself it goes to the overview). The offline page shows nobody's name. The product's look is kept on the device so the offline page draws properly. A new version of the dashboard is always picked up, never an old copy kept on the device.

### 13-016: Signing in with a username and password.
- Where: accounts-privacy-legal / Who may sign in
- What: The sign-in page shows the studio name and a sign-in box: "Use the username and password your admin gave you.", "Your admin creates this account for you. If you do not have one yet, ask them before installing.", a username box (no automatic capitals or spell check), a password box and "Sign in". The username is trimmed and lower-cased. After signing in the person goes to the page they were trying to reach, but only if it is on this same site; anything else sends them to the overview. A person already signed in who opens the sign-in page is sent straight on, unless they asked to sign in afresh, in which case the form shows with the line "Sign in again to keep this phone or computer working offline for another 100 days." A refusal shows a "refused" state and the message.

### 13-017: A site can use its organisation's single sign-on, with an emergency password door for admins.
- Where: accounts-privacy-legal / Who may sign in
- What: With single sign-on, the sign-in page offers "Sign in with SSO" and hides the password form behind "Single sign-on is configured for this dashboard. Admin sign-in if the identity provider is down." "Admin sign-in" shows the password form under an "admin sign-in" divider. Only an admin may sign in with a password then; anyone else gets the generic refusal.

### 13-018: What a refused sign-in says.
- Where: accounts-privacy-legal / Passwords, sessions and failed sign-ins
- What: Checked in this order:
  - The server has no sign-in secret set: "login not configured on the server".
  - The dashboard is set to secure connections only and was reached over plain http: the page refuses with "this dashboard is configured for https only but you reached it over http. Use the https URL." and the form with "use the https URL".
  - Too many recent failures for this username or from this address: a message naming how long to wait. Unknown usernames are slowed down exactly like real ones.
  - Too many sign-ins being checked at once: "the server is busy checking sign-ins. Try again in a moment." This does not count as a failure.
  - Wrong password, unknown user, or a person who has been deleted (even if their NAS password still works): one message for all, "sign-in refused - check your username and password, then try again". Every failure counts towards the slow-down.
  - Oversized or malformed sign-in requests are refused.

### 13-019: Signing in, signing out and signing out everywhere.
- Where: accounts-privacy-legal / Passwords, sessions and failed sign-ins
- What: A successful sign-in clears the failure count and ends whatever sign-in that browser had before. Signing out ends this browser's sign-in on the server too. Signing out everywhere (signed-in only) ends every sign-in of this person on every device. Both land on the sign-in page, and a real sign-out (not an expired one) also deletes the Timeline Cards episode list saved on that device.

### 13-020: An admin who signs in while required setup is unfinished is taken to the setup wizard.
- Where: server-install-and-running / Settings and secrets
- What: When an admin signs in without asking for a particular page and some required setup step is still outstanding, they land on the setup wizard instead of the overview. Never for an editor. If the server cannot tell, the normal landing is used.

### 13-021: Any signed-in person can download the installer for a new editor computer or to repair one.
- Where: editor-app / Installing and setting up
- What: The download picks the platform from the browser: a Mac gets the macOS installer, Windows gets the Windows one, anything else (Linux, a browser that hides its system) gets a chooser instead of a guess. The download is the full clean-install and repair package, not the bare app, named with its version. The chooser ("INSTALLER", "for a new editor computer, or to repair one") says: "The full clean-install and repair package for a new editor computer. Save it to that computer's own disk: running it off the shared drive locks the file for everyone, and the setup wizard refuses it." On a phone: "On a phone: this package cannot be run here. Download it and send it to the editor's own computer, Windows or macOS, and run it there." Each platform shows its version, size, "published <ago>", a shortened checksum (the full one on pointing), and a download button; the one matching this browser is marked "this computer". With nothing published: "Nothing published for this platform yet." A direct download with nothing published says "No <platform> installer has been published for this fleet yet, so there is nothing to download. Ask whoever set this dashboard up for the installer." plus a line telling admins how to publish one; a published installer whose file has gone says "installer file is missing on the server: re-publish it".
- Flag: several ways in: the direct download and the chooser.

### 13-022: The installer chooser tells editors how to get past the operating system's warnings about an unsigned program.
- Where: editor-app / Security warnings, permissions and certificates
- What: Windows: the beta is not code-signed, so expect "Windows protected your PC"; run it, More info, Run anyway; if there is no Run anyway, open Properties, tick Unblock, OK, run again; Smart App Control must be turned off first. macOS: the program is not notarised; open it once and click Done, then System Settings, Privacy & Security, Open Anyway with the Mac password, open again and click Open; this may repeat after an update.

### 13-023: The sync status overview shows each person what concerns them, and an admin the whole studio.
- Where: dashboard / Overview, menus and finding things
- What: Any signed-in person can open it. An editor sees their own computers plus summary counts of the rest; an admin sees every computer. An admin can look at, and tick for, another person; an editor cannot. The view can be narrowed to one of the chosen person's computers; a computer that is not theirs is ignored. The head reads "N computer(s) · N project(s)". Admins get a "Stop the fleet" shortcut with the explanation "it pauses syncing on every computer at once until you start it again. Nothing is deleted, and the pause ends by itself after 24 hours."
- Flag: several ways in: the shortcut leads to the one studio-wide stop control.

### 13-024: Choosing whose sync plan, and which computer's, a tick changes.
- Where: dashboard / Ticking and unticking
- What: An admin who has other editors can pick "<me> (me)" or any other known editor; picking one clears the computer choice. When the chosen person has more than one computer, a computer choice offers "every computer" or each computer ("A sync plan belongs to a computer, not a person. Every computer ticks or unticks all of them at once."). With exactly one computer it simply says "computer: <name>". It works without scripts too. When acting for someone else a warning reads "acting as <name>: a tick here starts a real sync on their computer".

### 13-025: The project list, and finding a project in it.
- Where: dashboard / Projects
- What: A find box ("find a project", with "/" as its shortcut key) filters as the person types; "No project matches." when nothing does. Projects are grouped into foldable year and show folders, each with its project count; a folder holding the project being viewed starts open. A count line reads "N of M ticked for <computer or person>". The list re-reads every 30 seconds while in view and straight after any tick or untick on the page. Each project name leads to its own project view. Empty: "No projects yet: they appear after the server's first look at the tree."

### 13-026: Ticking or unticking a project from the project list.
- Where: dashboard / Ticking and unticking
- What: Each project has a tick box whenever there is a person to tick for.
  - A computer (or every computer of a person) that is wired to the server cannot be ticked: "<name> is wired to the server: it works directly off the NAS and syncs nothing. Change it on that computer: tray, Settings, This computer." Existing ticks on it stay visible.
  - With one computer chosen: "Tick to sync <project> to <computer> only. Untick to stop it there." With none chosen: "Tick to sync <project> to every computer <person> uses. Per-computer plans: pick a computer above, or Settings, Sync plans."
  - A box always does what it showed: a box drawn unticked only ever ticks, one drawn ticked only ever unticks, so a list that is out of date can never do the opposite.
  - Unticking for a whole person asks: "This removes <project> from <person>'s N computer(s) (<names>). Their copies stay on disk; nothing new comes down and proxy sync stops for it." For one computer: "This removes <project> from <computer>. Its copies stay on disk; nothing new comes down and proxy sync stops for it there."
  - Ticking the project whose view is open, when its proxies may not fit, asks "<space warning> Sync it there anyway?"
  - Tags beside a project: "upload only" (leading to the glossary entry); "link" when a shared folder on the project needs attention; a number with a down arrow when N computers are still catching up.
- Flag: several ways in: a project can be ticked from the project list, the project's own view, the sync queue, a person's own account (per computer), and the sync plan grid; all follow the rules in 13-047.

### 13-027: Four readouts sum up the studio at a glance.
- Where: dashboard / Overview, menus and finding things
- What: Drawn when the page opens and refreshed with the computers list.
  - online: "N / M", M being the computers with at least one project ticked (a wired computer, or one with nothing ticked, is left out) and N those not silent. Underneath: "<computer> not heard from[, and N more]" as a warning; "every computer with a project ticked has reported"; or "no computer has a project ticked".   - in sync: "N / M", M the projects ticked anywhere (by this person for an editor, by anyone for an admin), N those not behind and not getting ready. Underneath: "all caught up", "N still catching up", or "no project is ticked anywhere".

### 13-028: Admins see the problems the server found, each with what to do, and can dismiss one.

After a dismiss, every count and list that includes it re-reads itself.

  - time since its last report.

### 13-031: Banners above the computers list say when syncing is stopped, stopped itself, or paused somewhere.
- Where: dashboard / Each computer's state

### 13-032: The server stops and asks an admin before it stops sending many projects to computers at once.
- Where: sync / Safety stops
- What: When one round would take away more projects from computers than the safety limit allows, nothing is taken away and the computers list shows "refused", "N share removal(s) refused: shares are frozen. ### 13-035: Each computer's row lists what is wrong with it, worst first, each with its explanation.
- Where: dashboard / Each computer's state
- What: Errors first, then warnings; "nothing wrong" when none. Each item carries an explanation:
  - "proxy download stopped itself": "<reason>, stopped <ago>. Upload and folder sync are still running; nothing was deleted."
  - "stopped by your admin" or "syncing paused on this computer", with the reason.
  - "shared-file syncing down <ago>[, N restarts failed]" (not on wired computers): it has been down since <time>, N automatic restarts failed, and whether anything is still trying; last error.
  - "clock <amount> ahead/behind": "this computer's clock is <amount> ahead of/behind the server's. Proxy download uses a minimum file age, so a clock this far out can make it transfer nothing at all while reporting no error. Fix the clock on that computer (enable automatic time)."
  - "stalled: <what>[, killed]": it made no progress for N seconds and was stopped (or reported without being stopped), <ago>; "A local drive that stops answering reads exactly like this." Only while the stall is current.
  - "being refused: sign in on its tray": "the last report from this computer was refused <ago>: <reason>. Nothing below is current. The editor has to click Sign in... on this computer's tray."
  - "update kept crashing": it installed <version>, kept crashing and was rolled back; it will not take that build again on its own; "Do not install it by hand: publish a newer build."
  - "update failed xN": it tried to install <version> N times and failed; "Antivirus quarantine, a proxy mangling the download and a full disk all look like this."
  - "recalled build": the recall reason (or "no reason given").
  - "unverified": "this app has not signed in with verified credentials".
  - "suspended": "an admin paused this person on Settings, Users. Their computers are being turned away and their projects are unshared. Their sync plan is kept: Resume puts it all back."
  - "reverted from <version>": it installed <v>, could not start it, and put itself back on <running>; "That build should not be made current for the fleet."
  - "unfiltered folders: N": N project folders on this computer have no filter keeping camera originals out of shared-file syncing, so originals would travel both ways.
  - "conflicts: N": "Two people saved one project file; nothing was lost, but somebody's edit is sitting in a renamed copy."
  - "N clips outside the tree": the project open in Resolve uses N clips from outside the synced tree[, N of them under the wrong drive letter]; they will never upload, so the timeline opens with missing media on every other computer. Scanned <ago>.
  - "N project(s) with clips only here": N clips exist only on this computer, outside the tree, in Resolve projects it does not have open ('<first three names>'[ and N more]); they never upload until the editor opens each project and presses FIX ALL.
  - "N stray project dirs": N project folders on this disk are not in the synced tree, holding <size>; nothing in them is on the server or visible to anybody else.
  - "project folder moved": N project folders are not where the tree expects; syncing for them looks busy and moves nothing; move it back or use the move on the server and every computer (13-052).
  - "won't upload: N": N files exist on the NAS under the same name at a different size (counted under <subfolder> when known); upload never overwrites a file already on the server, so this computer's newer versions will never go up.
  - "relayed: N": N other computers are reached only indirectly, so shared-file syncing on this computer is limited to about 1-5 MB/s, not the link's speed. Checked <ago>.
  - "orphans: N": <size> of half-uploaded pieces left on the NAS by an interrupted upload; never deleted automatically; remove them by hand to reclaim the space.
  - "express upload failed" with the last error, or "express dropped: N": N files left out of a quick upload by its batch limit still go up on the next regular pass.
  - "crashes: N": N background tasks on this computer crashed and wrote a report; the tray stays up and syncing looks normal, so ask the editor to open the app's diagnostics and send it.
  - "youtube clips waiting for resolve: N" (they are on the disk, nothing is lost) or "youtube import gave up" (they stay on the disk under the YouTube folder and are retried when the app restarts).
  - "N need proxies": N clips on this computer have no proxy yet, so nobody else can see that footage; the state of proxy making and how many are queued.
  - "trash: <size>" (only above 5 GB): N recoverable files in this computer's own trash, removed automatically after 14 days.
  - "ingest staging <size>": footage in this computer's drop folder not yet filed into a project; "It is on one disk."
  - b-roll indexing and music indexing warnings when either reports one.
  - "version unknown" ("this app has never reported its version") or "out of date" ("<platform>: running <v>, current is <v>").

### 13-036: A computer's row warns when its sync drive is running out of space, and explains what happens next.
- Where: sync / Disk space
- What: "disk N%" (shown only when the disk is not healthy): the sync drive has <free> of <total> free and the system drive <free>, measured <ago>. Proxy downloading fills a drive file by file. When the drive drops below its floor, proxy downloading stops and the product's own trash on that computer is emptied oldest first until the drive has twice the floor free, which starts proxy downloading again. A proxy download the safety stop has halted waits for a person to resume it, from that computer's tray or by an admin on the computer's row.
- Flag: differs: older app versions stopped emptying the trash at the floor, so downloading restarted only when somebody freed space up to twice the floor or pressed Resume.

### 13-037: Each computer's row shows the work in progress on it.
- Where: dashboard / Each computer's state
- What: After the issues:
  - "indexing b-roll: done/total" and "indexing music: done/total", with the batch, clip or track, its state, quality level, percent of this item, failures and when reported, on pointing; marked as a warning when indexing reported one.
  - "<kind of shared work>: N%" (or "job N"), leading to the list of shared work, with job number, kind, state, file and last sign of life on pointing.

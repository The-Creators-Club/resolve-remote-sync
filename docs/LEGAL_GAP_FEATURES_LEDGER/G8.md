## Departures from the plan, and why

1. **The licences are shown in the wizard's own window, not handed to the
   OS viewer.** A one-file build extracts to a temp folder that is deleted
   when the wizard exits, so an external viewer could lose the file.
   "Links the file" is met by a button on the last page.
2. **The wizard guards four requests, not only the save.** The plan says
   "http_public cannot be saved". The wizard sends the password (`/verify`)
   before it saves anything, so the refusal sits in `verify_account` itself,
   and in the other three calls, on their worker threads. Only
   `http_public` is refused. `invalid` addresses keep today's behaviour,
   and the probe still names them.
3. **A site-greyed row keeps the computer's own answer on disk**, rather
   than writing `false`. The plan says the effective value is local AND site
   (G1a's `effective`). Writing false would leave the category silently off
   on this computer if the admin later switched the site back on.
4. **The role page may do one DNS lookup on the Tk thread.** This happens
   only for a plain-http name the table cannot judge by its shape, which
   is rare. transport caches the answer for 30 s, so the later pages reuse
   it. Moving it to a worker would have meant a new async state on the
   role page for a rare case.
5. **There is no separate "privacy" section in `ensure_config` for a
   missing page.** Every wizard run passes through the page, and `None` is
   kept for other callers and tests.

# Extract of inventory section 23

## Items

### 23-001: The b-roll archive is reached from the dashboard, behind its sign-in; only client links and the studio's own computers get in without one.
- Where: accounts-privacy-legal / What each person may see and reach
- What: Searching, browsing, playing previews, client folders and adding footage all need a person signed in to the dashboard. The only addresses answered with nobody signed in are the client links (see 23-042) and the calls the app on an editor's computer makes while adding footage, which must prove both the computer and the person it belongs to. A computer whose proof is refused is told "sign in again from the CC Sync tray". When a session runs out while the archive page is open, the next action shows "Session expired, signing in again…" and takes the person to the sign-in page, returning them to the same place afterwards.

### 23-002: The archive can also be run on its own with no sign-in at all, for the people building it.
- Where: broll / Givens: browsers, cameras, files and Resolve
- What: Run outside the dashboard, the archive's search, previews and editing pages answer anyone who can reach them, with no sign-in of any kind.
- Flag: dev only

### 23-003: A site names its own footage and says which collections count as its own.
- Where: broll / How the archive is laid out
- What: Set when the site is set up: the label the folder browser gives the studio's own footage (default "Our Footage"); which collections count as the studio's own footage (besides those the product already knows are its own because the studio added them through the dashboard or archived them as previews only); the top folder of the archive under which shoots added through the dashboard are filed; the organisation name a client sees on a client link (default "CC Sync"); and an optional list of collections with a one-line description of each, shown to editors for information only. Everything that is not the studio's own footage is "Downloads".

### 23-004: Some clips never appear in the archive, whether searching or browsing.
- Where: broll / Search
- What: Never shown: clips that are editors' proxy copies; camera originals in a collection the studio archives as previews only; clips still being added (their media not yet on the server); and clips that are byte-for-byte copies of another clip already in the archive.

### 23-005: An editor searches the archive by words, and finds both what is seen and what is said.
- Where: broll / Search
- What: Typing in the search box searches 250 ms after typing stops and goes back to the first page. Words are separate terms and every term must match; text in double quotes is one exact phrase. Punctuation is taken as plain text, never as search syntax. English words match their other forms ("surf" finds "surfing"). Searched: what is seen (the description, objects, setting, on-screen text in the original and in English) and what is said (the transcript). Chinese is matched so that Traditional and Simplified script find each other, two-character words match, and an unquoted Chinese term of more than two characters also finds clips where its words appear separately; quoting keeps it as one unbroken phrase. Clips are ordered by their single best matching moment. Each result carries up to 20 matching moments, best first, each with its time range, a snippet with the matched words highlighted, and whether it was seen or said.

### 23-006: An editor can narrow a search, and every narrowing applies together.
- Where: broll / Search
- What: Narrowings, all applied at once: a subject category (which includes everything under it, so "military" also finds "military / naval"); "uncategorised", which finds clips that have been described but given no category (not clips still waiting to be described); own footage or Downloads; a shoot, optionally a folder inside it (matched at folder boundaries, so "Day 1" never matches "Day 10"); a folder of a collection (also at folder boundaries); "hide flagged", one tick per quality flag (shaky, soft focus, overexposed, underexposed, noisy, rolling shutter), hiding every clip carrying any ticked flag; and what to search: All, Visuals ("what is seen on screen, including burned-in on-screen text") or Transcript ("what is said (spoken word)"). With Visuals or Transcript, a clip with no match of that kind is dropped. If the studio has no own footage known, the own-footage choice shows nothing and Downloads shows everything.

### 23-007: With no search words, the archive is browsed newest first.
- Where: broll / Search
- What: With the search box empty, every clip allowed by the narrowings is listed, newest added first, with no matching moments, and the total is the full count.

### 23-008: An editor chooses between three ways of searching: words, words plus related meaning, or meaning only.
- Where: broll / Search
- What: Hybrid (the default) shows exactly the word-search results in their order, then up to 5 more clips found only by meaning, always after every word result, under a "Related" heading and with a dashed border; a meaning match on a clip the words already found never changes the order. If the search is mostly Chinese and the words found nothing, no related clips are added. Keyword is words only. Semantic is meaning only, with no limit of 5 and no Chinese rule. Meaning matches count only when close enough. A way the server cannot run is greyed out with its reason as the tooltip. The reasons, word for word: "Meaning-based search is not available on this server: <a part it needs> is missing.", "Meaning-based search is not available on this server: the query model is not installed.", "No clips have been prepared for meaning-based search yet, so it can only find nothing." When meaning search is unavailable, Hybrid carries "Keyword only right now: the meaning-based half of this search is not available." If the page is in a way that cannot run, it switches to Hybrid, searches again and warns "<reason> Switched to Hybrid." or "<reason> Switched to Hybrid, which is searching by keyword only for now."
- Flag: undetermined: whether meaning search is available on the studio's live server at all.

### 23-009: Search forgives misspellings and partial words when the exact words find little.
- Where: broll / Search
- What: A "fuzzy" tick, on by default, works with Hybrid and Keyword. When the exact words find fewer than 5 clips, the search also tries: the start of any word of 5 or more letters ("ambul" finds "ambulance"; shorter words are not expanded); the Chinese word split described in 23-005; and spelling correction, replacing each word of 3 or more letters that the archive has never seen by the closest word the archive does contain, only if it is very close ("ambluance" becomes "ambulance"). Forgiving matches never replace the snippet shown for an exact match.

### 23-010: The search page says while it is searching and when a search fails.
- Where: broll / Search
- What: While a search is running the results are dimmed and "Searching..." shows above them (and screen readers are told the area is busy). Only the newest search's answer is shown; an older answer arriving late is thrown away. A failed search shows "Search failed: <message>".

### 23-011: The way of searching, what to search, the fuzzy tick and hidden flags are forgotten on reload.
- Where: broll / Search
- What: Search words, category, own footage or Downloads, folder, page and open clip are kept in the page's address (23-018); the way of searching, what to search, the fuzzy tick and the hidden flags are not, and go back to their defaults on reload or when the address is shared.

### 23-012: An editor browses the archive through a folder tree with two roots.
- Where: broll / How the archive is laid out
- What: The tree always shows Downloads first, then the studio's own footage, each with its clip count; a root or folder with no clips is left out. Downloads is organised by subject: groups (each a subject name) holding categories, both ordered by clip count, largest first, with "Uncategorised" always last when any described clip has no category; its counts include only fully described clips, while the Downloads total counts every browsable clip, so it can exceed the sum of its folders. Own footage is organised by shoot: one group per collection, largest first, under it the real folders up to 5 levels deep, alphabetical, with proxy folders left out; its counts are exactly what a click shows. A folder shows an expand mark only when it has sub-folders, and its sub-folders show only when it or one inside it is selected; each folder's tooltip is its short name. Clicking a folder selects it; clicking the selected folder moves up exactly one level; clicking a selected root with no folder clears the choice. "clear" ("Show everything") selects nothing. Choosing a folder clears any folder chosen from a clip's path, goes to page 1 and makes a step Back can undo.

### 23-013: A category list beside the search box filters by subject.
- Where: broll / Search
- What: "All categories" plus every category, indented by depth. Choosing one clears any folder chosen from a clip's path, goes to page 1, makes a step Back can undo and searches. It shows blank while browsing own footage, whose shoots are not categories.
- Flag: several ways in: the same subject choice is made from the folder tree's Downloads half, this list, and a clip's category in the clip view (23-019).

### 23-014: A line above the results says what is being shown.
- Where: broll / Search
- What: The line reads, as applicable and joined by " · ": `search: "<words>"`, `folder: <root> / <folder>`, `folder: <collection>/<path>`; or "browsing all videos" with nothing chosen. When a folder from a clip's path is chosen, a "clear folder" link is shown.

### 23-015: Results are thumbnails that scrub on hover and show the best moment of a search.
- Where: broll / The clip player
- What: Each result is a still with the clip's length (m:ss) in a corner and a tooltip "<file name> - <category, or suggested category, or uncategorised>". Stills load as they come into view; a clip with no still shows a "no preview" placeholder. Moving the pointer across a thumbnail shows the frame at that point of the clip (frames are fetched on first touch of the pointer). In search results the thumbnail instead holds the frame of the best matching moment, and returns to it when the pointer leaves. Each thumbnail has a "+" that adds the clip to a client folder without opening it: shown on hover, and always on touch screens or when focused. Clicking a thumbnail opens the clip at its best matching moment (at the start when browsing).

### 23-016: Results come 24 to a page.
- Where: broll / Search
- What: The pager reads "← prev", "<from>–<to> of <total>", "next →". Each press is a step Back can undo.

### 23-017: An empty result says why and offers the likely way out.
- Where: broll / Search
- What: Browsing: "There are no clips in <scope>." where the scope names the root, folder or path, or "the whole archive". Searching: `Nothing matched "<words>" in <scope>.`, then "N clips were searched." (or "1 clip was searched."), then "Try fewer words, or switch to Semantic search, which finds meaning rather than words." If meaning search is unavailable and the way chosen is not Keyword, its reason is added as a warning. Links shown only where they apply: "switch to Semantic search", "clear the folder filter", "stop hiding flagged clips", "turn fuzzy matching back on".

### 23-018: The page's address holds the search and the open clip, so it can be reloaded, shared and walked with Back and Forward.
- Where: broll / Search
- What: The address holds the search words, category, own footage or Downloads, folder, page, open clip and the second the clip was opened at. Reloading or following such a link restores the search and reopens the clip at that second; the highlighted matching moments on the clip's bar are not restored from a link. Back and Forward walk folder choices, pages and clip openings; typing in the search box does not add steps. Links made before the studio's own-footage collection was renamed still open it.

### 23-019: Opening a clip shows its player, details and everything known about it beside the results.
- Where: broll / The clip player
- What: The clip opens beside the results, which keep their place. A "close this clip" control goes back (as Back would). The player has no built-in controls and starts at the matching moment that opened it. Shown: the file name; its path, where the collection and every folder are clickable and show that folder (clearing the search words), then the file name, length and frame rate ("@ ?fps" when unknown); "category: <name>", clickable to show that category (clearing the search words and folder), or "none"; "themes:", each clickable to search for it as an exact phrase; "flags:" listed, not clickable. "Visual segments": each time range (hours:minutes:seconds:frames at the clip's rate, or 24 if unknown), what is seen, on-screen text in quotes and its English. "Transcript", only when the clip has speech: each time range and the words said. Clicking any entry jumps there and plays.

### 23-020: The clip's bar shows the matching moments, the described segments, the playhead and the in and out points, and is dragged to seek.
- Where: broll / The clip player
- What: The bar marks each search match that opened the clip as a band (never narrower than half a percent of the bar; a match with no end is drawn one second long), the start of each described segment as a tick, the playhead, and the in and out points with the range between them shaded. Press-and-drag with the left button seeks to that point, pausing while dragging and resuming if it was playing. Readouts show the current timecode, IN, OUT and the play rate.

### 23-021: Dragging across the picture scrubs; clicking it plays or pauses.
- Where: broll / The clip player
- What: Pressing and dragging sideways on the picture scrubs from where the press began, the full width being the whole clip, once the pointer has moved a few pixels; the picture keeps up while dragging. A click without moving plays or pauses.

### 23-022: An open clip is driven from the keyboard.
- Where: broll / The clip player
- What: Only while a clip is open, not while typing in a field, and not while a panel or the client-folder list is open: Space or K play and pause; L plays forward, and each further L goes 1x, 2x, 4x, 8x; J plays backward the same way, stopping at the start; Left and Right arrows pause and step one frame; I and O set the in and out point at the current position; Enter appends to the timeline (unless a focused button or link takes the Enter); Shift+Enter places at the playhead. A help line reads "space/K play/pause · J/L shuttle · ←/→ ±1 frame · I/O set in/out · Enter append · ⇧Enter place at playhead".

### 23-023: An editor sends the marked part of a clip to the timeline open in Resolve on their own computer.
- Where: broll / Sending a clip to Resolve
- What: Two buttons: "Append to Timeline ⏎" (adds it at the end) and "Place at Playhead ⇧⏎" (places it at the playhead). Both need an in and an out point: without them, "Set both an in point (I) and an out point (O) first."; the two may be set in either order and the earlier is the in; if they fall on the same frame, "Out point must be after in point." The browser hands the request to the app on the editor's own computer, which puts the clip into Resolve; a clip whose frame rate is unknown is sent as 24 fps. Success: the app's own message, or "Sent to Resolve."

### 23-024: The file that lands in Resolve is the original when there is one, and the product says whether it is light enough to edit.
- Where: broll / Sending a clip to Resolve
- What: For a clip filed in the archive, what goes is the original beside its preview (the single file of the same name; a name typed on a Mac matches one typed on Windows), with the editing proxy of the same name where one exists; with no original found, or several candidates, the preview itself goes. A clip not yet filed in the archive goes from where it is. The original counts as light enough to edit directly when it is H.264, HEVC or any ProRes, at most 1080 lines and at most 12 megabits per second; when the archive's folders cannot be read at that moment (the share is away), the clip is treated as light enough. When the original is still being uploaded by the person who added it, the clip goes with a note of where the original will land so it can follow.
- Flag: undetermined: what the app on the editor's computer does with "light enough" and with an original still on its way.

### 23-025: A clip not yet on the editor's computer is fetched first, and the button shows the progress.

When the computer is busy with other downloads: "Waiting for this computer's other downloads to finish.", the button reads "WAITING…", and the page asks again when the app says to (at least every second); after 15 minutes it gives up with "This computer has been busy with other downloads for a while. Try again when they have finished."

### 23-028: Messages on the archive pages stay long enough to read, and errors stay until dismissed.

Message text can be selected and copied. Questions before a destructive step offer "Cancel" (the default) and "Go ahead". Tooltips show on hover or keyboard focus, and on touch screens on tap; Escape or scrolling hides them.

Escape does not close it.

### 23-030: Editors gather archive clips into client folders, each with its own link for a client.
- Where: broll / Client folders and links
- What: A client folder is a titled, ordered set of archive clips with one link a client opens without signing in, showing previews only. Folders belong to the studio: every signed-in editor can see, change, revoke and delete every folder; who made it is recorded and shown but grants nothing. Each folder is "live" (green; its tooltip gives the expiry), "revoked" (red) or "expired" (amber); revoked wins over expired.

### 23-031: A client folder has limits, and going over one is refused with a message, never cut short silently.
- Where: broll / Client folders and links
- What: Title required ("a folder needs a title"), at most 120 characters; description up to 2000; licensing contact up to 200; a clip's caption up to 500; at most 500 clips in a folder. Adding clips that would pass 500 adds nothing and says "a client folder holds at most 500 clips. This one has X, so there is room for Y more and Z new clips were sent. Nothing was added." Adding a clip already in the folder is not an error. A clip no longer in the archive cannot be added ("clip N is not in the archive index").

### 23-032: The client link is unguessable and can be copied again at any time.
- Where: broll / Client folders and links
- What: The link carries 22 random characters (as hard to guess as a 128-bit key). It is kept so it can be copied again later. The folder shows the link in a read-only field with "Copy" ("Link copied"; when the browser refuses the clipboard, the field is selected and "Copy failed: select the link and press Ctrl+C") and "open", which opens the client's view in a new tab without counting as a client's visit.

### 23-033: An editor can revoke a link, reactivate it, or issue a new one.
- Where: broll / Client folders and links
- What: "Revoke link" (after "Revoke this link? ...") makes the link dead until "Reactivate link". "New link" (after "Issue a new link? The old one stops working immediately.") replaces the link; the old one is dead at once, and a revoked folder becomes live again. Messages: "Link revoked", "New link issued", "Link reactivated", "Failed: <message>". A link already open in a client's browser stops serving at its next request.

### 23-034: An editor writes what the client reads, and sets when the link expires.

### 23-041: Each client visit is counted, but not the studio's own looks.
- Where: broll / Client folders and links
- What: Every opening of a client link adds one to the folder's visit count and records when, except an opening by a signed-in person or through the folder's own "open". The count and last visit show in the list and in the folder.

### 23-042: A client opens a link and sees only what is in that folder, with no sign-in.
- Where: broll / Client folders and links
- What: Everything behind a client link answers on the link alone, read only, checked afresh on every request. ### 23-048: Adding footage shows whether the app on this computer is ready to do the work.
- Where: broll / Bringing new footage in
- What: A status line with "recheck": "checking…"; "connected (v<version>, <graphics card, or N GB of graphics memory, or no GPU>)"; "the CC Sync tray can't index yet: <reasons>"; "your CC Sync tray is too old for b-roll ingest: take the update it offers, then reload this page"; or "not reachable: the CC Sync tray is not running, or the browser blocked local connections (self-test: open <the app's local status address> in a tab; if that shows ok:true it is the browser, not the tray)".
- Flag: built twice: the same check appears in the collections panel (23-029).

### 23-049: Only video files are taken, at most 2000 to a drop, and only if this computer has the room.
- Where: broll / Bringing new footage in
- What: Every nested folder of a drop is read. Only video files are taken, by the kinds the site lists (by default Blackmagic RAW, QuickTime, MP4, MXF, AVI, AVCHD, Matroska, RED, Canon RAW Light, MPEG, Windows Media, WebM and Insta360 files): "N of M files were not video and were left out."; nothing usable: "Nothing there this app can index: b-roll takes video files (...)". A drop holds at most 2000 clips: "Only the first N clips were taken: a batch holds 2000." or "A batch holds at most 2000 clips. Run this one first." A file name may be up to 255 characters and a sub-folder path up to 1024. The whole drop, with clips already listed, is refused before anything is copied if it does not fit the free space this computer reports where clips are staged, less a safety margin: "That drop is X and this computer has Y free where clips are staged... Nothing was staged...".

### 23-050: Clips chosen through the computer's own file picker are described where they are, not copied through the browser.
- Where: broll / Bringing new footage in
- What: "Choose files…" and "Choose a folder…" ask the app on this computer to open the computer's own picker; those clips are marked "indexed in place".

### 23-051: A drop is filed under a shoot name, which is suggested and made safe for every computer.
- Where: broll / Bringing new footage in
- What: One dropped folder becomes the suggested shoot name and is not repeated as a sub-folder; several dropped folders keep their names as sub-folders. Otherwise the suggestion is "<YYYY-MM-DD> ingest". Once the editor types a name, a later drop does not replace it. The name is made safe as it is typed: characters Windows forbids (the less-than and greater-than signs, colon, double quote, both slashes, vertical bar, question mark, asterisk and control characters) become an underscore, trailing dots and spaces go, and it is cut to 90 characters; Chinese and other scripts are kept. When the server would save it differently: "the shoot name will be saved as “<name>”"; a name sent unsafe is refused with "the shoot name must be '<suggestion>' (Windows forbids some characters, and the archive caps a name at N characters here)". With "Keep sub-folders" off, the clips' sub-folders are dropped.

### 23-052: The editor sees each clip of the drop, its archive name, and whether it is already in the archive.
- Where: broll / Bringing new footage in
- What: "<chosen> of <n> clips selected", a tick per clip, a thumbnail (made in the browser from about a tenth of the way in, or the app's own once handed over, else "no preview"), the name with its sub-folder, size, length, "indexed in place" where so, "will be saved as <name>", and an upload bar. The archive names and the duplicate check are asked of the server shortly after each change. A clip whose content matches a clip already in the archive shows "already in the archive: clip #N (<name>)" and is unticked once, the first time it is found; the editor may tick it again (duplicates are reported, never skipped by the server). A clip the app refused shows its reason and cannot be ticked. "clear" empties the drop.

### 23-053: Dropped files are handed to this computer's app with progress, and interrupted hand-overs retry.
- Where: broll / Bringing new footage in
- What: Shortly after a drop the files are copied to the app on this computer, two at a time, with progress. A broken connection is retried automatically, 3 tries in all (after 2 then 4 seconds), showing "upload interrupted, retrying (n of 3)..."; two minutes without progress counts as broken. After that: "<message> Tried N times: press retry when the connection is back." with "retry" on the row and "retry all failed (N)". A file the app already has counts as done. Leaving the page while files are still being handed over brings up the browser's leave warning.

### 23-054: The editor chooses the description quality, when the work runs, and what is uploaded.
- Where: broll / Bringing new footage in
- What: "Model": Good (needs about 8 GB of graphics memory) or Best (about 12 GB); a choice this computer's graphics card cannot hold is disabled with the reason, and one not yet on the computer says "not downloaded yet, about <size>". The default is the site's choice (Good unless the site says otherwise) unless it does not fit. "When to run": "Only when idle" (default) or "Foreground". "Keep sub-folders" (on). "Upload the originals too" (on). The summary reads "<n> clips, <size> - will run now" or "... will run when you're away".

### 23-055: Transcribing the speech of added footage is offered but cannot be chosen.
- Where: broll / Bringing new footage in
- What: "Transcribe speech" is always disabled, marked "phase 2, not available yet"; the server refuses it ("transcription is not available yet (phase 2)").
- Flag: dormant

### 23-056: Running a drop asks first when it is large or needs a download, then starts or queues it.
- Where: broll / Bringing new footage in
- What: "Run" is available only with clips chosen, the app reachable, a shoot name and every file handed over. A drop of 50 GB or more asks "This drop is X across N clips. Staging it needs X free on this computer and it has Y. Indexing will run for about H hours. Start it?" (estimated at a minute and a half per clip). A quality not yet on the computer asks "The <quality> model isn't on this computer yet. Running this batch downloads it first (about X). Continue?". Success: "Indexing started on this computer." or "Queued: it starts when you step away from this computer." When the app cannot take it (for example the card cannot run the chosen quality), a lasting notice tells the editor to change the quality or take over from another computer; any other failure: "The CC Sync tray did not take the batch: <message>".

### 23-057: Added clips are filed and named in the archive so nothing is overwritten.
- Where: broll / How the archive is laid out
- What: Each clip goes to the archive's own-footage top folder, then the shoot, then its sub-folders, then its name, with its preview and editing proxy in a proxy folder beside it. A name already used or reserved in that folder (letter case and extension ignored) gets "_2", "_3" and so on. Names are capped at 90 characters. A shoot added this way counts as the studio's own footage. The names are reserved when the work starts, so two drops can never take the same name.

### 23-058: An added clip becomes searchable only once its preview is safely on the server.
- Where: broll / Bringing new footage in
- What: A clip appears in search and browse only when it has been described and its preview has arrived complete (present, not empty, the declared size); the original and the editing proxy are checked the same way when sent. Until then it is hidden. A clip whose original has not arrived yet, in a drop set to upload originals, is searchable and shown as "original still owed", and Send to Resolve says where the original will land (23-024).

### 23-059: While a drop runs, the editor sees its progress and can pause, start now or cancel.
- Where: broll / Bringing new footage in
- What: "<shoot> - <state>"; counts "<done> of <n> indexed · <live> searchable · <failed> failed · <dup> already in the archive · <owed> still to send the original"; when the computer last answered; what it is waiting for, in words: waiting for the indexing model, waiting until you step away from the keyboard, waiting for DaVinci Resolve to close, paused, waiting for the video tool to be installed, waiting: the sync drive is not connected, waiting: this computer's sync config needs fixing, this GPU cannot run the chosen model, b-roll ingest is off on this computer, nothing to do, indexing; the model download with its rate and minutes left; the current step and percent; uploads queued or paused; up to 200 clip lines. Buttons: Pause or Resume, "Start now" (only while waiting for the editor to step away or Resolve to close), "Pause uploads"/"Resume uploads", "cancel batch…". All are disabled once finished; Pause, Resume and Start now are disabled while the app does not answer, with "the CC Sync tray isn't answering right now - the batch keeps its place on the server (...)". The view refreshes every second or two for the computer's progress and every few seconds for the server's record. Reopening the page shows the editor's newest unfinished drop again.
- Flag: undetermined: the "done" count also counts failed, duplicate, cancelled and skipped clips.

### 23-060: A drop's state is shown in fixed words.
- Where: broll / Bringing new footage in
- What: "waiting to start"; "waiting: <computer> stopped answering <ago>"; "starting on <computer>"; "indexing on <computer>"; "stopping"; "finished"; "finished, N could not be indexed"; "stopped"; "could not run". "ago" reads "Ns ago" under 90 seconds, "Nm ago" under 90 minutes, else "Nh ago", or "never". A drop that ends with clips failed or originals still owed finishes as "finished, N could not be indexed". A clip's own state never goes backwards except a failed clip being tried again; searchable, duplicate, cancelled and skipped clips are final.

### 23-061: Editors see their own drops; an admin sees every computer's.
- Where: broll / Bringing new footage in
- What: "Batches" with "Mine" and, for an admin only, "All computers" (others are refused: "only an admin can see every computer's batches"); newest first, up to 200. Another editor's drop is invisible to a non-admin, as if it did not exist. Each card: shoot, state, editor (in the all view), computer or "no computer yet", last answer, quality, "foreground" or "when idle", counts, "uploads paused", and any stored error (up to 500 characters). Actions: "clips"/"hide clips" (up to 200 lines); "take over on this computer" (a waiting drop of one's own); "try the N failed again" or "finish the N still uploading" (a finished drop of one's own); "cancel" (unfinished). Cancel and retry are for the drop's owner or an admin.

### 23-062: A drop whose computer stops answering goes back to waiting and can be taken over by another computer.
- Where: broll / Bringing new footage in
- What: A computer working a drop answers about every 30 seconds; after 5 minutes without an answer the drop goes back to waiting, still naming that computer ("waiting: <computer> stopped answering <ago>"), and another of the editor's computers may take it over. While a computer is still answering, another is refused: "<computer> is already indexing this batch". A computer that loses a drop (cancelled, finished, taken by another) stops working on it.

### 23-063: Cancelling a drop keeps what is already in the archive.
- Where: broll / Bringing new footage in
- What: The question reads "Stop this batch? Clips already in the archive stay there; the rest are dropped and their staged files are kept for a week." A drop no computer is working is stopped at once; one being worked shows "stopping" until its computer learns of it at its next answer (within about half a minute). A finished drop answers that it was already finished.

### 23-064: Failed clips and owed originals of a finished drop can be tried again.
- Where: broll / Bringing new footage in
- What: Every failed clip and every clip still owing its original goes back to waiting, keeping its archive name, and the drop waits for a computer again; the editor is told how many. Refused while a computer is still working the drop: "<computer> is still working on this batch. Stop it first, then try the failed clips again."
- Flag: several ways in: a clip's hand-over to this computer is retried per row or all at once (23-053), and a finished drop's failed clips here.

### 23-065: Uploads of a drop can be held while describing carries on.
- Where: broll / Bringing new footage in
- What: "Pause uploads" holds the drop's uploads to the server while the clips go on being described; "Resume uploads" lets them go. The choice is kept on the server, so it holds whichever computer works the drop.

### 23-066: A clip moved or described again in the archive keeps what is known about it.
- Where: broll / Describing and indexing clips
- What: Describing a clip again replaces its descriptions, themes and quality flags but keeps its category, duplicate mark, place and other details unless new ones are given. A clip moved to a new place keeps its descriptions; a move onto a place where a clip already is, is refused. The descriptions of each collection (where it lives, whether originals or previews are archived) are added to, never removed.

# Extract of inventory section 06

## Items

### 06-001: Each editor's computer finds the clips in its projects that have no proxy, tells the editor, and makes the missing proxies itself.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Editors cut with proxies: small, low-resolution copies of each original. A proxy lives in a folder named "Proxy" beside its original, with the same file name apart from the file type. Other computers in the team receive proxies, not originals, so a clip with no proxy is invisible to everyone else. On every editor's computer the app looks for originals with no proxy, tells the editor about them, and (where proxy making is on and the computer is able to) makes the missing proxies while nobody is using the keyboard or mouse. Telling and making can each be switched off for a computer. If both are off, the computer does neither, and nobody is told that it has stopped looking.
- Flag: undetermined: whether proxy making is on by default, and on which computers, is decided by a rule the inventory section could not see.

### 06-002: Which files count as originals that need a proxy, and how soon a new one is noticed.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: The app looks again for clips with no proxy when it starts, about every 15 minutes after that, at once when the editor asks for proxies to be made, and at once when the sync folder's drive comes back after being away. It only looks while the sync folder is present, and only in the projects this computer is set to sync (when that list is known). Only video files count. These are never counted: the small hidden companion files macOS writes beside files on shared drives (their names start with a dot and an underscore); the working files left by a YouTube download in progress; 360-degree camera files; empty files; and files changed within the last 2 minutes (they may still be arriving). Folders named "Proxy" (in any letter case), the sync folder's holding area for removed files, and hidden folders are not looked in. A clip counts as having a proxy when a QuickTime or MP4 file with the same name sits in the "Proxy" folder beside it; existing MP4 proxies stay valid. A clip whose proxy the Blackmagic Proxy Generator is writing at that moment is counted neither as missing nor as waiting.
- Flag: undetermined: the exact list of video file types counted.

### 06-003: Camera raw clips are counted as missing a proxy but are left for Resolve's own proxy generator.
- Where: proxies-and-file-moves / Raw camera formats and Blackmagic Proxy Generator
- What: Blackmagic RAW, RED and Canon RAW clips can only be read by DaVinci Resolve and its Blackmagic Proxy Generator, not by the product's own proxy maker. Such clips are counted as missing a proxy and as "needs Resolve" (Blackmagic RAW is also counted on its own), and are never put in the product's own queue. The folders that hold them are gathered (at most 24 across the whole sync folder) so that the Blackmagic Proxy Generator can be pointed at them (06-026).

### 06-004: Two originals that would share one proxy name get one proxy, made from the newer.
- Where: proxies-and-file-moves / Pairing proxies with their originals
- What: When two originals in one folder have the same name but different file types (for example a QuickTime and an MP4 of the same clip name), they would both need the same proxy file. Only the newest is queued for a proxy; both are still counted as missing. Two such clips are never made at the same time. Nobody is told about the clip that was passed over.

### 06-005: The waiting list for proxies is limited per project and fills newest first.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Clips waiting for a proxy form one list across all projects, newest original first. At most 500 clips per project are queued at once; when a project has more, the counts stay exact and the editor is told: "There are more clips without proxies than CCSync queues at once. It will pick up the rest as the queue drains." At most 64 projects are looked at, with the projects this computer syncs and the most recently touched kept first. Clips the app has given up on (06-018) do not take queue places.

### 06-006: A project folder that cannot be read is never reported as having all its proxies.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: When a project folder cannot be read at all (for example its drive was unplugged) or reading it fails partway, that project is marked as unknown rather than covered, with the sentence: "CCSync could not read <folder> to check its proxies (<reason>). Until it can, nobody knows whether that project's clips have proxies." Whatever was already counted before the failure is kept.
- Flag: undetermined: the inventory found that this unknown state is not passed on to the tray or the dashboard, so the editor and the admin may never see it.

### 06-007: The editor gets a notification naming the project with the most clips lacking a proxy.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: When clips without a proxy are found, the editor gets an operating-system notification, titled with the studio's brand. It names the project with the biggest gap: "N clips in <Project> have no proxy, so nobody else in the team can see them." (one clip: "1 clip in <Project> has no proxy, so nobody else in the team can see it."), or, when the computer has more missing clips than that project alone, "N clips in <Project> (M on this computer) have no proxy, so nobody else in the team can see them." One sentence follows: if every missing clip is a format only Resolve can read, "Run the Blackmagic Proxy Generator on them."; if proxy making is off, "Ask your admin to generate proxies for them."; if this computer cannot make proxies, that it can only tell; otherwise "I'll make them while you're away from the keyboard." It is shown at most once while the same gap lasts (a new gap starts when the old one closes or the drive comes back), and at most once a day by default, remembered across restarts. The editor can switch these notifications off (on by default) and can change the minimum time between them (default one day; zero means no minimum).

### 06-008: Proxies are made only while nobody is at the computer, and making stops within seconds when the editor comes back.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Making starts only after 5 minutes with no keyboard or mouse use (a setting on the computer, default 5 minutes). If the app cannot tell how long the computer has been idle, it assumes someone is there. When the editor touches the keyboard or mouse, pauses syncing, presses stop, or the app is shutting down, the clip being made is abandoned within about 2 seconds, its half-made file is removed, it goes back to the front of the list, and no further clip is started. The reason given is one of "you're back at the keyboard", "syncing is paused", "you asked it to stop", "the companion is shutting down". Making runs at low priority with no window, so the computer stays usable.

### 06-009: Before a clip is made, it is checked again so nothing still arriving or already covered is made.
- Where: proxies-and-file-moves / Writing, copying and deleting files safely
- What: Just before making each proxy, the clip is skipped, silently and without counting as a failure, if: it is itself a proxy (inside a folder named "Proxy" or "proxies" at any depth, or a half-made file); it no longer exists or is empty; it changed within the last 2 minutes (setting, default 2 minutes); its size or time changed between two looks about 5 seconds apart (setting, default 5 seconds; zero switches the check off), meaning it is still being copied; it already has a proxy (for example one just arrived from the server); the Blackmagic Proxy Generator is writing its proxy; or it has been given up on.

### 06-010: Proxy making stops by itself when the drive is nearly full, says so, and resumes on its own.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Before writing a proxy, the free space on the drive that will hold it is checked against the larger of 20 GB and 5 % of that drive (both settings on the computer; zero switches either part off). Below it the clip is skipped, never counted as a failure, and the editor is told: "only X GB free on the drive holding <folder> (CCSync keeps Y GB clear so syncing and Resolve's cache do not run out)". A notification titled with the brand and "low disk space" says "CCSync stopped making video proxies: <reason>. Free some space and they will resume on their own." at most once per notification interval (06-007). The tray and dashboard show "CCSync stopped making proxies: <reason>. They start again on their own once there is room." This clears on the next clip that has room. If free space cannot be read, making goes ahead.

### 06-011: While Resolve is open, proxies are made one at a time, and an editor can stop all making while Resolve runs.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Several clips are made at once normally, but only one at a time while DaVinci Resolve is running, so Resolve stays responsive. After Resolve closes, making widens again within about a minute. A setting on the computer (off by default) stops all proxy making while Resolve is running, including when the editor asked for proxies now; if the app cannot tell whether Resolve is running, it assumes it is.

### 06-012: A proxy for camera footage keeps the original's timecode, audio and look within a fixed size.
- Where: proxies-and-file-moves / What a proxy must be
- What: A proxy made for camera footage is a QuickTime file (which Resolve's own proxy generator recognises as an existing proxy) holding 10-bit high-efficiency (HEVC) video tagged so QuickTime and Resolve accept it; at most 1080 pixels tall by default, never enlarged, width in proportion; about 7 Mbit/s on average with short peaks to about 10 Mbit/s (both size and rate are settings on the computer). It keeps every audio track of the original (a silent original still gets a proxy), the original's descriptive information, and the original's start timecode, because Resolve refuses to attach a proxy whose timecode does not match its original. It is laid out so it starts playing before it has fully loaded.

### 06-013: Downloaded and reference footage gets a lighter proxy than camera footage.
- Where: proxies-and-file-moves / What a proxy must be
- What: A clip is treated as downloaded or reference footage when any folder or file name on its path contains "youtube", "yt" or "downloads" as a separate word (words split on anything that is not a letter or digit, so "Kyoto" does not count but "YouTube Downloads" and "yt-clips" do). Everything else, and every camera format (Blackmagic RAW, MXF, RED, Canon RAW, AVCHD), is camera footage; doubtful paths count as camera footage. A downloaded-footage proxy is 8-bit H.264 video at most 1080 pixels tall, never enlarged, with a keyframe every second, audio at a modest quality, and a timecode only where the original has one (YouTube downloads have none).

### 06-014: Timecode from cameras at 29.97 and 59.94 frames per second is written in drop-frame form so Resolve accepts the proxy.
- Where: proxies-and-file-moves / What Resolve accepts as a proxy
- What: Some cameras (Sony among them) record a non-drop-frame style start timecode at 29.97 or 59.94 frames per second without a separate timecode track. Resolve refuses a proxy for such a clip unless the proxy's timecode is in drop-frame form, so the product writes it that way. A timecode from a proper timecode track, one already in drop-frame form, or any other frame rate is kept as it is.

### 06-015: A new proxy only counts once it plays cleanly from start to end and is nearly as long as its original.
- Where: proxies-and-file-moves / What a proxy must be
- What: Every new proxy is played through in full. Any playback error fails it ("the proxy does not decode cleanly (N error line(s))"), and so does a proxy shorter than 97 % of its original ("the proxy is X s of a Y s source", saying that making stopped early). A clip that cannot be read at all, for example a truncated download, fails before making starts. Making a single clip is abandoned and counted as a failure after the larger of 30 minutes and 60 times the clip's length ("the encode was still running after N minutes"). A failure message quotes the last few lines of what went wrong, at most 500 characters.

### 06-016: A proxy appears under its real name only when it is finished, and a proxy that arrives meanwhile wins.
- Where: proxies-and-file-moves / Writing, copying and deleting files safely
- What: While being made, a proxy has an in-progress name in the "Proxy" folder (created if missing) that is never synced to anyone. When it is finished, if a proxy for that clip appeared meanwhile under any accepted name (for example downloaded from the server), the new one is thrown away and the clip counts as done. Otherwise it takes its real name. If that is refused (for example Resolve holds the file open), it counts as a failure and the finished file stays under its in-progress name: "could not put the finished proxy in place (...) -- it is still there as <name>".

### 06-017: Every proxy made or failed is counted at once, so the counts shrink during a run.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: As each proxy is finished, the number of missing clips shown drops straight away. Each finished or failed clip is added to this computer's proxy history (06-025) with the size of the original and the proxy, the clip's length and how long making took. Skipped and interrupted clips are not recorded.

### 06-018: A clip that fails three times is given up on until it changes or the app restarts.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: After 3 failed attempts on the same unchanged file (setting on the computer, default 3), the app stops trying it. The editor is told: "N clip(s) failed too many times and CCSync has stopped trying them. It will try again if the file changes, or after CCSync restarts." A file that changes (different size or time) starts a fresh count, and the count is forgotten when the app restarts. Running out of disk space never counts as a failure.

### 06-019: The editor can make the missing proxies now, or stop the proxy making.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: "Make the missing proxies now" looks for missing proxies at once, forgets every clip given up on, and makes proxies straight away without waiting for the editor to be away from the keyboard. It still respects a pause in syncing, a computer that is not set up right or cannot make proxies, and the Resolve rules (06-011). It ends when its list is done. "Stop making proxies" abandons the clips being made (leaving no half-made files) and drops the current list; it is not a switch-off, and the next regular look fills the list again.
- Flag: undetermined: the exact labels and where the editor finds these two actions.

### 06-020: The editor and the admin are shown what proxy making on a computer is doing.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: One state is shown at a time, the first that applies, in this order: switched off; the sync folder's drive is not there (if the app cannot tell, the drive counts as there); syncing is paused; held back because other heavy work on this computer goes first, with the reason (for example "indexing b-roll first"); the computer is not set up right; this computer cannot make proxies (it still says which clips have none); nothing to do; waiting because someone is at the keyboard; waiting because Resolve is open (only with the setting in 06-011 on); making proxies. The state is worked out again right after each look for missing proxies, so "nothing to do" is never shown while clips are waiting. When the computer becomes able to make proxies, making starts without a restart.
- Flag: undetermined: the words each state is shown in.

### 06-021: The editor sees progress for each proxy being made, with time left.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: The editor is shown: how many clips have no proxy, how many are Blackmagic RAW, how many need Resolve, how many are left to make, whether making is under way and which clips are being made, and for each clip its percentage done, the time left and the time taken (updated about once a second). Also how many were made and failed since the app started, and the three reasons making may be held back (given up on, low space, too many to queue) with their sentences. From the last 60 clips finished (at least 3 needed), it shows clips made per hour and an estimate of how long the rest will take; this rate starts afresh when the app restarts.

### 06-022: The dashboard shows each computer's proxy coverage.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: For each computer the dashboard is told: the proxy-making state and whether it is on; how many clips have no proxy, split into Blackmagic RAW, needing Resolve, camera footage and downloaded footage; how many are waiting; how many were made and failed; whether the computer can make proxies and whether it has fast hardware video encoding; when it last looked; any low-space reason; per project, the clips missing a proxy (only projects with a gap, at most 64); the history totals; any held-back reason; and the three reasons making may be held back.

### 06-023: While proxies are being made, the computer stays awake and Windows is told why it should not shut down.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: While any proxy is being made the computer is kept from sleeping, and on Windows a shutdown is met with the reason "still making video proxies so the rest of the team can see this footage (N clip(s) left, M at once)". Once making stops the computer may sleep again. When the app quits, proxy making is stopped first.

### 06-024: Half-made proxies left by an interruption are never deleted and never synced, and are made again.
- Where: proxies-and-file-moves / Writing, copying and deleting files safely
- What: A half-made proxy left behind by an interruption (older than 6 hours) is never deleted by the product and never synced to anyone; the clip is made again on a later run. Nobody is told; it is only written to the app's log.
- Flag: undetermined: when, and how often, the product looks for these leftovers.

### 06-025: The editor can open a report of every proxy made on their computer.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: On request the app writes a plain-text report, "CCSync: proxies made on this machine", with where the history is kept and "Since: <first> (last: <last>)"; a TODAY block and an ALL TIME block, each with "N proxies made, M failed", "<size> of footage → <size> of proxies (N× smaller)" and "<duration> of footage covered, <duration> spent encoding"; "Recent rate: N clips/hour"; BY DAY for the 14 most recent days (made, failed, sizes, ratio); and the last 60 clips, newest first, each "ok" or "FAIL" with time, name, project, sizes, how it was made, time taken, or the error (at most 300 characters). With nothing made yet: "Nothing has been encoded on this machine yet."; if the history cannot be read: "The proxy history could not be read." Sizes are shown in B, KB, MB, GB, TB (1024-based); durations like "45s", "18m", "2h 40m", "3d 4h". Daily totals are kept for the last 90 days; totals for all time are kept indefinitely. Today's and all-time totals, the rate and the estimate are also shown in the tray and on the dashboard.
- Flag: undetermined: how the editor asks for the report.

### 06-026: When raw clips need proxies and the editor is away, the app opens Resolve's Blackmagic Proxy Generator for them.
- Where: proxies-and-file-moves / Raw camera formats and Blackmagic Proxy Generator
- What: The Blackmagic Proxy Generator comes with DaVinci Resolve. It takes no list of files: it watches the folders listed in its own settings and makes a proxy for every clip there that has none. Its window opens idle, with a Start button. The app opens it when all of these hold, checked in this order (the first that fails is the reason given): the feature is on ("disabled"); the generator is installed ("no proxy generator installed"); at least one clip needs it ("nothing needs BPG"); the product's own proxy list is empty and nothing is being made ("still has clips queued"); the editor is away from the keyboard ("user is at the keyboard"); a generator the app started is not still running, and no generator is already running on the computer ("already running", in which case it tries pressing Start); at least 30 minutes since the last attempt to open it ("launched too recently"); and the folders could be added to its watch list ("watch folders could not be set"). It is never opened while syncing is paused, the drive is absent, the computer is not set up right, other heavy work goes first, or the product is making proxies itself. It may run beside an open Resolve, it keeps running after the app quits, and the app never stops or closes it. A failed attempt to open it also waits 30 minutes before the next.

### 06-027: The app adds the raw clips' folders to the Blackmagic Proxy Generator's watch list, without disturbing what is already there.
- Where: proxies-and-file-moves / Raw camera formats and Blackmagic Proxy Generator
- What: Only while the generator is not running, the app adds the folders holding raw clips that lack proxies to the generator's watch list. Existing entries are kept as they are; a folder already covered by an entry or by one of its parent folders is not added (compared ignoring letter case and slash direction). At most 8 folders are added each time, and the list is never taken above 32 entries; when it is full the generator is not opened and nobody but the log is told. Entries an earlier version of the product garbled are replaced when they match a folder being added. Before the first change, the generator's original settings are saved once and never overwritten. If the settings do not exist yet they are created. This can be switched off for a computer (on by default).

### 06-028: On Windows the app presses Start in the Blackmagic Proxy Generator, and tells the editor when it could not.
- Where: proxies-and-file-moves / Raw camera formats and Blackmagic Proxy Generator
- What: After opening the generator, the app waits up to 3 minutes for its window and presses Start, only if the button reads Start, then checks it now reads Stop. It tries at most once every 5 minutes. If the window or button cannot be found, or pressing changed nothing, the editor is told: "CCSync opened the Blackmagic Proxy Generator to make proxies, but could not press Start. Press Start in its window." The note clears once Start is pressed or the generator is running. Pressing Start can be switched off for a computer (on by default).
- Flag: differs: on macOS the app does not press Start; the generator is left idle for the editor.

### 06-029: Handing raw clips to the Blackmagic Proxy Generator is on wherever the computer makes proxies and the generator is installed.
- Where: proxies-and-file-moves / Raw camera formats and Blackmagic Proxy Generator
- What: Unless set on or off for a computer, this is on wherever the computer makes proxies and the generator was found. The generator's location can be set; if set to a place where nothing is, it counts as not installed. On Windows it is found in Resolve's usual install place; on macOS there is no usual place, so it is off unless its location is set. The editor (or settings window) can see whether it is on, whether it is installed, whether Start is pressed for them, whether a generator the app opened is still running, how many clips it was opened for, and the note in 06-028.
- Flag: differs: on by itself only on Windows; on macOS only once its location is entered.

### 06-030: Resolve clips are pointed at their synced proxies automatically.
- Where: proxies-and-file-moves / Relinking and gathering missing clips
- What: About every 2 minutes, for clips in the open Resolve project whose original is in the shared tree (the editor's own local or cloud media is left alone) and whose proxy does not work (Resolve shows it offline or has none), the app attaches the proxy file that is sitting in the "Proxy" folder beside the original (a QuickTime proxy is preferred over an MP4). It never copies, moves or deletes a file. The path written into Resolve keeps the original's own spelling (the shared drive spelling stays the shared drive spelling, so the project still opens on other computers), even on a Mac without that drive. Each change is recorded as a proxy that was attached but unreachable, or one that was not attached at all, and can be undone like every other change the product makes in Resolve.
- Flag: undetermined: the 2-minute pace comes from the present notes, not from what the inventory could see.

### 06-031: Some clips are deliberately not pointed at a proxy, and the editor can be told why.
- Where: proxies-and-file-moves / Relinking and gathering missing clips
- What: If the clip already points at that exact proxy and Resolve still cannot play it, the proxy itself is damaged: "Resolve already points at this proxy and still cannot play it, so the proxy file itself is damaged. Delete it and CCSync will make it again." In the b-roll archive only, an MP4 in the "Proxy" folder is the browser preview, not an editing proxy; when the full-quality original is on this computer, it is not attached: "This file is the b-roll browser preview, not an editing proxy, and the full quality original is already on this computer. CCSync left the clip on the original so you are not cutting at preview quality." Outside the archive an MP4 proxy is attached normally.

### 06-032: The editor is told what the automatic proxy attaching did, and refused pairings are not retried until the proxy changes.
- Where: proxies-and-file-moves / Relinking and gathering missing clips
- What: Each run gives one sentence built from: "Repointed N proxy file(s) to the copies in your sync folder.", "N could not be attached: usually the proxy's timecode does not match the original.", "N got no answer from Resolve and will be tried again." Per clip: "Resolve would not attach this proxy. Usually the proxy's timecode does not match the original.", "Resolve did not answer about this clip, so CCSync will try it again.", "This clip is not in the project's media pool any more, so there was nothing to attach the proxy to." A pairing Resolve refused is not offered again until the proxy file changes (size or time) or the app restarts. A clip Resolve did not answer about is tried again next time.
- Flag: undetermined: whether and where these sentences are shown to the editor.

### 06-033: An archive clip that started life as a stand-in preview is re-read by Resolve once its real original arrives.
- Where: broll / Previews standing in for originals
- What: When an archive clip in Resolve was placed from a stand-in (the preview saved under the original's name) and the real original is now on this computer, Resolve may still hold the stand-in's frame count and picture size. If the clip's frame count disagrees with the file's, the app makes Resolve re-read the clip from its own file, before attaching any proxy to it. It knows a file is no longer a stand-in from its own record, from what the server reports about stand-ins placed by any computer, or by comparing lengths (within 1 frame). If either side cannot be read, nothing is done. If the clip had a working proxy before and lost it in the re-read, the proxy is attached again at once. A clip whose re-read changed nothing is not tried again until the file changes.

### 06-034: The editor is warned when the open Resolve timeline uses VP9 originals, which Resolve cannot render.
- Where: resolve-on-the-editors-computer / Media Resolve cannot render
- What: DaVinci Resolve cannot render VP9 originals (typical of YouTube downloads) at full resolution, although editing with H.264 proxies looks fine. When the open timeline's video clips change, and about every 2 minutes otherwise, the app checks each original used on a video track. If any are VP9, a window titled "<brand>: VP9 media in this timeline" says: "N source media file(s) is/are VP9 in project “<project>”, and DaVinci Resolve cannot render VP9 originals at full resolution. This timeline WILL FAIL to render with “Error decoding full resolution media”." then "It plays fine now only because Resolve is using the H.264 proxies." then "Affected clips:" listing up to 12 files, each with clip name, file name and up to 4 positions such as "V2 clip 5" ("and N more"), then "... and N more files". Then "How to fix it: convert each original to H.264, then relink the clip to the converted file or remake its proxy." and "STOP WARNING FOR THIS TIMELINE keeps this quiet until a new VP9 clip is added to this timeline." Buttons: "STOP WARNING FOR THIS TIMELINE" and "CLOSE". The warning is on by default and can be switched off for a computer. A file that cannot be found (for example on a computer holding only proxies) or read is never warned about. If the window could not be shown, the warning is shown at the next chance.

### 06-035: The VP9 warning is shown once per set of files, and "stop warning" is remembered per timeline.
- Where: resolve-on-the-editors-computer / Media Resolve cannot render
- What: While the app runs, the same VP9 files on the same timeline are not shown again after either button. "STOP WARNING FOR THIS TIMELINE" remembers those files for that project and timeline across restarts (up to 500 timelines, the oldest forgotten first). A VP9 file newly added to the timeline warns again. If a remembered file is later found not to be VP9 (converted in place), it is forgotten, so a new VP9 file at that path warns again.

### 06-036: When an admin moves a file or folder on the server, every computer that holds it moves its own copy.
- Where: proxies-and-file-moves / Following a move on an editor's computer
- What: An admin can move or rename a file or folder on the server from the dashboard. Each computer that holds a copy is told, moves its own copy, carries the proxies along, points Resolve at the new place, and answers the dashboard with one sentence. Nothing is ever deleted and nothing is ever overwritten. Answers that count as done: "nothing at the old path on this computer"; "already where the server has it"; "moved", with ", N proxy file(s) with it" and "; N proxy file(s) were in use and stayed at the old path" as they apply. A failure answers "could not move it on this computer: <error>". The dashboard names who asked, or "your administrator".

### 06-037: A move this computer had already finished, or that proxy downloading already carried out, is recognised and not done twice.
- Where: proxies-and-file-moves / Following a move on an editor's computer
- What: If the file is already at the new place because this computer was interrupted partway through, the answer is "finished a move this computer was interrupted during". If the computer's own proxy download already carried this exact file to the new place within the last day, the answer is "proxy download had already moved it on this computer"; for a folder, "proxy download had already moved this folder on this computer" (also when only an empty old folder is left). Either way Resolve is then pointed at the new place. A move told again after a restart is not applied twice.

### 06-038: Some moves are refused on the computer, and the admin is told why.
- Where: proxies-and-file-moves / Following a move on an editor's computer
- What: Refused: when something already exists at the new place ("the destination already exists on this computer (<path>)"); when a folder would move into itself ("a folder cannot be moved into itself"); when a folder's new name differs only in letter case or accents ("a folder cannot be renamed by spelling alone on this computer; ask your admin to do it in two steps"). A move instruction naming an unsafe place (a full path, a drive letter, a step up out of the folder, a blank or control character) is ignored, and nobody is told.

### 06-039: A file renamed only in letter case or accent form is renamed to match on each computer.
- Where: proxies-and-file-moves / Names: letter case and Unicode
- What: The server's disk treats "a.mov" and "A.mov" as two names, Windows and macOS treat them as one, and macOS spells accented letters differently from Windows and the NAS. When a file is renamed on the server only in letter case or accent form, each computer renames its copy in two steps (putting the original name back if the second step fails), with its proxies: "renamed to match the server's spelling, N proxy file(s) with it"; on failure "could not rename it on this computer: <error>".

### 06-040: A file moved to a place this computer does not sync is set aside on that computer, never deleted.
- Where: proxies-and-file-moves / Following a move on an editor's computer
- What: When the new place is outside what this computer syncs (its ticked projects and borrowed folders; when that is not known, or the move stays inside one project, it counts as synced), the local copy is set aside in the sync folder's dated holding area for removed files, and Resolve is not changed. For a file (with its proxies) the answer is "trashed locally, destination not synced here"; on failure, "could not move it out of the way on this computer: <error>". For a folder, each file is set aside only if the server is known to hold it at the new place (same name ignoring case and accents, same size); anything else stays at the old place and is uploaded later. Emptied folders are removed one by one. Answers: "trashed locally, destination not synced here", or "destination not synced here; kept N file(s) at the old path that the server may not have (e.g. <name>), trashed M". If the server cannot be asked and the folder holds originals: "destination not synced here, and the server could not be asked which of these files it already holds; keeping the folder where it is and trying again". A folder with no originals is set aside whole in that case.

### 06-041: A clip's proxies follow it when it moves.
- Where: proxies-and-file-moves / Moves that reach every computer
- What: Every proxy beside a moved file whose name matches (ignoring letter case and accents) goes to the "Proxy" folder beside the new place. When the move also renames the file, the proxies take the new name. A proxy is never overwritten: if a different file is already there, the proxy stays. A proxy that cannot be moved (for example Resolve has it open) stays at the old place and is named in the answer; the move still counts as done. In a folder move the proxies travel inside the folder.

### 06-042: A move that could not be done is tried again for a week, then shown as blocked.
- Where: proxies-and-file-moves / Moves that reach every computer
- What: A move that could not be applied on a computer is tried again after 10 minutes and then every hour, until it succeeds or 20 attempts or 7 days have passed, whichever comes first. Then it is shown as blocked on the dashboard; before that it is shown as waiting to retry.

### 06-043: A moved file is not uploaded again from its old place.
- Where: proxies-and-file-moves / Moves that reach every computer
- What: For 24 hours after a computer hears of a move, whether it applied it or not, that computer does not upload anything from the old place; while a move is still waiting to retry, blocked or partway done, for as long as it stays so. This holds for accented names spelt the macOS way too. Without it, a computer still holding the file at the old place would upload it again and the moved file would come back.

### 06-044: Resolve clips are pointed at the moved file's new place, now or when the project is next open.
- Where: proxies-and-file-moves / Relinking Resolve after a move
- What: After a move, every clip in Resolve's media pool at the old place (or inside the old folder) is pointed at the new place, written in the shared drive spelling, and can be undone like every other change the product makes in Resolve. Old and new places are compared ignoring letter case (on Windows and macOS) and accent form. Answers: "Resolve not relinked (<reason or 'not open'>)", "N Resolve clip(s) relinked, M could not be", or "Resolve relink failed (see the log)". When no clips were found (the project was not open), the relink stays pending for 30 days and is tried again when the open project changes.

### 06-045: A clip missing in Resolve because of a move can be traced to that move.
- Where: proxies-and-file-moves / Relinking Resolve after a move
- What: For 30 days after a move, when Resolve shows a clip as missing at the old place (or inside a moved folder), the product can tell that a move took it away and where to. Moves where the copy was set aside rather than moved, and interrupted moves whose file is not actually at the new place, are never given as the answer.

### 06-046: Whether a file is already light enough to edit with is decided by a fixed rule.
- Where: broll / Bringing new footage in
- What: A file is light enough to edit with as it is when its video is H.264, HEVC or any ProRes, it is at most 1080 pixels tall, and its bitrate is at most 12 Mbit/s. If the bitrate is unknown the answer is "cannot tell"; any other video type is not light enough.

### 06-047: Each editor's computer gets the means to make proxies on its own, with nothing for the editor to install.
- Where: proxies-and-file-moves / Making proxies on editors' computers
- What: Without any step by the editor and without any error window, the app equips the computer to make proxies (and to do the b-roll and downloaded-footage work that needs the same ability). It never holds up starting. It needs about 300 MB free on the computer's drive; otherwise it does not proceed. If the editor already has their own copy of what is needed, that is used instead. Supported: Windows on Intel or AMD processors, and Macs with Apple or Intel processors. On anything else (Windows on ARM, Linux) the computer cannot make proxies or index b-roll. Where equipping fails twice running, the computer is not offered shared proxy, sound-extraction or waveform work; nobody is told except in the app's log. It becomes able without a restart as soon as equipping succeeds.

### 06-048: Signed-in YouTube downloads on an editor's computer are equipped only where the site has switched on getting past YouTube's blocks.
- Where: youtube / Keeping the downloader working
- What: The extra ability needed for signed-in YouTube downloads on an editor's own computer is set up only when YouTube downloads are on for the site and this computer, and the site's option for getting past YouTube's blocks is on. Even if it is present on the computer, it is used only while that option is on. If it cannot be set up, signed-in YouTube downloads stay off on that computer; if the basic ability is missing, YouTube downloads stay on the server.
- Flag: dormant

### 06-049: A camera card is copied only when it is in a card reader on the computer the copy was sent to.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The Footage Sorter plans which files on a camera card (or a local drive) go where, and sends the copy to a computer. The card is known by its serial number and must be in a card reader on that computer (never the system disk), or "card <serial> is not in a card reader on this computer, so nothing was copied". If the drive letter that last held this card now holds another: "drive <X> now holds a different card (<serial>), not <wanted>: nothing was copied". A plan with no card: "the job named no card serial". For a local drive: "the drive with serial <serial> is not on this computer" (worth trying again later); a drive copy that names no source drive is refused. Every place the files are going must be reachable before anything is copied, so a missing NAS share fails the whole copy up front instead of file by file. Folders the plan lists are made first ("could not make the folder <path>: <error>" stops the copy). While a card is being copied nothing else in the app reads it. A plan naming an unsafe place on the card (empty, a full path, a step up, a drive letter, a control character) is refused.

### 06-050: A card copy never overwrites anything, and decides file by file what to do with what is already there.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: For each file: if the card's file is no longer the size the plan listed, it fails ("the source is N bytes now and the job listed M: it changed since it was scanned"); unreadable: "the source cannot be read (<error>)"; not a file: "the source is not a file". At the destination: nothing there, it is copied; a file of the same size is compared byte for byte, identical is skipped and counted as checked, different is left alone as a conflict ("a different file of the same size is already there (<why>); it was left alone"); a folder or link there: "a folder or link is already there; it was left alone"; any other file: "a different file is already there; it was left alone"; destination unreadable: "the destination cannot be read (<error>)". A file that appears during the copy: "a file appeared at the destination during the copy; it was left alone". Two files in one copy going to the same name: the later is "another file in this job is going to the same name; it was left alone".

### 06-051: A card copy can resume a short file or write beside an existing one, when the plan says so.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The plan says for each file whether to copy, resume, or write beside. Resume: a shorter file already at the destination is finished from the card, but only if every byte already there matches the start of the card's file ("the file already there is not the start of the card's file; it was left alone") and it did not change while being finished. Write beside: the copy is named "name (2)", "name (3)" and so on up to 99; if the plain name or a numbered copy is already an identical copy (from an interrupted earlier run) it is skipped; with 99 numbered copies already there: "99 renamed copies of it are already there". Any other instruction fails that file, saying the instruction is not one the computer knows.

### 06-052: Every copied file is read back from the drive and compared before it gets its real name.
- Where: footage-sorter-and-camera-cards / Checking a copy
- What: Each file is copied under a temporary name, written fully to disk, given the card file's dates, then read back from the drive itself (not from the computer's memory, where the system allows) and compared with what was read from the card. Only then does it take its real name, and never over an existing file. Any failure removes the temporary file: "verify failed: the copy is N bytes and the source M", "verify failed: the copy read back differs from the source", "verify failed: the copy cannot be read back / could not be verified (<error>)", "the copy failed (<error>)", "could not make the destination folder (<error>)". A leftover temporary file from a crashed copy is removed first.

### 06-053: A card pulled out mid-copy stops the copy with one clear reason, and a stopped copy still reports what landed.
- Where: footage-sorter-and-camera-cards / Drives, speed and interruptions
- What: If a read fails and the card is no longer in any reader, the whole copy stops with "the card was taken out of its reader" (worth trying again) instead of failing every remaining file. A copy halted or cancelled stops between or during files, and what landed before is still reported.

### 06-054: Automatic drive backups copy only when the computer is at home on the NAS's network.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: An automatic backup of a local drive that is set to run only at home first checks that the computer is on the NAS's home network: the NAS must answer at least 2 of 3 quick checks, with a typical answer under 15 ms (the limit can be set per backup). Otherwise nothing is copied and the reason is "away from home: the NAS's home address <host> did not answer; nothing was copied", "... answered in N ms, not like the same network (under 15 ms); nothing was copied", or, when the product does not know where the NAS is, that it cannot tell whether the computer is at home.

### 06-055: The Footage Sorter is given a receipt and live progress for each card copy.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The receipt lists files copied, skipped, in conflict and failed, each with where it came from, where it went, its size, whether it was checked, the name it was written under, or the reason. While copying, the Sorter is shown bytes and files done out of the total, the file in hand, whether it is copying or checking, and the speed averaged over about the last 5 seconds (zero while checking).

### 06-056: On Windows, a card copy can be handed to a separately installed verifying copy program, which behaves differently.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: On a Windows computer that has a particular third-party copy program installed, files that keep their card name and go to a Windows drive are copied by that program instead (other files are copied as in 06-052). A setting on the computer chooses automatic (default) or always the product's own copier. The program is used only if its own verify-after-copy is switched on; otherwise the copy is refused with an instruction to switch it on and restart the program, or to open the program once if its settings do not exist yet; a setting (off by default) allows it with verify off. Before each batch every destination is looked at again. Resuming is allowed only if the first and last MiB of the existing file match the card. A file the program reports checked and of the right size is copied and checked; the right size without the program's check is copied but unchecked; otherwise it fails ("it did not reach the destination whole (N of M bytes)", "... reported it verified but <name> is missing / N bytes at the destination", "... could not be run (<error>)"). The product never closes the program, since it may also be copying the person's own files, and gives up waiting after 30 minutes plus the time to copy the total at 20 MB/s.
- Flag: differs: this program writes straight to the final name, so a stopped copy can leave a short file under the real name (which the Sorter's next plan resumes), and with the setting on it can land copies nobody checked; the product's own copier does neither.

### 06-057: Sound recordings' lengths on a card are read the same way the Footage Sorter reads them, including unfinished recordings.
- Where: footage-sorter-and-camera-cards / Damaged and unfinished recordings
- What: The length of each WAV recording on a card is worked out from the start of the file without reading the sound itself, so the card listing matches the Footage Sorter's own figures. A recorder that stopped without closing its file leaves a length marker that says "never closed" or claims more than the file holds; then the bytes actually on the card are used. A file that is not a readable WAV has no length.

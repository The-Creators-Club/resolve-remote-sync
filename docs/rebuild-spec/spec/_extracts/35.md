# Extract of inventory section 35

## Items

### 35-001: The Sorter looks for footage in a set of folders the server is configured with, and files it into the studio's sorted tree.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Three kinds of folder matter: the folders still holding footage to sort (copies of cards, folders on other computers), the studio's sorted project tree, and a staging folder where cards are copied when they are not sorted straight away (by default the first of the folders to sort). The sorted tree is always looked at as well, even when not listed. Folders that are looked at for their own files only, never their sub-folders, can also be given (for loose sound files beside a drone card's folder); such a folder that is also a full folder to sort is looked at in full. Many features refuse while no sorted tree is configured, and say that no sorted tree is configured. On the studio's server these folders are set by the server's configuration and cannot be changed from the page: a person who tries is told "the source folders are set by the server's configuration, not from the page".
- Flag: differs: on a development copy run on one computer, the folders to sort can be added and removed from the page (see 35-002).

### 35-002: On a development copy, the folders to sort can be added and removed from the page, with no sign-in.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: A development copy runs on one computer, answers only that computer, has no sign-in and treats everyone as an admin. There, a folder to sort can be added or removed by its full path (surrounding quotes are ignored; letter case is ignored in every comparison). Refusals, each told in words: no folder given; "give the full path"; removing a folder that is not one ("not a source root"); removing the only one ("that is the only source root"); adding a folder that does not exist ("no such folder: <path>"); one inside the sorted tree ("that sits inside the destination <tree>"); one already listed; one already covered by a listed folder ("already covered by <folder>"); one that contains a listed folder ("that contains the existing root <folder>"). A development copy can also be started with all of its own periodic work switched off.
- Flag: dev only

### 35-003: Looking for footage never changes footage; only an admin's move ever renames it.
- Where: footage-sorter-and-camera-cards / Moving footage on the NAS
- What: Looking through folders and cards only reads: it lists folders, reads file sizes and dates, reads the start of camera metadata files and sound files' headers, and occasionally asks a video file for its recording time. It never writes, renames or deletes anything in a folder it looks at. The Sorter keeps its own records only in its own folders and refuses to write anywhere else. The only thing that moves footage is a move an admin starts (35-038); a copy from a card only adds files (35-054 onward).

### 35-004: The studio's time zone is a setting, used for every recorded time that carries no zone of its own.
- Where: footage-sorter-and-camera-cards / Clocks and file dates
- What: The studio's fixed offset from UTC is a setting, default +8 hours. Camera times, calendar times and file times that do not state a zone are read as studio-local at this offset.
- Flag: differs: when matching clips to calendar events (35-028), event times with no zone are always read at +8, whatever this setting says.

### 35-005: The files of one recording are shown together as one clip.
- Where: footage-sorter-and-camera-cards / Telling recordings apart
- What: Files in one folder that share a name (without the extension) are one clip: the recording itself, its proxy, the small files and look files a camera or tool writes beside it, the camera's metadata file and its camera thumbnail. The file that names the clip is the highest-ranked one, in this order: Blackmagic RAW, RED, MXF, MOV, MP4, M4V, MTS, M2TS, AVI, MKV, MPG, MPEG, WMV; then raw stills (Sony, DNG, Canon, Nikon, Fuji, Olympus, Panasonic, Samsung, Pentax); then PSD, EXR, DPX, TIFF, HEIC/HEIF, PNG, BMP, JPEG; then sound: WAV, AIFF, FLAC, M4A, MP3, AAC, OGG. Ties go by name. A JPEG beside a raw still of the same name is that still's companion picture. Files in a folder named "proxy" or "proxies" (any case, including folders nested inside it) belong to the clip of the same name in the folder above, as its proxy or one of its side files; a Sony proxy whose name ends in "S03" joins the recording without that ending, and a Sony metadata file ending "M01" joins its recording. A proxy with no matching recording, or a lone metadata or look file, still becomes a clip of its own, so nothing is lost. A folder (other than a top folder) holding a numbered run of at least 3 frames with the same prefix, type and digit count, in EXR, PNG, TIFF or DPX, is one clip (an image sequence) whose size and file count are the whole folder's. Each clip is shown as one of: video, audio, still, image sequence, or other. Clips are listed by recorded time, then name.

### 35-006: Sony card layouts are understood, so a camera's thumbnails, proxies and index files travel with the right clip.
- Where: footage-sorter-and-camera-cards / What cameras and recorders write
- What: On a Sony card, the camera's own thumbnail of a clip (in its thumbnail folder, or beside the video when a card was copied flat) is part of that video's clip and moves with it. Proxies in the card's sub-clip folder join the matching video in the clip folder. The card's own index and status files are never listed as clips, but are copied when a whole card is copied, so a copied card stays a complete card. Footage looked at before this grouping existed is regrouped the same way without being looked at again.

### 35-007: System, hidden and junk files and folders are never listed.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Ignored folders (any case): recycle bins on Windows and on the NAS, Windows' system volume folder, macOS's indexing, trash and event folders, version-control and package folders, "lost+found", the duplicate-quarantine folder, any folder whose name starts with a dot, and test folders the Sorter's own tests leave. Ignored files: macOS folder-settings files and the "._" files macOS leaves on other drives, Windows' thumbnail cache and folder-settings files, and a sync tool's state file. Shortcuts and links to other folders are not followed.

### 35-008: Each clip's camera is guessed, and gives the camera word used in automatic folder names.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: The camera is guessed from, first match winning: a folder in the path named B-cam (or Bcam) as a word, then A-cam, then a Blackmagic folder name; the file name containing "fx3" as a word; a Blackmagic RAW file; a file name starting "DJI_" (a drone); otherwise "other". For automatic folder names a camera word is chosen, first rule winning: sound clips get the audio word; stills, image sequences and "other" get none (and so no automatic folder); a Sony FX3 (by the model the camera wrote, not FX30) gets the A-camera word; any other Sony model gets the B-camera word, and the model the camera wrote beats the folder name; a Blackmagic clip gets the Blackmagic word; a drone clip the drone word; else the folder guess (A or B) or none. The words are a setting, defaults A-CAM, B-CAM, BMCC, DRONE, AUDIO.

### 35-009: Each clip's recording time is worked out from the best evidence available.
- Where: footage-sorter-and-camera-cards / Clocks and file dates
- What: First source that works: (1) a Blackmagic file name (such as A007_08090854_C137) gives month, day, hour and minute; the year comes from a date in the path with the same month and day, else a year in the path, else the file's date, and if that would put the recording more than 30 days after the file's date the year before is used (shot in December, copied in January). (2) The creation time in a Sony camera's metadata file, kept at its own offset. (3) A date in the file name (2026-08-09, 2026_08_09 or 20260809), else in the folder path (deepest folder first): if the file's own date is that day its hour and minute are used; if not, the video file itself is asked for its recording time (giving up after 20 seconds); failing that the date with the file's hour and minute. (4) The file's own modified time. A sound recorder stamps a WAV when it closes it, so a WAV timed by its file date is moved back by its length. Duration comes from the Sony metadata (rounded to a hundredth of a second) or the WAV header. An image sequence takes a date in its path with the time of day of its oldest frame, else the oldest frame's time.

### 35-010: A clip is recognised as the same recording wherever it is copied.
- Where: footage-sorter-and-camera-cards / Telling recordings apart
- What: The identity that survives copying is, most trusted first: the unique recording id a Sony camera writes; for an image sequence, the folder name, frame count and total size; otherwise the file name (any case), the size of the recording and its recorded day. A second, looser match (same name and day, with the same recording size, or the same total size when sizes are unknown) finds the same recording on a camera's second card slot or recorded differently in the Sorter's record; it is only used to borrow a backup state (35-016), never as an identity on its own.

### 35-011: A full look through every footage folder happens on demand, after every move and card copy, nightly, and on first start.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Any signed-in person can start a full look. It also runs after every move, after every card copy, every night at 03:30 local (a safety net) and once on first start. Only one runs at a time: asking again just reports the one running. While it runs the number of clips found so far is shown. A folder that is missing is reported as unavailable, a file where a folder was expected as not a folder, and a folder that cannot be read as unreadable, with the reason; the look carries on with the rest, and the first 50 such warnings are shown. If the look fails, the previous list stays and the error is shown. Status shows whether one is running, clip count, total size, start and finish times, the error, the warnings and the last account of clips moved outside the Sorter (35-039).

### 35-012: New footage appears by itself within about 20 seconds, once it has finished arriving.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Every folder the last full look saw is checked about every 20 seconds and only the folders that changed are read again; new sub-folders are found the same way. A clip appears only once its files have stayed the same size and date across two checks in a row, so a file still being copied is not shown half-done (the clip as it was before, if any, stays shown meanwhile). A deleted folder's clips go. A drive that is unplugged or a share that is not mounted changes nothing: its clips stay as they were. Status shows the time of the last check, how many folders were checked and changed, and how many files are still arriving. Nothing is checked while a full look is running.

### 35-013: A person can ask for chosen folders to be read again now.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Any signed-in person can name folders to be read again at once, in the background. This catches a file replaced in place under the same name, which the automatic check cannot see. Only folders that exist inside a folder to sort or the sorted tree count; if none do, the person is told "none of those is a folder inside a source or destination root".

### 35-014: The Sorter keeps a record of every place each clip has ever been seen.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: For each recording it keeps the name, kind, camera, model, Sony recording id, recorded time, duration, size, checksum when one is known, and its origin (which card, by serial and label, its kind, and when first seen), plus every place it was seen: on a card, in staging, in the sorted tree ("final", which wins if the two overlap) or elsewhere, with when last seen, whether it is there now, how it was learned (looking, a card copy, a move), whether the copy was checked and when, file count, each file's size, and whether it is damaged. Nothing is ever removed: a place where the clip is no longer found is marked not present and keeps its last-seen time, so an unplugged card, an unmounted drive and a deleted file look the same. A thinner look never erases details a richer one found. If the record is unreadable, it starts empty and nobody is told; it fills again as folders are looked at and from an audit (35-018). A checksum that differs from one already held is noted, and nobody is told. Letter case and slash direction are ignored when comparing places.

### 35-015: Every clip shows how well it is backed up.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: From places where it is present and not damaged: "final-verified" when a checked copy is in the sorted tree, "final" when any copy is there, "staging" when a copy is in staging, otherwise nothing.

### 35-016: A clip with no record of its own borrows the backup state of the same recording found under another identity, and says so.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: When a clip (not an image sequence) is not in the record, the looser match of 35-010 is tried; of several, the best backed up wins (final-verified, then final, then staging). The clip then shows that state, marked as borrowed from a twin. Separately, a clip on a card that is already filed in the sorted tree (same identity, or same name and exact recording size) shows where it is filed and shows "final" if it had no state.
- Flag: built twice

### 35-017: Moves the Sorter makes are followed in its record, and a clip only half moved is held back so the rest can be moved later.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Each recording the Sorter moved gains its new place (keeping whether it was checked) and its old place is marked not present; proxies and metadata files are not separate places. This is caught up after every look, every change found, every move plan, and when any signed-in person asks for it now (they are told how many moves were applied and skipped). A clip's sorting is counted as done only when all its planned files moved. A clip whose recording moved but whose other files did not is held back, even across a restart, so its leftover files go into the next move plan.

### 35-018: Any signed-in person can audit the sorted tree against the record.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: The audit looks through the sorted tree in the background, records every clip found there as in the sorted tree, and marks anything recorded there but not seen as not present. Progress, the number linked and any error are shown. Refused, saying so, when no sorted tree is configured. Asking again while one runs just says one is running.

### 35-019: The record can be looked up by clip, place or name, and summarised.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: A lookup by clip, by path, or by name (at most 50 results for a name) returns the matching entries with their backup state; with none of these given the person is told what to give; an unknown entry is "not in the catalog". The summary gives the number of clips, of places, of present places on each shelf (card, staging, sorted tree, other) and of clips with a checked copy in the sorted tree.

### 35-020: The studio's calendar is read so clips can be matched to shoots.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Events come from the studio's connected online calendar when one is connected; otherwise from an exported calendar archive a setting points at (with a setting naming which calendar in it). Events are kept only from a starting day (default 1 April 2026). The calendar is refreshed about every 15 minutes (a setting, never more often than every 5), and any person can force a refresh. Calendar rules: times stated in UTC are kept; times naming any zone, or none, are read as studio-local; date-only events are all-day; an all-day event with no end lasts one day, a timed one with no end has no length, and an end before the start is ignored. Daily and weekly repeating events are expanded (honouring interval, count, until, weekdays, week start) up to the end of 2026, at most 2,000 times; monthly, yearly and other repeats keep only their first occurrence. A changed single occurrence of a repeating event replaces it. A calendar status is shown: where events come from (online, file or none), the connection, the last error, the calendar ids, the refresh interval and the starting day. If the archive does not hold the named calendar, the calendar stays empty and nobody is told except through the log.

### 35-021: An admin keeps a rules file and a roster of people that tell the Sorter where each event's footage belongs.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: The rules, edited by hand on the server, hold: patterns on event titles that skip an event or set its kind, person, episode or whole destination; short names for episodes; the top folder of the season (default "2026/FF5"); the episodes; and the folder layout. The roster lists, per person, their episode, Chinese name and English name (no contact details). Both are picked up while the server runs, within the calendar refresh interval. Patterns match ASCII-only digits, word characters and spaces, "." stops at a line break and "$" means the very end; a pattern that cannot be used is skipped and nobody is told. With no rules file there is no automatic placing at all and no list of misses. A missing or unreadable roster counts as empty.

### 35-022: The Sorter decides on its own which episode and person an event's footage belongs to.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: For each event title, in order: (1) the first rule pattern that matches (any case) skips it or sets its kind, person, episode or destination; (2) else the leftmost (then longest) episode short name in the title; (3) a roster name in the title: the Chinese name, the Chinese given name alone for 3-4 character names, the full English name, or English surname-like words of 4 or more letters (never "the", "and", titles such as dr, mr, prof, or jr, sr, iii), Latin names only as whole words; with an episode known, a person in that episode is preferred, and without one, a name in exactly one episode sets the episode; (4) else, for events that are not b-roll, an existing person folder under an episode's interviewees whose first word is in the title (longest wins). Each placement carries how it was made and a plain reason, such as '"X" is in the Y roster', 'title matches /pattern/', '"X" already has a folder in Y'. A person overrides it by binding the event by hand (35-027).

### 35-023: The Sorter decides on its own whether an event is an interview or b-roll.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: B-roll when the title has a b-roll word (b-roll, event, shooting, filming, montage, or the Chinese words for press conference, parade, drill, competition, open tournament, course, activity) and no interview word (interview, or the Chinese words for interview); otherwise interview. A rule can set the kind instead; binding the event by hand overrides it.

### 35-024: The Sorter names the destination folder for an event and reuses a folder that already exists.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: The destination is season folder / episode / B-roll or Interviewees / subject. For an interview the subject is the person's folder name (Chinese and English, or whichever exists); otherwise the title with the episode short name removed from either end, trailing words "interview", "broll", "filming" and a leading "broll" removed, and separators trimmed. Characters Windows forbids in folder names become spaces, control characters go, spaces collapse, trailing dots and spaces go. A b-roll event with no subject goes to the episode's B-roll folder itself; an interview with no subject is not placed. An existing sibling folder whose name equals, starts with, or is the start of the wanted name is used instead (shortest wins), so a folder named with the Chinese name lands in an existing folder named in Chinese and English. Existing folders are considered 6 levels deep.

### 35-025: Events the Sorter could not place are listed with the reason.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: An event that is neither placed nor bound by hand is listed as a miss: skipped (naming the rule), ambiguous (a roster name in several episodes, naming the name and the episodes), or unmatched.

### 35-026: A roster could be built from the studio's planning spreadsheet, and a season's empty folder layout listed, but nothing reaches either.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: The spreadsheet reading takes the episode, name and optional English name columns, splits several names in one cell on line breaks, semicolons and the Chinese list comma, removes bracketed text and filler words, and keeps only episodes and names, never contact details. The layout listing would give every episode's planned sub-folders. Neither can be started by anyone.
- Flag: unreachable

### 35-027: A person can bind a calendar event to a destination by hand, or dismiss an event.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Any signed-in person can bind an event to a destination; a hand binding overrides the automatic placing for that event, and binding to nothing removes it. The suggestions are recalculated at once. An event can be dismissed and later restored. Destination text follows 35-031.

### 35-028: The Sorter suggests where each clip belongs from the calendar.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Only placed or bound events suggest. Every clip with a recorded time is considered, including clips on cards still in readers. High confidence: recorded between 1 hour before the event starts and 2 hours after it ends. Low confidence: no high match, but a placed event covers the clip's day. Among candidates, timed events beat all-day ones, then the nearest, then the shorter event, then the earlier. Each suggestion shows how many minutes the clip is outside the event (0 inside), whether it came from a hand binding or the automatic placing (with its reason), and up to 3 alternatives: other events in the high window or on the same day pointing to a DIFFERENT destination, one per destination, nearest first, each saying high or same-day and minutes off. An event counts for at most 400 days. Matching by what is said in the clip adds suggestions for clips the calendar left without one.

### 35-029: Sorted clips can be put into automatic day, time and camera folders.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: A setting, off by default; always on for card copies to staging. A clip gets one only when the setting is on, it is not filed with its original sub-folders kept, it is a video or sound clip with a recorded time and a camera word. Clips are grouped by destination, camera word and local day; the folder is named "YYYY-MM-DD HH.mm-HH.mm LABEL" from the earliest to latest recording (a dot instead of a colon). The folders each assigned clip would get are shown before anything moves.

### 35-030: An existing day folder is reused and never renamed; a different shoot with the same name gets a number.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: An existing folder for the same day and camera that already holds one of the group's clips (by the record, or by name and recording size among its own files) is reused under its existing name. If the times now span more, the person is warned "range widened: <new name> reused <existing name>". Existing folders are never renamed. A folder with the new name that holds none of the group's clips belongs to another shoot, so the new one becomes "<name> (2)", "(3)" and so on. Which shoot gets the number follows the name order of 35-043. Existing folders are re-read about every 30 seconds and right after any change to assignments.

### 35-031: Any signed-in person can assign clips to a destination folder, or clear their assignment.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Clips are assigned either keeping their original sub-folders under the destination (no automatic folders) or by the studio's convention. Destination text: backslashes become forward slashes, spaces at the ends and empty parts are dropped; it is refused ("invalid dest") when empty, starting with a drive letter or a network path, when a part is only dots or empty, or when it holds broken characters. Each destination is re-spelled to match a folder already on disk, or a planned folder, that differs only in letter case, so a second tree differing only in case is never made on the NAS (where case matters). With no clips chosen the person is told clips are required. The person sees the count and the resulting folders. Clearing works the same way.

### 35-032: A person can plan folders that do not exist yet, singly or many at once.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Any signed-in person can add a planned folder, or many at once (duplicates differing only in case skipped, invalid ones returned as rejected), optionally marked as placeholders. Planned folders are shown in the destination tree alongside real ones, in name order.

### 35-033: A person can remove a folder from the plan, after a preview, and nothing on disk is touched.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Removing covers the folder and everything under it. The preview shows the planned folders, assigned clips and event bindings that would go, whether it exists on disk and how many files are on disk (counted up to 2,000). Removing clears those from the plan only. If nothing in the plan refers to it the person is told '"<folder>" only exists on disk. This app never deletes inside <tree>.' when it is on disk, else "nothing here to remove".

### 35-034: A person can move or rename a planned folder, and nothing on disk is moved.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Any signed-in person can give a folder a new parent (or the top) and a new name. Planned folders, placeholders, assignments and bindings under it follow. A folder that exists on disk but holds no files may be moved in the plan; its empty path on disk is reported as left behind. Refusals: invalid source or target; "that is not a usable folder name"; "a folder cannot be moved inside itself"; '"<from>" holds N file(s) on disk. Move it with the dashboard's file move, then reload.'; '"<from>" is not a folder this app can move.'; '"<to>" already exists'; '"<to>" already exists on disk and is not empty'. The same place again is reported as unchanged.

### 35-035: Every change to the sorting plan is recorded with who made it and when, and a change that cannot be saved is undone.
- Where: footage-sorter-and-camera-cards / Sorting into shoots, people and cameras
- What: Each change is all or nothing: if it cannot be saved the plan stays as it was. Each change is recorded with the time, the person, what was done and the detail, and a copy of the whole plan as it stood at the end of each day is kept.

### 35-036: The sorted tree is shown with planned folders merged in, and follows changes within about a minute.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Folders up to 8 levels deep (hidden and system folders left out), plus planned folders, re-read about every minute and straight after looks, moves and card copies. With no sorted tree configured, the tree is empty.

### 35-037: Any signed-in person can plan a move of sorted footage and see a dry run.
- Where: footage-sorter-and-camera-cards / Moving footage on the NAS
- What: A plan covers every assignment not yet done, or only chosen clips, plus leftover files of half-moved clips. If any target holds a different file the plan is blocked with "destination occupied by a different file: <path>"; otherwise a dry run decides whether it is ready or blocked. The person sees the number of files and folders, total size, collisions, files already there, duplicates, clips that could not be found, the groups and the dry run's result. Plans made since the server last started are listed newest first; after a restart the list is empty. Refused when no sorted tree is configured.

### 35-038: Only an admin can carry out a move, and it is checked and followed by a fresh look.
- Where: footage-sorter-and-camera-cards / Moving footage on the NAS
- What: Anyone else is told "moving footage needs an admin of this dashboard". Only a plan whose dry run passed can run ("this plan is <state>" otherwise). It runs in the background with progress (done of total) and ends done (checked), check failed, failed or refused. If it stops with an error the person is told the error, that what had already moved stays where it was recorded as moved, that nothing was copied or deleted, and to dry-run the plan again to carry on. Afterwards the record of every copy follows every file that moved, the tree is re-read and a full look starts.

### 35-039: Clips moved by other means are noticed and adopted.

- What: After every look and every change found, clips found moved outside the Sorter keep their assignments, and assignments they fulfil are marked done. The counts (re-identified, fulfilled, adopted, folder moves, gone, ambiguous) and a sentence describing them are shown in the status. When a whole destination folder is found moved, the old and new places are remembered.

### 35-040: The page shows every clip with where it is, how well it is backed up, and its thumbnail.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Each clip shows whether it is in staging, in the sorted tree, elsewhere, or on a card, its backup state (35-015, 35-016), and its thumbnail; clips can be limited to some of these places. One clip's full detail lists its files ("unknown clip" when gone). The opening view is prepared ahead of time (shortly after start, daily, and after every change), so a first visit does not wait.

### 35-041: The page summarises the sorted tree by destination and by day.

- What: The number and size of clips in the sorted tree; per destination, how many are assigned and their size; the total assigned; sorted clips whose name matches a clip still waiting to be sorted (possible duplicates); per day the count, size and cameras, for choosing a day; which timed events already have sorted footage within 30 minutes of their time; and how many clips each name heard in the footage was heard on.

### 35-042: Each folder to sort is shown with the computer it is on, and the computers are listed.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: A folder is on the computer recorded for it (the deepest recorded parent), else, when it is on the server, the server (called "NAS" unless named), else, for a Windows drive, the old Windows computer it was recorded under, else "Unknown computer". The computer list holds the computers of these folders, the server, any extra names configured, computers that reported cards, and computers where drives or watched folders were seen. Spellings are merged ignoring case and treating spaces and underscores as hyphens; the first readable spelling is shown; "Unknown computer" is never listed; the NAS comes first, then alphabetical. The page also knows the person's name and whether they are an admin.

### 35-043: Folder names and groups are put in a fixed order that handles Chinese.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Folder names, groups and plan entries sort in British English order: spaces before punctuation, then symbols, digits, Latin letters, other scripts, then Chinese characters in radical and stroke order; accents count before case; lower case before upper. Characters outside this order come last, by character code. The order decides which of two same-time shoots is called "(2)".

### 35-044: A clip's thumbnail and hover filmstrip are made on demand.
- Where: footage-sorter-and-camera-cards / Thumbnails and hover filmstrips
- What: A thumbnail not yet made is made when asked for; the page waits up to 10 seconds for it, and up to 20 seconds for a filmstrip. When none can be made the page is told there is no thumbnail and does not ask again for 5 minutes. The server cannot read a card, so card clips get their thumbnails from the editor's computer (35-053). Thumbnails missing on the server are filled in about every 6 hours, staging first, newest first, and new clips get them as they appear.

### 35-045: A clip can be played in the browser, with seeking.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: The clip's proxy plays if it has a playable one, else the recording, else any playable file. Playable: MP4, M4V, MOV, MKV, WebM, WAV, MP3, M4A, AAC, FLAC, OGG. A card clip cannot play from the server. Messages: "unknown clip", "no playable file for this clip", "file unavailable".

### 35-046: A clip's technical details can be shown.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: File format, duration, bit rate and number of streams; video codec, profile, size, frame rate and average frame rate, pixel format, bit depth, colour space, transfer and primaries, pixel shape, frame count; audio codec, channels, layout, sample rate and bit depth. Read from the recording (giving up after 30 seconds) and remembered until the file changes. Messages: the reading tool is missing, timed out, its own error line, unreadable answer, no data, unknown clip (also for card clips), clip has no files.

### 35-047: Showing a clip in the file browser is refused, because the files are on the server.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: The person is told "there is no Explorer on the server: the path is in the info pane".
- Flag: unreachable

### 35-048: Moving footage and the admin actions of the record of every copy need an admin; everything else needs only a sign-in.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: Admin only: carrying out a move; changing a drive's details, reading a drive or a folder, adding, removing or changing a watched folder; answering a question about footage; changing the cloud backup schedule or starting a cloud backup; backing up the record; copying between drives and cancelling such a copy. A person who is not an admin is told "<what> needs an admin of this dashboard". Any signed-in person may assign, edit planned folders, plan moves, start looks and audits, and copy cards.

### 35-049: Cards in readers on editors' computers appear in the Sorter by themselves.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: The app on an editor's computer reports the cards in its readers; each report replaces that computer's list. A card needs a serial and a drive; a drive must be a Windows drive root or a macOS volume, otherwise the card is refused with "the drive must be a Windows drive root or /Volumes/<name>" (a Linux mount is never accepted). Limits: at most 4 computers per editor (a fifth is refused, "at most 4 machines per editor"); at most 16 cards per computer per report (extra cards are dropped and nobody is told); at most 5,000 files per card (the card is refused, "more than 5000 files"). A card's files are grouped and timed by the same rules as folders (35-005 to 35-009), except that the video file itself cannot be asked for its time, so a date in a name falls back on the file's own time. A card left unchanged keeps its state and any running copy. A card that leaves the report is dropped, unless a copy is running; a card not reported for 30 minutes is dropped, unless a copy is running.
- Flag: differs: card clips can get a different recorded time from the same files looked at on the server, when a date in a name disagrees with the file's date.

### 35-050: Each card in a reader is shown with what it holds and where its copy stands.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: Shown per card: drive, kind, serial, label, camera (up to two camera models or guesses joined by "/", else the kind), state (ready, planned, copying, closed), number of clips (index files not counted), size, when detected and read, error, number of warnings, the computer, copy progress (state, done of total, bytes, and while copying the speed, time left, phase, current file), capacity, the card's fleet name (from the card tracker, else its label), a guess at which known card it is, and how many thumbnails are still missing. After a copy ends the card is ready again.

### 35-051: A person can close a card, which clears its clips' assignments, and bring it back while it is still in the reader.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: Closing is refused while a copy runs ("a copy is running for this card"). Closing drops every assignment of that card's clips. Closed cards still in a reader are offered back; bringing one back returns it to the state it was closed in, with its clips unassigned. If it has left the reader: "that card is not in a reader any more. Put it back in and it will be listed again."

### 35-052: Asking to read a card again changes nothing, and linking a folder or detecting a card on the server is refused.
- Where: footage-sorter-and-camera-cards / Recognising cards and drives
- What: Reading again only shows the card as it is (the editor's computer re-lists cards by itself). Linking a folder or detecting a card from the server is refused: the card is in a computer, and the app on that computer reads it. A live update stream for cards exists but never carries anything.
- Flag: unreachable

### 35-053: A card's thumbnails are made on the editor's computer and sent to the server.
- Where: footage-sorter-and-camera-cards / Thumbnails and hover filmstrips
- What: The server asks the editor's computer for every card clip still lacking a thumbnail (up to 2,000 per card, in recorded order), video and stills only (never sound, "other" or index files). Thumbnails come back in a large and small size, up to 2,000 per card at a time; unreadable ones are skipped. The card shows how many are still missing.

### 35-054: A person can plan a card copy to staging or straight into the sorted tree.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: Any signed-in person picks staging (refused, saying so, when no staging folder is configured) or the sorted tree (refused, saying so, when none is configured), and chooses clips or the whole card. The card's index files go only with a whole-card copy. Proxies are left out unless "Back up proxies too" is ticked (a server setting decides when it is not said, default off). The plan remembers the assignments as they stood. Refused for an unknown or closed card.

### 35-055: Copying straight into the sorted tree copies only assigned clips, and says which unassigned clips are already backed up.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: An unassigned clip is not copied. If it is already in the sorted tree (a recorded copy that exists with the same recording size) it is listed as unassigned but backed up, with where; otherwise as unassigned. The person can choose to stage the unassigned clips in the same copy. Destinations are spelled to match folders on disk, consistently within one copy. Automatic folders apply only if that setting is on.

### 35-056: Copying to staging files each card by day, time and camera, and the rest in a "loose" folder.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: Automatic folders are always used. Clips that get none go to "<day> <label, serial, drive or 'card'> loose" in the staging folder (forbidden characters replaced).

### 35-057: The plan shows, for each clip, whether it will be copied, skipped, resumed or written beside a different file.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: Not there: copied. Already there at full size (by the record, by the Sony recording id in a neighbouring metadata file, or a file of exactly the same size): skipped. There but smaller: resumed, and only the difference counts. A different file there: written beside it under another name. Not at the target but already in the sorted tree elsewhere at the same size: left out, and not counted against space, unless chosen. Two clips that would land on the same name: the second is written beside. A clip with nothing to copy (only proxies left out) is skipped. Clips are grouped by automatic folder or destination, each showing its path, whether it exists, whether it merges into an existing folder, camera, day, size, counts per state, and its clips (copies first, then collisions, then skips).

### 35-058: A copy plan warns about long paths and too little free space.
- Where: footage-sorter-and-camera-cards / Drives, speed and interruptions
- What: "long path (N): <path>" for a target over 240 characters. "not enough free space on <target>: need X + Y margin, have Z" when free space is less than needed plus a margin (default 256 MB, a server setting); the plan is then not ready. Unknown free space counts as enough.

### 35-059: Any signed-in person can start a card copy, which runs on the computer the card is in.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The copy runs on the editor's computer holding the card and needs that computer to reach the NAS's footage share. It is checked after copying. There is also a one-step "stage these clips" that plans and starts in one go. Refusals: "plan first"; "that plan is stale: plan again"; "a copy is already running for this card"; "assignments changed since the plan was made: plan again"; "nothing to copy: every selected clip is already there"; unknown card; and, on a copy run without the studio server or with no NAS footage share, that card copies cannot run here. Changing "Back up proxies too" re-plans first. Clips can be chosen within the plan; with none chosen, clips already elsewhere in the sorted tree are left out.

### 35-060: A card copy shows live progress and can be cancelled.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: About every 2 seconds: bytes and files done of total, current file, speed, time left (while copying) and phase (copying or checking). Speed, time left, phase and current file show only while the copy runs and the last news is under 30 seconds old. Before the first news, a rough progress bar. States: queued, copying, then done, error or cancelled. The status also shows the plan, mode, times, groups, errors and how many clips are unchecked. Any signed-in person can cancel; cancelling with nothing running just says so.

### 35-061: The server checks a card copy for itself and never takes the editor's computer's word for it.
- Where: footage-sorter-and-camera-cards / Checking a copy
- What: A copied file counts only if it was asked for, landed where planned, the planned place is inside the NAS footage share (following links), and a file of the planned size is really there. A file written beside a different one may have another plain name in the same folder. Each refusal is listed on the copy, naming the file and saying which: not a file this copy asked for (ignored); reported at a place other than the planned one (ignored); planned place outside the NAS footage share (ignored); a name it may not be written under (ignored); a name outside the share (ignored); not at the place with the expected size (not counted). A file left alone is listed as "left alone, a different file is at <path>"; a failure names the file and why. A clip missing its recording or some files is an error ("not copied", "N of its files not copied"). A file once checked stays checked when a retry skips it.

### 35-062: After a card copy, checked clips count as sorted or staged, and a fully backed-up card may be marked safe.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Every clip that landed is recorded with its origin card. Only a fully checked clip then counts: copied into the sorted tree, its assignment is done; copied to staging, its assignment carries over to the staged copy, so it shows assigned there and the next move takes it. Every checked copy on the NAS is also recorded as a trusted copy (a failure to record never undoes a copy). A partial report applies what landed and keeps the copy open for a retry. A copy ends done only if every clip was copied, else error, or cancelled. A copy that ends done with nothing unchecked may mark the card as backed up. After any report the folders are re-read and a full look starts, so the copies show. If the copy job ends without a report, the copy ends as an error (or cancelled) with the job's reason, or saying the editor's computer finished without reporting what it copied, nothing is recorded, and the next look finds whatever landed.

### 35-063: An admin can copy files from one drive to another on the same computer, or between a drive and the NAS.
- Where: footage-sorter-and-camera-cards / Copying a card
- What: The admin chooses the computer, the source and target drive, files or a folder, and optionally a target folder. Only adds: files already on the target are left out. Runs on the computer holding the drive and is checked after copying; the NAS end is checked on disk. Refusals, in words: the record of every copy is not available; no studio server to run it; source, target and files are required; "copy to a different volume"; the target folder must be a folder path; no NAS footage share; only a drive plugged into a PC, or the NAS, can be copied; the drive is not plugged into any reporting computer right now; the two drives are on different computers; NAS to NAS needs a drive plugged into a PC; that computer does not have those drives (they are on another); nothing to copy. Progress, errors and cancelling (admin) as for a card. A copy into the NAS triggers a fresh look. The 40 most recent drive copies are kept.

### 35-064: The automatic backup of drives to the NAS skips what is already there and runs only on the home network.
- Where: footage-sorter-and-camera-cards / Backed up and safe to format
- What: Files already on the NAS anywhere are left out, at most 2,000 files go at a time, and the copy runs only when the computer is on the studio's home network (round trip within 15 ms by default). It is checked on a regular interval (about every hour by default, never more often than every minute).

### 35-065: Running copies appear in the activity list.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: As "Copying <card label or serial> to the NAS" and "Copying <drive> to <drive>", each with phase, bytes, files, speed, time left, current file and start time.

### 35-066: Drives and watched folders can be listed and their clips browsed; watched folders are read on an interval.
- Where: footage-sorter-and-camera-cards / The record of every copy
- What: Anyone signed in can list drives, a clip's known copies and a drive's clips (5,000 at a time), the open questions about footage, footage not at home, and the activity list. An admin adds a watched folder on a drive (a drive must be named), with a label and how often it is read (default every 60 minutes), and can remove, read now, or switch its automatic backup. Messages: unknown clip, unknown volume, a number expected, the record of every copy is not available, already finished or answered.

### 35-067: The Sorter does regular work on its own through the day and night.
- Where: footage-sorter-and-camera-cards / The sorter page
- What: A person notices: new footage within about 20 seconds; the sorted tree re-read about every minute; the calendar about every 15 minutes; missing thumbnails filled about every 6 hours; cards no longer reported dropped after 30 minutes; a full look every night at 03:30; the record backed up every night at 04:00; the whole NAS footage share walked every night at 04:30. A failure in any of these is only logged and nobody is told; the work tries again next time.

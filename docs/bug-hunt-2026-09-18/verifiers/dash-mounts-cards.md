Wrong word, action still legal (MAKE CURRENT on the locally held bytes is a valid act), conflict already surfaced elsewhere: low.
- Evidence: `release_feed.py:513-545` (`_valid_records`, the `recalled` set), `:789-792` (cache population from `_valid_records`), `:682` (`verified_records` reads that cache), `db.py:4102-4127` (the only `retracted_at` writer), `grep -rn retract_package dashboard/src` -> one caller. `admin_packages.html:169-191` (the `vendor_row` macro), `:411`/`:421` (the conflict and recall blocks).
- Fix note: carrying `retracted` into the vendor dict would be dead code today; the honest fix is the sha one - give a sha mismatch its own state word in `_vendor_rows` and suppress MAKE CURRENT for it, or cross-link the row to the `sha_conflicts` block. ## dash-cards-5
- Verdict: CONFIRMED (medium, as rated)
- Duplicate of: none
- Reasoning: confirmed in the installed a2wsgi: `WSGIMiddleware.__init__` builds `ThreadPoolExecutor(thread_name_prefix="WSGI", max_workers=workers)` eagerly (`dashboard/.venv/Lib/site-packages/a2wsgi/wsgi.py:153-159`), and `cards.py:620` passes `workers=24`. `CardsDispatch._gates` is written at `cards.py:461` and appears nowhere else in the tree - there is no deletion path - so a dropped slug's `(asgi, gate)` tuple stays reachable from the mounted dispatcher for the life of the container, with whatever WSGI threads that executor has already spawned. Two honest mitigations that the finding should carry but that do not refute it: the same-slug reopen case IS handled (`_gates` is keyed on the app identity, so a reopened episode replaces the tuple and the old middleware becomes collectable, and CPython's `_worker` weakref callback then drains its idle threads); and the executor spawns threads lazily, so the leak is "as many threads as that episode concurrently used", not 24 per close. Still a real unbounded accumulation that sits directly against §12's thread accounting.
- Evidence: the a2wsgi source above; `grep -n "_gates" dashboard/src/ccsync_dashboard/*.py` -> three hits, all in `cards.py`, none a delete; `cards_pool._stop` clears `entry.asgi` only.
- Fix note: the fix is right but needs a seam - `EnginePool` has no reference to the dispatcher today, so either pass an eviction callback into `EnginePool` at construction (`cards.py`'s `mount_cards`) or have `CardsDispatch` prune `_gates` for any slug `pool.get(slug)` no longer knows. `executor.shutdown(wait=False)` on the discarded middleware is the other half and must not be called while a request is in flight on it. Touches `cards.py` and `cards_pool.py`; `test_cards_pool.py`'s close tests would need the new callback wired in their fake.

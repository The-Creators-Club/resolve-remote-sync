## security-1
- Verdict: CONFIRMED (medium)
- Duplicate of: none (dash-cards-6 is the adjacent "a mid-build episode is closable once its opener's 15 minutes lapse"; this one is about a READY engine with a live-but-offline occupant, and they want one fix)
- Reasoning: I could not refute the mechanism. `Entry.seen` is stamped only from `CardsDispatch._note` (a request SERVED through the mount) and `cards_landing.cards_open`; `cards_tunnel`'s `/cards/agent/*` never calls `note_visit`, so an editor whose companion agent is driving Resolve against that engine holds no seat either. After `ACTIVE_SECONDS` of no served request `occupants()` is empty and `may_close` returns "" for every signed-in session, and the landing template draws `[ CLOSE ]` from exactly that. What narrows it: the page polls the server roughly twice a second while online (`multicam_pipeline/cards/page/01-state.js`), so "left the tab open and went to Resolve" keeps the seat - the exposed cases are a genuinely offline session (the shipped feature the same fix pass protected when it narrowed the `sw.js` kill switch), a sleeping phone, and a tab a laptop suspended. What keeps it at medium rather than low: `drop()` is not free by its own docstring (three upstream threads leak per close, per CLAUDE.md), the close can land mid-conform, and the actor set widened from "admins only" to "every signed-in session". What keeps it off high: no data is destroyed - the engine's state is on disk under `<data>/cards/<slug>` and a rebuild replays against it - and the worst realistic outcome is a rebuild plus, if both seats are taken meanwhile, a cap refusal with the edits still queued in the browser.
- Evidence: scratch probe against the real `cards_pool` in the dashboard venv (test object only, no live dashboard): `occupants: ['alice']` / `may_close(bob) while alice active: 'somebody else is in that episode. ...'` / `occupants after 15 min quiet: []` / `may_close(bob) after quiet: ''`. Plus reads of `cards_pool.py:228-231, 329-339, 399-430, 469-489`, `cards.py:498/538-552`, `cards_landing.py:112-116, 183, 223`, and a grep showing `note_visit` has exactly those two callers. KNOWN_BUGS:26407-26418 documents CR-285P's intent and carries no open entry for this neighbour.
- Fix note: do not simply lengthen `ACTIVE_SECONDS` - that trades this against the wedge CR-285P exists to end. The honest fix is a second liveness signal: have the page beat while offline is impossible, so instead treat an episode as occupied while the OFFLINE seam has unacknowledged work (the page's last known rev) or while `cards_tunnel` has seen an agent for that slug, and make the close a confirmed act that names who was last in and when ("nobody has been in for 22 min" beside the button).

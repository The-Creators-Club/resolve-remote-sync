# Knowledge base part M06

## Entries

### M06-001: A delete on the NAS share reported success but the file was still there.
- What was going on: From Windows, deleting a file on the NAS share sometimes returned success while the file stayed; files another program had just renamed were the ones affected.
- What the product must do: After deleting or replacing a file on the NAS share, the product re-lists the folder and treats a file still present as a failed delete, not a success.
- Kind: 1a
- Capability: proxies-and-file-moves
- Found by: real use
- Date: 2026-08-14
- State: a standing rule
- Sources: M-home-truenas-nfs-mount

### M06-002: Long Chinese file names failed to save onto the NAS from Windows.
- What was going on: A NAS mount limits a file name to 255 bytes, not 255 characters; a long Chinese title (3 bytes per character) passes Windows checks but fails with "Invalid argument".
- What the product must do: Any file name the product creates on the NAS, such as one built from a video title, is cut to fit 255 bytes in its encoded form, never 255 characters.
- Kind: 1a
- Capability: youtube
- Found by: real use
- Date: 2026-08-14
- State: a standing rule
- Sources: M-home-yt-batch-downloader, M-home-ytdlp-403-nightly-fix

### M06-003: YouTube refused anonymous bulk downloads although search still worked.
- What was going on: YouTube bot-checks anonymous downloads while search and details keep working; Chrome and Edge sign-in cookies cannot be read while the browser runs.
- What the product must do: When YouTube refuses a download as a bot check, the product says so plainly and does not report it as a missing video or a network fault.
- Kind: 1a
- Capability: youtube
- Found by: real use
- Date: 2026-08-08
- State: a standing rule
- Sources: M-home-yt-batch-downloader

### M06-004: Every YouTube download died with "403 Forbidden" partway through.
- What was going on: The downloader started each video fine, then failed 40 to 70% in; only its newest pre-release fixed it, and switching the YouTube player it imitates led to false "DRM protected" or no formats.
- What the product must do: A download that fails mid-stream with 403 is reported as "the downloader needs updating" and the downloader can be updated without a product release.
- Kind: 1b
- Tool: yt-dlp
- Capability: youtube
- Found by: real use
- Date: 2026-08-14
- State: a standing rule
- Sources: M-home-ytdlp-403-nightly-fix

### M06-005: Copying to the NAS one request at a time ran at half speed.
- What was going on: Over a 10 gigabit link, 1 MB writes with one in flight reached about 390 MB/s; four in flight held about 785 MB/s across 160 GB.
- What the product must do: Any bulk copy the product makes to or from the NAS keeps several requests in flight and sustains at least 80% of a buffered Windows file copy's speed.
- Kind: 1a
- Capability: footage-sorter-and-camera-cards
- Found by: real use
- Date: 2026-09-26
- State: a standing rule
- Sources: M-home-truenas-nic-rx-discards

### M06-006: Rendering proxies on the NAS during a card offload halved both.
- What was going on: The NAS disks are one shared bottleneck; reading footage for proxies while a card offload writes cuts both jobs' speed roughly in half.
- What the product must do: Proxy rendering that reads from the NAS does not run while a camera-card offload to the NAS is in progress, or yields to it.
- Kind: 1a
- Capability: fleet-jobs
- Found by: real use
- Date: 2026-09-03
- State: a standing rule
- Sources: M-home-truenas-nic-rx-discards

### M06-007: A copy inside the NAS share was slow, while a rename was instant.
- What was going on: Copying a file within the NAS share from Windows still reads and rewrites every byte on the NAS disks (190 to 450 MB/s); a rename moves no data.
- What the product must do: Moving a file to another folder on the same NAS share is done as a rename, never as a copy then delete.
- Kind: 1a
- Capability: proxies-and-file-moves
- Found by: real use
- Date: 2026-09-09
- State: a standing rule
- Sources: M-home-truenas-smb-block-cloning

### M06-008: Blackmagic Disk Speed Test showed the NAS writing at 119 MB/s.
- What was going on: Blackmagic Disk Speed Test writes through the cache, forcing slow committed writes on a NAS; a normal buffered copy to the same share ran at 758 MB/s.
- What the product must do: Any NAS speed figure the product shows or tests against comes from buffered large-file writes and reads, never from write-through or cached reads.
- Kind: 1a
- Capability: server-install-and-running
- Found by: real use
- Date: 2026-07-21
- State: a standing rule
- Sources: M-home-truenas-smb-sync-write

### M06-009: Windows could create files on the NAS mount but not list or read them.
- What was going on: The Windows built-in network-file client checks the file's "other" permission bits itself; with "other" set to none, reads and listing fail with "Access is denied" whatever the NAS allows.
- What the product must do: Setup verifies that an editor's computer can list, read, write and delete in the shared tree, and names which of the four failed.
- Kind: 1a
- Capability: server-install-and-running
- Found by: real use
- Date: 2026-07-24
- State: a standing rule
- Sources: M-home-truenas-nfs-mount

### M06-010: NAS snapshots keep deleted footage using space until they expire.
- What was going on: An unchanged snapshot costs almost nothing, but footage deleted from the NAS stays on disk for the whole retention window; on TrueNAS, two schedules sharing a name pattern prune each other's snapshots.
- What the product must do: Media snapshots are kept weeks, not months, and every snapshot schedule the product sets up has its own distinct name pattern.
- Kind: 1a
- Capability: server-install-and-running
- Found by: real use
- Date: 2026-07-22
- State: a standing rule
- Sources: M-home-truenas-snapshots
